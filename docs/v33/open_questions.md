# V3.3 问题记录

编号 V33Q-01 起；V3.2.1 及以前的问题见 docs/v321/open_questions.md 等各阶段文件。新问题接着往下编号，写现象、做法与状态，每条几行。

### V33Q-01 构建脚本要求 `python3`，Windows 构建机上是应用商店占位程序（低，V33-A-01）

* 现象：V321-Z 构建发布包时，本机 `python3` 是占位程序，要临时定义 shell 函数指到 `python` 才能构建（docs/acceptance/V3.2.1升级记录.md）。
* 做法：依次试 python3、python、py -3，以能真正执行为准；可用 `PYTHON` 指定。见 PLAN A-01。

### V33Q-02 升级包每次带全部镜像（中，V33-A-02）

* 现象：3.2.1 包 9.4 GB，转写、翻译等模型镜像多数版本不变，也随包传输、导入。
* 做法：`--base` 指定上一版包，按各镜像构建目录的 git 差异决定重建或沿用；upgrade.sh 按镜像 ID 核对服务器已有镜像并打新标签，缺失则在备份前停止；install.sh 拒绝增量包。见 PLAN A-02。

### V33Q-03 会议纪要旧数据兼容未验证（中，V33-B-01）

* 现象：V321-Z 无录音样本，只验证了旧审核、旧会话、旧翻译（V321-Z 遗留第 1 条）。
* 做法：本机合成虚构录音，在 v3.1.0 上造旧会议，换 main 后逐项打开。见 PLAN B-01。

### V33Q-04 真实模型是否按提示词写依据编号（中，V33-B-02）

* 现象：E-13 的锚点只用模拟回复验证过（V321-Z 遗留第 2 条）。
* 做法：约 12～16 次真实调用、虚构样本，统计可定位比例、变体写法与错指；必要时放宽本地识别或改提示词说明。见 PLAN B-02。

### V33Q-05 是否加统一的“页面不存在”页（用户 2026-11-15 确认做，承接 V321Q-67）

* 现状：未知路径直接回首页、不提示；任务 / 会话不存在时各页就地提示（不区分他人与不存在）。
* 建议：只为未知路径加一个主框架内的“页面不存在”页，各页就地提示不变。方案见 PLAN B-03，用户 2026-11-15 随计划确认。

### V33Q-06 缺必选项时按钮变灰，用户找不到哪里没选（中，V33-C-01，已处理）

* 现象：用户反馈确认页按钮灰着，找“业务立场”花了好几秒；灰按钮点了没反应，条件清单是按钮上方的灰色小字。合同只有甲乙方标签时立场按设计不带默认值（V321-C-01），这种情况常见。
* 处理：见 PLAN C-01；规则写入 frontend.md 第七节第 4 条。

### V33Q-07 采纳或忽略后还要再点一次才收起（低，V33-C-02，已处理）

* 现象：用户反馈问题卡点了采纳 / 忽略后仍展开，要再点标题收起才能看下一条；快捷键 A / I 早已会跳到下一条待处理，点按钮却不会。
* 处理：点按钮与快捷键行为一致，见 PLAN C-02。

### V33Q-08 工控合同的技术词被替换（中，V33-C-03，已处理）

* 现象：用户在服务器的真实合同（汽轮机拖动项目）确认页看到“施工”被当人名替换，DCS、PTO、PLC、土建、汽阀总成列为待判断并默认替换，型号“WZP-014S Pt100”只切出 WZP；“IP55，PLC”被当成英国公司（PLC 后缀）列为签约方。
* 处理：见 reports/V33-C-03.md。型号按用户意见整体作为一个待判断项，不默认保留。
* 续（用户追问举一反三）：用虚构多工种技术文本归出 8 类同类问题并改成规则（短代号、标准代号、技术缩写、设备名、岗位、部门、“动词 + 电厂”、标签后职务）；“普通词 + 公司 / 厂”仍列为待判断，因为真实字号也常由普通词组成。

### V33Q-09 知识库片段因“公司”“财务总监”整段不发（中，V33-B-02 发现，未处理）

* 现象：虚构的公司制度片段“公司作为付款方时……须经财务总监审批”，问题脱敏把“公司”（3 处）和“财务总监”识别为疑似名称（reason=ner），kb/retrieve.protect 遇到疑似项就整段丢弃（kb_dropped），模型拿不到最相关的制度，用户只看到“未发送 1 段”。公司制度里“公司”“总监”等写法很常见。
* 建议：知识库片段的疑似项按普通名称处理或只替换不丢弃（与问题脱敏的疑似项处理一致），或把“公司”“财务总监”等通用称谓加入通用词；属于脱敏行为，需另开任务并补 golden 样本。
