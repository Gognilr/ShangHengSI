## 原因与改动

| 现象 | 原因 | 改动 |
|-|-|-|
| “施工”当人名（确定替换 8 处） | “姓 + 称谓”规则把“施 + 工”当作“王工”，在“及施工图纸”处命中后全文传播 | detect.find_persons：姓字与后文连成普通词（plain.surname_in_word，用普通词库切分）时不算称呼；“王工”“方经理”不受影响 |
| “IP55，PLC”当签约方 | PLC 在英文企业后缀表中，识别副本把全角逗号折成半角后与 IP55 连成名称 | parties：PLC 只认“英文单词 + 一个空格 + PLC”（Barclays PLC） |
| DCS、PTO、PLC 待判断 | 实体识别中置信，缩写不在 plain_terms | plain_terms.txt 增工控、电气、仪表通用缩写与 Pt100、IP55 等 37 条 |
| 汽阀总成 待判断 | 实体识别中置信，“汽、阀”不在普通词库 | 实体识别中置信结果为“2～6 字 + 总成 / 装置 / 系统 / 阀 / 控制器 / 传感器 / 热电阻……”且无名称证据时自动保留，原因“设备或部件名称”（suspects.ordinary_reason；前端 AUTO_KEPT_REASON 加一条） |
| 型号只切出 WZP | 实体识别把连字符型号切开 | 实体识别中置信结果落在字母数字型号中间时扩到整个型号，空格后紧跟的含数字规格段并入（suspects.model_token），仍为待判断 TERM |

“土建”是连带修复：“施工”不再被替换后，实体识别不再在“土建”处给出名称。

## 续：举一反三（同日，用户追问“同类问题能否举一反三”）

用三批虚构技术文本（电气、仪表、DCS、机械、土建、化工、IT 系统、环保、英文技术条款，约 100 行）跑引擎，逐条看全部替换与待判断，归出同类问题，改成规则而不是逐词补：

| 类 | 例 | 改动 |
|-|-|-|
| 短代号 | WCB、OA / OB / OZ | 实体识别中置信的 2～3 个大写字母自动保留（原因“短代号”） |
| 标准代号 | TSG 21-2016 | 标准号前缀加 TSG、JJG、JJF、CECS、HJ、AQ、GA、SY、JC、CJ、JTG、TB、MT、DB××、QC、WS、FZ、YS、NFPA、NACE、MSS、UL |
| 4 字母以上缩写 | TEFC、HART、XLPE、SPIR | plain_terms 再加通讯协议、IT 与工程文档缩写 36 条 |
| 设备名 | 主汽门、私有云、××器、××机、××炉 | 设备头词扩为单字“器 / 机 / 炉 / 塔 / 罐 / 门 / 云 / 柜 / 屏”与“管道、电缆、桥架、平台、软件、终端、网关”等（前面至少 2 字） |
| 岗位 | 实施顾问、起重工 | 角色后缀加 顾问、工程师、专家、师傅、班组长、班长、队长、组长、工（前段须是普通词；王工、刘班长仍是人名） |
| 部门 | 设备部（高置信也被替换）、安环部 | “2～4 字 + 部 / 处 / 科 / 室 / 车间 / 班组 / 工段”是内部部门；实体识别高置信的机构名命中泛称或部门时不替换 |
| 叙述 + 普通名词 | 接受电厂 | “公司 / 厂”前整段由普通词组成、末词含后缀（电厂）且前面是动词时为叙述文字 |
| 标签后职务 | 联系人：施工队长 | 3 字以上取值、姓字与后文连成普通词时按职务用语保留；“联系人：方圆”仍替换 |

另外：标准号、行业缩写与公共机构的命中先静默排除，不再进“已自动保留”清单。
