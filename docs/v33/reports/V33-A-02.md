# V33-A-02 增量升级包（Opus）

完成（2026-11-15）。

* **做法：**
  * build_release.sh 新增 `--base <上一版包目录>`：读基准包的 VERSION、images.txt（基准是增量包时另读 reuse.txt），要求本地有标签 `v<基准版本>`；对每个镜像的构建目录做 `git diff --quiet v<基准> HEAD`，无差异的沿用（不构建、不冒烟），写入 `images/reuse.txt`（镜像名 基准版本 镜像 ID）。包名 `aireview-<版本>-from-<基准>.tar.gz`；无镜像需重建时 images.txt 为空、不出 tar。不给 `--base` 时行为不变。
  * lib.sh：新增 `is_incremental_release`、`check_reused_images`；`load_release_images` 增加 profile 参数，tar 可缺省（images.txt 为空时），给沿用镜像打新版本标签，按 `COMPOSE_PROFILES` 核对主线四个及 transcriber / translator。
  * upgrade.sh 在快照确认与备份之前调用 `check_reused_images`；install.sh 遇增量包即拒绝。
  * 运维说明第 11 节加完整包与增量包、缺镜像提示、清理旧版本只用 `docker rmi` 不用 `prune -a`；第 13 节加 `--base` 用法与包名规则。
* **验收：**
  1. 本机以 3.2.1 包为基准、按 main（8d115b1）构建 `3.3.0-rc1` 增量包：只重建 web（v3.2.1 以来只有 frontend/ 有差异，与 git 一致），沿用 backend、converter、db、transcriber、translator。包 30,251,820 字节（3.2.1 完整包 9,364,742,888 字节）。
  2. 服务器 3.2.1 → 3.3.0-rc1：升级前备份成功；五个沿用镜像打上 3.3.0-rc1 标签，ID 与 3.2.1 相同；七个服务全部以 3.3.0-rc1 运行、健康；HTTPS 200、未登录 401；用户、任务、轮次、问题、文件、模型调用、法规计数与升级前相同，备份记录多 1 条（升级前备份）。
  3. 服务器上对增量包跑 install.sh：报“增量包只能用于升级，全新安装请用完整包”，未生成 .env。另用临时目录中的假 reuse.txt 调 `check_reused_images`，报缺 3.2.1 的 converter 镜像并给出 ID 前 12 位（据此把提示缩短为只写前 12 位，d5d34d0）。
  4. 完整包（不给 `--base`，d5d34d0）：`aireview-3.3.0-rc1.tar.gz` 9,364,740,435 字节，六个镜像全部构建并冒烟，没有 reuse.txt，文件清单与 3.2.1 包逐项一致（版本号除外）。backend 源码未变，但重建后的 ID 与 3.2.1 不同，印证了按源码而非按 ID 判断沿用的做法。
* **服务器现状：** 172.16.11.252 为 3.3.0-rc1（增量包升级），3.2.1 镜像标签仍在。
