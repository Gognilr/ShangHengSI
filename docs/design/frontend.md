# 前端界面规范

本文件是全部前端任务（`frontend/` 下的页面、组件、样式）共同遵守的界面约定，由 Opus 制定，经用户确认后生效。不论任务由 Sonnet 5.5 还是 GPT-6.1 Sol 执行，都按本规范实现；Opus 评审前端提交时也按本规范逐条检查。

* 与 docs/SPEC.md 冲突时以 SPEC 为准；与里程碑设计文档（docs/design/Mx.md）冲突时，以设计文档中针对具体页面的写法为准。
* 本规范从 M2 已完成的页面（新建审核、结果页基础版、审核历史）中整理而来。新页面应当看起来与这些页面属于同一个产品。
* 遇到本规范没写到的界面细节：先找现有页面中最接近的写法照做；仍然没有的，选 Element Plus 默认的做法，并在完成报告中写明。不要自己发明新的视觉样式。
* 修改本规范只能由 Opus 在 Mx-00 中进行，或经用户同意后修改。

## 一、总体原则

1. **克制、一致、清楚**。这是一个办公用的审核工具，不是展示型网站。不做渐变、阴影、动画、插画和装饰性图标，也不做大面积色块。
2. **只用 Element Plus 默认主题**。不改主题色，不引入其他 UI 库、图标库、CSS 框架或字体。图标只用 `@element-plus/icons-vue`，而且只在 Element Plus 自身需要时使用（如上传区、加载中）。
3. **颜色只用 Element Plus 的 CSS 变量**（`var(--el-…)`），不写十六进制颜色或 rgb 值。
4. **只做桌面端**。`body` 的最小宽度为 1280px（SPEC 21），不做手机适配，也不写媒体查询。
5. **信息优先**。用户最关心的内容（问题、结论、拦截原因、错误原因）放在显眼的位置，说明性文字用次要颜色和小字号。
6. **不增加 SPEC 没有的菜单、页面、按钮或功能**（CLAUDE.md）。觉得缺少什么，在完成报告中提出，不要自行加上。

## 二、页面骨架

### 2.1 主布局（已有，不要改）

`layouts/MainLayout.vue`：顶栏高 56px，左右内边距 24px。左侧是产品名（18px、加粗），然后是“智能审核”“审核历史”两个菜单；右侧是“设置”（仅管理员可见）和用户名下拉。顶栏下方是管理员提醒条，再下方是 `el-main`（内边距为 0，由页面自己控制）。

### 2.2 页面容器

每个页面的根元素是 `<div class="page">`，水平居中，上下内边距 16px，左右为 0。宽度只用下面四档：

| 档位 | 最大宽度 | 用在什么页面 |
|-|-|-|
| 窄 | 720px | 只有一个表单的简单页面 |
| 标准 | 900px | 新建审核（三个步骤） |
| 宽 | 1100px | 审核历史、结果页基础版、设置页 |
| 双栏 | 1600px，两侧各留 24px | 结果页（M3 起：左栏问题清单，右栏原文预览） |

```css
.page {
  max-width: 1100px; /* 按上表选一档 */
  margin: 0 auto;
  padding: 16px 0;
}
```

双栏页面：左栏宽 44%，右栏宽 56%，两栏间距 16px。右栏（原文预览）用 `position: sticky; top: 16px`，高度为 `calc(100vh - 56px - 32px)`，内部独立滚动。点击左栏的问题时只滚动右栏，不滚动整个页面。

### 2.3 页面内的结构

* 一个页面由若干**区块**纵向排列，区块之间的间距是 12px（用 `.gap`，即 `margin-top: 12px`）。
* 区块的容器是 `<el-card shadow="never">`。不要用 `shadow="always"` 或 `shadow="hover"`。
* 区块内的小节标题用 `<h3>`：15px、加粗，上间距 20px、下间距 8px（第一个小节的上间距可以小一些）。带编号的写法与第二步一致：“1. 文件信息”“2. 签约方确认”。
* 页面顶部需要标题时（如结果页的主文件名），用 16px、加粗，下间距 10px。
* 不用 `<h1>`、`<h2>`，也不再给页面加一个“页面名称”大标题，菜单和步骤条已经说明了用户在哪里。

## 三、字号、颜色与间距

### 3.1 字号（只用这几种）

| 字号 | 用途 |
|-|-|
| 18px | 顶栏产品名（已有） |
| 16px | 页面标题（如结果页主文件名） |
| 15px | 区块小节标题 `h3`、问题卡片标题 |
| 14px | 正文（Element Plus 默认，不必设置） |
| 13px | 表单项旁边的说明、卡片中的标签列、文件大小等次要信息 |
| 12px | 提示文字 `.hint`、固定声明（如制裁结论下方的“未联网核查……”） |

现有代码中 `.hint` 有 12px 和 13px 两种写法，统一为 12px（见第十节）。

### 3.2 颜色

| 用途 | 变量 |
|-|-|
| 正文 | 默认，不设置 |
| 次要文字、提示、标签列 | `--el-text-color-secondary` |
| 警告文字（如文件警告“检测到修订痕迹……”） | `--el-color-warning` |
| 只读文本块的底色（外发文本、可直接替换的措辞） | `--el-fill-color-light` |
| 引用左边框 | `--el-border-color`，3px 实线 |
| 页面底色 | `--el-bg-color-page`（已在 App.vue 设置） |

### 3.3 间距

只用 4、8、12、16、20、24px。常用的几处：区块之间 12px；筛选栏内的控件之间 8px；卡片内的行与行之间 6px；页面上下 16px；操作按钮区的上间距 20px。

## 四、组件用法

| 场景 | 用什么 | 约定 |
|-|-|-|
| 区块容器 | `el-card shadow="never"` | 见 2.3 |
| 数据列表 | `el-table border` | 页面主列表用默认尺寸（如审核历史）；区块内的小表用 `size="small"`（如文件信息、签约方、逐条结论）。空数据用 `empty-text` 写明原因，如“没有审核记录”。时间列宽 170px，操作列放在最右 |
| 键值信息 | `el-descriptions border size="small"` | 顶部信息栏，每行 4 项 |
| 表单 | `el-form label-width="110px"` | 单选用 `el-radio-group`，选项不超过 4 个时不用下拉框；多行输入写 `maxlength` 和 `show-word-limit` |
| 可选可输入的值 | `el-select filterable allow-create default-first-option` | 如签约方的国家、类型（Q-50 ②） |
| 筛选栏 | 一行 `display:flex; gap:8px` | 放在列表上方；下拉框用 `clearable`，占位文字写“全部等级”“全部类别”这样的说法 |
| 分页 | `el-pagination` | 放在表格下方、右对齐，上间距 12px；每页条数固定（审核历史每页 20 条），不提供切换 |
| 步骤 | `el-steps align-center` | 只在新建审核页使用 |
| 标签页 | `el-tabs` | 结果页：问题清单 \| 本地校验 \| 审核要求逐条结论（SPEC 6.3），数量写在标签名里，如“问题清单（7）” |
| 折叠内容 | `el-collapse` | 默认收起，展开时才加载内容（如“查看将发送的文本”） |
| 侧边说明 | `el-drawer`，从右侧打开，宽 560px | 审核要求抽屉（SPEC 6.5） |
| 对话框 | `el-dialog` | 表单类宽 480px，内容较多的宽 640px；主按钮放右边，“取消”放在它左边；提交中显示 loading |
| 删除等不可恢复的操作 | `ElMessageBox.confirm(…, { type: 'warning' })` | 写明删除什么、会连带删除什么、“无法恢复”；确定按钮文字写动作，如“删除” |
| 操作完成的短反馈 | `ElMessage.success` / `ElMessage.error` | 只用于用户刚刚点击的操作，如“已保存”“已删除”“文件类型已修改”。不要在页面加载时弹出 |
| 需要用户看到并处理的状态 | `el-alert :closable="false" show-icon` | 如拦截原因、解析失败原因、部分审核要求无法判断。持续显示，不要用会自动消失的提示代替 |
| 整页的结果状态 | `el-result` | 如解析失败（带“重新上传”按钮） |
| 没有内容 | `el-empty` 或表格的 `empty-text` | 说明为什么没有内容，必要时说明下一步怎么做 |
| 小标签 | `el-tag size="small"` | 颜色见第五节 |

不要使用：`el-carousel`、`el-timeline`、`el-avatar`、`el-backtop`、`el-tour`、骨架屏、通知框 `ElNotification`、全屏加载 `ElLoading.service`。

## 五、状态与颜色的对应

同一个枚举在所有页面用同一套颜色。枚举的中文翻译和标签颜色都集中写在 `src/utils/labels.ts`，组件中不要再各自定义一份（见第十节）。

| 枚举 | 对应 |
|-|-|
| 严重程度 | 高 `danger`、中 `warning`、低 `info`，用 `effect="dark"` |
| 审核要求结论 | 有问题 `danger`、未发现问题 `success`、不适用 `info`、无法判断 `warning` |
| 引用状态 | 引用已校验 `success`、待核实 `warning`、缺失型 `info`，用 `effect="plain"` |
| 问题类别 | 一律 `info` |
| 轮次状态 | 已完成 `success`、部分完成 `warning`、已被拦截 `warning`、失败 `danger`、排队中和审核中 `info` |
| 任务状态（历史列表） | 纯文字，不加颜色；解析失败可用 `--el-color-danger` 文字 |
| 制裁结论 | 文字显示，不加标签颜色；“高风险（建议合规人员或律师确认）”用 `--el-color-danger` 文字。下方固定声明不可省略 |

## 六、各种状态的表现

每个页面和区块都要处理下列状态，不能出现空白页面或一直转圈。

| 状态 | 表现 |
|-|-|
| 加载中 | 在要加载的区块上加 `v-loading`，不要整页遮罩；按钮操作期间按钮显示 `loading` |
| 加载失败 | `el-alert type="error"`，写明原因（取接口返回的中文 message）和下一步，如“加载失败，请刷新页面”。404 统一写“任务不存在或已被删除” |
| 没有数据 | `el-empty` 或表格 `empty-text`，见第四节 |
| 处理中（解析、排队、审核） | 区块居中显示加载图标和一句话（如“正在解析文件，请稍候……”），下方用 `.hint` 说明“可以离开页面，稍后从审核历史进入”。排队时显示“排队中，前面还有 n 个任务” |
| 轮询 | 每 3 秒一次（SPEC 21），任务结束或离开页面（`onBeforeUnmount`）时停止；同一时间只有一个请求在进行；网络错误不打断轮询，404 停止轮询 |
| 被拦截 | 第二步顶部显示 `el-alert type="warning"`：标题“上次提交被拦截，未发送给模型”，内容为拦截原因（只有类别和位置）和“请检查……后重新提交” |
| 失败 / 部分完成 | 结果页信息栏下方显示 `el-alert`（失败 `error`，部分完成 `warning`），写明原因 |
| 按钮不可用 | 必须能看到原因：在按钮附近用 `el-alert type="warning"` 或 `.hint` 说明，如“请先选择哪一方是我方”“未识别到签约方，暂时不能提交 AI 审核” |
| 接口 409 / 422 | 按错误码给出中文提示（如 `api/runs.ts` 的 `RUN_ERROR_MESSAGES`），没有对应时显示接口返回的 message；`TASK_STATE_CONFLICT` 时重新读取任务状态 |

## 七、按钮与操作

1. 每个区块最多一个主按钮（`type="primary"`），放在区块右下角（`.actions { margin-top: 20px; text-align: right; }`）。第一步的“开始解析”放在表单最后一项，与输入框左对齐，这是例外。
2. 表格行内的操作用文字按钮（`link`）：普通操作 `type="primary"`，删除 `type="danger"`，并按第四节做二次确认。
3. 页面上的按钮文字用动词开头、写清结果：“确认发送并开始审核”“重新上传”“导出报告”，不要写“确定”“提交”“OK”。对话框和二次确认框的标题已经说明了动作，里面的按钮可以用“确定”“取消”（如修改密码对话框），删除确认的按钮写“删除”。
4. 提交期间按钮显示 `loading`，防止重复点击；有修改正在保存时（如签约方保存中），相关的提交按钮也要禁用。
5. 修改一项就立即保存的控件（下拉框、单选），保存失败时恢复为服务端的值，并提示原因。
6. 复制按钮：先用 `navigator.clipboard`，失败时用 textarea 加 `execCommand` 兜底，与 `FindingCard.vue` 一致；成功提示“已复制”。

## 八、文字

1. 全部用简体中文，使用全角标点。中文与数字、英文之间加一个空格：“最多 10 个文件”“单个不超过 30 MB”“5 个工作日”。
2. 接口返回的代码（状态、类别、结论等）一律经 `labels.ts` 翻译后显示，界面上不出现 `awaiting_confirm`、`issue` 这类英文代码。未知代码原样显示（labels.ts 已有兜底）。
3. 提示语写“发生了什么 + 用户该做什么”：“出口复检发现未脱敏的信息，已拦截，未发送。请检查签约方和外发文本后重新提交。”不写“操作失败”“系统错误”这类没有信息量的话（作为兜底除外）。
4. 不用感叹号，不用“您”，不用“亲”“哦”等口语。称呼用户时不写主语，直接写动作：“请先选择要审核的文件”。
5. **界面中不得出现“审核通过”“无风险”字样**（A-08）。“无明显风险”是 SPEC 规定的制裁结论档名，可以使用。没有问题条目时写“本次没有列出问题条目。结果由 AI 生成，仅供参考，请以人工复核为准。”这类说法，不要写“文件没有问题”。
6. SPEC 中写明的文字（如 6.2 的占位提示、6.3 的固定声明、6.5 的说明文字）逐字照抄。
7. 时间一律用 `utils/time.ts` 的 `formatDateTime` / `formatDate`（按 Asia/Shanghai 显示，格式 `2026-10-16 16:10:16`），不要自己格式化，也不要显示“3 分钟前”这类相对时间。
8. 金额、数字按接口返回的原样显示，前端不做计算或重新格式化（金额计算只在后端用 Decimal 进行）。

## 九、安全相关的写法

1. 不使用 `v-html`、`innerHTML`、`ElMessageBox` 的 `dangerouslyUseHTMLString`。外发文本、原文引用、模型返回的文字都按纯文本显示（`<pre>` 或 `white-space: pre-wrap`）。
2. 不用 `console.log` 等输出任何内容；提交的代码中不留 `console.*`。
3. 本地存储（`localStorage`）只能存界面偏好（如上次的立场和来源，Q-51），不得存文件内容、名称、问题、对照表或任何接口返回的业务数据。
4. URL 中只放 ID 和页码、日期等筛选条件，不放文件名、公司名等文字（搜索关键词只在请求参数中传给后端，不写进地址栏）。
5. 所有请求经 `api/http.ts` 发出（自动带 CSRF 令牌、统一处理 401），不在组件中直接用 `fetch`。每个后端资源在 `api/` 下一个文件，接口类型与后端返回字段同名。
6. 前端检查（文件数量、大小、扩展名、必填项）只是提示，后端一定会再检查；不要因为前端检查过就省略对接口错误的处理。

## 十、代码组织

1. 组件一律 `<script setup lang="ts">`，样式一律 `<style scoped>`。不写内联 `style`（动态尺寸等必要情况除外）。
2. `views/` 放页面，`components/` 放页面拆出来的子组件。单个 `.vue` 文件超过约 400 行，或一个区块有自己的加载、保存逻辑时，拆成子组件（如 `ConfirmStep.vue`、`FindingCard.vue`）。
3. 公共样式：下一个修改页面的前端任务新建 `src/styles/common.css`（在 `main.ts` 中引入），把各页面重复的写法收进去，之后各页面不再各自定义：
   * `.page`，以及宽度修饰类 `.page--narrow`（720px）、`.page--standard`（900px）、`.page--wide`（1100px）、`.page--split`（1600px）
   * `.gap`（`margin-top: 12px`）、`.hint`（12px、次要颜色）、`.actions`（右对齐、上间距 20px）
   * `.filters`（`display: flex; gap: 8px; margin-bottom: 12px`）

   同时把 `ReviewResult.vue`、`FindingCard.vue` 中的 `VERDICT_TAG`、`SEVERITY_TAG`、`CITE_TAG` 移到 `labels.ts`。这项整理只改样式和常量的位置，界面效果不变，需写在该任务的文件范围内。
4. 枚举翻译、标签颜色只在 `labels.ts` 定义；接口调用只在 `api/` 定义；时间格式只在 `utils/time.ts` 定义。
5. 不新增依赖。确实需要时（如 M3 的 pdfjs-dist，已在 SPEC 第 3 节列出），按任务说明添加并锁定精确版本。

## 十一、提交前的自检

完成前端任务时逐项检查，并在完成报告中写明检查结果。

1. `npm --prefix frontend run build` 通过（含 vue-tsc 类型检查）。
2. 在浏览器中打开本任务涉及的每个页面（http://localhost:5173，需先启动整套系统；模型用模拟服务，见 deploy/docker-compose.mock.yml），窗口宽 1440px 和 1280px 各看一遍：
   * 没有横向滚动条，没有文字溢出、重叠或被截断；
   * 宽度、间距、字号、颜色符合第二、三节；
   * 第六节中与本页相关的每种状态都看过（至少：加载中、正常、没有数据、出错）；
   * 浏览器控制台没有报错（未登录时 `/auth/me` 的 401 除外）。
3. 搜索本任务改动的代码，确认没有 `v-html`、`console.`、十六进制颜色、“审核通过”“无风险”。
4. 能截图的，在完成报告中附上主要页面的截图；无法截图的，说明看过哪些页面和状态。

Opus 评审前端任务和里程碑验收时，按本规范逐条检查，并在浏览器中截图核对。
