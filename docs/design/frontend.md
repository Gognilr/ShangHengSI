# 商衡SI 前端界面规范 · 澄明

V3.5 起生效。页面以 2026-11-20 确认的澄明设计和 F-00 定稿为基础，功能与交互以 [SPEC](../SPEC.md) 为准。标志采用 A「衡线」，源文件见 [标志资产](v35/brand/README.md)，各页面见 [设计稿](v35/preview.html)。历史素纸版与 V3.4 标书视觉稿适用于其所在版本。

## 二、设计目标与原则

**目标**：打开就觉得清爽、有精神、值得信任；每一屏一眼看懂“这是什么、现在怎样、我该做什么”。

**四条原则**

1. **分层**：画布是浅冷灰，内容放在白色卡片上，浮层再高一层。页面、对象、临时的东西一眼分得开。
2. **颜色要表达意思**：青 = 本机 / 安全 / 主要操作；紫 = 大模型；红黄蓝 = 严重程度；绿 = 流程完成；四个模块各有识别色。颜色用“浅底 + 深字”铺开，不只是一个圆点。
3. **字够大、层级分明**：正文 14px 起，阅读 15px，页标题 24px，首页问候 36px。12px 只给徽标和计数。
4. **动效说明因果**：东西从它的来源处出现，状态变化有过渡，进行中的事在流动。不做无意义的循环装饰。

**高级感从哪里来**（每页自查）

| 做法 | 具体要求 |
|-|-|
| 留白 | 区块间距 40～56px；一屏只有一个视觉中心 |
| 元素少而准 | 每个区域只有一个主按钮；同一件事只说一次；进度只出现在一处 |
| 字号反差 | 标题与正文至少差两档；数字用等宽、加粗 |
| 材质 | 只有三层：画布、卡片、浮层。阴影柔和，带一点冷色 |
| 色彩集中 | 大面积是中性色，颜色只出现在有意义的地方，但出现时要铺开、要饱满 |
| 动效有分寸 | 进入 320～520ms，带弹性；悬停 200ms；不做闪烁、旋转等炫技 |
| 对齐 | 4px 网格；同一列的左边缘严格对齐；图标与文字基线居中 |

## 三、品牌与标志

### 3.1 名称与寓意

* **商衡**：“商”是商务往来；“衡”是秤杆，引申为把条款放平了称一称，公允地看双方。
* **SI**：Secure Intelligence，安全的智能（SPEC 第 1 节）。
* 产品机制：原件留在本机，真实名称遮住之后才交给模型，结果回来再在本机还原。

标志要把这三层意思装进一个简单图形。

### 3.2 设计要求

1. 寓意能用一句话讲清。
2. 16px（浏览器标签页）仍能认出；单色可用（Word 报告页眉、打印件）。
3. 最多两种品牌色：衡青加灵紫。渐变只用在应用图标底块。
4. 几何构造：24 网格，笔画为 2 的倍数，圆角统一。
5. 不用以下图形：
   * 盾牌、锁、天平实物（现在的 favicon 是盾牌加天平，显得土）；
   * 彩带交织、单独的四角星（这是常见 AI 产品的标志手法，没有辨识度）。

### 3.3 定稿「衡线」

纸框中部的衡青横线伸出纸边，右上角的灵紫星点代表模型。在标签页等小尺寸使用简化版本，标准、大尺寸和单色版使用 F-00 定稿资产。

### 3.4 交付规格（F-00）

* **SVG 源文件**：彩色、单色（墨）、反白（深底）三版。
* **favicon.svg**：深色标签栏下换亮一档。
* **应用图标**：180、192、512 的 PNG，配 manifest。
* **字标组合**：横排为“图形 + 商衡 + SI”，竖排为图形在上。文字转成路径，不依赖字体。
* **尺寸与留白**：
  * 图形最小 16px，横排组合最小 96px 宽；
  * 四周留白不小于横线高度的 2 倍。
* **不得**：拉伸、改色、加阴影、旋转（404 彩蛋除外）、放在花底上。
* **使用位置**：
  * 侧栏顶部：横排，图形 28px；
  * 登录页：图形 96px，带动效；
  * 首页问候：图形 44px，带动效；
  * favicon；
  * Word 报告封面与页眉：单色；
  * 404 页。

## 四、颜色（只写在 theme.css，页面只用变量）

### 4.1 中性色（偏冷，与青色协调）

| 用途 | 浅色 | 深色 |
|-|-|-|
| 画布 | #F3F6F9 | #0B0F14 |
| 凹面（文件舞台、分段控件底） | #EAEEF3 | #080B0F |
| 卡片 / 次级卡片 | #FFFFFF / #F8FAFC | #121820 / #161D26 |
| 悬停 / 选中 | #F1F4F8 / #E8EEF5 | #1A222C / #202A36 |
| 细线 / 强细线 / 弱细线 | #E1E6ED / #C9D2DD / #EDF1F5 | #222B36 / #2F3A48 / #1A212A |
| 文字：标题 / 正文 / 辅助 / 占位 | #0E1726 / #334155 / #5E6B7E / #94A0B2 | #EDF1F6 / #C6CFDA / #8E9AAB / #5E6A7B |

辅助字对比度不低于 4.5:1；占位色只用于占位符和禁用。

### 4.2 品牌、语义、模块

每种颜色都有三档：实色、浅底、深字（深字用于浅底上的文字）。

| 名称 | 实色 | 用在 |
|-|-|-|
| 衡青（主色） | 按钮 #078A76，图标与进度 #10A58C | 主要操作、选中、焦点光圈、链接、进度，以及一切“本机 / 安全”的标识 |
| 灵紫（模型） | #6D5BF6 | **只用于和大模型有关的东西**：模型徽标、模型步骤、生成中、“AI 建议”分区、AI 视野。看到紫色就知道这部分出过网关 |
| 严重 / 高 | #E5484D | 严重问题、高等级、失败 |
| 注意 / 中 | #F2A20C | 中等级、待你处理、被拦截 |
| 提示 / 低 | #1E95E0 | 低等级、进行中、说明 |
| 完成 | #1FA05A | 只表示**流程完成**，绝不表示“文件没问题” |
| 模块识别色 | 审核 #10A58C，标书 #EE7A1E，纪要 #E14E86，翻译 #1E95E0 | 模块图标底块、首页模块插画、侧栏选中图标、近期会话圆点。不用于按钮和文字 |

脱敏类别色沿用七类，并提亮一档：单位蓝、人名紫、联系方式青、证件橙、地址橄榄、金额琥珀、其他灰。深色模式全部单独取值，不用反色。

令牌的实际取值与兼容映射以 `frontend/src/styles/theme.css` 为准。原有 `--si-ink-*`、`--si-hair-*`、`--si-surface-*` 保留名称并按澄明取值。`--si-accent` 映射到灵紫，`--si-ok` 用于表示流程完成。选中与悬停底为半透明色（V35Q-21）。

### 4.3 渐变与氛围光（只有这些地方可以用）

1. 标志的应用图标底块。
2. 头像。
3. **氛围光**：只在首页顶部和登录页品牌区。
   * 用衡青、灵紫、少量天蓝的大块径向渐变，浅色不透明度不超过 12%，深色不超过 18%；
   * 24 秒缓慢漂移；
   * 只动 transform，不用 filter 模糊；
   * 精简档静止，关闭档不显示。
4. 进行中的进度条（青到紫流动）。
5. 模型“正在生成”的指示。

静止的按钮、卡片、页面背景一律用纯色。

## 五、字号与字体

字体是 SI Sans（Noto Sans SC 子集，400～600）。数字一律等宽。

| 档 | 字号 / 行高 · 字重 | 用于 |
|-|-|-|
| 主视觉 | 40 / 52 · 600，字距 −0.02em | 登录页主标题 |
| 问候 | 36 / 44 · 600，字距 −0.02em | 首页问候 |
| 页标题 | 24 / 32 · 600 | 每页一个 |
| 区块 | 18 / 26 · 600 | 卡片组标题、侧栏面板标题、模块卡片标题 |
| 卡片标题 | 16 / 24 · 600 | 问题标题、列表主行 |
| 阅读 | 15 / 28 · 400 | 文件正文、模型回答、建议条文、逐字稿、译文 |
| 正文 | 14 / 22 · 400 | 界面默认：按钮、表格、说明 |
| 辅助 | 13 / 20 · 400 | 只用于时间、来源、位置 |
| 标签 | 12 / 16 · 500 | 只用于徽标与计数 |

* 说明性文字不得用 12px；13px 在一屏中不超过三成。
* **新增“字号”外观选项**：标准 / 较大 / 特大，倍率 1 / 1.07 / 1.14。放在设置的“个人”分页。

## 六、表面、圆角、阴影、间距、图标与插画

**表面层级**

| 层 | 外观 | 用于 |
|-|-|-|
| 画布 | 画布色 | 页面背景 |
| 卡片 | 白底，1px 细线，极浅阴影 | 一切成组的内容 |
| 抬起 | 阴影加深，上移 3px | 可点卡片的悬停状态、首页输入框 |
| 浮层 | 最深一档阴影 | 下拉、弹窗、抽屉、全局搜索、Toast |
| 纸面 | 纸色，纸面阴影，放在凹面舞台上 | 原文预览、译文、逐字稿 |

**圆角**：控件 10，卡片 14，大卡片 18，首页输入框 24，浮层 16，纸面 6，徽标全圆。

**毛玻璃**：只在完整档使用，只有两处——首页输入框、全局搜索浮层。精简和关闭档用实色。基线机器没有显卡，不能处处模糊。

**间距**：4 为基数。
* 卡片内边距 20～24，卡片之间 16；
* 区块之间 40～56；
* 页面两侧 40（1366 以下 28）。

**控件高度**：默认 36，小 30，大 44。表格行高约 56。

**图标**：lucide，线宽 1.75。
* 尺寸：按钮内 16，导航 18，卡片标题 20，空状态 24（放在 56px 的浅色圆内）。
* 模块图标统一放在 40～44px 的圆角方块里，底色用模块浅底。

**插画**：只在首页模块卡片、空状态和 404 页出现。
* 线条风格，用模块色，单个不超过 30 个元素；
* 悬停时才动，只动 transform 和 opacity；
* 放在 components/brand/illus/。

## 七、布局：外壳与五种页面模板

**外壳**：左侧栏宽 248px，白底，可收起到 68px（宽度小于 1280 时自动收起）。右边是画布，页面放在上面。

| 模板 | 用于 | 结构 | 内容宽度 |
|-|-|-|-|
| ① 中枢页 | 工作台 | 氛围区 → 问候 → 输入框 → 模块 → 待你处理 | 主列 880，模块区 1040 |
| ② 入口页 | 文件审核、会议纪要、翻译的首页 | 页标题和一句说明 → 大号拖放区或二选一的大卡片 → 最近 5 条 | 960 |
| ③ 工作区 | 脱敏确认、审核结果、标书项目、会议、翻译 | 顶部 64px 工具条 + 主体两栏（纸面 + 右栏 420～460，或清单 + 证据） | 占满 |
| ④ 列表页 | 历史记录、标书项目列表、设置里的列表 | 页标题 → 筛选条 → 表格卡片 | 1200 |
| ⑤ 设置页 | 设置 | 页标题 → 左侧分组导航 220 + 右侧分组卡片 | 1200 |

**三条硬规定**

1. **进度只出现在一处**：工作区在顶部工具条；列表在行内徽标；首页在文件标签上。结果区不重复显示进度。
2. **进度和结论分开**：没算完不出结论，只写“检查中”；扫描页还在识别时，结论标“初步”。
3. **一个对象一张卡**：文件、投标人、会议、项目都是卡片。卡片收起时只显示状态和计数，点开才看明细。

## 八、逐页设计

每页按这几项写：来这页做什么、布局、主次、各种状态、要改掉的旧问题。

### 8.0 外壳

* **侧栏自上而下**：
  1. 标志组合；
  2. “新建会话”：青色浅底大按钮；
  3. 工作台；
  4. 文件审查：文件审核、合同对比、标书初审；
  5. 工具：会议纪要、翻译；
  6. 历史记录；
  7. 搜索（Ctrl K）；
  8. 近期会话：最多 8 条，每条带模块色圆点；
  9. 账号行。
* **选中**：选中底色，字重 600，图标变成模块色；工作台、历史记录、搜索没有模块色，用衡青。
* **菜单右侧的数字**：只显示**等你处理的数量**（例如待确认脱敏 2），不显示总数。
* **账号行**：显示头像、姓名和所兼角色。点开菜单可查看管理员提醒、设置外观、修改密码及退出。管理员提醒用琥珀色圆点。
* **全局搜索**：屏幕居中的浮层，宽 640，结果按模块分组，键盘上下选择。

### 8.1 登录

* **布局**：左右分屏。
* **左侧品牌区（55%）**：
  * 深色底，加衡青和灵紫的氛围光；
  * 标志 96px 带开场动效；
  * 主标题 40px：“商务文件的安全初审助手”；
  * 副标题 16px：“原件留在本机，真实名称遮住后才交给模型，结果回来在本机还原。”；
  * 三个要点横排，每个配图标：原件不出内网、名称发出前遮住、几分钟出问题清单；
  * 页脚：版本号与“仅限公司内网使用”。
* **右侧**：400 宽的登录卡。
  * 标题“登录”24px，输入框 44 高，“记住账号”，满宽主按钮；
  * 错误显示在对应字段下方；
  * 首次登录需要改密码时，同一张卡切到第二步。
* **宽度小于 1280** 时隐去左侧，只留登录卡和标志。
* **去掉**：登录页漂浮的合同用字。

### 8.2 工作台（首页）：要高端、大气

**来这页做什么**：开始一项工作（拖入文件或直接提问），以及处理等着你的事。

**构图**（自上而下居中，整页只有一个视觉中心——输入框）：

1. **氛围区**：页面顶部约 420px 高的氛围光（4.3）。
2. **问候**：
   * 位置：距顶部约 10vh；
   * 标志 44px，带开场动效；
   * 问候 36px，例如“下午好，王经理”；
   * 一句副标题 16px：“把合同、标书或录音交给我。原件和真实名称只留在本机。”
3. **输入框**：宽 760，圆角 24，浮起一层，完整档带毛玻璃。
   * 框内上方是文件标签：文件类型色图标、名称、页数、状态。状态依次为“正在本机读取 · 第 3 / 12 页”（带细进度条）、“已遮住 37 处”、“等你确认”（琥珀色，点了去确认）。
   * 文件还在处理时，框内底部一行写：“文件处理完成后自动发送 · 取消”（问题 12：不再浮在页面左下角）。
   * 底栏：添加文件、模型（灵紫星点 + 模型名；外发策略为只在本机时显示青色“只在本机”）、业务立场、知识库（管理员开启时）。
   * 发送按钮：40px 圆形，衡青。
4. **快捷开始**：输入框下方一行 4 个文字建议，带图标，悬停浮起：全面审核这份合同、起草回复函、核对单证、比较几份报价。
5. **开始一项工作**：四张模块卡横排，每张约 240×208。
   * 上半部是模块插画：浅底加线条，悬停时动起来。
     * 文件审核：原文行上滑过一道高亮；
     * 标书初审：四张投标人小卡，其中一张变红；
     * 会议纪要：声波跳动；
     * 翻译：左右两列对齐。
   * 下半部：标题 18px、一句话 14px、状态行（例如“2 份等你确认”，或“上次：周例会 11-18”）。
6. **待你处理**：只列需要你动手的事，每行一个主按钮。
   * 包括：待确认脱敏、被拦截待处理、转写完成待校对、失败需重传。
   * 最多 5 条，没有就整块不显示。
   * 只用现有状态，不新增“未读”标记。
7. **页脚信任条**：一行 13px，带图标：“本月在本机遮住 1,284 处名称与金额 · 发送前复检拦截 3 次 · 模型调用 46 / 500 次”。只显示现有接口能给的数据，不为它新增统计表。

**不放**：最近列表（侧栏已有）、大统计卡、图表、公告横幅。

**动效**：
* 问候、输入框、模块卡依次浮现；
* 发出第一条消息后进入对话页（8.3），输入框平滑滑到底部，问候淡出。

### 8.3 对话页

* **布局**：中间一栏宽 800；输入框固定在底部，和首页是同一个组件；右侧可展开 360 宽的文件面板。
* **用户消息**：靠右，次级卡片底。
* **模型回答**：靠左，不加气泡，阅读字号 15px。开头一行灵紫小徽标：“DeepSeek · 只见遮住后的文字”。
* **结论分区**：
  * 本机计算的部分放在中性卡里，青色计算器图标，标题“本机计算 · 结果确定”；
  * 模型说的部分标题是“AI 建议 · 请核实”，用紫色。
* **等待**：
  * 本机读取附件时，用青色文字“正在本机读取附件”，不出动点；
  * 等模型首字时，出现紫色动点“模型正在思考”；
  * 首字到达后，由正文末尾的光标接手。
* **未能还原**：原文字保持不变，加琥珀色虚线下划线，悬停说明原因。

### 8.4 文件审核

**① 入口页（/review）**
* **结构**：
  * 标题“文件审核”，一句说明：“合同、报价单、订单、函件都可以。文件在本机读取和遮住名称，你确认后才交给模型初审。”
  * 大号拖放区：220 高，圆角 18，2px 虚线；中间放模块色图标，文字“拖入要审核的文件，或点击选择”；可接受的格式写在下面；支持 Ctrl+V 粘贴。
  * 拖放区下方是“最近的审核”5 条，加“全部历史”。
* **拖入时**：边框变模块色，底色变浅，放大 1.01，提示“松开即可加入”。

## 九、组件要点

* **按钮**：
  * 主按钮：衡青实底，每个区域只有一个；
  * 次按钮：白底细线；
  * 文字按钮：透明底；
  * 危险按钮：红字；
  * 按下时缩到 0.97；
  * 禁用的主按钮不能像可点：浅色为淡衡青底，深色为 16% 衡青底加禁用色文字（V3.5.1）。
* **徽标**：浅底深字的全圆胶囊，可以带图标。等级、状态、模型、本机都用它。
* **分段控件**：凹面底上一块白色滑块，切换时平移，只用于视图切换。**页签**：下划线，切换时平移。
* **二元决策切换**（V3.5.1）：会改变外发内容的决定（如不确定项的保留 / 遮住）不用白色滑块。选中侧写「已保留」「已遮住」，加对勾、字重 600，按含义着色：外发原文用琥珀浅底、琥珀细线和深琥珀字，本机保护用衡青浅底、细线和深青字。两列等宽，滑块平移，切换时宽度不跳；按钮带 `aria-pressed`，外层为带标签的 `role="group"`。
* **字号**：页面和组件里的固定 px 字号都乘以 `--si-fs`，随外观「字号」档缩放；只有标志字标的固定字号属于品牌资产，不缩放。
* **输入框**：获得焦点时边框变青，并带 3px 光圈。缺少必填项时，用虚线框标出，点按钮时滚过去并闪一次（沿用 V33-C-01）。
* **可点卡片**：悬停上移 3px，阴影加深，模块图标放大 1.08 并轻转。
* **投标人卡**：代号方块加字号；有严重问题时，顶部一条 3px 红线，边框偏红；选中时青色光圈。
* **文件标签**：类型色图标（PDF 红、Word 蓝、图片紫、录音玫红）、名称、页数、状态，以及处理中的细进度条。
* **步骤条**：已完成为青色实心对勾；进行中为浅底，图标转动，模型步骤用紫色；未开始为占位色。
* **证据并排**：左右两张纸面卡，卡头写代号、文件和页码，相同处用琥珀色浅底高亮，右上角可翻到上一处、下一处。

## 十、内容与文案：让每一屏一眼看懂

1. **每页一句话**：入口页、列表页和空状态，在标题下写一句话说明这页做什么，不超过 40 字。工作区不写。
2. **标题写对象本身**：用文件名、项目名、会议名，不写“任务详情”。
3. **状态写三件事**：在做什么、真实进度、你能做什么。例如“正在本机识别扫描页 · 第 23 / 76 页 · 可以离开页面”。
4. **数字带对象**：徽标里可以写“严重 2”，句子里写“2 个严重问题”。
5. **结论在前，理由在后**：问题卡片的顺序是一句话结论 → 为什么 → 依据与位置 → 建议条文。
6. **本机的和模型的分开说**：本机的用青色，写“本机计算 · 结果确定”；模型的用紫色，写“AI 建议 · 请核实”。
7. **长度**：卡片标题不超过 24 字；说明超过 80 字时折叠，带“展开”。
8. **不写内部术语**：

| 内部说法 | 界面写法 |
|-|-|
| 实体、敏感实体 | 名称、金额等 |
| 脱敏（动作） | 遮住；页标题和设置项里仍可用“脱敏” |
| 不确定项 | 需要你看一眼的 |
| 出口复检 | 发送前复检 |
| 还原 | 还原真实名称 |
| 外发策略 local_only | 只在本机处理 |
| 解析 | 读取 |
| 运行、run | 第 n 轮审核 |
| L-INFO | 无法核验 |

9. **全站文字**：全角标点；中文与数字、英文之间留空格；不用感叹号和“您”；界面不出现“审核通过、无风险、已安全、零泄露”；SPEC 规定的文字逐字照抄。

## 十一、动效

| 令牌 | 值 | 用于 |
|-|-|-|
| `--ease-out` | cubic-bezier(.22,1,.36,1) | 进入、移动（默认） |
| `--ease-spring` | cubic-bezier(.34,1.56,.64,1) | 小元素弹入、图标、单选点、Toast |
| `--ease-io` | cubic-bezier(.65,0,.35,1) | 循环指示 |
| 时长 | 120 / 200 / 320 / 520ms | 按下 / 颜色变化 / 移动 / 页面进入 |

**规定的动效**

* 页面进入：淡入并上浮 10px。
* 卡片依次浮现：每张晚 45ms，最多 8 张。
* 可点卡片悬停：见第九节。
* 新问题弹入：从下方弹入，带轻微过冲。
* 滑块、下划线：平移。
* 统计数字：从 0 滚动到目标值。
* 进行中的进度条：青紫流动。
* 加载：骨架屏光泽。
* 抽屉：滑入 320ms。弹窗：从 0.96 放大进入。
* 原文定位：平滑滚动后闪一次。

**品牌时刻**（三处）

1. 标志开场：登录页与首页问候。
2. 氛围光漂移：同样只在登录页与首页。
3. 纸面扫描线：读取文件、模型审核时。

去掉“审核中舞台”和“登录漂浮文字”。

**四档**（沿用自动 / 完整 / 精简 / 关闭和 data-fx 机制）

* **完整**：全部开启。
* **精简**：去掉依次浮现、数字滚动、悬停转动、氛围光漂移和毛玻璃；品牌时刻定格在终态。
* **关闭**：只保留 120ms 内的淡入淡出。
* **自动**：按第十五节的判定规则选档。

**性能底线**：
* 只动 transform 和 opacity；
* 不用 filter 模糊做氛围光；
* 完整档在开发机上不低于 55 帧，精简档在 `--disable-gpu` 下不低于 30 帧。

## 十二、状态与颜色的对应

| 枚举 | 对应 |
|-|-|
| 严重程度 | 高为红，中为琥珀，低为天蓝。用浅底徽标加圆点，原文高亮用同色 |
| 任务状态 | 读取中、排队、审核中：天蓝，圆点带呼吸；待你确认、被拦截：琥珀；已审核：衡青加对勾；已确认遮住、转写完成：绿；失败：红；已过期：中性 |
| 标书结论 | 只有“严重”（红）和“提示”（中性，默认折叠）两档 |
| 本机与模型 | 本机为衡青，带锁或计算器图标；模型为灵紫，带星点图标 |

绿色只表示流程完成，不表示文件没问题。“低”等级不用绿色。

## 十三、安全相关的写法

1. 不使用 `v-html`、`innerHTML`、`ElMessageBox` 的 `dangerouslyUseHTMLString`。外发文本、原文、原文引用、模型返回的文字都按纯文本显示（文本插值、`<pre>` 或 `white-space: pre-wrap`）。需要高亮片段时，拆成片段数组逐个插值。
2. 不用 `console.log` 等输出任何内容；提交的代码中不留 `console.*`。
3. 本地存储（`localStorage`）只能存界面偏好：上次的立场和来源（Q-51）、登录页记住的用户名（`si.login.username`，SPEC 6.1；密码只交给浏览器密码管理器，不进本地存储）、侧栏收起与宽度（`si.sidebar.collapsed`、`si.sidebar.width`）、审核结果问题栏宽度（`si.review.findingsWidth`）、外观设置（`si.appearance`，第十五节）。工作文件夹的授权句柄存本浏览器 IndexedDB（库 `si`、表 `prefs`、键 `workFolder`）。唯一例外是现场录音的防丢分片（IndexedDB 库 `si-recording`，上传成功或放弃即清除，界面写明“保存到本机浏览器”，V31Q-106）。其余不得存密码、文件内容、名称、问题、对照表、文件夹路径、文件名或任何接口返回的业务数据。读写包在 try/catch 中，读不到按默认值。
4. URL 中只放 ID 和页码、日期等筛选条件，不放文件名、公司名等文字。
5. 所有请求经 `api/http.ts` 发出，不在组件中直接用 `fetch`。每个后端资源在 `api/` 下一个文件，接口类型与后端返回字段同名。
6. 前端检查（文件数量、大小、扩展名、必填项）只是提示，后端一定会再检查；不要因为前端检查过就省略对接口错误的处理。
7. 外发栏（对照视图、外发文本）显示的内容只来自后端返回，前端不拼接、不替换；对照视图只用于阅读，不影响实际发送的内容。

## 十四、代码组织

1. 页面放在 `views/`，子组件放在 `components/`，使用 `<script setup lang="ts">` 与 `<style scoped>`。动态尺寸可用绑定样式，Element Plus 局部覆盖用 `:deep()`。主题与动效选择器直接写 `html[data-fx="…"] .x`，避免把 `html` 包在 `:global()` 中。
2. `styles/fonts.css` 管理本地字体，`theme.css` 定义令牌与 Element Plus 映射，`skin.css` 集中定义控件外观，`common.css` 定义页面与组件共用样式，`motion.css` 定义动效及过渡。页面从令牌取色。
3. 接口定义放在 `api/`，标签映射统一放在 `utils/labels.ts`，时间经 `utils/time.ts` 格式化，显示时区为 Asia/Shanghai。导出通过 `utils/save.ts` 的 `saveBlob` 保存。
4. 步骤条只在系统处理中转动，等待用户时保留步骤编号与待办文字。

## 十五、外观设置

* 「设置 · 个人」支持浅色、深色、跟随系统，字号标准、较大、特大，动效自动、完整、精简、关闭。修改立即生效，同一浏览器的登录页也使用上次的设置。
* `si.appearance` 仅存外观偏好。默认 `{"shell":"light","fx":"auto","fs":"md"}`，旧值缺少字号时为标准。`index.html` 在样式生效前设置 `data-shell`、`data-fx` 与 `data-fs`，页面启动后由外观 store 接管。
* 自动档依次判断系统减少动态效果（关闭）、软件渲染或核心数不超过 2（精简）、运行中明显掉帧（本次精简），其余为完整。手动档优先。结果可用即显示，动画随工作完成结束。

## 十六、实施与验收

* 前端构建须通过 `npm --prefix frontend run build`，并按任务范围用虚构数据、模拟服务走查。
* 浅色、深色各看 1366 和 1440 宽两种视口。检查页面与操作状态、横向滚动、文字遮挡、键盘焦点和控制台。涉及动效时覆盖自动、完整、精简、关闭四档。截图留在会话中。
* 核对颜色、字号、间距、版式及状态文案与本规范一致。逐页用到的状态至少看加载、正常、空与失败。保留服务器返回的原文和外发文本，按纯文本显示。
