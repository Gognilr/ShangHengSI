# 前端界面规范（素纸版）

V3.4 起生效（V34-Z 合并，2026-11-19），取代 V3.1 的“光幕”版。来源：docs/v34/design/visual.md（用户 2026-11-15 确认，预览 visual-preview.html）与 V34Q-11～15 的实施决定；状态与颜色的对应、各种状态、按钮、文字、安全写法、代码组织、动效、外观设置、自检沿用上一版并按素纸改色。页面的功能与交互以 SPEC 为准；标书初审结果页另以 docs/v34/design/bid-frontend-spec.md 为硬性规范。

本文件是全部前端任务（`frontend/` 下的页面、组件、样式）共同遵守的界面约定。不论任务由哪一侧的模型执行，都按本规范实现；评审前端提交时也按本规范逐条检查。

## 一、总体原则

**整个系统是一张连续的纸：内容直接写在纸上，层次靠细线、留白和字重，不靠灰底上贴白卡、不靠光。**

1. **一张纸。** 主区域只有一个底色，内容区与背景是同一层。分组用 1px 细线和留白；只有“独立的、可以拿走的对象”（一条问题、一家投标人、一份文件正文）才有边框，且边框内外同色。
2. **墨为主，色为点。** 屏幕上 95% 是墨色的五个深浅。主色“松青”只出现在六处、暖色辅助色“松果赭”只出现在四处（第三节）；状态色只出现在一个 6px 圆点或一个数字上，不铺成色块。
3. **阴影只属于浮在纸上的东西。** 下拉、弹层、对话框、抽屉，以及首页那个输入框。其余一律无阴影、无辉光、无渐变。
4. **静止即安静。** 静止的界面没有任何渐变与光效；动的东西只在“系统正在工作”时出现，颜色由松青与松果赭派生（冷暖交替的多色），不出现别的色相。
5. **为长时间阅读而设计。** 正文对比度不低于 WCAG AA（4.5:1），阅读区不用纯黑纯白，行长、行高沿用排版升级方案（docs/design/shangheng-si-typography-upgrade.md）。

## 二、品牌标识

产品名“商衡SI”，标识为“松鳞”（用户 2026-11-15 选定，V34Q-11 修订轮廓）：松果外形——圆冠、展开的肩部、收拢的底部，内有鳞片折线，底部一片菱形鳞填为松果赭。守护的外形里有一片被遮住，即脱敏。

* 两档：完整版（≥ 32px：登录页、报告封面）为外形 + 两层鳞线 + 一片松果赭鳞；小尺寸版（≤ 26px：标签页 16px、侧栏、窄栏）去掉内部两层折线、加粗外线，赭色鳞片与完整版同位置、同比例。favicon 与小尺寸版同形。
* 不用底板、不用渐变；图形以松青为主体，只有一笔是松果赭；夜幕下松青换成较亮的一档（`--si-logo-a`），形状不变。
* 字标“商衡”600、字距 0.14em，后接细竖线与等宽小字“SI”。
* `components/brand/SiLogo.vue` 两档 SVG（`hero` 尺寸图形 64px、字标 34px），颜色取 `--si-logo-a` 与 `--si-accent`；`frontend/public/favicon.svg` 用 `prefers-color-scheme` 在深色标签栏下换亮一档的松青。登录页短横线、报告封面条为单色松青。

## 三、色彩

### 3.1 主色松针青，辅助色松果赭

主色松针青：浅色按钮底 / 文字 / 按下 `#1F5F58` / `#1B564F` / `#184C46`，夜幕 `#2F8177` / `#7FCDBF` / `#296F66`。它明确不是蓝，也不是会被误读为“通过”的正绿。令牌 `--si-brand` 为主色（`--si-blue` 只是旧名映射，留在 theme.css C 块，新代码用 `--si-brand`）。

暖色辅助色松果赭 `#9C5B34`（夜幕 `#D39A6A`），另有浅一档的琥珀 `#C99A5B`（夜幕 `#E6BE8A`）只用于动效。

**冷暖各有含义**：松青＝本机、已保护、可以确定的；松果赭＝模型、进行中、需要人核实的。护盾胶囊、本机计算、主按钮是松青；“AI 建议 · 请核实”的小图标、等待动效里的暖点、标识的那片鳞、入口线描图里的那一笔是松果赭。松果赭不作状态色、不作大面积底色、不作按钮。

### 3.2 颜色出现在哪里

**松青六处**：① 标识主体；② 每屏至多一个的主按钮与发送按钮；③ 链接与行内文字按钮；④ 键盘焦点外环、输入中的选区；⑤ “已在本机保护”的护盾胶囊与本机保护指示点；⑥ 进度（进行中的圆环、步骤条当前步、入口格悬停线）。

**松果赭四处**：① 标识的一笔；② 首页四张入口线描图里的一笔；③ “AI 建议”分区的小图标；④ 等待动效（与松青混排）。

**不再用品牌色的地方**：侧栏选中、表格当前行、页签下划线、分段控件选中、文件类型徽标、“新建会话”、统计数字、卡片悬停——全部中性墨色。

**语义色的调整**（避免与松青、松果赭相撞）：

* **成功 / 已完成不再用绿色**：改为“墨色对勾 + 文字”（`--si-ok` 取墨色二级）。绿色与松青太近，且“已完成”本来就不该比“有问题”更抢眼；这也顺带消除了“绿色＝审核通过”的误读。
* **警告由琥珀橙改为偏黄的赭黄**（`#C28A00`，文字 `#7D5F00`），与松果赭在色相上分开；警告永远带圆点或图标，不单靠颜色。
* 危险红不变（`#C4262E`）。低风险、中性仍为灰。
* 替换类别色 `--si-k-*` 中“地址”一类原为绿色（`#2E7D4F`），与松青接近，改为橄榄 `#6B6B2A`（底 `#F1F1E2`）；其余类别不变。

## 四、表面与层级

由五层收为三层：

| 层 | 底 | 边界 | 用于 |
|-|-|-|-|
| 纸 | `--si-bg-canvas` | — | 主区域及其上的一切内容：标题、列表、表格、表单、面板 |
| 侧 | `--si-bg-side` | 右侧 1px `--si-hair-faint` | 侧栏；登录页左半 |
| 浮 | `--si-surface-pop` | `--si-shadow-3`（自带 1px 边） | 下拉、弹出框、对话框、抽屉、提示；`--si-blur` 毛玻璃取消（纯色更稳，也省性能） |

规则：

* **`.panel` 不再是卡片**：背景透明、无边框、无阴影、无圆角、内边距 0；两个面板之间用 32px 留白 + 1px `--si-hair` 分隔（`.panel + .panel { margin-top: 32px; padding-top: 32px; border-top: … }`）。`el-card` 同样处理。
* **`.si-card`（对象卡）**：只用于问题卡片、投标人卡片、选项卡片。背景透明（与纸同色）、1px `--si-hair`、圆角 10px、无阴影；可点击的悬停为 `--si-hover-bg` + 边框 `--si-hair-strong`，**不上移**。
* **区块标题**：一行小标题（`--si-font-overline`，见第五节）+ 其下一条线；列表、表格的第一条线用 `--si-hair-strong` 或 `--si-hair`，行间线用 `--si-hair-faint`。
* **文件正文纸面**（`.si-paper` + `.si-stage`）是唯一允许“底色不同”的内容区：外围 `--si-stage`，纸面白、一圈细线、圆角 3px、无投影。夜幕下为暗纸。
* **输入框是唯一带投影的纸上元素**（首页与对话页的 Composer），因为它是整个产品的入口，需要一点“可以落笔”的分量。

### 5.3 圆角（改值，令牌名不变）

纸面 3px；标签 6px；控件 8px；对象卡与拖入区 **10px**（原 12）；弹层 **14px**（原 16）；首页输入框 16px（`--si-radius-sheet` 由 20 改 16，登录不再有卡片）。

### 5.4 间距

沿用 4、6、8、10、12、16、20、24、32、48；新增 40（页面左右内边距）与 56（页面底部）。页面内边距改为 32px 40px 56px。区块之间 32～40px；小标题到内容 10px。

### 5.5 图标

仍只用 `@lucide/vue`，16px、线宽 1.75、继承文字色；**图标一律墨色，不单独上色**（侧栏选中项的图标也不变蓝）。菜单图标：工作台 `PanelsTopLeft`、文件审核 `FileText`、标书初审 `Scale`、会议纪要 `Mic`、翻译 `Languages`、历史记录 `History`、搜索 `Search`、新建会话 `Plus`、设置 `SlidersHorizontal`。

## 九、状态与颜色的对应

同一个枚举在所有页面用同一套颜色。枚举的中文翻译和标签颜色都集中写在 `src/utils/labels.ts`，组件中不要再各自定义一份。品牌化只改变 `primary` 等变量的具体色值，下表的对应关系不变。素纸版的外观：状态一律“圆点 + 文字”，`success` 显示为墨色对勾（不用绿），不铺彩色底（第六节）。

| 枚举 | 对应 |
|-|-|
| 严重程度 | 高 `danger`、中 `warning`、低 `info`，显示为透明底胶囊 + 6px 圆点 + `--si-*-ink` 文字（高 22px）；问题卡片标题前的圆点、等级计数的圆点与文档光谱条用同一状态色 |
| 审核要求结论 | 有问题 `danger`、未发现问题 `success`、不适用 `info`、无法判断 `warning` |
| 引用状态 | 引用已校验 `success`、待核实 `warning`、缺失型 `info`，用 `effect="plain"` |
| 问题类别 | 表格中一律 `info` 标签；问题卡片中为纯文字（卡片中只有等级用胶囊标签） |
| 轮次状态 | 已完成 `success`、部分完成 `warning`、已被拦截 `warning`、失败 `danger`、排队中和审核中 `info` |
| 任务处理状态（历史记录状态列、工作台附件标签与文件抽屉） | 圆点 + 文字：解析中、排队中、审核中 `info`；待确认 `warning`；已审核、本地校验完成 `primary`（不用绿色，避免读成“审核通过”）；文件已确认脱敏 `success`；失败 `danger`；只读、已过期为 `info` + `effect="plain"` |
| 制裁结论 | 文字显示，不加标签颜色；“高风险（建议合规人员或律师确认）”用 `--el-color-danger` 文字。下方固定声明不可省略 |
| 替换类别（对照视图） | `labels.ts` 的 `REDACTION_KIND` 映射到 `--si-k-*` 颜色组 |
| 画布胶囊（确认脱敏） | 确定替换：护盾胶囊（`--si-cap-bg` / `--si-cap-ink`，带盾形图标）；不确定项默认替换（`detected_by=uncertain`）：同底色、1px 虚线边框、无图标；保留原文的不确定项：普通文字加 1px 点状下划线（`--si-ink-3`）；AI 视野中替换处为代号胶囊（`--si-code-bg` / `--si-code-ink`，等宽，不确定项仍为虚线） |

低风险不用绿色，也不用任何暗示“安全”的颜色或文字。

**两种结论的分区**（V31-U3 0.3）：凡同时出现本机算出的与模型说的，一律分开放、分开标，标题用 `ZoneHeader`（行高 28px、`--si-font-label`、14px 图标、右侧可放计数）：

| 分区 | 标题 | 图标与色 | 用在 |
|-|-|-|-|
| 本地计算 | “本地计算 · 结果确定” | `Calculator`，`--si-ink-2` | 结果页本地校验、确认页本地校验抽屉、本机计算卡片、助手本地校验 |
| 无法核验 | “无法核验”（本地计算内的子组，默认折叠） | 同上，次要色 | L-INFO |
| AI 建议 | “AI 建议 · 请核实” | `Sparkles`，`--si-ai` | 结果页问题、逐条结论、追问与助手回复 |

“结果确定”只在本地计算分区出现；AI 分区不出现“确定、通过、无风险”等字样。本机计算卡片挂在 AI 回复中间也用本地计算的样式。

**未能还原**（V31-U3 0.4）：接口给出的标记 `{start, end, kind}`（码点下标）由 `MarkedText` 渲染：原文字不变，加 `--si-warn-ink` 1px 虚线下划线与 `--si-unresolved-bg` 底，悬停 / 聚焦提示原因（文字在 `labels.ts`）；有标记的卡片或消息底部一行“有 N 处未能还原，已原样标出”（不计 calc）。前端不猜、不替换。

## 十、各种状态的表现

每个页面和区块都要处理下列状态，不能出现空白页面或一直转圈。

| 状态 | 表现 |
|-|-|
| 加载中 | 在要加载的区块上加 `v-loading`，不要整页遮罩；外观由 `skin.css` 统一为区块顶部 2px 多色审阅光带（松青 → 浅松青 → 琥珀 → 松果赭，两端透明，整宽、约 2.2s 单向循环，只动 transform；特效关闭时不显示光带）加内容变淡（V33-C-04；文字流光 `.si-shimmer` 仅供等待模型文案，C-06 使用），不显示转圈（V321-E-11），300ms 后才出现，快速返回的请求不闪（V321Q-60）；同一个等待任一时刻只有一个指示，按钮已 `loading` 时不再给区块加 `v-loading`；按钮操作期间按钮显示 `loading` |
| 加载失败 | `el-alert type="error"`，写明原因（取接口返回的中文 message）和下一步，如“加载失败，请刷新页面”。整页 404 用 NotFound（SPEC 6.9），局部资源失败就地提示 |
| 没有数据 | `EmptyState`，见第六节 |
| 处理中（解析） | 按 V2-U 第七节第 4 条：标题“正在本机解析文件”、已用时间、SiScanDoc 扫描纸面（精简为终态、关闭不显示；OCR 的真实页数进度条保留，不显示预计剩余时间）、一句本机正在做什么的 `.hint`、文件清单、`.hint` 说明“可以离开页面，稍后从历史记录进入”与“返回历史记录”按钮；不用加载圆环（V2Q-113） |
| 处理中（排队、审核） | 按 V2-U 第七节：标题、排队位置或分段进度与已用时间（不显示预计剩余时间）、本机已完成的步骤、`.hint` 说明与“返回历史记录”按钮；不用加载圆环 |
| 轮询 | 每 3 秒一次（SPEC 21），任务结束或离开页面（`onBeforeUnmount`）时停止；同一时间只有一个请求在进行；网络错误不打断轮询，404 停止轮询 |
| 被拦截 | 第二步顶部显示 `el-alert type="warning"`：标题“上次提交被拦截，未发送给模型”，内容为拦截原因（只有类别和位置）和“请检查……后重新提交” |
| 失败 / 部分完成 | 结果页信息卡下方显示 `el-alert`（失败 `error`，部分完成 `warning`），写明原因 |
| 按钮不可用 | 必须能看到原因：在按钮附近（外发回执卡的条件列表、操作区左侧的 `.hint` 或 `el-alert`）说明，如“请先选择哪一方是我方” |
| 接口 409 / 422 | 按错误码给出中文提示（如 `api/runs.ts` 的 `RUN_ERROR_MESSAGES`），没有对应时显示接口返回的 message；`TASK_STATE_CONFLICT` 时重新读取任务状态 |

## 十一、按钮与操作

1. 每个面板最多一个主按钮（`type="primary"`），放在面板右下角的操作区（上间距 24px、上方 1px 分隔线；左侧可放 `.hint` 说明）。页面级的主按钮（如“新增账号”）放在 PageHeader 右侧。确认脱敏的“确认发送并开始审核”放在回执栏底部外发回执卡中，满宽。
2. 表格行内的操作用文字按钮（`link`）：普通操作 `type="primary"`，删除 `type="danger"`，并做二次确认。页面级的删除（如“删除任务”）用危险色文字按钮，放在操作区最右，与普通操作分开。
3. 页面上的按钮文字用动词开头、写清结果：“确认发送并开始审核”“重新上传”“导出报告”，不要写“确定”“提交”“OK”。对话框和二次确认框中的按钮可以用“确定”“取消”，删除确认的按钮写“删除”。
   * 做之前写动作、做完才写状态：可点的按钮或分段控件里未生效的一项写动作（“采纳”“忽略”“改回待处理”），已生效的一项才写“已采纳”“已忽略”“待处理”。“已××”只用于已经发生的状态、标签和完成提示，不能出现在还没点的按钮上。
4. 提交期间按钮显示 `loading`，防止重复点击；有修改正在保存时（如签约方保存中），相关的提交按钮也要禁用。
   * 缺的是用户该选的项（我方、业务立场、审核模型、文件）时，提交按钮不禁用：未选的控件静态标出（标签旁主色小字“请选择”、控件外主色虚线框 `.si-required-empty`），点按钮时用 `utils/nudge.ts` 的 `nudgeField()` 滚到第一个缺项、聚焦其中的控件并闪一次框（`.si-nudge`，特效关闭时显示约 1 秒的静态框）；按钮上方条件清单里的未完成项也可点，效果相同。等待类条件（解析中、保存中、正在读取）照旧禁用并写明原因（V33-C-01）。
5. 修改一项就立即保存的控件（下拉框、单选），保存失败时恢复为服务端的值，并提示原因。
6. 复制按钮：先用 `navigator.clipboard`，失败时用 textarea 加 `execCommand` 兜底，与 `FindingCard.vue` 一致；成功提示“已复制”。

## 十二、文字

1. 全部用简体中文，使用全角标点。中文与数字、英文之间加一个空格：“最多 10 个文件”“单个不超过 30 MB”。
2. 接口返回的代码（状态、类别、结论等）一律经 `labels.ts` 翻译后显示，界面上不出现英文代码。未知代码原样显示。
3. 提示语写“发生了什么 + 用户该做什么”。不写“操作失败”“系统错误”这类没有信息量的话（作为兜底除外）。
4. 不用感叹号，不用“您”，不用“亲”“哦”等口语。
5. **界面中不得出现“审核通过”“无风险”“已安全”“零泄露”字样**（A-08）。“无明显风险”是 SPEC 规定的制裁结论档名，可以使用。没有问题条目时写“本次没有列出问题条目。结果由 AI 生成，仅供参考，请以人工复核为准。”
6. SPEC 中写明的文字（如 6.2 的占位提示和外发策略说明、6.3 的固定声明、6.5 的说明文字）逐字照抄；R3.md 第四节给出的页面说明文字同样照抄。
7. 时间一律用 `utils/time.ts` 的 `formatDateTime` / `formatDate`（按 Asia/Shanghai 显示），不要自己格式化，也不要显示相对时间。
8. 金额、数字按接口返回的原样显示，前端不做计算或重新格式化（金额计算只在后端用 Decimal 进行）。统计块中的计数可以加千分位。
9. 产品名写“商衡SI”（中间无空格）；副标写“企业安全脱敏与智能审查平台”。

## 十三、安全相关的写法

1. 不使用 `v-html`、`innerHTML`、`ElMessageBox` 的 `dangerouslyUseHTMLString`。外发文本、原文、原文引用、模型返回的文字都按纯文本显示（文本插值、`<pre>` 或 `white-space: pre-wrap`）。需要高亮片段时，拆成片段数组逐个插值。
2. 不用 `console.log` 等输出任何内容；提交的代码中不留 `console.*`。
3. 本地存储（`localStorage`）只能存界面偏好：上次的立场和来源（Q-51）、登录页记住的用户名（`si.login.username`，SPEC 6.1；密码只交给浏览器密码管理器，不进本地存储）、侧栏收起与宽度（`si.sidebar.collapsed`、`si.sidebar.width`）、审核结果问题栏宽度（`si.review.findingsWidth`）、外观设置（`si.appearance`，第十六节）。工作文件夹的授权句柄存本浏览器 IndexedDB（库 `si`、表 `prefs`、键 `workFolder`）。唯一例外是现场录音的防丢分片（IndexedDB 库 `si-recording`，上传成功或放弃即清除，界面写明“保存到本机浏览器”，V31Q-106）。其余不得存密码、文件内容、名称、问题、对照表、文件夹路径、文件名或任何接口返回的业务数据。读写包在 try/catch 中，读不到按默认值。
4. URL 中只放 ID 和页码、日期等筛选条件，不放文件名、公司名等文字。
5. 所有请求经 `api/http.ts` 发出，不在组件中直接用 `fetch`。每个后端资源在 `api/` 下一个文件，接口类型与后端返回字段同名。
6. 前端检查（文件数量、大小、扩展名、必填项）只是提示，后端一定会再检查；不要因为前端检查过就省略对接口错误的处理。
7. 外发栏（对照视图、外发文本）显示的内容只来自后端返回，前端不拼接、不替换；对照视图只用于阅读，不影响实际发送的内容。

## 十四、代码组织

1. 组件一律 `<script setup lang="ts">`，样式一律 `<style scoped>`。不写内联 `style`（动态尺寸等必要情况除外）。覆盖 Element Plus 组件内部样式时用 `:deep()`，并只在该组件的 scoped 样式中写。
2. `views/` 放页面，`components/` 放页面拆出来的子组件，`components/brand/` 放品牌组件，`components/bid/` 放标书初审组件（图表在 `components/bid/charts/`，手写 SVG、只用令牌）。单个 `.vue` 文件超过约 400 行，或一个区块有自己的加载、保存逻辑时，拆成子组件。
3. 样式文件：
   * `styles/fonts.css`：SI Sans、SI Mono 的 `@font-face`，由 `frontend/scripts/build_fonts.py` 生成，不手改；字体文件在 `assets/fonts/`，来源与 SHA-256 见同目录 `SOURCES.md`，OFL 全文在 `public/licenses/`。
   * `styles/theme.css`：只放设计令牌，分三块且顺序固定：A 浅色外壳与纸面、B 夜幕外壳（只覆盖随外壳变化的令牌）、C 映射与派生（Element Plus 变量、旧令牌、`color-mix()` 派生色，同时写在 `:root` 与 `.si-paper` 上）。全仓只有这里可以写十六进制颜色。
   * `styles/skin.css`：Element Plus 组件的全局外观（按钮、输入、标签、表格、选项卡、弹层、对话框等），只用变量。
   * `styles/common.css`：页面容器 `.page` 及宽度类、`.panel`（素纸版无底无框，第四节）、`.si-card`（对象卡）、`.si-stage`、`.gap`（16px）、`.hint`、`.actions`、`.filters`、`.stat`、`.code`、`.avatar` 等多个页面共用的写法。
   * `styles/motion.css`：动效令牌与通用过渡类（第十五节）。
   * 在 `main.ts` 中依次引入 Element Plus 样式、`fonts.css`、`theme.css`、`skin.css`、`common.css`、`motion.css`。
   * 基础组件放在 `components/ui/`（`SiSegmented`、`SiIsland`、`SiToast`、`SiCount`），每个不超过约 200 行，在关闭特效下可用、键盘可操作、有 `aria-*`。
4. 枚举翻译、标签颜色、替换类别颜色组只在 `labels.ts` 定义；接口调用只在 `api/` 定义；时间格式只在 `utils/time.ts` 定义；可以脱离界面测试的逻辑（如对照配对）放在 `utils/`。
5. 不新增依赖。确实需要时，按任务说明添加并锁定精确版本。
6. 导出文件一律经 `utils/save.ts` 的 `saveBlob(blob, filename)` 保存，不在组件中自行创建下载链接。

* 页面进入只做 8px 上移 + 淡入（原有 `si-page`），不加其他入场效果。

| 层 | 时长 | 缓动 | 动什么 | 例 |
|-|-|-|-|-|
| 微交互 | 120～200ms（`--si-dur-1` 160ms） | `--si-ease` | 颜色、底色、透明度；按下 `scale(.98)` | 按钮、开关、悬停、选项卡 |
| 结构过渡 | 240～450ms（`--si-dur-2` 320ms，离开 `--si-dur-exit` 200ms） | 进入 `--si-spring`，离开 `--si-ease` | 位移与透明度 | 页面进入、抽屉、弹层、列表增删、定位原文、分段滑块、灵动岛变形 |

   等待指示（区块光带、解析纸面、对话墨点与文案）统一延迟 300ms 显示；快于此阈值返回不闪，结果就绪立即移除。关闭档仍保留一次无位移的 1ms 透明度显现，只用于延迟可见性，不播放循环。

   * **登录漂浮文字**（`brand/LoginWords`，V31-U4 4.1）：完整——左侧品牌区 `<canvas>` 上合同常用字缓慢上浮（页面隐藏停绘，开始时 `watchFrames()`）；精简——同一画面的静态一帧；关闭——纯底色。散布用低差异序列（R2），不用固定步长取模（会连成斜行，像乱码）；字色 `--si-ink-4`，不承载信息。

## 十六、外观设置

* **入口**：侧栏用户菜单“修改密码”之上的“外观”，打开 `AppearanceDialog`（宽 420px）：外壳“夜幕 / 浅色”，特效“自动 / 完整 / 精简 / 关闭”，下方一行说明自动档当前结果与原因（手动时写“已按你的选择固定，不再自动调整”）。修改立即生效，不进入未保存状态。登录页不放入口，按已保存的设置显示。
* **存储**：`localStorage` 键 `si.appearance`，值 `{"shell":"light","fx":"auto"}`；只存本浏览器，不发送到服务器。读不到按默认（浅色、自动，V31-U5F-06）。
* **首屏不闪**：`index.html` 的 `<head>` 内联脚本在样式生效前写 `<html>` 的 `data-shell` 与 `data-fx`；之后由 `stores/appearance.ts` 接管。页面和组件按 `data-shell`、`data-fx` 或 `useFx()` 判断，不各自读存储。
* **自动档**按顺序判定，命中即停：系统设置了减少动态效果 → 关闭；WebGL 检测为软件渲染（远程桌面或无显卡）→ 精简；处理器核心 ≤ 2 → 精简；品牌时刻开始后 1.5 秒内平均帧间隔 > 34ms → 本次打开期间降为精简（不写存储）；否则完整。用户手动选择的级别优先于以上全部。

2. 在浏览器中打开本任务涉及的每个页面（http://localhost:5173，需先启动整套系统；模型用模拟服务，见 deploy/docker-compose.mock.yml），夜幕与浅色两种外壳 × 完整与精简特效，按视口 1366×640、1440×900、1920×1080 各看一遍，另在 1280×800 看一遍无横向滚动：
   * 没有横向滚动条，没有文字溢出、重叠或被截断；粘底的栏与卡不遮挡内容；
   * 宽度、间距、字号、颜色符合第三～六节，与所在批次设计文档中对应页面的观感一致；没有白块“闪”出夜幕，浅色纸面为白底，弹层与提示可读；
   * 第十节中与本页相关的每种状态都看过（至少：加载中、正常、没有数据、出错）；
   * 用 Tab 键走一遍：焦点外环可见，顺序合理；
   * 浏览器控制台没有报错（未登录时 `/auth/me` 的 401 除外）。
3. 整仓挂载运行 `tests/test_frontend_style.py` 通过（命令见 docs/v2/design/V2-U.md 共同约定第 5 条；禁用词由第 4 条的搜索检查）。
4. 搜索本任务改动的代码，确认：除 `theme.css` 外没有十六进制颜色；没有 `v-html`、`console.`、“审核通过”“无风险”“已安全”。
5. 截图只留在会话里，报告写明看过哪些页面、外壳与特效档。

Opus 评审前端任务和里程碑验收时，按本规范逐条检查，并在浏览器中截图核对。
