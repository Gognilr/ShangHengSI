# 前端界面规范（第二版）

本文件是全部前端任务（`frontend/` 下的页面、组件、样式）共同遵守的界面约定，由 Opus 制定，经用户确认后生效。不论任务由 Sonnet 5.5 还是 GPT-6.1 Sol 执行，都按本规范实现；Opus 评审前端提交时也按本规范逐条检查。

* 第二版（R3-00，2026-10-23）采用“商衡SI”品牌视觉，依据用户提供的设计资料与 docs/design/R3.md。视觉目标见 docs/design/ui-preview.html。R3 各任务完成前，代码中仍有第一版的写法；改到哪个页面，就按第二版重写哪个页面。
* 2026-10-26 起按 V2-U 修订（第 2.2、2.3、3、4、5、6、11 节，用户已确认，V2Q-101～V2Q-108），视觉目标以 docs/v2/design/V2-U.md 为准；ui-preview.html 中与之不一致处以 V2-U 为准。V2-U 各任务完成前，代码中仍有修订前的写法。
* 与 docs/SPEC.md 冲突时以 SPEC 为准；与里程碑设计文档（docs/design/Mx.md、Rx.md）冲突时，以设计文档中针对具体页面的写法为准。
* 遇到本规范没写到的界面细节：先找已按第二版改过的页面中最接近的写法照做；仍然没有的，选 Element Plus 默认的做法，并在完成报告中写明。不要自己发明新的视觉样式。
* 修改本规范只能由 Opus 在 Mx-00 / Rx-00 中进行，或经用户同意后修改。

## 一、总体原则

1. **沉稳、克制、清楚**。大面积中性色，小面积品牌深海蓝；靠留白和分组建立层次，不靠颜色堆砌。不做插画、3D、粒子、光效和装饰动画。品牌渐变只用于 Logo、顶栏选中条和登录页的短横线。
2. **Element Plus + 品牌主题**。组件仍然只用 Element Plus；品牌色、字体、尺寸、圆角通过 `src/styles/theme.css` 覆盖 Element Plus 的 CSS 变量实现（取值见 R3.md 第二节）。不引入其他 UI 库、CSS 框架或外部字体。
3. **颜色只用变量**。页面和组件中只写 `var(--el-…)` 或 `var(--si-…)`；十六进制颜色和 rgb 值只允许出现在 `theme.css`。青蓝（`--si-cyan`）不作为白底上的文字颜色。
4. **只做桌面端**。`body` 最小宽度 1280px（SPEC 21），不做手机适配。媒体查询只允许用于两处：登录页窄窗口时隐藏左半，顶栏宽度小于 1440px 时隐藏副标。
5. **信息优先**。问题、结论、拦截原因、错误原因、提交条件放在显眼的位置，说明性文字用次要颜色和小字号。
6. **不增加 SPEC 没有的菜单、页面、按钮或功能**（CLAUDE.md）。觉得缺少什么，在完成报告中提出，不要自行加上。

## 二、页面骨架

### 2.1 主布局 `layouts/MainLayout.vue`

顶栏高 64px，白底，下边框 1px；内容最大宽度 1600px，左右 32px。左侧 `SiLogo`（nav 尺寸）+ 竖线 + 副标“企业安全脱敏与智能审查平台”；随后是“智能审核”“审核历史”两个菜单（选中：深海蓝加粗，底部 2px 品牌渐变条）；右侧是“设置”（仅管理员可见）和用户区（首字圆形 + 显示名 + 下拉）。顶栏下方是管理员提醒条（浅警告底），再下方是 `el-main`（内边距为 0，由页面自己控制）。需要按视口计算高度时，顶栏高度一律按 64px 计。

### 2.2 页面容器

每个页面的根元素是 `<div class="page …">`，水平居中，上内边距 32px、下内边距 48px。宽度只用下面三档（`styles/common.css`）：

| 类 | 最大宽度 | 用在什么页面 |
|-|-|-|
| `.page--standard` | 960px | 新建审核第一步、第三步 |
| `.page--wide` | 1200px | 确认脱敏（第二步）、审核历史、设置 |
| `.page--split` | 1600px，两侧各留 32px | 审核结果 |

页面只在 MainLayout 的 `.main` 中滚动，页面根元素不设高度和 `overflow`。

审核结果页为工作台：高度占满顶栏以下、整页不滚动；顶部工具条固定，下方左栏 `clamp(480px, 42%, 640px)`、右栏（原文预览）占余下宽度、间距 20px，两栏各自滚动。点击左栏的问题时只滚动右栏。

### 2.3 页面内的结构

* 设置各页顶部用 `PageHeader`（`--si-font-title` 标题 + 一行 14px 次要色说明 + 右侧插槽放该页已有的主按钮），标题与说明见 R3.md 第四节。智能审核、审核历史不用页面标题（顶栏选中项已说明位置）；审核结果页用工具条（V2-U 第四节）。
* 内容放在**面板** `.panel` 中：白底、1px `--el-border-color-light` 边框、`--si-radius-card`（12px）圆角、内边距 24px 32px，无阴影。面板之间 16px（`.panel + .panel`）。需要 Element Plus 卡片能力时可用 `el-card shadow="never"`，theme.css 已把它统一成同样的外观。
* 面板标题 18px / 600，下间距 16px；标题后可跟 13px 次要色说明，右侧可放该面板的次要操作。带编号的面板（确认脱敏）在标题前加 26px 圆形序号徽标。
* 面板内的分组标题 15px / 600；组与组之间 32px，用 1px `--el-border-color-lighter` 分隔线隔开。

### 3.3 间距、圆角

间距只用 4、8、12、16、20、24、32、48px。常用：面板之间 16px；面板内边距 24px 32px；分组之间 32px；筛选栏控件之间 8～12px；表单项之间 20px；操作区上间距 24px。

圆角分五级：纸张与行内高亮 4px（`--si-radius-paper`）；小标签 6px；按钮、输入框、下拉框、统计块、文件徽标 8px（`--el-border-radius-base`）；面板、卡片、上传区、对照区、对话框、抽屉 12px（`--si-radius-card`）；圆形 50%。

数字：需要纵向对齐的数字（表格、分页、统计、时间、条款号）加 `.num` 或使用已全局等宽的组件（`el-table`、`el-pagination`、`.stat-value`）；正文中的数字不设等宽。

控件高度：默认 40px（`--el-component-size`）；表格内的小控件 32px（`size="small"`）；登录页输入框和按钮 52px。

## 四、组件用法

| 场景 | 用什么 | 约定 |
|-|-|-|
| 页面标题 | `PageHeader` | 见 2.3 |
| 内容容器 | `.panel` 或 `el-card shadow="never"` | 见 2.3 |
| 品牌标识 | `brand/SiLogo` | 不在其他地方另画 Logo。SiLogo 的字标字号与字重属于品牌图形，不受 3.1 限制 |
| 步骤 | `StepBar` | 只在新建审核页使用；取值与原 `el-steps` 相同 |
| 数据列表 | `el-table`（不加 `border`） | 表头浅灰底、只有横线。页面主列表默认尺寸；面板内的小表 `size="small"` 并包一层 12px 圆角边框容器。空数据用 `empty-text` 写明原因。时间列宽 170px，操作列放最右 |
| 键值信息 | 3 列网格（标签 12px 次要色在上，值 14px 在下） | 只用于设置页；结果页元信息为工具条第二行的一行文字，用“ · ”分隔；不用 `el-descriptions border` |
| 统计数字 | 统计块（1px 边框、8px 圆角，标签 `--si-font-meta` + 数字 `--si-font-stat`） | 用于脱敏摘要、本月用量、系统状态、等级计数；数字按接口原样显示 |
| 表单 | `el-form label-width="110px"` 或标签在上（`label-position="top"`，设置页两列 / 三列网格） | 多行输入写 `maxlength` 和 `show-word-limit` |
| 2～4 个选项的单选 | `el-radio-group` + `el-radio-button`，样式为分段按钮 | 如业务立场、文件来源 |
| 需要解释后果的单选 | `el-radio-group` + 带边框的 `el-radio`，内容为卡片（标题 + 说明） | 如外发策略；保持方向键切换 |
| 可选可输入的值 | `el-select filterable allow-create default-first-option` | 如签约方的国家、类型（Q-50 ②） |
| 筛选栏 | 一行 `display:flex; gap:8px`（列表页放在表格面板的顶部一行） | 下拉框用 `clearable`，占位文字写“全部类别”“全部处理状态”。同一个筛选条件只能有一个入口（结果页的等级只由计数块筛选） |
| 分页 | `el-pagination` | 在表格面板内底部：左侧“共 N 条”，右侧页码；每页条数固定，不提供切换 |
| 标签页 | `el-tabs`（下划线式） | 结果页：问题清单 \| 本地校验 \| 审核要求逐条结论，数量写在标签名里 |
| 折叠内容 | `el-collapse` | 默认收起，展开时才加载内容（如本地校验结果） |
| 原文与外发文本对照 | `RedactionCompare` | 只在确认脱敏和重新审核确认中使用（R3.md 第五节） |
| 粘底操作栏 | `position: sticky; bottom: 0` 的白色条 | 只用于确认脱敏（列出提交条件 + 主按钮）；结果页的操作在工具条 |
| 侧边说明 | `el-drawer`，从右侧打开，宽 560px | 审核要求抽屉（SPEC 6.5） |
| 对话框 | `el-dialog` | 表单类宽 480px，内容较多的宽 640px；主按钮放右边，“取消”在它左边；提交中显示 loading |
| 删除等不可恢复的操作 | `ElMessageBox.confirm(…, { type: 'warning' })` | 写明删除什么、会连带删除什么、“无法恢复”；确定按钮文字写动作，如“删除” |
| 操作完成的短反馈 | `ElMessage.success` / `ElMessage.error` | 只用于用户刚刚点击的操作。不要在页面加载时弹出 |
| 需要用户看到并处理的状态 | `el-alert :closable="false" show-icon` | 持续显示，不要用会自动消失的提示代替 |
| 整页的结果状态 | `el-result` | 如解析失败（带“重新上传”按钮） |
| 没有内容 | `el-empty` 或表格的 `empty-text` | 说明为什么没有内容，必要时给出已有页面的入口（如“去新建审核”） |
| 小标签 | `el-tag size="small"` | 颜色见第五节 |
| 用户首字 | `<span class="avatar">` | 不用 `el-avatar` |

图标：只用 `@element-plus/icons-vue`（随 Element Plus 安装，不新增依赖）。可用于导航（设置、设置页左侧导航）、带图标的操作按钮（追问、导出、重新审核、复制、新增）、输入框前置图标（登录、搜索）、上传区与加载状态。不用图标代替文字，图标旁必须有文字（输入框前置图标除外，输入框须有 `aria-label`）。

不要使用：`el-carousel`、`el-timeline`、`el-avatar`、`el-backtop`、`el-tour`、通知框 `ElNotification`、全屏加载 `ElLoading.service`。骨架屏 `el-skeleton` 只用于审核历史表格与审核结果页的首次加载。

## 五、状态与颜色的对应

同一个枚举在所有页面用同一套颜色。枚举的中文翻译和标签颜色都集中写在 `src/utils/labels.ts`，组件中不要再各自定义一份。品牌化只改变 `primary` 等变量的具体色值，下表的对应关系不变。

| 枚举 | 对应 |
|-|-|
| 严重程度 | 高 `danger`、中 `warning`、低 `info`，用 `effect="dark"`；问题卡片左侧色条与等级计数的圆点用同一颜色 |
| 审核要求结论 | 有问题 `danger`、未发现问题 `success`、不适用 `info`、无法判断 `warning` |
| 引用状态 | 引用已校验 `success`、待核实 `warning`、缺失型 `info`，用 `effect="plain"` |
| 问题类别 | 表格中一律 `info` 标签；问题卡片中为纯文字（卡片中只有等级用实心标签） |
| 轮次状态 | 已完成 `success`、部分完成 `warning`、已被拦截 `warning`、失败 `danger`、排队中和审核中 `info` |
| 任务状态（历史列表） | 纯文字，不加颜色；解析失败可用 `--el-color-danger` 文字 |
| 制裁结论 | 文字显示，不加标签颜色；“高风险（建议合规人员或律师确认）”用 `--el-color-danger` 文字。下方固定声明不可省略 |
| 替换类别（对照视图） | `labels.ts` 的 `REDACTION_KIND` 映射到 `--si-k-*` 颜色组 |

低风险不用绿色，也不用任何暗示“安全”的颜色或文字。

## 六、各种状态的表现

每个页面和区块都要处理下列状态，不能出现空白页面或一直转圈。

| 状态 | 表现 |
|-|-|
| 加载中 | 在要加载的区块上加 `v-loading`，不要整页遮罩；按钮操作期间按钮显示 `loading` |
| 加载失败 | `el-alert type="error"`，写明原因（取接口返回的中文 message）和下一步，如“加载失败，请刷新页面”。404 统一写“任务不存在或已被删除” |
| 没有数据 | `el-empty` 或表格 `empty-text`，见第四节 |
| 处理中（解析） | 按 V2-U 第七节第 4 条：标题“正在本机解析文件”、已用时间、不确定进度条（不显示百分比与预计剩余时间）、一句本机正在做什么的 `.hint`、文件清单、`.hint` 说明“可以离开页面，稍后从审核历史进入”与“返回审核历史”按钮；不用加载圆环（V2Q-113） |
| 处理中（排队、审核） | 按 V2-U 第七节：标题、排队位置或分段进度与已用时间（不显示预计剩余时间）、本机已完成的步骤、`.hint` 说明与“返回审核历史”按钮；不用加载圆环 |
| 轮询 | 每 3 秒一次（SPEC 21），任务结束或离开页面（`onBeforeUnmount`）时停止；同一时间只有一个请求在进行；网络错误不打断轮询，404 停止轮询 |
| 被拦截 | 第二步顶部显示 `el-alert type="warning"`：标题“上次提交被拦截，未发送给模型”，内容为拦截原因（只有类别和位置）和“请检查……后重新提交” |
| 失败 / 部分完成 | 结果页信息卡下方显示 `el-alert`（失败 `error`，部分完成 `warning`），写明原因 |
| 按钮不可用 | 必须能看到原因：在按钮附近（粘底操作栏的条件列表、操作区左侧的 `.hint` 或 `el-alert`）说明，如“请先选择哪一方是我方” |
| 接口 409 / 422 | 按错误码给出中文提示（如 `api/runs.ts` 的 `RUN_ERROR_MESSAGES`），没有对应时显示接口返回的 message；`TASK_STATE_CONFLICT` 时重新读取任务状态 |

## 七、按钮与操作

1. 每个面板最多一个主按钮（`type="primary"`），放在面板右下角的操作区（上间距 24px、上方 1px 分隔线；左侧可放 `.hint` 说明）。页面级的主按钮（如“新增账号”）放在 PageHeader 右侧。确认脱敏的“确认发送并开始审核”放在粘底操作栏右侧。
2. 表格行内的操作用文字按钮（`link`）：普通操作 `type="primary"`，删除 `type="danger"`，并按第四节做二次确认。页面级的删除（如“删除任务”）用危险色文字按钮，放在操作区最右，与普通操作分开。
3. 页面上的按钮文字用动词开头、写清结果：“确认发送并开始审核”“重新上传”“导出报告”，不要写“确定”“提交”“OK”。对话框和二次确认框中的按钮可以用“确定”“取消”，删除确认的按钮写“删除”。
4. 提交期间按钮显示 `loading`，防止重复点击；有修改正在保存时（如签约方保存中），相关的提交按钮也要禁用。
5. 修改一项就立即保存的控件（下拉框、单选），保存失败时恢复为服务端的值，并提示原因。
6. 复制按钮：先用 `navigator.clipboard`，失败时用 textarea 加 `execCommand` 兜底，与 `FindingCard.vue` 一致；成功提示“已复制”。

## 八、文字

1. 全部用简体中文，使用全角标点。中文与数字、英文之间加一个空格：“最多 10 个文件”“单个不超过 30 MB”。
2. 接口返回的代码（状态、类别、结论等）一律经 `labels.ts` 翻译后显示，界面上不出现英文代码。未知代码原样显示。
3. 提示语写“发生了什么 + 用户该做什么”。不写“操作失败”“系统错误”这类没有信息量的话（作为兜底除外）。
4. 不用感叹号，不用“您”，不用“亲”“哦”等口语。
5. **界面中不得出现“审核通过”“无风险”“已安全”“零泄露”字样**（A-08）。“无明显风险”是 SPEC 规定的制裁结论档名，可以使用。没有问题条目时写“本次没有列出问题条目。结果由 AI 生成，仅供参考，请以人工复核为准。”
6. SPEC 中写明的文字（如 6.2 的占位提示和外发策略说明、6.3 的固定声明、6.5 的说明文字）逐字照抄；R3.md 第四节给出的页面说明文字同样照抄。
7. 时间一律用 `utils/time.ts` 的 `formatDateTime` / `formatDate`（按 Asia/Shanghai 显示），不要自己格式化，也不要显示相对时间。
8. 金额、数字按接口返回的原样显示，前端不做计算或重新格式化（金额计算只在后端用 Decimal 进行）。统计块中的计数可以加千分位。
9. 产品名写“商衡SI”（中间无空格）；副标写“企业安全脱敏与智能审查平台”。

## 九、安全相关的写法

1. 不使用 `v-html`、`innerHTML`、`ElMessageBox` 的 `dangerouslyUseHTMLString`。外发文本、原文、原文引用、模型返回的文字都按纯文本显示（文本插值、`<pre>` 或 `white-space: pre-wrap`）。需要高亮片段时，拆成片段数组逐个插值。
2. 不用 `console.log` 等输出任何内容；提交的代码中不留 `console.*`。
3. 本地存储（`localStorage`）只能存界面偏好：上次的立场和来源（Q-51）、登录页记住的用户名（`si.login.username`，SPEC 6.1）。不得存密码、文件内容、名称、问题、对照表或任何接口返回的业务数据。读写包在 try/catch 中。
4. URL 中只放 ID 和页码、日期等筛选条件，不放文件名、公司名等文字。
5. 所有请求经 `api/http.ts` 发出，不在组件中直接用 `fetch`。每个后端资源在 `api/` 下一个文件，接口类型与后端返回字段同名。
6. 前端检查（文件数量、大小、扩展名、必填项）只是提示，后端一定会再检查；不要因为前端检查过就省略对接口错误的处理。
7. 外发栏（对照视图、外发文本）显示的内容只来自后端返回，前端不拼接、不替换；对照视图只用于阅读，不影响实际发送的内容。

## 十、代码组织

1. 组件一律 `<script setup lang="ts">`，样式一律 `<style scoped>`。不写内联 `style`（动态尺寸等必要情况除外）。覆盖 Element Plus 组件内部样式时用 `:deep()`，并只在该组件的 scoped 样式中写。
2. `views/` 放页面，`components/` 放页面拆出来的子组件，`components/brand/` 放品牌组件。单个 `.vue` 文件超过约 400 行，或一个区块有自己的加载、保存逻辑时，拆成子组件。
3. 样式文件：
   * `styles/theme.css`：只放设计令牌（覆盖 Element Plus 变量、`--si-*` 变量）和 Element Plus 组件的全局外观统一（卡片、对话框、抽屉、表格表头、焦点）。全仓只有这里可以写十六进制颜色。
   * `styles/common.css`：页面容器 `.page` 及宽度类、`.panel`、`.gap`（16px）、`.hint`、`.actions`、`.filters`、`.stat`、`.avatar` 等多个页面共用的写法。
   * 在 `main.ts` 中依次引入 Element Plus 样式、`theme.css`、`common.css`。
4. 枚举翻译、标签颜色、替换类别颜色组只在 `labels.ts` 定义；接口调用只在 `api/` 定义；时间格式只在 `utils/time.ts` 定义；可以脱离界面测试的逻辑（如对照配对）放在 `utils/`。
5. 不新增依赖。确实需要时，按任务说明添加并锁定精确版本。
