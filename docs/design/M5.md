# M5 AI 审核完善：模块划分与接口约定

本文件由 M5-00 制定，是 M5 各任务之间的契约。执行任务的会话必须按这里的函数签名、数据格式和接口形状实现；需要改动时停下来报告，由 Opus 会话修改本文件。与 SPEC 冲突时以 SPEC 为准。前端任务同时遵守 docs/design/frontend.md。

M5 在 M2 的单次审核（review\_once）上补齐：分段审核与结论合并（11.5）、覆盖说明（11.6）、重新审核（7.4）、调用上限与各种失败的提示（7.3、7.5）、结果页完整版（6.3）、审核要求抽屉与 GET /requirements（6.5、19.5）、禁用词检查（A-08）。验收：A-02、A-05、A-07、A-08、T-12、T-13。另外处理 Q-72 ⑥（模型引用报价明细表汇总行的位置）、Q-60（unable 列入覆盖说明）、Q-77 ③（手动补充提示词中的常用词）。

不在 M5 范围内：结果页的“本地校验”标签页、【本地校验摘要】和汇总行中的“本地校验：…”（M6）；追问、导出报告按钮（M6，M5 的结果页不显示这两个按钮）；公司补充要求的设置页（M7-04，M5 只读取已有的 company\_requirements 表，表为空时照常工作）；管理员提醒条（M7-08）。

## 一、处理流程的变化

```text
确认发送（create_run，不变）：预检仍对“不分段的完整消息”做一次出口复检（与逐段检查等价：分段只在行之间切开）
review 处理函数：
  build_context() → split_chunks()（第二节）→ run.chunk_count = N，run.coverage = {"progress": {"done": 0, "total": N}}，提交
  逐段：build_messages(ctx, chunk) → review_once()（网关：上限 → 出口复检 → 发送 → 记录；输出不合格重试 1 次）
        每段结束（成功或失败）后 progress.done += 1 并提交
        BLOCKED：立即停止，整轮 blocked，任务回到 awaiting_confirm（不发送剩余分段）
        其他 GatewayError、OutputError：该段记为失败，继续下一段
  merge_reviews()（第三节）→ build_coverage()（第四节）→ 写结果
  状态：全部分段失败 → failed；有分段失败 → partial；否则有 unable → partial，没有 → completed
重新审核：PATCH /tasks/{id} 修改立场、来源、补充说明 → 按当前设置整体重算脱敏 → awaiting_confirm → 用户再次确认 → 新轮次
```

不分段（N = 1）时行为与 M2 完全一致：发送的消息逐字不变（不加分段说明），T-07、T-09～T-11 等原有测试不改。

## 二、分段（M5-01，新建 `app/review/chunking.py`，纯函数）

```python
@dataclass(frozen=True)
class OutLine:
    loc: str            # 行首方括号内的位置编号（节点 loc，或报价明细表汇总行的表格位置）
    text: str           # 整行文字（含 “[loc] ” 前缀），与外发文本中的行逐字相同
    boundary: bool      # 是否是首选切分点（见下）

@dataclass(frozen=True)
class Chunk:
    index: int          # 从 1 开始
    total: int
    lines: list[str]    # 本段的正文行（不含【主体说明】）
    first_loc: str
    last_loc: str

def outbound_lines(body: str, boundary_locs: set[str]) -> list[OutLine]
def split_chunks(lines: list[OutLine], limit: int) -> list[Chunk]
```

* 长度按字符数计（Python len），只计正文行（含行首编号和换行），不计【主体说明】、审核背景、审核要求。正文总长不超过 limit 时只有 1 段。
* 首选切分点（boundary=True）：每个文件的第一行；kind=heading 的节点；clause\_no 不含“.”的节点（“第8条”“8”“一、”这类一级条款）。报价明细表汇总行和其他行为 False。
* 切分规则：贪心。从当前段起点开始，取到“下一个首选切分点之前”为一个单元；单元能放进当前段就放入，放不下且当前段非空就另起一段。单元本身超过 limit 时按行贪心切开。单行超过 limit 时该行独占一段（不在行内切开，段长允许超过 limit；实际不会出现，节点文字远小于 60000）。
* limit 取设置 model.chunk\_chars（默认 60000），小于 1000 时按 1000（防止误配置把文件切成上千段）。
* `boundary_locs` 由 `app/review/service.py` 的 `build_context` 从 doc\_nodes 查出（part=body 的节点按上面的规则判断，再加每个文件的第一个正文节点），放进 ReviewContext。

ReviewContext 增加字段：`boundary_locs: set[str]`、`quote_tables: list[QuoteTable]`（第五节用）。为此 `app/redaction/engine.py` 增加一个函数，`build_outbound_text` 改为调用它，行为不变：

```python
@dataclass
class OutboundBuild:
    text: str                       # 与 build_outbound_text 相同
    quote_tables: list[QuoteTable]  # 本次识别出的报价明细表（汇总行的 loc、first_loc、row_locs 等）
def build_outbound(db: Session, task: Task) -> OutboundBuild
```

**每段的消息**（`app/review/prompt.py`）：`build_messages(ctx, chunk: Chunk | None = None)`。chunk 为 None 或 total = 1 时与现在逐字相同。total > 1 时：

* 【审核背景】末尾追加一项“分段：第 i/N 段（文件较长，分段审核，其余段落另行审核；只对本段内容给出问题，缺少某项内容的问题只在本段属于该内容应在的位置时提出）”。
* 【审核要求】【主体说明】【本地校验摘要】每段都完整带上（11.5）。
* &lt;document&gt; 中只放本段的行。

提示词版本：system.md 不改，版本号不变（分段说明在 user 消息中，属于“审核背景”的取值）。分段说明的措辞记入 Q-78 ①。

## 三、合并（M5-01，`app/review/validate.py`）

```python
@dataclass
class ChunkOutcome:
    chunk: Chunk
    review: ValidatedReview | None   # 失败时为 None
    error: str | None                # 失败原因（给用户看的中文，不含原文），如“模型服务调用失败”“模型返回的内容不符合要求”“已达本月调用上限，请联系管理员”

def validate_output(raw: str, ctx: ReviewContext, nodes: dict[str, DocNodeView], chunk: Chunk | None = None) -> ValidatedReview
def merge_reviews(ctx: ReviewContext, outcomes: list[ChunkOutcome]) -> ValidatedReview
def review_once(db, ctx, *, run, user_id, chunk: Chunk | None = None) -> ValidatedReview
```

* validate\_output 传入 chunk 时，第 3 条（删除无效 loc）只保留**本段**内的位置编号；不传时同现在（全部正文节点）。
* 审核要求结论：每条要求在全部**成功**分段中按 issue > unable > ok > na 取最高（11.5）；note 取给出该结论的第一个分段的 note。所有成功分段都没有给出该要求（validate\_output 已补记的 unable 不算“给出”）时记 unable，note 为“模型未返回结论”。没有任何成功分段时不合并，由处理函数置 failed。
* 问题：按分段顺序拼接，再整体做一次第 7 条的重复合并（不同分段的位置不重叠，实际只会合并 locs 为空的缺失型问题）。
* 制裁：取最高等级（high > attention > none；某段为 null 时忽略）；reasons 按出现顺序去重拼接。
* doc\_summary：第一个成功分段的摘要。
* tokens、llm\_call\_ids：累加全部分段（含失败分段已消耗的）。
* 处理函数写入：`run.chunk_count = N`；`run.failed_chunks = [{"index": i, "first_loc": "...", "last_loc": "...", "reason": "..."}]`（reason 为上面的中文原因）；全部失败时 `run.error_message` 取第一个失败分段的原因，有部分失败时为“第 2/3 段审核失败，结果不完整”这类说明（多段用顿号）。

**进度**：处理中 `run.coverage = {"progress": {"done": k, "total": N}}`，结束时被第四节的覆盖说明整体替换。RunDetail 增加 `chunk_count: int` 和 `progress: {"done": int, "total": int} | null`（status 为 running 时从 coverage.progress 取，其他状态为 null），`coverage` 只在轮次结束后返回（处理中返回 null）。记入 Q-78 ②。

## 四、覆盖说明（M5-03，新建 `app/review/coverage.py`）

```python
def build_coverage(db: Session, task: Task, ctx: ReviewContext, review: ValidatedReview | None,
                   chunk_count: int, failed_chunks: list[dict]) -> dict
def describe(coverage: dict, file_names: dict[int, str]) -> list[str]   # 限制事项的中文句子，结果页与 M6 报告共用
```

review\_runs.coverage 的结构（只存编号和数量，不存原文和名称；文件用 seq 表示，展示时换成文件名）：

```json
{
  "requirements": {"total": 32, "issue": 7, "ok": 18, "na": 5, "unable": 2},
  "unable": [{"req_id": "G-06", "note": "需合规人员确认"}],
  "excluded": [{"file": 1, "part": "header", "count": 2}, {"file": 2, "part": "hidden_sheet", "count": 15}],
  "quote_tables": [{"file": 2, "loc": "F2-S1", "rows": 12}],
  "ocr_low": [{"file": 3, "pages": [2, 5]}],
  "warnings": [{"file": 1, "text": "检测到修订痕迹，按接受修订后的文本审核"}],
  "chunked": true,
  "chunk_count": 3,
  "failed_chunks": [{"index": 2, "first_loc": "F1-P120", "last_loc": "F1-P260", "reason": "模型服务调用失败"}],
  "no_cross_chunk_check": true,
  "sanctions_offline": true
}
```

* requirements：按 ValidatedReview.requirement\_results 统计；全部分段失败时 total 为发送的要求数，四个数量都为 0。unable：全部 unable 的条目（Q-60：结果页不再为 partial 单独显示警告条，改为在覆盖说明中列出这些条目）。
* excluded：每个文件 part 不是 body 的节点（header、footer、comment、textbox、hidden\_sheet）按 part 计数；为 0 的不列。
* quote\_tables：ctx.quote\_tables 中每张报价明细表（行级数据未逐行发送，只发送了汇总行）。
* ocr\_low：part=body、kind=ocr\_block 且 ocr\_conf &lt; `LOW_OCR_CONF` 的节点所在页，按文件去重排序。
* warnings：task\_files.warnings 全文照录（解析器生成的固定句式，不含原文），保证 A-05 的“0 条被静默忽略”。
* chunked、chunk\_count、failed\_chunks、no\_cross\_chunk\_check：分段时 no\_cross\_chunk\_check 为 true（11.5“V1.0 不做跨分段的全局一致性检查”）。
* sanctions\_offline 固定为 true。
* blocked 的轮次不写覆盖说明（没有发送）；failed、partial、completed 都写。

describe() 的句子（固定写法，`file_names` 为 seq → 原文件名）：

| 项 | 句子 |
|-|-|
| excluded | “{文件名}：页眉 2 处、批注 1 处未参与 AI 审核”（part 中文：页眉、页脚、批注、文本框、隐藏工作表的单元格） |
| quote\_tables | “{文件名} {loc} 报价明细表共 12 行，只把汇总信息发给 AI，行级数据未逐行审核” |
| ocr\_low | “{文件名} 第 2、5 页 OCR 识别置信度低，请核对原件” |
| warnings | “{文件名}：{text}”（与 ocr\_low 重复的“OCR 识别置信度低”警告不再列出） |
| unable | “无法判断的审核要求：G-06（{note}）、G-09（{note}）” |
| chunked | “文件较长，分 3 段审核，未做跨分段的一致性检查” |
| failed\_chunks | “第 2 段（F1-P120 至 F1-P260）审核失败：模型服务调用失败，该部分没有审核结果” |
| sanctions\_offline | 不在 describe 中（结果页的制裁结论行固定显示 6.3 的那句说明） |

RunDetail 的 `coverage` 返回 `{"summary": "本次按 32 条审核要求审核：有问题 7 条，未发现问题 18 条，不适用 5 条，无法判断 2 条", "notes": ["…", "…"]}`；轮次未结束或 blocked 时为 null。数据库中的结构化 JSON 不直接返回前端。

## 五、汇总行的位置（M5-01，落实 Q-72 ⑥）

模型引用报价明细表汇总行的位置编号（如 F2-S1、F1-T2）时，validate\_output 不再当作无效位置删除：

* 位置映射为该表的 `first_loc`（表头行第一个单元格），点击问题时右栏定位到表头行。
* 引用校验对照汇总行的外发文字（`summary_text` 的结果，代号形式）做（与 11.4 第 4 条同样的规范化和相似度）；校验通过时 cite\_status=verified，quote\_snapshot 为汇总行文字按本任务对照表还原后的结果（加密存储，与其他快照一样）。
* 同一问题的 locs 去重后保持原顺序。

## 六、调用上限（M5-02）与 Q-77 ③

**调用上限**（7.5、T-13）：网关已在发送前检查（M2-10），本里程碑只补测试和提示：达到上限时第一段就失败 → 全部分段失败 → run=failed，error\_message=“已达本月调用上限，请联系管理员”，llm\_calls 不增加 status=sent 的记录；确认发送接口不提前拦截（7.5 要求轮次记为 failed）。

**Q-77 ③**：手动补充（POST /redaction/manual）和疑似遗漏选“替换”时，所选文字如果出现在固定的提示文字中，拒绝并返回 422 `TERM_IN_PROMPT`，消息“所选文字在审核提示中也会出现，设为敏感信息后将无法发送，请只选择具体的名称或编号”。

```python
# app/review/prompt.py
def fixed_prompt_text(db: Session) -> str
    # system 消息全文 + 全部内置要求文字（不按类型筛选）+ 启用的公司补充要求文字 + 公司说明 + 【审核背景】中的固定词
    # （立场、来源、文件类型的中文、“分段”说明）。只读，不调用模型。
```

engine 的 `_add_term` 和 `decide_suspect`（replace 分支）在写入前调用（函数内局部导入，避免循环导入）：`recheck(fixed_prompt_text(db), real_values=[term], terms=[])` 非空即拒绝。比较规则与出口复检完全一致，保证“拒绝的恰好是发送时会被拦截的”。前端 labels 中 REDACTION\_ERROR\_MESSAGES 增加该错误码（M5-05）。

## 七、重新审核（M5-04）

| 方法 | 路径 | 说明 |
|-|-|-|
| PATCH | /tasks/{id} | 入参 `{stance?, source?, user_note?}`（至少一项；user\_note 为空字符串表示清除，最长 500）。前置：policy=local\_only 返回 409 LOCAL\_ONLY；status 不是 reviewed 或 awaiting\_confirm 返回 409 TASK\_STATE\_CONFLICT。锁任务行 → 改字段 → `engine.apply_party_changes(db, task, [])` 整体重算（我方选择、国家类型修改、用户词条、“忽略”决定都保留，代号角色按新立场生成）→ status=awaiting\_confirm → 提交。返回 GET /tasks/{id} 的结构 |
