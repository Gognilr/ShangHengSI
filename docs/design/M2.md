# M2 最小闭环：模块划分与接口约定

本文件由 M2-00 制定，是 M2 各任务之间的契约。执行任务的会话必须按这里的函数签名、数据格式和接口形状实现；需要改动时停下来报告，由 Opus 会话修改本文件。与 SPEC 冲突时以 SPEC 为准。

M2 只支持 DOCX 的解析。上传接口按 SPEC 接受全部五种格式，但 PDF、XLSX、图片在 M3 之前解析会失败，提示“该格式的解析将在后续版本提供”。人名、地址识别、疑似遗漏、金额比例、报价明细表汇总、已记住名称的写入都在 M4；分段审核、覆盖说明在 M5；本地校验在 M6。

## 一、处理流程与状态

```text
POST /tasks ──> tasks.status=parsing，原件加密落盘，入队 parse
worker: parse ──> 解析 DOCX → 写 task_files / doc_nodes → 识别文件类型
              ├─ policy=local_only ──> status=completed_local（M6 起在此之前做本地校验）
              └─ policy=ai ──> 脱敏（parties、redaction_items、对照表、redacted_text）──> status=awaiting_confirm
              （任何异常）──> status=parse_failed，error_message 写明文件名和原因，不含原文
用户在第二步确认 ──> POST /tasks/{id}/runs：预检出口复检 → 新建 review_run(queued) → 入队 review → status=reviewing
worker: review ──> run=running → 拼接提示词 → 网关（上限检查 → 出口复检 → 发送 → 记录）→ 校验输出 → 写结果
              ├─ 成功 ──> run=completed（有 unable 结论时 partial），status=reviewed
              ├─ 网关拦截 ──> run=blocked，status=awaiting_confirm
              └─ 失败 ──> run=failed，status=reviewed
```

worker 处理任务时必须先重新读取 task；任务已被删除时直接结束，不报错。

## 二、后台任务队列（M2-01）

文件：`app/db/jobs.py`（队列操作）、`app/worker.py`（主循环）。

```python
# app/db/jobs.py
def enqueue(db, type: str, payload: dict, *, run_after: datetime | None = None) -> Job   # 只 add，不提交
def claim(db, worker_id: str) -> Job | None        # FOR UPDATE SKIP LOCKED；置 running、attempts+1、locked_by、heartbeat_at；提交

def complete(db, job_id: int) -> None              # status=done，finished_at
def fail(db, job_id: int, error_code: str) -> None # status=failed；last_error 只写异常类名或错误码，不写消息内容
def requeue_stale(db) -> int                        # running 且心跳超过 15 分钟：attempts < max_attempts 置回 queued，否则 failed
def queue_position(db, job_id: int) -> int | None   # 同类型、queued、id 更小的数量 + 1；不在排队时为 None
```

```python
# app/worker.py
HANDLERS: dict[str, Callable[[Session, dict], None]]   # 按 job.type 分派
def job_handler(type: str)                              # 装饰器，注册处理函数
def ocr_slot() -> ContextManager                        # 全局只允许 1 个 OCR（M3 使用）
```

- 并发数取 `WORKER_CONCURRENCY`（默认 2），每个并发一个线程，各自独立的数据库会话。
- 处理函数抛出异常：job 记为 failed；处理函数自己负责在抛出前把 task / run 置为失败状态。
- 没有注册处理函数的类型：job 记为 failed，last_error=`NO_HANDLER`。
- 每分钟执行一次定时工作：`requeue_stale`、删除已过期会话（open_questions Q-31）。提供 `register_periodic(name, func, every_seconds)` 供 M7 的备份和保留期清理使用。
- 日志只写 job id、类型、task id、耗时、错误码，不写文件名和任何文本。

## 三、上传与任务接口（M2-02）

文件：`app/tasks/router.py`、`app/tasks/service.py`、`app/tasks/schemas.py`、`app/tasks/storage.py`。

**上传检查（SPEC 17.6）**，任一不满足返回 422：

| 检查 | 错误码 |
|-|-|
| 没有文件 / 超过 10 个 | NO_FILES / TOO_MANY_FILES |
| 单个文件超过 MAX\_UPLOAD\_MB | FILE_TOO_LARGE |
| 扩展名不在 docx、pdf、xlsx、jpg、jpeg、png（jpeg 存为 jpg） | UNSUPPORTED_FILE_TYPE |
| 文件头与扩展名不符（docx/xlsx 必须是 ZIP 且含 `[Content_Types].xml` 和 `word/document.xml` 或 `xl/workbook.xml`；pdf 以 `%PDF-` 开头；jpg 以 `FF D8 FF` 开头；png 以 `89 50 4E 47` 开头） | FILE_CONTENT_MISMATCH |
| 宏文件：含 `vbaProject.bin`，或内容类型含 `macroEnabled` | MACRO_NOT_ALLOWED |
| ZIP 解压后总大小超过 200 MB，或条目超过 10000 个 | ARCHIVE_TOO_LARGE |
| main\_index 越界、stance/source/policy 取值不对、user\_note 超过 500 字 | VALIDATION_ERROR |

**存储**（`app/tasks/storage.py`）：`save_original(data: bytes) -> tuple[str, str]` 返回（storage_key=uuid4 十六进制，明文 SHA-256），用 `crypto.encrypt_to_file` 写入 `FILES_DIR/storage_key`；`load_original(storage_key) -> bytes`；`delete_original(storage_key)`（文件不存在不报错）。

**原文件名**：只取最后一段（去掉路径），截断到 255 字符。任务标题 = 主文件名。

**接口**：

| 方法 | 路径 | 入参 | 返回 |
|-|-|-|-|
| POST | /tasks | multipart：files（多个）、main\_index（默认 0）、stance、source、policy、user\_note | 201 `{"id"}`；同时更新 users.last\_stance / last\_source，入队 parse，审计 task\_create（detail 只含文件数和 policy） |
| GET | /tasks | page（默认 1）、q（文件名包含，不区分大小写）、from、to（`YYYY-MM-DD`，按 Asia/Shanghai 日界） | 分页：items 为 `{id, title, doc_type, stance, status, high_count, created_at}`，按 created\_at 倒序，每页 20 |
| GET | /tasks/{id} | — | 见下方 TaskDetail |
| DELETE | /tasks/{id} | — | 204；先删原件文件再删任务行（级联），审计 task\_delete；任何状态都可删 |
| PATCH | /tasks/{id}/files/{fid} | `{doc_type}` | 文件对象；只在 awaiting\_confirm 时允许，否则 409 TASK_STATE_CONFLICT；doc\_type\_source 置 user（M2-13 实现） |

```json
TaskDetail = {
  "id", "title", "status", "error_message", "stance", "source", "policy", "user_note", "created_at",
  "files": [{"id", "seq", "is_main", "original_name", "ext", "size_bytes", "doc_type", "doc_type_source",
             "page_count", "paragraph_count", "table_count", "has_revisions", "warnings": ["…"]}],
  "latest_run": {"id", "run_no", "status"} | null,
  "queue_position": 3 | null
}
```

paragraph\_count = 该文件 part=body 且 kind≠table\_cell 的节点数；table\_count = 该文件不同表格的数量。queue\_position 为最新轮次 review 任务的排队位置。

所有任务接口一律用 `security/deps.py` 的 `owned_task` / `owned_task_file` 等依赖取对象。

## 四、统一文档模型与 DOCX 解析（M2-07）

```python
# app/parsing/model.py
@dataclass
class ParsedNode:
    loc: str; ord: int; kind: str; part: str; text: str
    clause_no: str | None = None; parent_loc: str | None = None
    page: int | None = None; bbox: list[float] | None = None
    sheet: str | None = None; cell_ref: str | None = None
    ocr_conf: float | None = None; has_revision: bool = False

@dataclass
class ParsedFile:
    nodes: list[ParsedNode]; page_count: int | None; has_revisions: bool; warnings: list[str]

class ParseError(Exception): ...   # 消息为给用户看的中文原因，不含原文

# app/parsing/docx.py
PARSER_VERSION = "docx-1"
def parse_docx(data: bytes, file_seq: int) -> ParsedFile
```

- 节点 text 是原文；自动编号产生的编号只放在 clause\_no，不放进 text。用正则从“第X条”“X.Y”开头提取的 clause\_no，text 中本来就有。显示和外发时：text 不以 clause\_no 开头才在前面加 clause\_no。
- 空段落不生成节点；段落序号 P 只给生成的节点编号。表格序号 T 按正文顶层表格的顺序编号。
- 位置编号：正文按 SPEC 8.2；页眉 F1-H{n}、页脚 F1-FT{n}、批注 F1-CM{n}、文本框 F1-TB{n}；嵌套表格在外层单元格编号后追加 -T{表}-R{行}-C{列}（open_questions Q-15）。
- 警告文字（写入 task\_files.warnings）：`检测到修订痕迹，按接受修订后的文本审核`；有页眉页脚、批注、文本框时各加一条 `页眉页脚未参与 AI 审核` 等。

## 七、模型网关（M2-10）

```python
# app/llm/gateway.py —— 唯一可以访问外网的文件
@dataclass
class ModelResult:
    content: str; model_name: str; tokens_in: int; tokens_out: int; duration_ms: int; llm_call_id: int

class GatewayError(Exception):    # code：CAP_REACHED / BLOCKED / NOT_CONFIGURED / HTTP_ERROR / TIMEOUT / BAD_RESPONSE
    code: str; reasons: list[BlockReason]

def call_model(db, *, purpose: str, messages: list[dict], user_id=None, task_id=None, task_title=None,
               run_id=None, json_mode: bool | None = None) -> ModelResult
```

- 依次执行：每月调用上限检查 → 出口复检（对全部 messages 的 content 拼接后检查）→ 发送 → 写 llm\_calls。被拦截时写一条 status=blocked、request\_text 为空、block\_reason 只含类别和位置的记录，然后抛出 `GatewayError("BLOCKED")`。
- 失败重试 2 次，间隔 10 秒和 30 秒（间隔可在测试中注入为 0）；每次尝试都写一条 llm\_calls。
- 请求体：`model`、`messages`、`temperature`、`max_tokens`、json\_mode 开启时 `response_format={"type":"json_object"}`，再原样合并附加请求参数。超时取设置值。
- `test_connection(db, user_id) -> ModelResult`：发送不含业务数据的固定测试消息，purpose=test。
- 设置读取（`app/admin/settings_store.py`）：`get_setting(db, key)`，表中没有时返回 SPEC 18.20 的默认值；`set_setting(db, key, value, user_id)`。API 密钥用 `crypto.encrypt_to_b64` 存于 `model.api_key_enc`。
- 开发用命令（`app/cli.py`）：`set-model --base-url --model [--extra-params JSON]`，密钥从标准输入读取 `--api-key-stdin`。
- 用量（`app/llm/usage.py`）：`monthly_usage(db) -> {calls, tokens_in, tokens_out, cost}`，月份按 Asia/Shanghai 计算，只统计 status=sent。
- 模拟模型服务：`tests/mock_llm.py` 提供按规则生成回复的函数（可配置：正常、非 JSON、无效 loc、编造 quote、漏要求、HTTP 500、超时），测试中通过 httpx.MockTransport 注入网关；`tools/mock_llm_server.py` 用同一套规则起一个 OpenAI 兼容的本地服务，配合 `deploy/docker-compose.mock.yml` 供本地联调（base\_url 指向 `http://mock-llm:9000/v1`，仍经过网关的全部步骤）。
