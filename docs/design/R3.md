# R3 界面改版（商衡SI 品牌与原文对照）

来源：用户提供的设计资料包 SHSI_Design_Package_20261023_v2（Design_Guide.md 与参考图），以及用户认可的改造方案和优化版（2026-10-23）。用户在 2026-10-23 确认：采用该视觉方向，覆盖全部页面；“记住我”只记用户名；确认脱敏页做原文与外发文本常驻对照。本轮细化中的取舍记入 Q-147，执行时机见 Q-148。

效果预览：[ui-preview.html](ui-preview.html)（静态页面，虚构数据，浏览器直接打开，右下角可切换全部 11 个页面）。预览是视觉目标，不是实现代码：实现时用 Element Plus 组件，按本文和 frontend.md 第二版落地。

思路：**只换外观，不动业务。** 品牌色通过覆盖 Element Plus 的 CSS 变量实现，业务代码中的 `type="primary"`、`danger`、`info` 和 `labels.ts` 的枚举颜色保持不变；接口、状态流转、提交条件、脱敏与网关逻辑一律不改。唯一的新能力是确认脱敏页的“原文与外发文本对照”，它只组合现有三个接口的数据，不新增接口。

**记住我**（用户已确认：只记用户名）：

| 项目 | 规则 |
|-|-|
| 存储 | `localStorage` 键 `si.login.username`，值为用户名字符串；读写包在 try/catch 中，失败时当作未记住 |

### 4.3 确认脱敏（ConfirmStep，宽档 1200px）

- 4 疑似遗漏：标题右侧“还有 N 条未处理”警告色胶囊；上下文中命中词用浅警告底。

- 7 本地校验结果：保持折叠面板，标题右侧显示条数。

  - `disabledReason` 的其余情况原样显示。

### 4.4 审核结果 `/review/:taskId`

保持左 44% / 右 56% 双栏、间距 20px。

- **信息卡**（`.panel`，内边距 20px 24px）：类型色块 + 主文件名（18px）+ 附件数一行；右上为运行状态标签。下方 3 列网格的元信息：文件类型、立场 / 来源、审核时间、使用的模型、审核要求版本、审核轮次（多轮时为下拉）。不再用 `el-descriptions border`。
- **等级计数**：高 / 中 / 低三块（等级色圆点 + 数字），点击即把“全部等级”筛选设为该等级，再点一次取消。数字取当前轮次的问题数，不另请求。
- **摘要与覆盖**：浅灰面板，依次为文件摘要、覆盖说明与限制事项、制裁结论与固定声明（逐字不变）。
- **标签页**：下划线式，文字同现在。
- **问题卡片**（FindingCard）：左侧 4px 等级色条；标题 16px / 600 + 等级（`effect="dark"`）+ 类别 + 引用状态标签，右上角位置；原文引用为浅灰引用块（左 3px 边框）；问题说明、对我方的影响为“小标签 + 正文”；修改建议与可直接替换的措辞放在浅品牌色块中，措辞在白底虚线框内并带“复制”按钮；依据 12px 次要色；底部分隔线下为处理状态与备注。选中时边框变深海蓝并带 3px 浅品牌色外环；可定位的卡片鼠标为手形。
- **操作区**：左栏底部 `position: sticky; bottom: 0` 的半透明条：追问、导出报告、重新审核（带图标的普通按钮），最右“删除任务”（危险色文字按钮，二次确认不变）；导出不可用的原因照旧显示。
- **原文预览**（DocPreview）：外框 12px 圆角面板；顶部工具条（文件 / 工作表切换、右侧提示“点击左侧问题可定位原文”）；正文区浅灰底上的白色纸面（DOCX / XLSX 节点渲染时）；高亮改为浅警告底 + 2px 下划线。PDF、图片渲染与定位逻辑不变。

## 五、原文与外发文本对照（新组件 `components/RedactionCompare.vue`）

### 5.1 数据（只用现有接口）

| 内容 | 接口 | 字段 |
|-|-|-|
| 原文节点 | `GET /tasks/{id}/files/{fid}/nodes`（每个文件一次） | `loc`、`text`、`clause_no`、`cell_ref`、`sheet`、`page`、`parent_loc` |
| 替换位置 | `GET /tasks/{id}/redaction` | `items[]`：`loc`、`char_start`、`char_end`（按码点计）、`category`、`placeholder` |
| 外发文本 | `GET /tasks/{id}/redaction/outbound` | `text`：第一行【主体说明】，其后每行 `[loc] 内容`（`outbound.node_line`；报价明细汇总行为 `[表格 loc] 【报价明细表：…】`） |

ConfirmStep 已经读取 `/redaction` 与 `/redaction/outbound`，对照组件通过属性接收这两份数据，只自行读取各文件的节点（与 ManualRedactDialog 相同的接口）。

### 5.2 配对算法（纯函数，放在 `utils/compare.ts`）

1. 外发文本按 `\n` 分行。首行不以 `[` 开头时作为“主体说明”行（左侧显示固定说明“系统生成的签约方说明，原文无对应段落”）。
2. 其余每行用 `^\[([^\]\s]+)\] ` 取出 loc 与内容；取不到 loc 的行单独成为一行，左侧显示“—”。
3. 把全部文件的节点按接口返回顺序拼成一个列表，建立 `loc → 节点`。
4. 外发行的 loc 能找到节点：一行一对。
5. 外发行的 loc 找不到节点（报价明细汇总行，loc 是表格位置）：左侧取所有 loc 以 `{该 loc}-` 开头、且没有自己外发行的节点，按顺序列出，右侧标注“报价明细已汇总发送”。
6. 没有被任何外发行用到的节点：在文档顺序中的对应位置插入一行，右侧显示“—（不发送）”。
7. 原文分段：`Array.from(text)` 按码点切分，按 `items` 的 `char_start`/`char_end` 拼成片段 `{ text, placeholder?, category? }`（从 ManualRedactDialog 现有的 `segments()` 抽出共用，两处结果一致）。
8. 外发内容分段：在内容中查找本行出现的 `placeholder` 字符串（来自 `items` 中同 loc 的条目，以及【主体说明】行中的全部占位符），拼成 `{ text, placeholder? }`。不按正则猜测占位符格式。
9. 疑似遗漏：`suspects` 中未处理条目按 `loc`、`text` 在原文和外发内容中标出（警告色，标签“待处理”）。外发栏的这段文字就是原样会发出的内容。

函数签名（契约）：

```ts
export interface CompareSeg { text: string; placeholder?: string; category?: string; suspect?: boolean }
export interface CompareRow {
  kind: 'header' | 'pair' | 'grouped' | 'not_sent' | 'unmatched'
  loc: string | null
  label: string            // 位置显示，如“第 12 段”“报价明细 · B7”“第 3 页”
  left: CompareSeg[][]     // grouped 时为多段，其余为 0 或 1 段
  right: CompareSeg[] | null  // not_sent 时为 null
  hasRedaction: boolean
  hasPendingSuspect: boolean
}
export function buildCompareRows(outboundText: string, nodes: PreviewNode[],
  items: RedactionItemPos[], suspects: Suspect[]): CompareRow[]
```

右侧各片段的 `text` 依次相连，必须**逐字等于**该行去掉 `[loc] ` 前缀后的外发内容。实现中对每一行做这项校验，不相等时退回整行纯文本显示，并计入“未能对齐”的数量。

### 5.3 界面

- 面板标题“6. 原文与外发文本对照”，说明“左侧原文仅在本机显示；右侧是确认后实际发送给模型的文本”。
- 工具条：文件分段按钮（“全部文件”+ 每个文件“文件名 · N 段有替换”）；“只看有替换的段落”复选框（默认勾选；勾选时有待处理疑似遗漏的行也显示）；右侧统计“共 X 段，Y 段有替换”，有未能对齐的行时加警告色“Z 段未能对齐”。
- 图例：各类别色块 + “疑似遗漏（未处理，将原样发送）”；右侧 12px 提示“悬停任一处，两侧对应内容同时高亮；在左侧选中文字可直接补充脱敏”。
- 主体：一个最大高度 560px、内部滚动的网格，三列 112px / 1fr / 1fr，表头吊顶。连续被隐藏的行折叠为一条“已隐藏 N 段无替换的段落 · 展开”。

- 在左侧选中文字（同一节点内、2～100 个字符）：选区下方弹出浮层“设为敏感信息”，类别选项与疑似遗漏“替换”时相同（`UserCategory`：ORG / PERSON / CUSTOM，中文名取 `labels.ts`），调用现有 `redactionApi.manual(loc, char_start, char_end, category)`，错误码按 `REDACTION_ERROR_MESSAGES` 提示；成功后由 ConfirmStep 统一刷新数据。跨节点选择不弹出。
- 加载：首次加载与刷新时整块 `v-loading`；某个文件的节点读取失败时，该文件的行只显示右栏并提示“原文读取失败”。

### 5.5 安全要求

- 原文来自现有节点接口，只在浏览器内存中显示；不写 `localStorage`，不输出到控制台。

- 外发栏内容只来自 `/redaction/outbound` 的返回；前端不拼接、不替换。真正发送的仍是后端在确认时重新生成并复检的文本（SPEC 9.6），对照只用于阅读。
- 配对失败的行左右分开显示，不隐藏任何外发内容。
