# M3 解析补全与预览：模块划分与接口约定

本文件由 M3-00 制定，是 M3 各任务之间的契约。执行任务的会话必须按这里的函数签名、数据格式和接口形状实现；需要改动时停下来报告，由 Opus 会话修改本文件。与 SPEC 冲突时以 SPEC 为准。前端任务同时遵守 docs/design/frontend.md。

M3 在 M2 的链路上补齐另外四种格式（PDF 文字版、PDF 扫描页、JPG / PNG 图片、XLSX）的解析，并增加原文预览与“点击问题定位原文”。验收用例 T-03。

不在 M3 范围内：报价明细表整表汇总（Q-18，M4）、疑似遗漏与手动补充（M4，手动补充会用到本里程碑的预览组件）、覆盖说明卡片（M5，本里程碑只把低置信和未参与审核的信息写进 task\_files.warnings 和节点字段，供 M5 汇总）、本地校验和报价表行校验（M6）。

## 一、处理流程的变化

```text
worker: parse ──> 按扩展名分派解析器：
                    docx → parse_docx（M2）
                    xlsx → parse_xlsx
                    pdf  → 先 inspect_pdf 统计页数与扫描页数 → 检查页数与 OCR 预算 → parse_pdf（扫描页走 OCR）
                    jpg / png → 检查 OCR 预算 → parse_image（OCR）
                  需要 OCR 的文件在 worker.ocr_slot() 内解析（同一时间最多 1 个 OCR 任务，SPEC 21）
              ──> 写 doc_nodes / task_files（与 M2 相同，单事务）──> 识别文件类型 ──> 脱敏或 completed_local（与 M2 相同）
```

任务状态、轮次状态、出口复检、网关都不变。原先“该格式的解析将在后续版本提供”的分支删除。

## 二、统一文档模型的补充（`app/parsing/model.py`）

```python
@dataclass
class ParsedFile:
    nodes: list[ParsedNode]
    page_count: int | None
    has_revisions: bool
    warnings: list[str]
    ocr_pages: int = 0          # 本文件实际做了 OCR 的页数（图片记 1）

MAX_PDF_PAGES = 200            # SPEC 8.7
MAX_OCR_PAGES_PER_TASK = 100   # SPEC 8.7，整个任务合计
MAX_XLSX_CELLS = 20000         # SPEC 8.7，单个 XLSX 非空单元格
LOW_OCR_CONF = 0.80            # SPEC 8.5
```

坐标约定（open\_questions Q-61）：

* `bbox = [x0, top, x1, bottom]`，原点在左上角，x 向右、y 向下。
* PDF：单位是 PDF 点（1/72 英寸），以**页面显示方向**为准（页面有 /Rotate 时已换算到旋转后的方向），即与 pdfjs 以 scale=1、rotation=页面自身旋转渲染出的画面一致。
* 图片：单位是原图像素，以 EXIF 方向校正后的图片为准（与浏览器 `<img>` 默认显示的方向一致）。
* page 从 1 开始；图片固定为 1。

各格式的 loc、kind、part（SPEC 8.1、8.2）：

| 内容 | loc | kind | part |
|-|-|-|-|
| PDF 文字页的文本块 | F{n}-PG{页}-B{块} | paragraph（不区分标题和列表） | body |
| PDF 表格单元格 | F{n}-PG{页}-T{表}-R{行}-C{列} | table\_cell | body |
| PDF 扫描页、图片的文本块 | F{n}-PG{页}-B{块} | ocr\_block | body |
| XLSX 单元格 | F{n}-S{工作表序号}-{单元格地址} | sheet\_cell | 显示中的工作表 body，隐藏的 hidden\_sheet |

块序号 B、表序号 T 在每页内从 1 开始，按从上到下的阅读顺序编号；同一页的文本块和表格按 top 交错排列，ord 按此顺序在文件内连续递增。PDF 不区分页眉页脚，全部为 body（Q-61 ②）。

clause\_no：PDF 文本块、OCR 文本块沿用 `parsing.docx.manual_clause_no(text)` 的手写编号规则；XLSX 不提取。

## 三、XLSX 解析（M3-02，`app/parsing/xlsx.py`）

```python
PARSER_VERSION = "xlsx-1"

def parse_xlsx(data: bytes, file_seq: int) -> ParsedFile: ...
```

* 用 openpyxl 读两次：`data_only=True` 取缓存值，`data_only=False` 判断公式（SPEC 8.4）。不用 read\_only 模式（需要合并单元格信息）。
* 工作表序号按 `workbook.worksheets` 的顺序从 1 开始（含隐藏表，不含图表页）。`sheet_state` 为 hidden / veryHidden 的表，其节点 part=hidden\_sheet。
* 每个非空单元格一个节点，按行优先（行号、再列号）排序。合并区域只在左上角出节点，其他格忽略。
* 单元格文字（Q-62 ①）：
  * 字符串：原样，去掉首尾空白；空字符串视为空单元格。
  * 整数和小数：用 Decimal 转成不含科学计数法的十进制文字，去掉多余的尾随 0（`1250.0` → `1250`，`0.125` → `0.125`）；不按单元格格式补千分位。
  * 单元格格式含 `%`：值乘以 100 后按上一条格式化并加 `%`（`0.3` → `30%`）。
  * 单元格格式含货币符号或代码（`¥ ￥ $ € £`，或 `[$USD]`、`[$EUR-…]` 这类写法）：在数字前加对应符号或代码与一个空格（`USD 1250`、`¥ 800000`），让 9.3 第 5 步的金额规则能识别。
  * 日期和日期时间：`YYYY-MM-DD`，有时间部分时 `YYYY-MM-DD HH:MM`。
  * 布尔：`TRUE` / `FALSE`。
* 有公式但没有缓存值的单元格：不出节点；整个文件加一条警告“含未计算的公式，相关金额无法核验”（SPEC 8.4，只加一次）。不自行重算。
* 有隐藏的行或列：节点照常为 body，整个文件加一条警告“含隐藏的行或列，已按正常内容审核”（Q-62 ②）。
* 有隐藏工作表：警告“隐藏工作表未参与审核”（SPEC 6.2 的例句）。
* 非空单元格合计超过 20000：`ParseError("单个 XLSX 的非空单元格超过 20000 个")`。没有任何非空单元格：`ParseError("未能从文件中读取到内容")`。
* page\_count 为 None。文件损坏、加密（openpyxl 无法打开）：`ParseError("XLSX 文件无法读取，可能已损坏或已加密")`，消息不含原文。

## 四、PDF 解析（M3-03 文字页，M3-04 扫描页）

```python
# app/parsing/pdf.py
PARSER_VERSION = "pdf-1"
TEXT_PAGE_MIN_CHARS = 20   # SPEC 8.5，去掉空白后的字符数

@dataclass
class PdfInfo:
    page_count: int
    scanned_pages: list[int]   # 需要 OCR 的页码（从 1 开始）

def inspect_pdf(data: bytes) -> PdfInfo: ...
def parse_pdf(data: bytes, file_seq: int) -> ParsedFile: ...
```

* 打开失败、已加密（需要密码）：`ParseError("PDF 文件无法读取，可能已损坏或已加密")`。页数超过 200：`ParseError("PDF 超过 200 页")`（inspect\_pdf 和 parse\_pdf 都检查）。
* 每页先 `page.dedupe_chars()`，去掉空白后字符数 ≥ 20 的是文字页，否则是扫描页。
* **文字页**（M3-03）：
  * 表格：`page.find_tables()`；每个表格的单元格出一个 table\_cell 节点，行列从 1 开始，值为 None 的格（合并区域的其余格）不出节点；单元格 bbox 取自 `table.rows[i].cells[j]`。
  * 文本：取 `page.extract_text_lines()`，丢弃中心点落在任一表格 bbox 内的行（Q-16）。相邻两行属于同一块的条件：上一行 bottom 到下一行 top 的间距 ≤ max(3, 0.6 × 上一行高度)，且下一行不以条款编号开头（`manual_clause_no` 能匹配）。块文字按行拼接：两侧都是汉字或中文标点时直接相连，否则以一个空格相连。块 bbox 取各行的外接矩形。
  * 文本块和表格按 top 排序后依次编号。
* **扫描页**（M3-04）：用 pypdfium2 以 200 DPI 渲染（scale = 200 / 72），交给 `ocr.recognize`，得到的行坐标除以 scale 换算回 PDF 点，再按与文字页相同的规则合并为块（OCR 行没有条款编号判断以外的结构信息）。块 ocr\_conf 为块内各行置信度的平均值。
* 页面有旋转时，bbox 换算到显示方向（见第二节）；样本中必须有一页旋转 90° 的页面并有测试。
* 警告（Q-61 ③）：
  * 有扫描页：“第 3、5 页为扫描页，已用 OCR 识别”（页码合并成一条）。
  * 有块的 ocr\_conf < 0.80：“第 3 页 OCR 识别置信度低，请核对原件”（每页一条，最多列 10 页，其余写“等 N 页”）。
  * 扫描页没有识别出任何文字：“第 4 页未识别到文字”。
* 整个文件没有任何节点：`ParseError("未能从文件中识别出文字")`。
* page\_count 为实际页数；ocr\_pages 为扫描页数。

## 五、OCR 与图片（M3-04，`app/parsing/ocr.py`、`app/parsing/image.py`）

```python
# app/parsing/ocr.py
@dataclass
class OcrLine:
    text: str
    bbox: list[float]     # [x0, top, x1, bottom]，输入图片的像素坐标
    conf: float

def recognize(image: "PIL.Image.Image") -> list[OcrLine]: ...
def merge_lines(lines: list[OcrLine]) -> list[list[OcrLine]]: ...   # 合并为块，PDF 扫描页与图片共用

# app/parsing/image.py
PARSER_VERSION = "image-1"
MAX_OCR_SIDE = 4000   # 长边超过时先等比缩小再识别，坐标换算回原图像素

def parse_image(data: bytes, file_seq: int) -> ParsedFile: ...
```

* RapidOCR 引擎在进程内首次使用时创建一次并复用（加载约 1 秒）；调用方负责 ocr\_slot 互斥，`recognize` 本身不加锁。
* **导入 onnxruntime 之后、创建引擎之前调用 `onnxruntime.disable_telemetry_events()`**（Q-64）。模型文件随 rapidocr-onnxruntime 包进镜像，运行时不下载任何东西；M3-04 的完成报告须给出在 `--network none` 的容器中运行 OCR 测试的命令和结果（M3-09 验收时复核），并保持 T-20 静态扫描通过。
* RapidOCR 返回的四点框取外接矩形作为 bbox；空文字的行丢弃。
* 图片：Pillow 打开，`ImageOps.exif_transpose` 校正方向，转 RGB；超过 Pillow 的像素上限（DecompressionBombError）或无法打开：`ParseError("图片无法读取")`。page\_count=1，ocr\_pages=1，节点 page=1，loc 为 F{n}-PG1-B{块}。
* 图片的警告：“图片 OCR 识别置信度低，请核对原件”；没有识别出文字时 `ParseError("未能从图片中识别出文字")`。
* 日志只写页数、块数、耗时，不写识别出的文字。

## 六、pipeline 接入与脱敏适配（M3-05）

### 6.1 `app/tasks/pipeline.py`

* 按 ext 分派（第一节）。OCR 预算：任务内已用的 OCR 页数 + 本文件需要的 OCR 页数（PDF 用 `inspect_pdf().scanned_pages` 的数量，图片为 1）超过 100 时，`ParseError("扫描页和图片合计超过 100 页")`，在开始 OCR 之前判断（Q-61 ⑤）。
* 需要 OCR 的文件（有扫描页的 PDF、图片）整份在 `with worker.ocr_slot():` 内解析；不需要的不占锁。
* parser\_version 写各解析器的 PARSER\_VERSION。文件类型识别仍用正文前 1000 字（M2 的写法已与格式无关）。
* MSG\_UNSUPPORTED 删除。

### 6.2 表格列提示（`app/redaction/engine.py` 的 `_table_hints`）

M2 只认第 1 行为表头，且 loc 只认 `-T{表}-R{行}-C{列}`。改为（Q-65）：

* 表格标识与行列：DOCX / PDF 表格 `…-T{表}-R{行}-C{列}`（与 M2 相同）；XLSX 单元格 `F{n}-S{表}-{列字母}{行号}`，表格标识为 `F{n}-S{表}`。
* 表头行：在每个表格的前 20 行中，取**第一个**含单价或金额表头（M2 的 `_PRICE_HEADER`、`_AMOUNT_HEADER`）的行为表头行；只有该行之下的单元格按列得到 PRICE / AMOUNT 提示。没有这样的行时该表格没有列提示。
* 其余识别规则不变。脱敏回归测试集增加一份 XLSX 形式的报价单样本（单元格以 `F1-S1-B7 文字` 这类行写在 .txt 中，测试按 loc 构造节点），标题行在表头上方，并含百分比、货币格式和合计行。

### 6.3 问题位置的显示（`app/review/service.py` 的 `_View.locations`）

没有 clause\_no 的节点按格式给出可读的位置：PDF 和图片节点为“第 {page} 页”，XLSX 节点为“{sheet}!{cell\_ref}”，其他仍为 loc。前面照旧加原文件名，如“报价单.xlsx 报价!D7”“扫描合同.pdf 第 2 页”。

## 七、预览接口（M3-06，`app/tasks/router.py`、`service.py`、`schemas.py`）

| 方法 | 路径 | 返回 |
|-|-|-|
| GET | /tasks/{id}/files/{fid}/nodes | `{"text_available": bool, "items": [PreviewNode]}`，按 ord 排序，包含该文件全部 part 的节点 |
| GET | /tasks/{id}/files/{fid}/raw | 只对 pdf、jpg、png：解密后的原件字节流 |

```text
PreviewNode = {loc, kind, part, text, clause_no, page, bbox, sheet, cell_ref, ocr_conf, parent_loc}
  text：解密后的原文；保留期清理后 text_enc 为空时为 null，此时 text_available=false
```

* 两个接口都用 `owned_task_file` 取对象（他人返回 404，A-06）；任务在 parsing 或 parse\_failed 时 nodes 返回空列表。
* raw（Q-63）：
  * ext 不是 pdf / jpg / png：404 `RAW_NOT_AVAILABLE`；原件已按保留期删除（original\_deleted\_at 不为空）：404 `ORIGINAL_DELETED`，message “原件已按保留期限删除”。
  * 响应头：`Content-Type`（application/pdf、image/jpeg、image/png）；`Content-Disposition: inline; filename*=UTF-8''<百分号编码的原文件名>`；`Cache-Control: no-store`；`X-Content-Type-Options: nosniff`；`Content-Security-Policy: default-src 'none'; sandbox`。
  * 不写审计日志（只读预览）；日志不写文件名。
* 两个接口都是 GET，不需要 CSRF 令牌。

## 八、前端（M3-07、M3-08）

### 8.1 接口封装（`src/api/preview.ts`、`src/api/http.ts`）

* `http.ts` 增加 `getBlob(path): Promise<Blob>`：同样带 Cookie、统一处理 401 和错误码，不设 Accept 为 JSON。
* `previewApi.nodes(taskId, fileId)`、`previewApi.raw(taskId, fileId)`。原件一律先取 Blob：PDF 转 ArrayBuffer 交给 pdfjs 的 `getDocument({ data, isEvalSupported: false })`，图片用 `URL.createObjectURL`，组件卸载时 `revokeObjectURL`。不把原件地址直接交给 pdfjs 或 `<img src>`。

### 8.2 `src/components/DocPreview.vue`（M3-07）

```ts
props: { taskId: string; files: TaskFile[]; highlight: string[] }   // highlight：要高亮的 loc 列表
```

* 多个文件时顶部用 `el-tabs` 切换文件，标签为原文件名（主文件在前）。highlight 中第一个 loc 的文件号（`F{seq}`）不是当前文件时自动切换。
* 每个节点渲染出的元素都带 `data-loc` 属性（SPEC 6.3）；高亮的元素加 `is-highlight` 类（背景 `--el-color-warning-light-8`，左边框 `--el-color-warning`），并在预览区内滚动到第一个高亮元素（`scrollIntoView({ block: 'center' })`，只滚动预览容器）。
* DOCX：按 ord 显示 body 节点；段落为 `<p>`，有 clause\_no 时显示在文字前；表格单元格按 `-T{表}` 分组，按 R、C 排成表格（缺失的格留空）；页眉、页脚、批注、文本框节点放在底部的 `el-collapse`“未参与 AI 审核的内容”中，每条标明类别。
* XLSX：每个工作表一个 `el-tabs` 标签，隐藏工作表的标签后加“（隐藏）”；表格显示所用区域的行号和列字母，单元格带 data-loc。
* PDF：pdfjs-dist 逐页渲染到 canvas，宽度适应预览容器；页面进入可视区域时才渲染（IntersectionObserver）。每页上方叠一层绝对定位的高亮层，按 bbox × 当前缩放比例放置高亮框（第二节坐标约定）。高亮框也带 data-loc，供滚动定位。pdf.worker 用 Vite 的 `?url` 方式本地打包，不从 CDN 加载。
* 图片：`<img>` 宽度适应容器，高亮框按 显示宽度 / 原图宽度 缩放。
* 状态：加载中 `v-loading`；`text_available=false` 时显示 `el-alert`“原文已按保留期限清理，仅保留引用快照”；raw 返回 ORIGINAL\_DELETED 时 PDF 和图片区域显示同类提示，并退回按节点文字显示；其他错误按 frontend.md 第六节。
* 依赖：`pdfjs-dist` 锁定精确版本（选当时稳定版中发布满两周的版本），写进 package.json 和 package-lock.json。

### 8.3 结果页双栏与定位（M3-08，`src/views/ReviewResult.vue`、`src/components/FindingCard.vue`）

* 结果页改为 frontend.md 2.2 的“双栏”档：左栏为现有的问题清单与标签页，右栏为 DocPreview（sticky，独立滚动）。completed\_local 的任务也显示右栏。
* 点击问题卡片（或卡片中的“位置”）时，把该问题的 locs 交给 DocPreview 高亮；当前选中的卡片边框用 `--el-color-primary`。缺失型问题（locs 为空）点击无效果，卡片上不显示可点击的样式。
* 同一任务完成 frontend.md 第十节第 3 条的公共样式整理（`src/styles/common.css`，标签颜色移到 labels.ts），界面效果不变。

## 九、测试样本（M3-01）

样本全部虚构，生成脚本可重复运行，生成结果提交进仓库（与 M2 的 DOCX 样本相同），每个目录一份 manifest.yaml 写明预期事实。

* 生成工具：测试镜像增加 `reportlab`（requirements-dev.txt，锁定精确版本，只用于生成样本，不进运行镜像）和中文字体 `fonts-wqy-microhei`（Dockerfile 的 test 阶段 apt 安装）。扫描样本用 Pillow 把文字画成图片，再用 reportlab 把图片放进 PDF 页面。
* `tests/fixtures/pdf/`：文字版合同（含签约方、金额、表格、条款编号、页码行）；扫描版合同（2 页，其中 1 页故意模糊、加噪点，用于低置信）；文字页与扫描页混合；旋转 90° 的页面；加密 PDF；超过 200 页的 PDF 由测试临时生成，不提交。

* manifest 写明：每页是文字页还是扫描页、预期节点数量范围或关键节点的文字、必须出现的警告、必须被替换的敏感项（供 M3-05 的脱敏测试使用）。OCR 结果不要求逐字一致，测试只断言关键词出现、置信度高低和警告。

## 十、任务划分与完成标准
