# M4 脱敏完善：模块划分与接口约定

本文件由 M4-00 制定，是 M4 各任务之间的契约。执行任务的会话必须按这里的函数签名、数据格式和接口形状实现；需要改动时停下来报告，由 Opus 会话修改本文件。与 SPEC 冲突时以 SPEC 为准。前端任务同时遵守 docs/design/frontend.md。

M4 在 M2 的脱敏链路（9.3 第 1–5 步）上补齐：人名与地址（第 6、7 步）、数量脱敏、疑似遗漏（9.5）、手动补充、金额比例（9.6）、报价明细表汇总（9.7 后半）、已记住的名称（9.10）、第二步页面完整版。验收用例 A-03、T-06、T-08。

不在 M4 范围内：汇总行中的“本地校验：…”部分（M6，本里程碑的汇总行不含这一段）；自定义敏感词和已记住名称的设置页（M7-05，本里程碑只实现写入、匹配和命中计数）；分段、覆盖说明（M5）。

## 一、处理流程的变化

```text
parse（不变）──> redact_task：
                  读启用的已记住名称与自定义敏感词、本任务的用户词条（第四节）、数量脱敏设置
                  compute()：第 1 步（已记住名称、自定义敏感词、用户词条）→ 第 2、3 步 → 第 4 步 → 第 5 步（金额、单价；数量）
                            → 第 6 步人名 → 第 7 步地址 → 疑似遗漏 → 金额比例
                  写 parties、redaction_items、redaction_maps、redacted_text、redaction_suspects；已记住名称的命中计数
第二步：PUT /parties、POST /redaction/manual、POST /redaction/suspects/{sid} 都调用同一个 _run() 整体重算，
        用户词条和疑似遗漏的“忽略”决定在重算中保留
确认发送（create_run）：预检通过后，把签约方名称和用户确认的公司名、人名写入 redaction_terms（kind=learned）
外发文本：build_outbound_text() 在构建时识别报价明细表，整表（表头行至最后一个数据行）换成一行汇总
```

任务状态、轮次状态、出口复检、网关都不变。未处理的疑似遗漏仍由 create_run 的 SUSPECTS\_PENDING 拦截（M2 已有）。

## 二、识别规则（M4-01、M4-02，纯函数，不碰数据库）

所有规则只在单个节点的原文上运行，返回在节点原文中的位置；代号分配、重叠取舍在 engine.py。

### 2.1 人名、地址、数量（M4-01，`app/redaction/detect.py`）

```python
def find_persons(text: str) -> list[Hit]       # category="PERSON"，key=parties.normalize(姓名)
def find_addresses(text: str) -> list[Hit]     # category="ADDR"，key=国家（找不到时 "国家未知"）
def find_quantities(text: str, column: str | None = None) -> list[Hit]   # category="QTY"，key="QTY|单位|数值"
```

**人名**（9.3 第 6 步）：

* 标签：联系人、授权代表、法定代表人、委托代理人、经办人、签字、签名、签字人、代表人、收件人、Attn、Attention、Contact、Contact Person、Signed by、Signature、Name、Representative（英文不区分大小写）；标签后可有冒号或空格。
* 中文：标签后的连续汉字，先去掉末尾的称谓（先生、女士、小姐、经理、总经理、主任、董事长、总裁、代表），剩下 2–4 个汉字时为人名；超过 4 个或不足 2 个时不识别（不猜测）。
* 英文：标签后先去掉称谓（Mr.、Mrs.、Ms.、Miss、Dr.、Prof.），取 1–3 个首字母大写的单词；单词是职务或部门词（Manager、Director、Sales、Purchasing、Department、Team、Officer 等，常量放在 detect.py）或 common\_terms 中的词时停止。没有剩下单词时不识别。
* 标签后紧接的是公司名称时，engine 中第 2 步已占用该位置，不会再识别为人名，本函数不需要处理。

**地址**（9.3 第 7 步）：

* 标签：地址、注册地址、通讯地址、办公地址、联系地址、收货地址、Address、Registered Address、Add.（英文不区分大小写），标签后须有冒号。
* 范围：冒号之后到行尾；中途遇到另一个信息标签（电话、手机、传真、邮箱、联系人、Tel、Phone、Fax、E-mail、Email、Contact、Attn，后跟冒号）时在其前面结束；去掉首尾空白和标点。范围为空时不识别。
* 国家：`dictionaries.find_country(范围文字)`；找不到时 key 为 “国家未知”。

**数量**（只在设置 redaction.mask\_quantity=true 时由 engine 调用）：

* 数字（可含千分位和小数）后紧跟计量单位：MT、吨、公斤、千克、kg、KG、件、套、台、箱、桶、个、批、pcs、PCS、sets、units、cartons、bags、drums（英文不区分大小写，单位后不能紧跟字母）。
* column="QTY"（数量列，第 2.4 节）时，整格只有一个数字也算数量。
* 只替换数字部分，单位保留（与金额保留币种的做法一致）。同一单位、同一数值同一代号。

### 2.2 正文企业名称的起点（M4-01，`app/redaction/parties.py` 的 `find_other_org_names`，Q-56）

向前取汉字时遇到下列边界词即停止，名称从边界词之后开始：由、向、与、和、及、同、跟、经、经由、委托、通过、根据、按照、依据、代表、联系、致、自、从、为、对、将、把、被、给、在、即、系、是（多字的边界词优先）。名称部分不足 2 个汉字时仍按 M2 的做法整段替换（宁多勿漏）。回归集增加一份含“货物由……有限公司代为装运”“委托……有限公司办理”的样本。

### 2.3 疑似遗漏（M4-02，新建 `app/redaction/suspects.py`）

```python
@dataclass(frozen=True)
class Suspect:
    start: int
    end: int
    reason: str     # org_suffix / capitalized / long_digits / before_company（18.11）

def find_suspects(text: str, occupied: list[tuple[int, int]]) -> list[Suspect]
```

* 先把 occupied（已被替换的区间）中的字符换成同样长度的分隔符（如 `\x00`），再在其上识别，候选不会跨越已替换的文字。
* 同一位置命中多条规则时只保留一条，优先级：org\_suffix > before\_company > capitalized > long\_digits；互相重叠的候选取较长的。
* **org\_suffix**：带 9.3 第 2 步企业后缀表中的后缀（含“集团、研究院、研究所”，不含单独的“公司、厂”）但未被替换的名称。中文取后缀前 2–10 个汉字（边界词规则同 2.2）；英文取后缀前 1–4 个首字母大写的单词。
* **before\_company**：紧接“公司、厂”之前的 2–10 个汉字（去掉 2.2 的边界词之前的部分）。下列泛称不列为疑似遗漏：本、贵、我、我方、该、对方、双方、各、其、任何、子、分、母、总、关联、船、保险、物流、货运、运输、快递、航空（整段等于其中之一时）。
* **capitalized**：连续 2 个及以上首字母大写的英文单词。整段（不区分大小写）在 common\_terms.txt 中时排除；每个单词都是国家、城市、港口名称（countries.yaml）或 common\_terms 中的单个词、月份、星期时排除；全大写的 2–5 字母缩写（FOB、CIF、HS、USD）不算“首字母大写的单词”。
* **long\_digits**（Q-69）：数字之间的单个空格或短横线不打断“连续数字”（`6222 0000 1111 2222 333` 算 19 位）；数字合计 ≥ 8 位时列为疑似遗漏。排除：合法日期（YYYYMMDD，YYYY-MM-DD、YYYY/MM/DD、YYYY.MM.DD）；前面 12 个字符内有“HS、H.S.、海关编码、商品编码、税则号”的 HS 编码；后面紧跟 2.1 数量单位的数量；含千分位逗号或小数点的数字（金额由第 5 步负责）。
* common\_terms.txt 可以补充词条（M4-02 允许修改）。

### 2.5 金额比例（M4-03，新建 `app/redaction/ratio.py`）

detect.Hit 增加两个可选字段，find\_amounts 填写（其他函数不填）：

```python
@dataclass(frozen=True)
class Hit:
    start: int
    end: int
    category: str
    key: str
    currency: str | None = None    # 规范币种代码（CNY、USD…），未知为 None
    value: Decimal | None = None   # 换算后的数值（“万元”已乘 10000），无法解析为 None
```

```python
TOTAL_LABEL: re.Pattern   # 合同总价、合同总额、合同金额、总价、总金额、Total Amount、Total Value、Contract Value、Contract Price、Contract Amount

@dataclass(frozen=True)
class AmountAt:
    node: int            # 节点序号（compute 中 nodes 的下标）
    hit: Hit             # category=AMOUNT

def contract_total(nodes: list["NodeIn"], amounts: list[AmountAt], main_prefix: str | None) -> tuple[str, Decimal] | None
def ratio_text(value: Decimal, total: Decimal) -> str          # "（=合同总价的 30.0%）"
def insert_position(text: str, end: int) -> int                 # 金额之后紧跟的后置币种（美元、元、USD…）之后
```

* 合同总价（9.6）：先在主文件（loc 以 main\_prefix 开头，如 "F1-"）的节点中找“TOTAL\_LABEL 后 30 个字符内的第一个金额”，取文档顺序第一个；主文件中没有时再在其他文件中找。都没有标签时：所有带币种的金额是同一币种时取其中最大的；有多个币种时不确定合同总价，不加比例（Q-72）。
* 比例只加在 AMOUNT 上（单价、数量不加）：币种与合同总价相同、数值已知、合同总价大于 0，且不是合同总价本身的代号。数值用 Decimal 计算，`(value / total * 100).quantize(Decimal("0.1"), ROUND_HALF_UP)`，大于 100% 照常写。
* 比例文字插在 `insert_position` 处，如“USD \[金额\_2]（=合同总价的 30.0%）”“\[金额\_2] 美元（=合同总价的 30.0%）”；合同总价本身不加比例。比例只进入 redacted\_text，不进入对照表和 redaction\_items。

### 2.6 报价明细表汇总（M4-03，新建 `app/redaction/quotes.py`）

```python
@dataclass(frozen=True)
class QuoteTable:
    loc: str                    # 汇总行的位置编号（Q-18）：DOCX F1-T2，PDF F3-PG2-T1，XLSX F2-S1
    first_loc: str              # 汇总行放在这个节点的位置（表头行的第一个单元格）
    row_locs: frozenset[str]    # 被汇总替换掉的全部单元格（表头行至最后一个数据行）
    rows: int                   # 数据行数
    currencies: list[str]       # 按出现顺序去重；都识别不到时为空
    products: list[str]         # 产品列的已脱敏文字，按出现顺序去重；没有产品列时为空

def find_quote_tables(nodes: list["NodeIn"], redacted: dict[str, str]) -> list[QuoteTable]
def summary_text(t: QuoteTable) -> str
```

* 报价明细表：表头行（2.4 的规则）中有 PRICE 列，且表头行以下“单价列中有数字”的行 ≥ 3。数据行即这些行；最后一个数据行之后的行（如合计行、备注）和表头行以上的行照常逐格发送。
* 产品列：表头含 品名、产品、货物、名称、规格型号、Description、Product、Commodity、Item 的列（第一个命中的列）。
* 币种：数据行的单价、金额单元格中识别出的币种（detect.find\_amounts 的 currency），没有时看表头文字中的币种代码或符号。
* 汇总文字：`【报价明细表：共 12 行，币种 USD，产品：油系针状焦等 3 种】`；只有一种产品时 `产品：油系针状焦`；没有产品列时省略“，产品：…”；币种都识别不到时写“币种未知”，多个时用“、”连接。M6 在末尾补“，本地校验：…”。
* 外发文本中汇总行为 `[{loc}] {summary_text}`，同样经过 escape\_document\_tags。

## 三、engine 整合（M4-04，`app/redaction/engine.py`、`outbound.py`、`placeholders.py`）

```python
@dataclass(frozen=True)
class UserTerm:
    text: str          # 用户在本任务中选中或确认替换的文字（原文写法）
    category: str      # ORG / PERSON / CUSTOM

@dataclass
class SuspectOut:
    loc: str
    char_start: int
    char_end: int
    reason: str

@dataclass
class RedactionResult:          # 在 M2 的基础上增加
    parties: list[PartyOut]
    items: list[ItemOut]
    mapping: dict[str, str]
    redacted: dict[str, str]
    suspects: list[SuspectOut]
    matched_terms: set[str]     # 命中的已记住名称、自定义敏感词（规范形式），用于命中计数

def compute(nodes, stance, *, terms=(), overrides=None, user_terms: Sequence[UserTerm] = (),
            mask_quantity: bool = False, main_prefix: str | None = None) -> RedactionResult
```

* **第 1 步**：已记住名称、自定义敏感词、用户词条一起作为第 1 步的词条；用户词条的替换项 detected\_by="user"，其余仍为 "term"。用户词条 ORG 登记为主体（角色“其他”，代号“公司\_X”，国家和类型按 9.4 判断），出现在签约方列表中，可设为我方（Q-54）；PERSON 为“人员\_n”；CUSTOM 为“\[敏感词\_n]”。
* **不能留下半个名称**：用户词条（或已记住名称）是某个已知主体名称的一部分时，作为该主体的简称处理（同一代号），且第 1–3 步的候选统一按“长的优先”取舍，不得出现“公司\_C Fictive Energy Co., Ltd.”这类结果。用测试覆盖：用户选中“Aurora Fictive”而全称“Aurora Fictive Energy Co., Ltd.”也在文中。
* **第 6 步人名**：先用 find\_persons 在全部节点中收集人名，登记为 PERSON 对象（同一规范形式同一代号），再在全部节点中全文匹配这些人名：中文精确匹配；英文区分大小写、要求单词边界（避免单个英文名误伤普通单词）。detected\_by="person"。
* **第 7 步地址**：find\_addresses 的范围与已替换的文字重叠时，取去掉重叠部分后的各段，每段含字母、数字或汉字的才替换，用同一代号。代号 `[地址：{国家}]`（placeholders 增加 ADDR，与 FIXED 一样不能唯一还原：真实值存为“代号#序号”，只用于出口复检，Q-45 ①）。detected\_by="address"。
* **账号、SWIFT 带序号**（Q-59，SPEC 9.2 已改）：ACCOUNT、SWIFT 从 placeholders.FIXED 移到按对象编号的类别，代号 `[账号_n]`、`[SWIFT_n]`。detect.find\_formatted 给这两类命中填 key：账号为去掉空格和短横线后的大写字符（IBAN 与本地写法不同时视为不同账号），SWIFT 为大写代码；8 位与 11 位的同一 SWIFT（后者末尾为 XXX）视为同一代号。对照表中这两类代号改为可唯一还原（键为代号，值为第一次出现的写法；其他写法存为“代号#序号”）。出口复检对它们的真实值照常生效。
* **数量**：mask\_quantity=True 时在第 5 步之后、第 6 步之前识别（find\_quantities，表格数量列用 table\_hints(with\_qty=True)），代号 `[数量_n]`，detected\_by="amount"。
* **疑似遗漏**：全部替换项确定后，对每个节点调用 `suspects.find_suspects(原文, 该节点已替换的区间)`。
* **金额比例**：在 `_assemble` 生成 redacted 时按 2.5 插入比例文字。
* `_run()` 读取设置 `redaction.mask_quantity`、本任务的用户词条（第四节）和主文件的 `F{seq}-` 前缀，传给 compute；写入疑似遗漏（第四节）。
* `outbound.build(parties, nodes, quote_tables=())`：row\_locs 中的节点不再单独成行，first\_loc 处换成汇总行。`build_outbound_text` 解密正文节点原文，调用 `quotes.find_quote_tables(原文节点, redacted)` 后构建。
* **命中计数**（9.10、18.12）：只在 `redact_task`（解析时）统计：每个命中的已记住名称、自定义敏感词 hit\_count += 1（每个任务最多加 1），last\_hit\_at = 当前时间；第二步重算不计数（Q-73）。
* 回归测试集：现有 6 份样本补标人名（PERSON）和地址（ADDR）；标注文件增加 `must_suspect`（必须列为疑似遗漏的文字）；新增 Q-56 样本和 Q-69 样本（OCR 把“收款账号”识别错的扫描件文字，账号必须列为疑似遗漏）；测试函数按新签名调用 compute，并检查 must\_keep 的内容没有被列为疑似遗漏。

## 四、用户词条、疑似遗漏决定与已记住的名称（M4-04 实现函数，M4-05 实现接口）

**用户词条的保存**：不新增表。用户词条就是本任务 detected\_by="user" 的 redaction\_items：`_run()` 删除替换项之前，先读出这些项，按 loc 和字符位置从节点原文中取出文字，按（规范形式, 类别）去重，作为 user\_terms 传给 compute。这样 PUT /parties、手动补充、处理疑似遗漏之后整体重算，用户词条都保留，且对照表只有一份。

**疑似遗漏的保存**：`_run()` 每次重算后：与上次相同位置（loc, char\_start, char\_end, reason）的行保留原 id 和决定；不再出现的行删除（已被替换覆盖）；新出现的行插入，decision=pending。

## 五、接口（M4-05，`app/redaction/router.py`）

| 方法 | 路径 | 入参 | 返回 |
|-|-|-|-|
| GET | /tasks/{id}/redaction | — | `{"summary": {…}, "suspects": [SuspectView], "items": [{loc, char_start, char_end, category, placeholder}]}` |
| POST | /tasks/{id}/redaction/suspects/{sid} | `{"decision": "replace" \| "ignore", "category": "ORG" \| "PERSON" \| "CUSTOM" \| null}` | 同 GET /redaction |
| POST | /tasks/{id}/redaction/manual | `{"loc", "char_start", "char_end", "category"}` | 同 GET /redaction |

```text
SuspectView = {id, loc, reason, decision, category, text, before, after}
```

* 两个 POST 与 PUT /parties、确认发送共用任务行锁，取得锁后重读状态；不是 awaiting\_confirm 时 409 TASK\_STATE\_CONFLICT。
* sid 不存在或属于其他任务：404 SUSPECT\_NOT\_FOUND。decision=replace 而 category 为空或不在三种之内：422 VALIDATION\_ERROR。
* manual 的错误码：loc 不是本任务正文节点或范围越界：422 INVALID\_SELECTION“所选位置不正确”；与已替换的文字重叠：409 ALREADY\_REDACTED“所选文字已被替换，请选择未替换的文字”；长度不符：422 SELECTION\_LENGTH“请选择 2–100 个字符”。
* 任务归属仍用 owned\_task（他人和管理员 404，A-06）。返回的 text、before、after 是本人的原文，只用于第二步显示。
* 不写审计日志（SPEC 17.7 的审计动作不含脱敏确认）；日志不写任何文字。
* `app/review/service.py` 的 `create_run`：出口复检预检通过后、提交前调用 `learn_confirmed_names`（与轮次创建同一事务；预检拦截时不写入）。
* 系统提示词（Q-59，SPEC 11.2 已改）：`resources/prompts/system.md` 第 2 条按 SPEC 11.2 补充“代号代表原文中完整的真实信息，不得以只有代号、代号相同为由认定信息缺失、不完整或不一致。”，并升提示词版本号；test\_review\_prompt 中逐字比对 SPEC 的测试随之更新。
