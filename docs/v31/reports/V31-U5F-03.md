# V31-U5F-03 确认工作台、审核中、结果页状态、悬停胶囊、乐观保存与流式字数

2026-11-05 · Opus 5.5（任务卡原定 Sonnet 5.5）· 设计见 [V31-U5F.md](../design/V31-U5F.md) 第三节、1.2 第 1 条界面部分与第 5 条。

## 改了什么

* **工作台布局（2B）**（`ConfirmWorkbench.vue`）：
  * 根因：工作台靠 `flex: 1` 撑高，智能助手、会议纪要、翻译的确认页放在块级容器（全屏对话框）里，高度变成随内容增长，右栏跟着左侧拉长。
  * 改为工作台高度固定为容器高度，左侧文档、右侧栏各自滚动；“即将发送”与确认按钮固定在栏底。
  * 右栏让出页签行，顶端与纸面顶端对齐；“按 ? 查看快捷键”（可点）与加文件时的状态岛移到文件页签行右侧（`ConfirmCanvas` 新增 `bar` 插槽）。
  * 02 的 LeakPanel 保留在右栏顶部，定位与刷新逻辑不变。
* **乐观更新与保存队列（1.2 第 1 条）**：
  * 改我方、改国家与类型、保留 / 改回替换 / 指定类别、批量处理、划选补充、撤销误识别：界面立即变化，请求按顺序在后台保存，页面不再锁住。页签行显示“正在后台保存…”。
  * 队列清空时用最后一次返回值与服务器对齐，再刷新签约方与外发文本。
  * 任何一次失败：整体回读服务器状态（回滚）并提示原因。
  * “确认发送”是唯一等待队列清空的操作，有失败则停在本页。
  * 手动补充与撤销的请求从画布移到工作台，画布只发事件。后端脱敏逻辑未改。
* **审核中四步（问题 4）**（`ReviewCeremony.vue`）：
  * 每步固定标题、说明两行（网格布局），完成的步骤保留说明，例如“通过，拦截 0”“已复检 2/2 段，拦截 0”“已返回”“已还原”；未开始的显示“等待”。四步基线一致。
* **流式字数（1.2 第 5 条）**：
  * 网关 `call_model` 新增 `on_delta`：给出时请求带 `stream`，流式接收，每收到一段以本次尝试累计字数回调。上限检查 → 出口复检 → 发送 → 记录的顺序与重试、失败分类都不变。
  * 服务端忽略 `stream`、直接返回整段 JSON（`application/json`）时照常解析。
  * 进度回调出错只记一条警告，不影响发送与记录。
  * 审核任务按段记已收字数，最多每秒写一次进度 `received`（各段合计）；接口 `progress.received`。
  * 审核中模型一步显示“已收到约 3,200 字”，分段时为“已回复 1/2 段 · 已收到约 3,200 字”（未全部发出时为“已发出 n/N 段”）。
* **文件页签（问题 6）**：选中为主色文字 + 加粗 + 下划线，未选中为次要色。确认页与结果页共用 `ConfirmCanvas`，所以是同一款。
* **问题卡片处理状态（问题 7）**（`FindingCard.vue`、`FindingsRail.vue`）：
  * 已采纳：左侧色条变绿，标题前“✓ 已采纳”，卡片降亮；
  * 已忽略：灰色色条、整卡变灰；
  * 选中时恢复全亮，方便阅读。
  * 点处理状态时卡片立即变化（原来要等保存返回）。
  * 原来的“处理状态”下拉改为分段计数切换“全部 / 待处理 / 已采纳 / 已忽略”，计数随等级、类别筛选变化。
* **悬停胶囊（问题 8）**（`ConfirmCanvas.vue`）：
  * AI 视野下悬停代号，显示“原文：…”胶囊；
  * 原文视图悬停替换处，显示“类别 · 发送为 [代号]”胶囊，取代原来浏览器自带的 title。
  * 只在本机浏览器渲染，不经过任何接口。
