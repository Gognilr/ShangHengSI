## 〇、结论与共同约定

一句话：**首页一屏放下，拖进来就开始解析，点了才前进；确认页是一张回执——左边一张纸看原文、一键翻成 AI 看到的样子，右边从上到下是签约方、不确定项、文件、外发回执，正常文件只点一次“确认发送”。**

现状（`6f56107`）：新建审核第一步是 960px 的长表单（上传区、立场、来源、模型、两张外发策略卡、补充说明），选好全部文件后点“开始解析”，解析完自动跳到第二步，加一个文件要删任务重来；第二步是 7 个编号面板纵向排列，原文与外发文本分在两栏对照，手动补充要另开对话框，提交条件里还有“疑似遗漏未处理”（后端已在 V31-S 取消，前端仍拦）。

### 共同约定

1. **开工条件**：本文件与 V31Q-34～37 经用户确认。
2. **只改前端**，例外只有 U2-01 的一处后端（1.2，V31Q-37）。不加菜单、页面与路由：首页与确认页仍是 `/review/new`（`?task=` 选中任务），审核中（第三步）留到 V31-U3，本批只把它原样保留。
3. **不新增 npm 依赖**；颜色只用变量（frontend.md 第一节第 4 条）；新代码用 U1 的新令牌与 `components/ui/` 组件（`SiSegmented`、`SiIsland`、`SiToast`、`SiCount`）。
4. **验收视口 1366×640**（Edge 标签页最大化），侧栏展开：首页不出现纵向滚动；确认页整页不滚动、两栏各自滚动。`body` 最小宽度 1280px 不变。
5. **动效**按 frontend.md 第十二节：循环动画只在解析中出现（`useLoop`），AI 视野切换是品牌时刻、在精简特效下为直接切换加 160ms 淡入、关闭特效下直接切换；动画从不推迟结果可操作。
6. **安全**：页面只显示接口给的数据，原文、代号一律按纯文本渲染（不用 `v-html`）；拖入只上传用户拖入或选中的文件；删除在撤销期过后真删（PLAN 第四节第 4 条）；快捷键不触发外发——“确认发送”的快捷键只把焦点移到按钮并高亮，仍须按 Enter 或点击（3.6）。
7. **测试**：界面任务只跑 `npm --prefix frontend run build`；U2-01 的后端字段跑 `tests/test_redaction_api.py`。浏览器检查与帧率在 U2-05 集中做一次。不为样式、动效写测试。
8. **报告**：`docs/v31/reports/V31-U2-test.md`（新），写短，附截图清单。

## 一、接口类型与小工具（V31-U2-01，Opus，medium）

### 1.1 前端接口（`api/tasks.ts`、`api/redaction.ts`）

| 项 | 内容 |
|-|-|
| `TaskStatus` | 加 `draft` |
| `TaskFile` | 加 `parse_state: 'parsing' \| 'done' \| 'failed'`、`parse_error: string \| null` |
| `TaskDetail` | 加 `busy: boolean` |
| `tasksApi.create` | 输入加 `draft?: boolean`（表单字段 `draft`）；草稿时 `mainIndex` 固定 0 |
| `tasksApi.addFiles(id, files)` | `POST /tasks/{id}/files`，返回 `TaskDetail` |
| `tasksApi.removeFile(id, fid, { keepalive })` | `DELETE /tasks/{id}/files/{fid}`，返回 `TaskDetail` |
| `tasksApi.setMain(id, fid)` | `PATCH /tasks/{id}/files/{fid}` `{is_main: true}`，返回 `TaskFile` |
| `tasksApi.proceed(id, body)` | `POST /tasks/{id}/proceed` `{stance, source, policy, user_note}`，返回 `TaskDetail` |
| `Suspect` | 加 `category: string`（默认类别）、`placeholder: string \| null`、`kept_by: 'user' \| 'memory' \| 'vector' \| null`；`decision` 注释改为 pending（默认替换）/ ignore（保留原文） |
| `RedactionItemPos` | 加 `detected_by: string` |
| `redactionApi.decideSuspect` | `decision` 加 `reset`；`category` 类型加 `NAME`、`TERM` |
| `redactionApi.batchSuspects(id, ids, decision)` | `decision: 'ignore' \| 'reset'`（替代 `ignoreSuspects`） |
| 错误码文字 | `RUN_ERROR_MESSAGES` 加 `FILES_PARSING`“还有文件正在解析，请稍候”、`FILE_PARSE_FAILED`“请先删除解析失败的文件”；任务接口加 `DUPLICATE_IN_TASK`“该文件已在本任务中”、`LAST_FILE`、`FILES_NOT_READY`“文件还没有解析完成” |

`api/http.ts` 的请求选项加 `keepalive?: boolean`，透传给 `fetch`（关闭标签页时仍能发出删除，2.4）。

### 1.2 后端：替换项返回 `detected_by`（V31Q-37）

`GET /tasks/{id}/redaction` 等返回 `RedactionInfo` 的接口，`items[]` 每项加 `detected_by`（库中已有，不含原文）。画布据此把不确定项（`uncertain`）画成与确定替换不同的胶囊（4.2）。`tests/test_redaction_api.py` 现有用例加一行断言。

### 1.3 文字（`utils/labels.ts`）

* `STATUS_OPTIONS.draft = '草稿'`；审核历史状态标签 `draft` 用 `info`（与“解析中”同色）。
* `REDACTION_CATEGORY` 加 `NAME: '名称（不确定）'`、`TERM: '专有名词（不确定）'`；`REDACTION_KIND` 加 `NAME`、`TERM` → `uncertain`（4.2 的胶囊样式，不用 `--si-k-*` 类别色）。
* 界面文字统一：“疑似遗漏” → “不确定项”；“忽略” → “保留原文”。
* `KEPT_BY = { user: '你保留的', memory: '按术语记忆保留', vector: '本机判断为普通术语' }`。

### 1.4 小工具

| 文件 | 内容 |
|-|-|
| `utils/hotkeys.ts` | `useHotkeys(map, { enabled })`：在 `window` 上监听 `keydown`；焦点在输入框、文本域、下拉、`contenteditable`、对话框或抽屉内时不触发；组件卸载自动解绑。键名写法 `'j'`、`'shift+j'`、`'ctrl+enter'`、`'?'` |
| `composables/useTaskPoll.ts` | `useTaskPoll(taskId, { active })`：`active` 为真时每 3 秒读一次 `GET /tasks/{id}`（同一时刻只一个请求，页面隐藏时暂停），返回 `task`、`refresh()`；404 时停止并给出 `notFound` |
| `composables/usePendingDeletes.ts` | 延迟删除队列：`schedule(key, run, { label, onUndo })` 弹 `toast('已删除 {label}', { action: 撤销, duration: 5000 })`，5 秒后执行 `run()`；`flush({ keepalive })` 立即执行全部；组件卸载、路由离开时 `flush()`，`beforeunload` 时 `flush({ keepalive: true })`。同时只保留最新一条提示，被替换的旧条目立即执行（不丢删除） |

### 2.1 布局（`views/ReviewNew.vue` 第一步，`.page--standard` 960px）

```
StepBar（上传与设置 · 确认脱敏 · 审核中）
┌ 面板 ───────────────────────────────────────┬─────────────────┐
│ 工作文件夹：…  · 更换 · 不使用               │ 审核设置  沿用上次选择 │
│ ┌ 拖入区 / 文件清单 ───────────────────────┐ │ 业务立场 [销售|采购|其他]│
│ │ 未拖入：大拖入区（图标、两行说明、格式）  │ │ 文件来源 [我方发出|对方发来]│
│ │ 已拖入：文件行列表 + 底部一条“继续拖入”   │ │ 审核模型 [下拉 / 只读文字]│
│ └──────────────────────────────────────────┘ │ □ 不外发，仅本地校验   │
```

* 一块面板内两栏网格 `1fr 320px`、间距 24px；左栏拖入区高度填满（最小 320px），右栏设置。面板底部一行：左为 `SiIsland`，右为主按钮。1366×640 下整页不出现纵向滚动；补充说明展开后允许出现滚动。
* **审核设置**：立场、来源用 `SiSegmented`；审核模型同现状（1 个时只读文字，下拉项带用途说明）；外发策略改为一个复选框“不外发，仅本地校验”，下方一行次要色说明随选中状态切换：未选“名称、联系方式、账号等先在本机替换为代号，确认后才发送给云端模型审核。”，选中“文件不离开本系统，只做金额、日期等本地校验，不产生 AI 审核意见。”（V31Q-34）。选中时隐藏审核模型。
* **补充说明**：默认收起为文字按钮“＋ 添加补充说明”，展开为 3 行文本域（500 字、计数）；已有内容时默认展开。“查看审核要求”打开现有抽屉。
* 右栏标题旁小字“沿用上次选择”：立场与来源按现有 `aireview:last-choice:{用户}` 读取与保存（保存时机改为 proceed 成功时）。

### 2.2 拖入即解析

| 时机 | 行为 |
|-|-|
| 第一次拖入或选择 | 前端检查（格式、大小、空文件、≤ 10 个）后立即 `create({draft: true, stance, source, policy, userNote, allowDuplicate})`，成功后 `router.replace({query: {task: id, model_id?}})`，页面不跳走。409 `DUPLICATE_FILE` 时弹现有“重复文件”对话框（打开上次结果 / 继续新建），继续新建带 `allowDuplicate` 重发 |
| 之后再拖入（含从工作文件夹选择） | `addFiles`；本任务已有同一文件时由后端 422 `DUPLICATE_IN_TASK` 提示，前端不另判；合计超过 10 个时前端先拦 |
| 解析中 | `useTaskPoll` 在 `busy` 或有 `parsing` 文件时轮询；文件行显示状态 |
| 删除文件 | 行立即从列表消失并 `usePendingDeletes.schedule`，5 秒内“撤销”恢复；到期发 `removeFile`。删的是最后一个文件时，到期改为删除整个任务（`tasksApi.remove`）并回到空白首页（`router.replace({name: 'review-new'})`），提示文字为“已移除 {文件名}，本次草稿将删除 · 撤销” |
| 设为主文件 | `setMain`，标题与总价比例随后台重算更新 |
| 修改设置 | 只改本地状态，到 proceed 时一并提交；草稿的脱敏按创建时的立场预算，proceed 会按新设置重算 |
| 点“下一步” | `proceed({stance, source, policy, user_note})` 成功后：ai → 进入第二步（`step = 1`）；local\_only → 转到结果页。**永不自动跳页**：解析完成只改变按钮与灵动岛 |

* **按钮**：没有文件时禁用，文字“下一步：确认脱敏”（local\_only 时为“完成本地校验”）。ai：至少一个文件 `done` 时可点；local\_only：全部 `done` 且不 `busy` 时可点。旁边一行次要色说明不可点的原因（“先拖入文件”“正在解析，至少一份完成后可以继续”“还有文件正在解析”）。
* **灵动岛**：无文件 `idle`“把合同、报价单拖到左侧”；解析中 `busy`“本机正在解析 {n} 个文件”；全部完成 `done`“{n} 个文件已在本机就绪”；有失败 `error`“{n} 个文件解析失败，可删除后继续”。
* **文件行**：类型徽标、文件名（主文件加“主文件”小标签）、大小、状态（解析中：行底 2px 扫描光条，`useLoop`，精简与关闭特效为静态“解析中”文字；完成：段落数 / 页数；失败：危险色“解析失败：{原因}”），行尾“设为主文件”（非主文件、已完成时显示）与删除图标按钮（`aria-label="删除 {文件名}"`）。行增删用 `si-list` 过渡。
* **离开与返回**：有草稿时离开页面不提示（草稿已保存在审核历史，状态“草稿”）。从审核历史打开草稿时回到本页，设置按任务的 `stance`、`source`、`policy`、`user_note` 回填。旧的 `parsing` / `parse_failed` 任务保持现有显示（解析中视图、`el-result`“重新上传”）。
* 拖放事件：整个面板接受拖入（不只拖入区），拖入时面板显示 2px 主色虚线框与“松开即开始解析”。

### 3.2 回执栏各节（上下排列，每节标题 `--si-font-h4` + 右侧一行摘要，无编号徽标）

1. **签约方与我方**：每方一行——单选“我方”、真实名称、代号（等宽胶囊）、角色；行尾“编辑”文字按钮展开该行，出现国家、类型两个可输入下拉（同现状 Q-50 ②，修改即保存）。没有签约方时为警告文字“未识别到签约方：在左侧原文中划选我方名称、类别选“公司”后再设为我方”。
2. **不确定项**：标题摘要“{总组数} 组 · 已替换 {a} · 保留 {b}”，**默认折叠**；有 `kept_by='user'` 以外的保留（记忆、向量）时摘要另加“其中 {c} 组按记忆或本机判断保留”。展开为按文档顺序的组列表，每行：文字（纯文本）、出现次数、当前状态——已替换显示代号胶囊，已保留显示 `KEPT_BY` 文字；行尾操作见 3.3。列表上方复选框全选与“保留所选 / 改回替换（N 组）”，每次最多 200 组（超过时按钮禁用并说明）。点行即在画布定位到该组第一处（4.4）。
3. **文件**：每个文件一行——徽标、文件名（主文件标签）、文件类型下拉（同现状，改即保存）、规模、警告（图标 + 悬停全文；有警告时行下方直接显示第一条）、解析状态（同首页）。从未提交审核的审核任务另有：行尾“⋯”（设为主文件、删除，删除同首页的 5 秒撤销）、节底“加入文件”按钮；整个工作台接受拖入（3.5）。
4. **本地校验 · 公司范本**：一行“本地校验 {n} 条 · 查看”，点击打开右侧抽屉（560px）显示现有 `LocalFindings`；有合适范本时一行“将对照公司范本：{名称}”与“不对照”复选框；“查看审核要求”文字按钮。
5. **外发回执**（粘底卡片，`--si-surface-2` 底）：
   * 标题“即将发送给 {模型显示名}”，副标“只发脱敏后的文字，结果在本机还原”；
   * 两个统计块：“正文（只含代号）{字数}”（外发文本长度，`SiCount`）、“已在本机保护 {替换总数} 处”；其下一行按类别的小胶囊（公司 6 · 人名 4 · 金额 9 …，来自脱敏摘要）；
   * 一行“不发送：原件 · 图片 · 文件名”；一行次要色“确认后本机再做一次出口复检，命中即拦截、不发送”；
   * “查看将发送的全文”文字按钮：打开抽屉（640px），纸面上显示外发文本原样（含 `[F1-P1]` 位置标记与比例注记，与实际发送一字不差）；
   * 提交条件列表（未满足的用警告色）：我方（审核须恰好一方；助手可不设）、文件正在解析、有解析失败的文件、正在保存修改；
   * 主按钮“确认发送并开始审核”（助手：“确认脱敏”），高 44px，满宽。

### 3.3 不确定项的操作

| 当前状态 | 操作 | 接口 |
|-|-|-|
| 已替换（pending，无 `kept_by`） | “保留原文”：立即生效，`toast('已保留“{文字}” · 撤销')`，撤销 = `reset` | `decision: ignore` |
| 已替换 | “指定类别…”：小弹层列出手动补充的十类，选后作为用户词条全文替换（以后自动记住，SPEC 9.10） | `decision: replace, category` |
| 你保留的（ignore） | “改回替换” | `decision: reset` |
| 按记忆或本机判断保留（pending + `kept_by` memory / vector） | “替换”：按默认类别替换；记忆保留的同时删除本人对该词的记忆（后端已实现） | `decision: replace, category: 默认类别` |

* 批量“保留所选”弹确认：“所选 N 组将按原文发送给模型。请确认其中没有公司名、人名等敏感信息。”；批量“改回替换”不弹确认（只会多替换）。
* 手动补充对话框中“以后自动替换”复选框去掉（V31Q-35）：用户确认的替换在确认发送时已全部记住。
* 每次操作成功后用返回的 `RedactionInfo` 刷新，并重读签约方与外发文本（同现状 `afterChange`）。操作期间该行禁用，其余可继续浏览。

### 3.4 状态与刷新

* 进入第二步时并行读取签约方、脱敏信息、外发文本、拦截原因（同现状 `loadAll`）。
* 任务 `busy`（刚加入或删除了文件、改了主文件）时：画布与回执栏上方显示灵动岛“正在加入文件并重新计算…”，签约方、不确定项、手动补充的操作禁用（浏览不受影响），`useTaskPoll` 轮询；`busy` 变为假后自动重新读取全部数据，灵动岛显示“已更新”2 秒后收起。
* 409 `TASK_STATE_CONFLICT` 时同现状发出 `stale`，由父页面刷新任务。

### 3.5 拖入

审核任务从未提交审核时，整个工作台接受拖入：拖入时画布上叠一层“松开加入本任务”，松开后 `addFiles`，进入 3.4 的 busy 状态。已提交过审核（重新审核）时不接受拖入、不显示文件增删。

### 3.6 键盘操作

焦点不在输入控件、对话框、抽屉中时有效（`useHotkeys`）；画布上方小字“按 ? 查看快捷键”，`?` 打开说明弹层（`el-dialog` 480px，表格列出下表）。

| 键 | 作用 |
|-|-|
| `V` | 切换“原文 / AI 视野” |
| `J` / `K` | 下一个 / 上一个不确定项：自动展开不确定项一节，选中该行并在画布定位 |
| `B` | 对选中的不确定项“保留原文”（已保留时无作用） |
| `T` | 对选中的不确定项“改回替换 / 替换” |
| `[` / `]` | 上一个 / 下一个文件页签 |
| `Ctrl+Enter` | 把焦点移到“确认发送”按钮并闪一次高亮（不直接发送；再按 Enter 发送） |
| `Esc` | 关闭弹层、取消画布中的划选 |

选中的不确定项行有 2px 主色焦点框，画布中对应胶囊同时高亮；`aria-live` 读出“第 n 组，共 m 组：{文字}，{状态}”。

## 四、单画布“原文 / AI 视野”与划选补充脱敏（V31-U2-04，Sonnet，high）

### 4.1 画布（新组件 `ConfirmCanvas.vue`，取代确认页中的 `RedactionCompare` 与 `ManualRedactDialog`）

* 顶部一行：文件页签（只有一个文件时不显示；页签名为文件名，主文件在前，带该文件替换数）、右侧 `SiSegmented`“原文 / AI 视野”；页签下为 `.si-stage` 包裹的 `.si-paper` 纸面，最大宽度 760px 居中，正文 `--si-font-reading`。
* 底部一行次要色状态：“{n} 处已在本机保护 · 划选文字可补充”（AI 视野下为“这是模型将看到的样子 · 代号在本机还原”）。
* **数据**：节点用现有 `previewApi.nodes`（助手用 `assistantApi.nodes`），一次只渲染当前页签的文件；切换页签时读取，读过的缓存在组件内。替换位置用 `items`，按 `utils/compare.ts` 的 `splitOriginal` 切分（码点下标，与后端一致）。
* **排版**：标题、段落、列表项按节点 `kind` 排版；表格单元格（loc 含 `-T{表}-R{行}-C{列}`，Word 与 PDF 表格）与工作表单元格（`sheet`、`cell_ref`）按行列排成简单表格（同一表 / 工作表连续的单元格组成一个 `<table>`，合并单元格不还原），OCR 文字块按段落显示；页眉、页脚、批注等非正文节点同现状对照区的处理。本次补充说明在最后一个文件页签末尾，单独一块，标题“本次补充说明”。
* **长文档**：当前文件节点超过 800 个时，默认只显示有替换或不确定项的节点，其余折叠为“{n} 段未改动 · 展开”（同现状对照区的写法）；节点块加 `content-visibility: auto`。
* 原文按保留期清理时显示该文件“原文已按保留期清理”（同现状）。

### 4.2 胶囊

| 种类 | 原文视图 | AI 视野 |
|-|-|-|
| 确定替换（规则、词条、签约方、实体识别、用户词条） | 护盾胶囊：`--si-cap-bg` 底、`--si-cap-ink` 字，显示原文；左侧 10px 盾形图标；悬停提示“{类别} · 发送为 {代号}” | 代号胶囊：`--si-code-bg` 底、`--si-code-ink` 字、等宽字体，显示代号 |
| 不确定项默认替换（`detected_by=uncertain`） | 同护盾胶囊，但边框为 1px 虚线、无盾形图标；悬停提示“不确定是否敏感，已默认替换为 {代号}” | 代号胶囊（虚线边框） |
| 保留原文的不确定项（不在 `items` 中，按不确定项文字在当前节点中匹配） | 普通文字加 1px 点状下划线（`--si-ink-3`） | 同原文视图（模型看到的就是原文） |

* 点击任何胶囊或点状下划线文字弹出小弹层（`el-popover`，`trigger="click"`）：不确定项显示 3.3 的操作；确定替换中 `can_revoke` 的显示“撤销（不是敏感信息）”（现有确认文字与接口），其余只显示类别与代号。弹层中的操作与回执栏共用同一套处理函数。
* **AI 视野切换**（品牌时刻）：完整特效下各胶囊依次（每个延迟 12ms，最多 40 个，其余同时）做 `rotateX` 翻面换字，320ms，`--si-spring`；精简为整体 160ms 淡入；关闭为直接切换。切换期间不阻塞点击。可视区外的胶囊不做动画。

### 4.3 划选补充脱敏

* 只在原文视图有效；在纸面内选中同一节点内的文字（跨节点、跨表格单元格的选择不处理，提示“请在同一段内选择”）后，选区上方出现浮条：“补充脱敏”+ 类别下拉（十类，默认“公司”）+“设为敏感信息”。选金额时规则同现状（可带币种或单位，只替换数字）。
* 位置换算沿用 `RedactionCompare` 的选区逻辑（码点偏移，`NOTE` 节点偏移相对补充说明原文），抽出为 `composables/useTextSelection.ts`，两处共用。
* 成功后 `ElMessage.success('已设为敏感信息，相同文字已全文替换')`，刷新同 3.3；失败按现有错误码文字显示在浮条下方。
* 任务 `busy` 时浮条禁用并提示“正在重新计算，请稍候”。

### 4.4 定位

回执栏点不确定项、`J` / `K`、文件警告中的位置都调用画布的 `locate(loc, text?)`：切到对应页签 → 必要时展开折叠段 → 只滚动画布自身到节点 → 对应胶囊或文字闪烁 1.6 秒（`si-pop`，关闭特效下为静态 2px 焦点框）。

### 4.5 清理

U2-04 完成后删除 `ConfirmStep.vue`、`SuspectList.vue`、`ManualRedactDialog.vue`；`RedactionCompare.vue` 只剩重新审核对话框使用（只读），其中“未处理的疑似遗漏”标色改为只标 `decision=ignore` 的保留文字、文字改为“保留原文”，其余不动（重新审核对话框在 V31-U3 重做）。

## 九、风险

| 风险 | 应对 |
|-|-|
| 拖入即建任务，用户拖错文件也留下草稿 | 删除有 5 秒撤销；删最后一个文件即删草稿；未完成保留层按期清理（V31-S 4.1） |
| 撤销期内关闭标签页，删除没发出去 | `beforeunload` 用 `keepalive` 立即发出；万一失败，文件仍在草稿中、用户下次可见，不会误外发（确认页按服务器的文件列表计算） |
| AI 视野由替换位置拼出，与实际外发文本不完全相同（缺位置标记与比例注记） | 画布底部写明“这是模型将看到的样子”；外发回执提供“查看将发送的全文”，原样显示实际文本；发送前后端仍重新生成并复检 |
| 大文件（上万单元格）画布卡顿 | 一次只渲染一个文件；超过 800 个节点默认只显示有替换的段落；`content-visibility: auto`；切换动画只作用于可视区内且最多 40 个胶囊依次翻面 |
| 单字母快捷键误触 | 输入控件、弹层中不触发；`B` 只作用于已选中的行且可撤销；确认发送不设直接快捷键 |
| 智能助手提前换用新工作台（原计划 U4） | 助手模式只隐藏不适用的节，接口与现有完全相同；U4 只做助手页面其余部分 |
