| 情形 | `validated` | 去向 |
|-|-|-|
| 带标签的证件号、账号、SWIFT（`_LABELED_ID`、`_ACCOUNT`、`_SWIFT` 等） | 有校验器时按校验，否则 None | 照常替换；校验不过**不降级**（标签是强证据） |

## 二、出口复检加固（V31-P-02，GPT-6.1 Sol，high）

### 2.1 不可见字符（47，来源处清理）

`parsing/model.strip_invisible` 删除范围扩为：U+200B–U+200F、U+202A–U+202E、U+2060–U+2064、U+2066–U+2069、U+061C、U+FEFF、U+00AD、U+E0000–U+E007F。现有调用点（节点、补充说明、追问、助手消息）自动生效；另检查知识库片段与公司范本条款的入库路径，没有调用的补上。这些字符在商务文件中没有正当用途，删除不影响显示。

### 2.2 归一化 `redaction/normalize.py`（新，纯函数，无数据库、无日志）

```python
@dataclass
class NormText:
    text: str
    index_map: list[int]   # 归一化文本下标 → 原文下标，长度 = len(text)

def normalize_with_map(text: str) -> NormText
def normalize_value(value: str) -> str     # 对真实值做同一套变换
```

逐字变换，每个原文字符产生 0 个或多个输出字符，多个输出字符映射回同一原文下标：

| 顺序 | 变换 |
|-|-|
| 1 | 删除 2.1 的不可见字符（复检时文本已在来源处清理，这里是兜底） |
| 2 | NFKC（全角转半角、兼容字符统一） |
| 3 | 形近字归一：`resources/confusables_ascii.json`，只收“源字符是单个拉丁、希腊、西里尔或全角字符，目标是单个 ASCII 字母或数字”的条目（第九节） |
| 4 | 繁→简：`resources/t2s_chars.json`，只收单字对单字（第九节） |
| 5 | 中文单字数字 `〇零一二三四五六七八九` → `0`～`9`（逐字等长；多字数值仍由现有金额数值等价规则处理） |
| 6 | casefold |

归一化只用于比对，不改存储文本；拦截原因的 `position` 经 `index_map` 换回原文位置（`format_reasons` 的“类别@位置”格式不变）。字表用 `lru_cache` 加载一次。

### 2.3 `recheck()` 改为四道

0. **标签字符**：文本中仍有 U+E0000–U+E007F 时拦截，类别 `INVISIBLE`（来源已清理，出现即说明有未经清理的入口）。
1. **对照表与词条比对**：在归一化文本上进行；真实值与词条用 `normalize_value` 变换后走现有 `_value_positions`（数字边界、短数字须带币种、大额数值等价等规则全部保留）。代号遮盖 `_mask_placeholders` 改为先把代号归一化再在归一化文本上遮盖。另加**紧凑比对**：ACCOUNT、SWIFT、REFNO、IDNO、PHONE 的真实值去掉空格与短横线后，在文本的字母数字串（同样去分隔符，保留下标映射）中查找；比对时文本一侧把 `O o→0`、`l I|→1`、`S→5`、`B→8` 当作数字（OCR 混淆，补充项 52），只在“真实值是数字串、文本串中数字占多数”时使用。现有“≥ 8 位数字去分隔符比对”保留。
2. **格式化重扫**：`_RESCAN_CATEGORIES` 扩为 `find_formatted` 的全部类别（加 SWIFT、URL、IM、POSTCODE），原文与归一化文本各扫一遍。URL 若在系统提示词或法条中出现导致误拦，把这些固定文字中的网址去掉，不缩小重扫（A-03 会暴露）。
3. **人名、地址重扫**：先遮盖代号（本任务代号，以及符合代号文法的方括号写法），再跑 `detect.find_persons`、`detect.find_addresses`，命中即拦（类别 PERSON、ADDR）。**不做 ORG 重扫**：企业后缀会命中法条中的机关名、范本文字，造成每单必拦；公司名的防线是第 1 道（SPEC 写明理由）。

调用点、`RecheckContext`、拦截处理（`LlmCall(status=blocked)`、任务退回待确认、原因不含真实值）全部不变。

## 三、日期平移与“未知日期不写入”（V31-P-03，GPT-6.1 Sol，high）

### 3.1 为什么平移

审核要判断的是关系（交货是否晚于签约、账期多长），换成代号关系全灭；明文外发又把签约、交付这些准标识符给了云端。全任务所有日期加同一个偏移 Δ（7 的倍数），间隔、先后、星期不变，绝对日期不可知。本地校验（L-07 有效期、L-08 交货与签约、L-10 废止法）在脱敏之前用原文运行，不受影响。

### 3.2 开关与范围（V31Q-40）

* 管理端开关 `redaction.date_shift`，**默认关**，照 `redaction.mask_quantity` 实现（`settings_store.DEFAULTS`、`admin/redaction.py` GET/PUT、审计 `setting_update`）；关→开只影响之后重算的任务。
* 只用于智能审核（`style="review"`）与追问；智能助手不平移。
* V31-E 双指标评测对同一组样本开 / 关各跑一次，审核保真度不低于关闭时，在 V31-E 审核时改为默认开。

| F4 | 20260305 | 只在前 10 个字内有“日期、签约、签订、交货、交付、有效期、装运、至”等词时才认 |
| F5 | 二〇二六年三月五日 | 年逐位读，月日按中文数值读（十、二十三）；渲染回汉字 |

不认：只有年月或只有月日、日月顺序不明的 `05/06/2026`、相对期限（“30 天内”“次月”）、不合法日期（2026-02-30）、编号中内嵌的 8 位数字。时间部分（“10:00”）不动。规则参考 JioNLP `parse_time`（只借方法，不取代码）。

### 3.4 平移（`engine.compute()` 新增一步）

* `compute(..., date_shift_days: int = 0)`；为 0 时整步跳过，输出与现状逐字一致。
* 位置：地址之后、项目名称之前。只在未占位区间内识别，已替换的编号、金额优先。
* 每个日期生成 `_Span(category="DATE", key=ISO 日期, detected_by="date")`；`_assemble` 的 DATE 分支不走代号分配，`placeholder` 为按原写法渲染的平移后日期。
* **偏移**：任务首次需要时生成，`Δ = 7k`，`k` 从 `[-52, -8] ∪ [8, 52]` 用 `secrets` 均匀取；**一经生成终身不变**，存为全量对照表的特殊键 `@date_shift_days`。`_write_map` 保留该键；`load_redaction_map`、`load_real_values`、`load_placeholders` 排除 `@` 开头的键。
* **还原对**：`mapping[f"{平移后写法}#D{n}"] = 原写法`（沿用 `#` 变体键：不参与代号还原，原日期进入复检真实值，原日期以未平移形态出现在外发文本中时被第 1 道拦下）。新增 `load_date_pairs(db, task_id)`。

### 3.5 还原与闸门（`restore.check()`）

`check(text, mapping, *, clause=False, locations=None, dates=None)`，`dates` 为本任务的还原对（未平移时为 None）：

* 文中日期是还原对的键 → 换回原写法，计入 `restored`。
* 文中日期不是还原对的键 → 原样，标 `date`（模型推算或照抄错的日期，处在平移后的坐标中）。`clause=True` 时因此进入批注，即修订版“未知日期不写入”。
* `dates=None` 时不处理日期，与现状一致。
* 不用“见日期就减 Δ”：外发文本中有未平移的法条日期，反算会改错。

`_View`（结果页、报告、批注版）、`chat.message_out`、`revised_docx.build_revised` 传入 `dates`。`Mark.kind` 新增 `date`，`MarkOut` 不变（kind 为字符串）。

### 3.6 外发说明与提示词

* `outbound.build` 加参数 `date_shifted`：为真时在主体说明后加一行“文中日期已整体平移，间隔、先后与星期不变；判断期限请用日期间的关系，不要以绝对日期判断法律、政策的生效时间。”
* 审核与追问提示词加一句：引用日期照抄原写法；给期限结论用相对表达（“签约日后 30 日内”），不要自行算出新的绝对日期。提示词版本号加一。
* 追问：`chat/service._redact` 完成后对问题文本用任务偏移调用 `dates.shift_text`（与 compute 共用识别与渲染）；回复按还原对展示。

### 3.7 测试

* `tests/test_redaction_dates.py`：F1～F5 平移 +70 天的渲染与星期；同一日期两种写法各有还原对；不合法日期与无标签 8 位数字不平移；重算两次偏移不变；`check` 对含法条日期与未知日期的文本（本任务日期还原、法条日期原样标 `date`、`clause=True` 时修订版改批注）；开关关时逐字不变。
* golden 新样本 `date_shift.txt/.yaml`，测试函数加断言键 `must_shift: [{text, shifted}]`，用固定偏移 70 运行，并断言任意两个日期的间隔不变。其他样本默认偏移 0，`must_keep` 中的日期保留不改。
* A-03 加一条：外发文本混入未平移的原日期被拦下。

## 四、跨节点预登记与叙述人名地址（V31-P-04，GPT-6.1 Sol，high）

### 4.1 相邻标签（整改 12）

在 `compute()` 第 4 步之前做一轮**预登记**，只登记、不直接产生替换区间：

* **表格左格**：同一行紧邻左格的全文是信息标签（账号、户名、开户行、身份证号、证件号、联系人、电话、手机、邮箱、地址、SWIFT 等，复用 `detect` 现有标签词）而本格不含标签时，把“左格文字 + `：` + 本格文字”交给 `find_formatted` / `find_persons` / `find_addresses`，命中且覆盖本格文字的部分即登记为对象（类别与 key 同单节点识别）。只认紧邻左格，不跨空列（同 `table_hints` 的 R4 规则）；表头行向下的列标签也按同样方式（列头为上述标签、本格无标签）。
* **相邻段落**：同一文件中，前一节点以“标签 + 冒号”结尾（冒号后只有空白）、本节点不含标签时，同样拼接识别。只看紧邻的前一个节点。
* 登记后在本节点按精确区间替换（`detected_by` 用原识别方式，不新增取值）。

### 4.2 格式化值全文回扫

ACCOUNT、SWIFT、REFNO、IDNO、IM、EMAIL 的已识别值，在全部节点未占位文字中再匹配一次并替换为同一代号：字母数字值按原文精确匹配（区分大小写同识别时的口径）；≥ 8 位数字的值也按去掉空格与短横线的紧凑形匹配。PHONE、POSTCODE 不回扫（共用代号，短号码易误伤）。做法同地址的重复出现替换（Q-76）。

### 4.3 叙述人名（整改 13）

新增 `detect.find_narrative_persons(text)`，结果只作为**不确定项**（原因沿用 `person_name`，默认替换，可保留原文），不进自动替换：

| 结构 | 例 |
|-|-|
| 动作词 + 姓 + 1～2 字 + 动作或标点 | 由张伟负责、请李娜确认、经王强签字、与赵敏联系、交刘洋签收 |
| 姓 + 总 / 工 / 经理 / 主管 / 老师（后接标点、动作词或结束） | 张总、李工、王经理 |
| 人名标签值中以“、，/”分隔的多个姓名 | 抄送：张三、李四 |

* 姓取 `cn_surnames.txt`；动作词前置表与后置表写在函数内，各不超过约 20 个。
* 姓名部分（不含称谓）在 `zh_words`、`common_terms`、`zh_legal_finance` 中，或整段在 `plain_candidate` 中的不列。
* 已识别为人名的（标签人名、实体识别高置信）沿用现有全文替换，本函数只补缺口。

### 4.4 行政区划词典与叙述地址（整改 13、补充项 50）

* 数据：JioNLP `china_location.zip`（第九节），取省、市、县三级与乡镇街道一级的名称与别名，生成 `resources/cn_admin_divisions.txt`（每行：名称、级别、上级名称）；**村级不取**（V31Q-42：“新村”“和平村”等与普通词、企业字号重名多，误伤大于收益）。
* `detect.find_addresses` 增加：**连续两级以上且最后一级为县级或乡镇街道级**的行政区划链（上下级关系须与词典一致，如“浙江省湖州市长兴县”“长兴县和平镇”），后可接村、社区、工业园、开发区、园区及道路门牌部分；整段为 ADDR（key 为“中国”）。只有省、市（含“XX市XX区”中区级是市辖区）的链保留不替换（9.2 保留城市名称）。
* 现有 `_CN_UNLABELED_ADDRESS` 的起点判断（“运至、位于、在”等动作词截断）改为：从词典中能接上的最长行政区划链起点开始，链之前的文字不算地址。词典接不上时沿用现有规则（只增不减）。
* 复检第 3 道的地址重扫用同一函数，自动增强。

### 4.5 测试

golden 新样本 `cross_node.txt/.yaml`（含 DOCX 风格表格单元格位置编号，账号、户名、联系人分在左右两格；“开户行账号：”与账号分两段；合同编号在正文无标签再出现）与 `narrative.txt/.yaml`（叙述人名三种结构入 `must_suspect`；“由于”“请于”“与其”等非人名不列，入 `must_keep`；区县 + 乡镇地址入 `must_replace`；单独的“杭州市”入 `must_keep`）。

## 五、回程落点（V31-P-05，GPT-6.1 Sol，high）

### 5.1 引用按原文位置还原（整改 8）

* `engine` 新增 `redacted_to_original(text, items, inserts)`：与 `_render` 同一算法，返回脱敏文本每个下标对应的原文区间（代号整体对应原文区间，比例文字对应空区间）。需要节点的替换项与比例插入点时从 `redaction_items` 与节点原文现算（比例插入点用 `_ratio_inserts` 的同一结果；无法重现时不做 5.1，退回现状）。
* `validate_output` 第 5 条：引用经 `normalize_for_quote` 后**在第一个位置节点的脱敏文本中恰好出现一次**时，取对应原文片段存入 `quote_original`（入库加密为 `findings.quote_orig_enc`）；出现多次、模糊匹配或跨节点时为空。`quote_snapshot` 不变。
* `FindingOut` 加 `quote_excerpt: str | None`（界面在 U3 使用）。
* 修订版、批注版定位：有 `quote_original` 时用它作为定位文字，否则沿用 `restore(quote_model)`。

### 5.2 共用代号就地还原

修订版的建议条文（`clause=True`）中出现共用代号（`[电话]`、`[邮箱]`、`[证件号]`、`[地址：中国]` 等）时：若该问题第一个位置节点中，被替换为同一代号的原文值**只有一个**（按规范形式去重），换成该值，计入 `restored`；否则照旧标 `shared` 并改批注。实现为 `check()` 的可选参数 `local: dict[str, str]`（代号 → 本节点唯一值），由调用方从 `redaction_items` 现算；结果页、报告、批注版的展示字段同样传入。

### 5.3 修订版字面值闸门（补充项 48）

`check(..., clause=True)` 对**还原前**的建议条文，先遮盖全部代号写法，再跑 `detect.find_formatted`（ACCOUNT、SWIFT、PHONE、EMAIL、IDNO、IM、URL）与 `detect.find_amounts`（AMOUNT、PRICE）；命中的标 `literal`，修订版因此改批注。模型只见过代号，条文中出现这些字面值说明是编造或受注入影响。非条文字段不查（避免“100 元以下”等叙述产生噪声）。

### 5.4 测试

回程样本（golden `returns`）补：引用含 `[电话]` 时修订版按原文片段精确定位并写成修订；节点中只有一个电话时建议条文的 `[电话]` 被就地还原，有两个时改批注；建议条文含“账号 6222…”“人民币 1000 元”时改批注。`test_revised_docx.py` 补一条端到端用例（引用含共用代号仍能写成修订）。

## 十一、风险

| 风险 | 对策 |
|-|-|
| 复检人名、地址、URL 重扫在固定文字（提示词、法条、范本）上误拦，每单必拦 | 先遮盖代号；A-03 与 P-06 统计固定文字误拦数，必须为 0；需要时改固定文字，不缩小重扫 |

| 行政区划链误吞叙述（“在长兴县和平镇的工厂”中的“的工厂”） | 链后只接村、社区、园区与道路门牌结构；golden 护栏 |
| OCR 混淆导致误拦 | 只在数字类真实值的紧凑比对中使用，只会命中与真实值相同的串 |
| 引用的脱敏文本映射回原文出错 | 只在恰好出现一次时使用，否则退回现状；修订版另有生成后校验（`revised_docx.validate`） |
