## 〇、结论与共同约定

一句话：**录音只在本机变成文字，人校对过、确认脱敏过的文字才外发；纪要还是智能助手的一次普通对话。**

### 0.1 现状（代码依据）

| 问题 | 代码 |
|-|-|
| 智能助手只收文档（docx、pdf、xlsx、图片与旧格式），上传 ≤ 30 MB，Caddy 请求体上限 320 MB | `tasks/service.check_uploads`、`tasks/filecheck.py`、`deploy/Caddyfile` |
| 原件加密是整个文件读进内存一次加密（`crypto.encrypt_to_file`），500 MB 录音会让 app 进程瞬时占用 1 GB 以上 | `tasks/storage.save_original` |

| 节点只有文档类（段落、单元格、OCR 块），没有时间、发言人 | `parsing/model.ParsedNode`、`doc_nodes` |
| 本地模型各自处理，线程写死，无清单（规范第〇节） | `ner.py`、`embedding/engine.py`、`build_release.sh` |
| 助手模板只有翻译、摘要、起草回复、单证核对、比价 | `assistant/templates.py` |

### 0.2 流程（智能助手内，不加菜单）

```text
加入录音 ─► app 分块加密保存 ─► worker：解密写入 /spool ─► converter：ffmpeg 解码
   ─► 16 kHz 单声道 PCM（给转写）+ 回放副本（Opus，加密保存）；删除录音原件（V31Q-69）
   ─► transcriber：语音分段 → 转写 → 标点 → 说话人分段与声纹聚类 ─► worker 写逐字稿节点
   ─► 用户校对：参会人名单、发言人改名、同音纠正建议、改字、改发言人、点句回放
   ─► 现有“确认脱敏”工作台 ─► “会议纪要”模板（经网关、出口复检）─► 本地还原 ─► 导出 Word
         └─ 不外发也能用：逐字稿 Word 随时可导出（V31Q-72）
```

### 1.4 预定规则

1. **转写模型**：FireRedASR2-AED 满足全部条件即选它，否则依次试 SenseVoice-Small：
   * 容器峰值 ≤ 4 GB（可用 INT8 量化达到；量化后字错率比 FP32 差 ≤ 1 个百分点）；
   * 8 线程实时率 ≤ 0.5（3 小时录音 ≤ 90 分钟）；
   * 繁忙场景下无 OOM、无持续交换，1 万字识别 ≤ 15 秒、500 字追问 ≤ 3 秒（SPEC 第 3 节现有门槛）。
   
   balloon 能设到 24 GiB 时按 24 GiB 的结果判，做不到时按 16 GiB 判（V31Q-27）。两者都不满足时停下交用户。
2. **说话人分离**：第一版就做（V31Q-23）。归属错误 > 15% 时照常接入，报告写明，界面的“改发言人”承担纠正。
3. **脱敏召回**：漏掉的名称、金额若因同音错字，由第五节的同音纠正兜底；若因数字写成汉字或口语单位，列入 M-05 的口语金额修复。召回只报数，不设门槛（外发前还有用户校对和出口复检）。
4. **低置信高亮**：模型能给逐字置信度就做字级高亮，阈值取使脚本错字约 70% 落在高亮内的值；不能则只按整句（句平均置信度）高亮。

### 3.2 上传与检查

* 只在智能助手加入文件处接受录音（审核任务仍不接受，返回现有“格式不支持”）。一次加入最多 1 个录音；录音与文档同样计入会话 ≤ 10 个文件。
* 大小 `MAX_AUDIO_MB`（默认 500）；Caddy 只对 `/api/assistant/sessions/*/files` 把请求体上限放到 `{MAX_AUDIO_MB}+20` MB，其他路径仍为 320 MB。
* 内容检查（`filecheck.py`，按扩展名核对文件头）：mp3（`ID3` 或帧同步 `FF Ex/Fx`）、wav（`RIFF....WAVE`）、m4a / mp4（第 4～8 字节 `ftyp`）、amr（`#!AMR`）、aac（ADTS `FFF1` / `FFF9`）。不符即“文件内容与扩展名不符”。时长在解码时检查（3.3）。
* 转写功能未启用（`COMPOSE_PROFILES` 不含 `asr`）时拒绝录音：“录音转写未启用，请联系管理员”。

### 3.3 分块加密保存与解码

* **分块加密**：`crypto.encrypt_stream(path, chunks)` / `decrypt_stream(path)`：每块 4 MiB 明文单独 AES-256-GCM，随机 nonce，附加数据含块序号与“是否最后一块”，防重排与截断。上传按块读入、按块写出，app 内存峰值约 8 MiB。只用于录音，现有文件格式不变。
* **解码**（converter 加 ffmpeg，Debian 软件包锁定版本，V31Q-71）：worker 按块解密写入 `/spool/in/{id}.audio`，converter 识别为录音后执行
  `ffprobe` 取时长（> 3 小时即 `TOO_LONG`）→ `ffmpeg -nostdin -protocol_whitelist file,pipe -i in -vn -ac 1 -ar 16000 out.wav` 与 `-c:a libopus -b:a 24k out.ogg`，单个文件超时 `时长 ÷ 10 + 120` 秒。结果为 `out/{id}.wav`、`out/{id}.ogg`，失败为 `out/{id}.err`（新增 `TOO_LONG`、`NO_AUDIO`）。mp4 只取音轨。
* **保存**：回放副本（Opus，16 kHz 单声道，3 小时约 35 MB）用现有整文件加密存入原件目录，写 `media_storage_key`；**录音原件解码成功后即删除**（V31Q-69）。PCM 留在 /spool 交给 transcriber，转写结束即删。
* `/spool` 内存盘改为 1 GiB（录音 ≤ 500 MB + PCM ≤ 346 MB + 回放副本，输入解码完即删）。converter 的 `mem_limit` 不变。
* 保留期与删除：回放副本按原件层处理（16.4：到期删除回放副本，清空节点原文与 `speakers_enc`、`participants_enc`），任务删除时一并删除；备份、恢复、主密钥更换按原件处理。

### 3.4 状态

`task_files.media.stage`：`decoding` → `queued` → `transcribing` → `done` / `failed`。解析状态沿用文件级解析状态（S-04），录音在 `done` 之前视为“解析中”；会话详情接口的文件项带 `media`（时长、阶段、进度百分比、排队位次）。排队位次 = 排在它前面的 `transcribe` 任务数，查询时现算。

### 3.5 测试

一个用 `ffmpeg -f lavfi -i sine` 在测试中生成的 5 秒 wav：上传 → 解码得到 PCM 与回放副本，原件已删；文件头不符被拒；分块加密篡改一块解密失败。converter 自身测试加一条录音转换。

## 四、transcriber 容器与转写任务（V31-M-04，GPT-6.1 Sol，high）

### 4.1 容器（规范第四、五节）

```yaml
transcriber:
  image: aireview-transcriber:${APP_VERSION:-dev}
  profiles: [asr]
  network_mode: none
  read_only: true
  user: "10003:10001"
  cap_drop: [ALL]
  security_opt: [no-new-privileges:true]
  tmpfs: [/tmp:size=64m]
  environment: {CONVERT_SPOOL_DIR: /spool, ASR_THREADS: "${ASR_THREADS:-8}", ASR_MEM: "${ASR_MEM:-4g}"}
  volumes: [convert_spool:/spool]
  mem_limit: ${ASR_MEM:-4g}
  cpus: ${ASR_CPUS:-8}
  cpu_shares: 256          # 低于其他服务的默认 1024
  pids_limit: 128
  healthcheck: {test: ["CMD", "python", "/srv/transcriber/main.py", "--check"], interval: 15s, retries: 3}
```

* 镜像：python:3.12-slim + M-01 选定的推理库与模型文件；启动时 `sha256sum -c MANIFEST.sha256`，不通过则不写心跳（容器不健康，功能显示“暂不可用”）。
* 交换协议（与 converter 同法，子目录分开）：`asr/in/{id}.wav` + `asr/in/{id}.json`（只含 `{speakers: null | 2～10}`）→ `asr/work/{id}/` → `asr/out/{id}.json` 或 `asr/out/{id}.err`；`asr/progress/{id}` 写已处理毫秒数；`transcriber.alive` 心跳；超过 10 分钟无人取的输出删除。
* **用时加载、用完卸载**：取到任务才加载模型，队列空闲 5 分钟后释放（进程内删除会话；做不到时进程自行退出，由 restart 拉起）。
* **开始前等内存**：`/proc/meminfo` 的 MemAvailable 小于 `ASR_MEM` 时每 30 秒再查，进度写 `waiting_memory`。
* **段落边界让路**：每个语音段开始前检查 `asr/pause` 文件，存在则等待。worker 在有解析任务运行时创建、全部结束后删除（文件 mtime 超过 10 分钟视为失效，防止 worker 崩溃后永久暂停）。追问、助手对话在 app 进程，靠 `cpu_shares` 保证，不另做协调。
* 一次只处理一个任务。

### 4.2 处理

1. 语音分段：每段 ≤ 30 秒（超出按最长静音处再切），模型超过 60 秒会编造文字（补充项 63）。
2. 逐段转写、加标点；有逐字置信度与时间戳时一并输出。
3. 说话人：分段模型 + 声纹聚类；`speakers` 给定时按该数目聚类，否则按阈值自动。
4. 输出：

```json
{"duration_ms": 3600000, "segments": [
  {"start_ms": 12050, "end_ms": 19800, "speaker": 1, "text": "……",
   "low": [[3, 5]]}]}
```

`low` 为低置信的码点区间（按 1.4 第 4 条；只能句级时整句为一个区间）。不输出声纹向量，声纹只在容器内存中。

### 4.3 worker 转写任务

* worker 增加一组 `("transcribe", WORKER_TRANSCRIBE_CONCURRENCY=1, ("transcribe",))`，不占用解析与助手的并发。
* 解码完成后入队 `transcribe`；任务把 PCM 交给 transcriber，按 `progress` 每 10 秒更新 `media.progress`，等待上限 `时长 × 2 + 30 分钟`（含等内存与让路）。transcriber 不可用（心跳过期）时 `failed`，`media.error = "unavailable"`，界面提示“转写服务暂不可用，可稍后重试”；会话文件接口加 `POST .../files/{fid}/retranscribe`（只在 failed 时，需 PCM 已删时从回放副本重新解码）。
* worker 重启后任务从头重做（结果与 id 无关，旧输出按 id 删除）。

### 4.4 逐字稿节点

* 每个 segment 一个节点：`kind=utterance`、`part=body`、`loc=F{n}-U{k}`（k 从 1 起按时间顺序）、`text` 为转写文字（加密，同其他节点）、`t_start_ms`、`t_end_ms`、`speaker`、`low_conf_spans`。不设 `clause_no`、`page`。
* `parser_version` 写 `asr-{模型简称}-{MANIFEST 前 8 位}`。
* 文件类型 `doc_type` 固定为 `letter`（助手不用它），文件名照常不外发。
* 解析完成后照常进入确认脱敏（第五节外发格式）；表格本地校验（13A 第 1 条）跳过录音文件。

### 4.5 测试

transcriber 用一个 `--fake` 模式（读同名 `.fake.json` 直接输出，只在测试镜像中可用）验证交换协议、进度、让路与超时；worker 用模拟输出验证节点写入。真实模型的断网冒烟由 M-02 的 `smoke` 承担。

## 五、校对、同音纠正与逐字稿外发（V31-M-05，GPT-6.1 Sol，high）

### 5.1 校对范围（V31Q-72）

确认脱敏之前（文件 `confirmed_at` 为空）可以：设置参会人名单、发言人改名、改一句的文字、改一句的发言人、采纳同音纠正建议、点句回放。不做：拆句、并句、改时间、局部重转写。确认后逐字稿只读（与文档文件一致：已确认的文件不能修改）。

### 5.2 参会人名单

* `PUT /assistant/sessions/{id}/participants {names: [...]}`：≤ 30 个，每个 2～40 字，加密存 `tasks.participants_enc`。
* 每个名字作为本会话的用户词条（PERSON，`add_user_term` 的按文字版本，全文匹配替换），与“划选补充脱敏”同一机制；不因名单本身写入术语记忆（确认发送时的 S-03a 全量记忆照旧按确认的替换处理）。名单删除某人时撤销对应词条。
* 名单也是同音纠正的候选来源（5.4）。

### 5.3 发言人

* `PUT .../files/{fid}/speakers {"1": "张伟", "2": null}`：改名或恢复“发言人 N”，加密存 `speakers_enc`；名字同样登记为本会话 PERSON 词条（已在名单中则复用）。
* `PATCH .../files/{fid}/utterances/{loc} {text?, speaker?}`：改文字（≤ 2000 字，按现有不可见字符清理）或改发言人编号；节点文字重新加密，该文件的脱敏按现有“正文变化即重算”处理（S-04 的保存点与任务锁）。
* 审计只记事件与 loc，不记文字。

### 5.4 同音纠正建议

* **拼音数据**（V31Q-70）：Unicode 17.0.0 Unihan 的 `Unihan_Readings.txt`（与 V31-P 的 Unihan_Variants 同一版本，Unicode License V3），取 `kMandarin`、`kHanyuPinyin`、`kXHC1983` 合并为每字的无声调读音集合，生成 `backend/resources/hanzi_pinyin.json`，来源、SHA-256、生成脚本按 V31-P 的 README 写法。下载前经用户确认。
* **候选**：参会人名单、发言人名字、本人已启用的已记住名称（PERSON、ORG，S-03）中 2～8 个汉字的项。
* **匹配**（`app/assistant/homophone.py`，纯函数）：在每个 utterance 节点的文字上，对每个候选取等长窗口；窗口与候选逐字读音集合有交集、至少一个字不同、窗口不是常用词（`zh_words.txt`）也不是另一个候选，即给出建议。不做模糊音（n/l、zh/z 等），避免误报。
* `GET .../files/{fid}/suggestions` → `[{loc, start, end, from, to}]`（本人数据，返回真实文字，只给本人）；`POST .../suggestions/apply {items: [{loc, start, end, to}]}` 逐条改字（等同 5.3 的改文字）。界面在 U4：逐条采纳或全部采纳。

### 5.5 回放

`GET .../files/{fid}/audio`：解密回放副本，整文件返回 `audio/ogg`，`Cache-Control: no-store`，非本人 404；前端用 `currentTime` 跳到句首。审计 `audio_play`（只记文件）。

### 5.6 逐字稿外发格式

外发构建（9.7 / 助手外发）中 utterance 节点写为：

```text
[F1-U12] 【发言人1｜00:12:05】……
[F1-U13] 【[[PERSON_2]]｜00:12:31】……
```

改过名的发言人写成该名字在对照表中的代号（由 5.3 的词条保证已替换）；未改名的写“发言人 N”。时间写 `hh:mm:ss`，不平移（助手不平移日期，V31Q-40）。

### 5.7 口语金额（只在 utterance 节点）

转写稿常见“三十五万”“两百多万”“八千块”“三个亿”，不带“元”。在 utterance 节点上，中文位权数字或阿拉伯数字后接 `万` / `千万` / `亿` / `个亿` / `块` / `块钱` / `万块` 时按 AMOUNT 处理，币种未知；E-06a 的护栏（一元化、多元化、“X 块区域”等）保留，另护栏“万一”“千万（别）”“一亿人”等非金额（后接人、次、个人、台等量词时不算）。文档节点不变。写 2～3 条 golden 样本（utterance 节点的虚构逐字稿），进 A-03。

### 5.8 测试

模拟逐字稿一份：名单与改名后外发文本不含真名、发言人行为代号（A-03 口径）；“章伟”在名单有“张伟”时给建议、“往返”不因“王芳”给建议；他人访问 404；口语金额 golden。

## 六、会议纪要模板与导出（V31-M-06，GPT-6.1 Sol，medium）

### 6.1 “会议纪要”模板

* `templates._RULES` 加 `"minutes": ({"file_ids"}, 1, 3)`，只接受已确认的录音文件；默认消息“把录音 {序号} 整理为会议纪要”。
* `assistant_templates.md` 加 `## minutes`：输出固定小节——会议概况（时间按逐字稿时长、参会发言人代号）、议题、讨论要点（按议题，注明发言人代号）、决议、待办（事项 | 负责人 | 期限，无则写“未明确”）、需确认的事项。另加两句：“转写稿可能有同音错字，按上下文理解，不要改写代号”“代号、数字、日期照抄，不推算”。助手提示词版本加一。
* 回复照常本地还原、标出（9.9），【算式】照常本机计算。

### 6.2 导出

* **纪要 Word**：沿用助手消息导出（`assistant/export.py`），对 minutes 回复加标题“会议纪要”与小节样式，待办表格导出为 Word 表格；不新增接口。
* **逐字稿 Word**：`GET .../files/{fid}/transcript?format=docx`（新，非本人 404）：在内存中生成，标题为文件名，每句一段“【张伟 00:12:05】……”（用真名与校对后的文字，低置信处不标），不保存在服务器。确认前后都可导出，**不外发也能用**（V31Q-72）。审计 `transcript_export`。

### 6.3 测试

模板参数校验一条（非录音文件被拒）；模拟模型回复导出纪要 Word 含待办表格；逐字稿 Word 含真名与时间、他人 404。

## 十一、风险

| 风险 | 对策 |
|-|-|
| 转写与主线争抢内存、带宽，解析变慢 | 独立容器硬上限、低 `cpu_shares`、开始前等内存、解析时段落边界让路；M-01 按 SPEC 门槛实测，不过则换 SenseVoice-Small |
| 首选模型无法在不装 torch 的条件下导出或推理 | M-01 先验证导出与 sherpa-onnx 支持；不行即按 1.4 换备选 |
| 同音纠正误报（人名与常用词同音） | 只对等长窗口、排除常用词与其他候选、只给建议由用户采纳；不做模糊音 |
| 名字转写成错字导致真名漏脱敏外发 | 名单与改名登记为词条、同音建议、确认页人工查看、出口复检四道；M-01 报召回 |
| 口语金额误报（“千万别”“万一”） | 只在 utterance 节点、需后接金额单位，量词护栏，golden 覆盖 |

| 500 MB 上传占内存 | 分块加密，app 峰值约 8 MiB；Caddy 只对录音路径放宽 |
| 3 小时转写占用 worker 一个线程很久 | 单独的 transcribe 并发组，不占解析与助手 |
