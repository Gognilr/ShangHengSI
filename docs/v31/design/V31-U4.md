## 二、智能助手（V31-U4-02，Sonnet，high）

### 2.1 回复中的标出与本机计算（73、R 的助手部分）

* `MessageItem.vue`：`utils/markdown.ts` 的 `inline()` 增加可选参数 `tokens: Set<string>`（来自 `markTokens(content, marks)`，不含 calc），切分时把这些文字切成 `{ text, mark: kind }` 段，渲染同 `MarkedText` 的标记样式与提示；去掉现有的 `[[…]]` 正则判断与“回复中有无法还原的代号”一行，改为“有 N 处未能还原，已原样标出”（N 为非 calc 标记数）。
* 段落块文字以“【算式】”开头的，按出现顺序与 `calcs`（按 `line_start` 排序）配对，用 `CalcResult` 替换该段；配对不上时按普通段落显示。
* 翻译、比价、单证核对的附加结果不检查（SPEC 19.6A），不变。

### 2.2 本地校验卡片（74）

* 文件面板“文件”列表之下：会话有表格本地校验结果时显示一张卡片——`ZoneHeader kind=local`“本地计算 · 结果确定 {n}”，下方一行“高 a · 中 b · 低 c”与“无法核验 {m} 项”（为 0 不显示），文字按钮“查看”打开右侧抽屉（560px），内容为 `LocalCheckList`（`loader = assistantApi.localFindings(id)`），条目位置不可点（助手没有原文画布）。
* 读取时机：会话详情变为 `active` 或 `awaiting_confirm`、文件数变化时读一次；没有结果时不显示卡片。
* 卡片下一行次要色：“发给模型的只有不含金额的摘要”（SPEC 13A 第 3 条）。

### 2.3 会议纪要模板（65）

* `TemplatePicker`：加“会议纪要 · 把录音整理为议题、决议与待办”；`asr_enabled` 为假时不列出。
* `Composer`：minutes 的文件选择只列出已确认且转写完成（`media.stage = done`）的录音，1～3 个；不满足时按钮旁原因“请选择 1～3 个已确认的录音”。参数 `{ file_ids }`，同其他模板。
* 回复照常显示与导出 Word（后端已加标题与待办表格）。

### 2.4 文件面板与录音行（62）

文件面板（320px）重做为分节：文件、会话设置（立场、代号数、查看外发文本）、本地校验卡片。

* **加入文件**：选择框 `accept` 在 `asr_enabled` 时加 `.mp3,.m4a,.wav,.amr,.aac,.mp4`；拖入同样接受。录音单个 ≤ 500 MB（前端先查），文档仍 ≤ 30 MB。上传中显示进度条与“正在上传 {百分比}”，可继续浏览，不可取消（第一版）。
* **录音行**：徽标“音频”、文件名、时长（`duration_ms`，hh:mm:ss）与状态：

| `media.stage` | 显示 |
|-|-|
| decoding | “正在本机解码” |
| queued | “排队转写，前面还有 {queue_position} 个”（为 0 时“即将开始转写”） |
| waiting_memory | “等待服务器空闲内存” |
| transcribing | 进度条（`progress ÷ duration_ms`）与“本机转写中 {已处理时长} / {总时长}”；行底 2px 扫描光条（`useLoop`，同首页解析中） |
| done | 未确认：“转写完成，请校对”+ 主按钮“校对逐字稿”；已确认：“已确认”+ 文字按钮“查看逐字稿” |
| failed | 危险色原因：unavailable“转写服务暂不可用，可稍后重试”、timeout“转写超时”、transcribe_failed“转写失败”、decode_failed“无法解码该录音”；按钮“重新转写”（`retranscribe`，decode_failed 时不显示） |

  录音行另有文字按钮“逐字稿 Word”（`done` 后，确认前后都可），走 `saveBlob`。
* 会话中有录音在 decoding / queued / waiting_memory / transcribing 时，`useTaskPoll` 式轮询会话详情（每 3 秒，页面隐藏暂停）。转写期间会话与文档解析一样不能提问、不能再加文件（U4-07 更正：原写“照常可用”是对 M 0.4 第 5 条的误读，V31Q-89）。
* `asr_enabled` 为假且会话没有录音时，文件节下一行次要色“录音转写未启用”。

## 三、逐字稿校对（V31-U4-03，Sonnet，high；64）

### 3.1 形式（V31Q-84）

全屏对话框 `TranscriptEditor.vue`（与助手的确认脱敏对话框同一形式，不加路由），标题“校对逐字稿 · {文件名}”；从录音行“校对逐字稿 / 查看逐字稿”打开。

```
┌ 播放条：▶ ⏸  00:12:05 / 01:02:33  ━━━━━●━━━━━━  1x ─────────────────────┐
├ 逐字稿（纸面，滚动）───────────────────────────────┬ 侧栏 320px ─────────────┤
│ 张伟 · 00:12:05  ▶                                │ 参会人名单  [张伟][李娜]＋ │
│   我们这边的报价是三十五万，交货期……（低置信虚线）  │ 发言人                    │
│ 发言人2 · 00:12:31  ▶                             │  发言人1 → [张伟    ]     │
│   ……                                             │  发言人2 → [        ]     │
│                                                   │ 同音纠正建议 3 条 全部采纳 │
│                                                   │  章伟 → 张伟 · 00:14:02 采纳│
│                                                   │ ───────────────────────── │
│                                                   │ 逐字稿 Word                │
│                                                   │ [去确认脱敏]               │
└───────────────────────────────────────────────────┴───────────────────────────┘
```

### 3.2 逐字稿

* 数据：`assistantApi.nodes(id, fid)` 的 utterance 节点，按 `loc` 顺序；每句一块：发言人名（`speakers` 中的真名，否则“发言人 N”）· 时间（`t_start_ms`，hh:mm:ss）· 播放按钮（`aria-label="从 {时间} 播放"`）；下面为文字（纸面、`--si-font-reading`）。
* 低置信：`low_conf_spans` 的码点区间加 1px `--si-warn` 虚线下划线，悬停提示“转写置信度低，请听原音核对”。
* **改文字**（确认前）：点击文字进入编辑（同位置的多行文本框，2000 字），Enter 保存、Shift+Enter 换行、Esc 取消；保存调用 `utterance(loc, {text})`。
* **改发言人**（确认前）：点击发言人名弹出小下拉，列出本文件的发言人（真名或“发言人 N”），选后调用 `utterance(loc, {speaker})`。
* 正在播放的句子加 2px 主色左线（按 `timeupdate` 查找当前句，只在句子变化时更新）；不自动滚动，除非用户点了“跟随播放”（播放条右侧开关，默认开，用户手动滚动后自动关闭）。
* 长逐字稿（3 小时约 1500 句）：块加 `content-visibility: auto`，一次渲染全部文字，不分页。

### 3.3 播放

* 第一次点播放时才 `assistantApi.audio()` 取回放副本（显示“正在载入录音…”），得到 Blob URL 交给 `<audio>`；关闭对话框时暂停并 `revokeObjectURL`。
* 播放条：播放 / 暂停、当前时间 / 总时长、拖动条、速度（0.75 / 1 / 1.25 / 1.5）。点句播放 = 设 `currentTime` 后播放。
* 对话框内键盘：焦点不在文本框时，空格播放 / 暂停（`useHotkeys`，只在对话框打开期间注册）。

### 3.4 侧栏

1. **参会人名单**：标签输入（回车添加，2～40 字，最多 30 个，可删），每次改动调用 `participants(names)`；说明“名单中的名字会在整份逐字稿中替换为代号，并用于同音纠正”。
2. **发言人**：每个发言人一行“发言人 N → 输入框”，可从名单中选或直接输入，清空即恢复“发言人 N”；失焦或回车保存（`speakers(map)`）。
3. **同音纠正建议**：`suggestions()` 列表，每条“{from} → {to} · {时间}”，点击条目定位到该句并闪烁；“采纳”逐条、“全部采纳”一次（`applySuggestions`）；采纳后刷新建议与逐字稿。空时“没有同音纠正建议”。
4. **逐字稿 Word**（确认前后都可，`saveBlob`）。
5. **去确认脱敏**（确认前）：关闭本对话框并打开该会话的确认脱敏对话框（`ConfirmWorkbench mode="assistant"`）。

* 每次修改后会话进入重算（任务锁），期间对话框顶部灵动岛“正在重新计算…”，修改操作禁用、播放与浏览不受影响；轮询会话详情直到空闲后重读节点与建议（同 U2 3.4 的 busy 处理）。
* 已确认（`confirmed_at` 非空）时整个对话框只读：不显示编辑、名单与发言人只读、无建议节、无“去确认脱敏”。

### 3.5 画布中的逐字稿排版（`ConfirmCanvas`）

确认脱敏工作台的画布遇到 `kind=utterance` 的节点：每句上方一行小字——原文视图为“{发言人真名或发言人 N} · {hh:mm:ss}”，AI 视野为“{speaker_code} · {hh:mm:ss}”（`speaker_code` 改过名时以代号胶囊显示）；正文照常显示胶囊。超过 800 句时同样只显示有替换或不确定项的句子。结果页不涉及（录音只在助手中）。

## 五、设置新增（V31-U4-05，Sonnet，high）

### 5.1 脱敏（`views/settings/Redaction.vue`，业务管理员）

节顺序：识别与替换 · 我方主体 · 自定义敏感词 · 已记住的名称 · 术语记忆 · 脱敏操作统计。

1. **识别与替换**（三个开关一节，`PUT /admin/settings/redaction`，修改即保存并提示“已保存”）：
   * 数量脱敏（现有）；
   * 日期整体平移（`date_shift`，默认开）：说明“发给模型的日期整体平移同一天数，回来后在本机换回；只影响之后重新计算的任务”；
   * 向量辅助判断（`vector_assist`，默认开）：说明“用本机向量模型判断不确定项是否为普通术语，判断为普通术语的默认保留原文”。

## 十、风险

| 风险 | 应对 |
|-|-|
| 500 MB 上传期间用户以为卡住 | XHR 上传进度；上传完成后立即显示“正在本机解码” |
| 3 小时逐字稿渲染与播放跟随卡顿 | `content-visibility: auto`；只在当前句变化时更新；跟随可关 |
| 回放副本整文件取回占浏览器内存（约 3 小时 30～60 MB） | 第一次播放才取；关闭对话框即释放 |
| 校对与重算交错，界面显示旧数据 | busy 期间禁用修改，空闲后整体重读（同 U2 的 busy 处理） |
| Markdown 回复按文字匹配标出，同一文字在别处正常出现也被标 | 标记文字都是代号写法或系统标记，正常文字中极少重复；只影响显示，不改内容 |
| 登录页漂浮文字在远程桌面上耗资源 | 只在完整特效绘制；自动档在软件渲染下为精简（U1） |
| 全站评审发现的问题过多拖延 V31-Z | 只直接修小问题；交互问题经用户决定，不在评审中扩大范围 |
