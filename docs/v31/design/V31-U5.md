## 二、智能助手自由对话（V31-U5-02，Opus）

示意图已在 2026-11-04 评审中给出。只改前端；用到的后端变化见第三节，02 先按现有接口实现，05 完成后自然生效。

### 2.1 首页（`/assistant`，没有选中会话）

* 不再显示“开始一个新会话 / 新建会话”按钮。主区域垂直居中：一行“今天要处理什么？”，下为输入框（最大宽 760px）。
* 输入框：多行文本（Enter 发送、Shift+Enter 换行、输入法组字不处理）；左下 📎（加入文件或录音）、🎙（录音，见第四节，asr 启用时显示）、模型下拉；右下发送。整页可拖入文件，拖入时输入框高亮“松开即加入”。
* 输入框下一排模板快捷标签：翻译、摘要、起草回复、单证核对、比价、会议纪要（asr 未启用时置灰，悬停写原因）。
* **会话在第一次动作时才建**：发送、加入文件或点模板时调用 `create`，地址换成 `/assistant/{id}`，不刷新页面、不丢输入内容。侧栏“新建会话”回到此首页，不调用接口（不再产生空会话）。

### 2.2 对话页

* 单栏，对话内容最大宽 760px 居中；去掉常驻的 320px 文件面板。标题栏：会话名（可改名）、右侧“文件 {n}”按钮与“⋯”（删除会话）。
* **附件在输入框里**：输入框上方一行附件标签，每个文件一个（图标、文件名、状态）：解析中（扫描光条）/ 待确认 / 已确认 / 解码中 / 排队 / 转写 {百分比} / 转写完成·请校对 / 失败（悬停原因，点“重试”）。点“待确认”或“请校对”的标签直接打开确认脱敏或逐字稿校对。未确认的标签可移除（×）。
* **“文件 {n}”抽屉**（右侧 400px）：全部文件（同上状态与操作，另有“逐字稿 Word”）、本地校验卡片与“查看”、会话设置（立场、代号数）、“查看外发文本”。原 FilePanel 的内容迁入，不再常驻。
* **一步发送**：点发送时依次：① 有正在解析 / 转写的文件且问题需要它（用户在模板中选了它）→ 提示“{文件名} 还在处理，完成后自动发送”，处理完自动继续；② 有待确认的文件 → 自动打开确认脱敏（或逐字稿校对），确认后自动继续；③ 调用预览，**消息里没有疑似敏感信息时直接发送**，有疑似项时才弹“确认发送内容”让用户逐项决定。每条已发送的用户消息下有“查看实际发送内容”（只读）。
* **模板在输入框里**：点快捷标签后输入框内出现一个模板标签，如“翻译 → 英文 ▾ ×”“摘要 · 侧重点 ▾”，参数就地选，× 取消模板；文件默认选当前会话中符合条件的全部已确认文件，标签后“使用 2 个文件 ▾”可改。缺文件时自动打开选择框（会议纪要只收录音）。
* 翻译模板标明去向：本地翻译可用时（第五节）默认“本地 · 不外发”，可切“云端 · 脱敏后发送”；不可用时只写“云端 · 脱敏后发送”。
* 回复、标出、本机计算卡片、导出、停止、重试保持现状（U4 已做）。

### 2.3 推翻的旧规定

SPEC 13A 第 1 条“新加入的文件解析后须由用户确认脱敏才能用于对话”的界面形式（右栏按钮）→ 改为发送时自动引导，确认本身保留；13A 第 2 条“输入框 Enter 打开发送确认”→ 只在有疑似项时确认；frontend.md 2.2“智能助手页为对话区 + 文件面板（320px）两栏”→ 单栏加抽屉；“新建会话”先建空会话 → 第一次动作时才建。

## 二A、会议纪要与翻译改为独立菜单（2026-11-04 用户确认，V31Q-98，取代第二节中的翻译 / 纪要模板与第四节的放置）

* **会议纪要**（`/meeting`、`/meeting/:id`，`views/Meeting.vue`）：首页为拖入区、“现场录音”（`components/meeting/MeetingRecorder.vue`，16 kHz 单声道 PCM 只在内存，停止后生成 WAV 上传；3 小时上限；离开页面提示）与最近的会议；单个会议页：转写进度（MediaRow）→ 校对铺满页面（TranscriptEditor）→ 确认脱敏 → 选模型“生成会议纪要”（只发脱敏后的逐字稿）→ 逐字稿 / 会议纪要切换，纪要可导出 Word、可到智能助手就这场会议继续提问。

## 三、后端：解析 / 转写期间照常对话（V31-U5-05，GPT-6.1 Sol）

* `assistant/service.availability`：`parsing`、`awaiting_confirm` 不再阻止发送；只要会话中有至少一个已确认文件或用户不带文件提问即可发送。外发仍只取已确认文件（`assistant/prompt.py` 现状），模板参数中的文件必须已确认，否则 422 `FILE_NOT_CONFIRMED`“{文件名} 尚未确认脱敏”。
* `add_files`：`parsing`、`awaiting_confirm` 时也可再加文件（合计 ≤ 10 不变）；生成中仍不可。
* 发送、加文件与解析 worker 都在任务行锁内串行；补一个用例：会话有已确认文件 A 时加入 B，B 解析期间提问，外发文本只含 A，且 A 的代号在 B 解析前后不变。
* 任务原因文字：录音转写中写“录音正在本机转写”。不改迁移。
* 走查 P13：英文星期、月份等常用词（MONDAY、JANUARY 等，大小写不限）进入本地不敏感词表，不再列为不确定的专有名词；用 golden 样本加一例。
* 测试：`tests/test_assistant_*.py` 相关文件、golden / A-03 / 回程样本。

推翻的旧规定：SPEC 第 7 节与 13A 中“会话解析中不能提问、不能加文件”（V31Q-89 原建议“首版保持现状”作废）。

## 四、浏览器内录音（V31-U5-03，Opus）

* 输入框 🎙（asr 启用、浏览器支持 `MediaRecorder` 且为 HTTPS 时显示）：点一下开始，输入框变为录音条（红点、已录时长、电平条、“暂停 / 继续”“停止并加入”“放弃”）；≤ 3 小时、≤ 500 MB，到限自动停止并加入。

## 五、本地翻译（V31Q-48、V31Q-93）

### 5.1 候选、实测与选型（V31-U5-04，GPT-6.1 Sol；用户 2026-11-04 改派）

按 [local-models.md](local-models.md) 第七节：

1. 候选：Hy-MT2-7B Q8_0（V31Q-48 首选）、Hy-MT2-1.8B Q8_0、7B Q6_K；推理用 llama.cpp（MIT）CPU 版，镜像不装 torch、transformers。
2. 下载前列出文件、来源、大小，经用户同意。
3. 测试虚拟机隔离实测（经用户同意）：三档模型 × 4 / 6 / 8 线程，万字中译英耗时与内存；**翻译运行时**万字脱敏 ≤ 15 秒、追问 500 字 ≤ 3 秒（SPEC 第 3 节门槛）；虚构样本中英、中日各 3 份的人工质量抽查（与当前云端模型对照）。
4. 选型报告 `docs/v31/reports/V31-U5-04.md`（写短）→ 用户确认。

### 5.2 实现（V31-U5-06，GPT-6.1 Sol，选型确认后）

* `translator` 容器：不接网络，只经 /spool 与 worker 交换（同 transcriber）；compose profile `mt`；固定 vCPU 与线程从 .env 读；同一时间只翻一个文件，按段翻译，有解析 / 脱敏 / 追问任务时在段落边界让路。
* 助手翻译模板参数加 `engine: 'local' | 'cloud'`：local 时**不要求文件确认脱敏**（文件解析完成即可），不经网关、不记 llm_calls，原文段落只进 translator；结果按现有助手消息存储（加密方式同现状），译文导出 Word（译文 / 双语对照）沿用。界面标明“本地 · 不外发”。
* 会话 `mt_enabled`（同 `asr_enabled` 的判断方式），系统状态“本地模型”表多一行。
* 测试：断网冒烟一条、一个代表性用例（local 不产生 llm_calls、不调用网关）；不写穷举。

## 十一、风险

| 风险 | 应对 |
|-|-|
| 一步发送时用户没看清确认脱敏就点确认 | 确认工作台照旧（不确定项须逐项处理才能确认）；自动打开只省“找按钮”，不省“确认”本身 |
