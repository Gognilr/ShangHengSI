# V35-D 多稿对比与增量复审：设计

状态：**已确认**（V35-D-01，2026-11-21 Opus 起草；用户 2026-11-21 按此开工 D-02）。D-02、D-03 照此实现；实现中的细节见 open_questions V35Q-28。

## 一、要解决的事

合同来回改。对方改回第二稿、第三稿时，用户要知道三件事：

1. **对方改了哪里**，包括没开修订模式偷偷改的地方（暗改）；
2. **上次提的问题改了没有**；
3. **新改的地方有没有新问题**。

现在的做法是把二稿当新文件加进会话，再全文审一遍。问题有三个：默认会把一稿、二稿一起发出去；一稿上的结论和二稿对不上；模型又从头审一遍没改过的条款。

本设计：同一会话内认出“新一稿”→ 本机确定性对比 → 只把变化和上轮没解决的问题交给模型 → 结果和上轮合在一起，每条标上“本轮新增 / 仍存在 / 已解决”。

**范围**：只做工作台会话里的文件审核（purpose=chat）。旧审核任务（/review/{id}）、标书、会议、翻译不做。不新增侧栏菜单。

## 二、稿次关系

**一个会话里，同一份文件的各稿连成一条链**：一稿 → 二稿 → 三稿。每个文件最多有一个“上一稿”，也最多有一个“下一稿”。

* 数据：`task_files.prev_file_id`（可空，指向同一会话里的上一稿）。“第几稿”按链现算，不存。
* **怎么认出来**（新文件解析完后，worker 在本机算）：
  * 新文件和会话里某条链的最新一稿比，正文段落相同或高度相似（逐段相似度 ≥ 0.6）的段落占新文件的一半以上，就**自动认作那一稿的下一稿**；有多个候选时取最像的。
  * 文件行上写“第 2 稿 · 对照《采购合同》第 1 稿”，下拉可改为“作为独立文件”或改对照哪一稿。改了只影响对比与审核范围，不改脱敏结果。
* **主动入口**：结果页“导出”旁加“传新一稿”（文件选择），文件审核首页“最近的审核”每行的“⋯”里也有“传新一稿”（打开该会话并选文件）。这样传进来的直接认作当前主文件的下一稿，不靠相似度判断。
* **跨会话**：用户若在文件审核首页新开了一个会话放二稿，系统不搬文件（两个会话的代号不同，搬过去要重新脱敏）。新会话解析完后，如果文件名去掉“第二稿 / v2 / 修改版 / 日期 / (1)”等字样后，和本人近 30 天某个会话的主文件名相同，结果页顶部提示一行：“这像是《采购合同》的新一稿。要和上一稿对比，请在那次审核里传入 · 打开那次审核”。只比文件名，不读别的会话内容。
* **发起审核时的默认文件**：每条链只勾选最新一稿，加上不属于任何链的附件。现在“默认全部已确认文件”会把一稿、二稿一起发，这一点必须改。
* 上一稿不能单独移除（被轮次引用时本来就不能移除，FILE_IN_USE）；下一稿可以移除，移除后链自动断开。

## 三、本机对比（D-02）

### 3.1 算法

纯函数 `app/review/drafts.py`，输入两稿的正文节点（part=body，含表格单元格），输出变化列表。全在本机、确定性、不调模型。

1. **对齐键**：节点原文做 NFKC、去空白、统一全半角标点，去掉段首的手写编号（“第八条”“8.3”）。自动编号本来就不在正文里（clause_no），所以中间插一条、后面编号顺延，不会算成变化。
2. **段落对齐**：两稿的键序列用 `difflib.SequenceMatcher(autojunk=False)` 对齐，得到相同 / 增 / 删 / 替换块。
3. **替换块内配对**：块内新旧段落按顺序贪心配对，相似度 ≥ 0.5 的算“修改”，配不上的算“删除”或“新增”。删掉的一段和新增的一段文字完全相同时算“位置调整”。
4. **字级差异**：每对“修改”的段落再按字对齐，得到插入、删除片段；相邻碎片间隔 ≤ 2 字时并成一段，免得满屏碎点。
5. **只改了标点、空格或编号**的修改，标为“格式变化”，默认收起，可展开。

每条变化带：类型（新增 / 删除 / 修改 / 位置调整 / 格式变化）、两稿的位置编号、所属条款（用现有“主合同 第8条”的写法）、字级片段、是否留痕（3.2）。

**不进对比**：页眉页脚、批注、文本框（与审核口径一致，变化面板底部写明）。扫描件、图片的识字结果也能对比，但变化面板顶部写“扫描件识字可能有误差，单字差异请对照原件”。

### 3.2 暗改：改了却没留修订痕迹

现在 Word 解析按“接受全部修订”取文字，只在节点上记了一个“有修订”标记。只靠这个标记，同一段里留痕改一个字、又悄悄改另一个字时会漏掉，而这种最阴险。

做法：解析 Word 时同一遍顺带算出每个有修订的段落在“**拒绝全部修订**”下的文字（w:del、w:moveFrom 计入，w:ins、w:moveTo 不计入），加密存入新列 `doc_nodes.text_before_enc`（只有带修订的节点才有值）。于是：

* **对方留了痕的改动** = 本稿“拒绝修订”文字 → “接受修订”文字；
* **暗改** = 上一稿文字 → 本稿“拒绝修订”文字。两者不一致的地方，就是对方没开修订悄悄改的。

每条变化标“已留修订痕迹”或“**未留痕**”（警示色），一处变化里两种都有时分开标。对方整份关了修订模式时，所有变化都是“未留痕”。PDF、扫描件没有修订概念，不标。

`text_before_enc` 与 `text_enc` 一起按保留期清理。旧版本解析的文件没有这一列的值时，按节点标记退回判断，并在面板写“本稿解析较早，只能按段落判断是否留痕”。

### 3.3 不存对比结果，打开时现算

计划原写“对比结果加密存储”。改为**不存，每次打开现算**，理由：

* 一份 300 段的合同两稿对齐加字级差异在毫秒到百毫秒级（D-02 实测），现算没有体验代价；
* 存下来就是又一份原文副本，要加表、加密、跟着保留期清理，还要在用户改稿次关系、重新解析时作废；
* 原件层按保留期清理后两稿原文都没了，存或不存都看不了对比，结果一样。

审核需要的是“哪些位置变了”，这只是一串位置编号，发起增量复审时写进轮次（第四节），不含原文。

### 3.4 对比视图

不加页面，放在结果页（全面审核视图）里：

* **纸面**：上方“原文 / 模型将看到的”分段开关后面加第三项“**对比上一稿**”，只有当前文件有上一稿时出现。对比模式下纸面显示本稿：新增文字加浅底下划线，删除文字原地显示为删除线浅灰，整段删除的显示成一块删除线段落并标“（本稿已删除）”，修改过的段落左侧一条竖线；未留痕的改动用警示色竖线和“未留痕”小标。画布右缘的光谱条标出变化位置。颜色只用澄明令牌（新增用主色浅底、删除用次要文字色、未留痕用警示色），不写死十六进制。
* **右栏**：页签“意见 / 追问”之间加“**变化 n**”（有上一稿时才有）。顶部一行摘要“对照第 1 稿：改 12 处 · 新增 2 条 · 删除 1 条 · **未留痕 5 处**”，下面分段筛选“全部 / 未留痕 / 新增 / 删除 / 修改”，“格式变化 n 处”折叠在最后。每条一行：类型、所属条款、一句摘录（“违约金 0.5% → **1%**”），点击时纸面切到对比模式并定位闪烁。
* **还没审就能看**：二稿解析完、确认脱敏之前，确认页文件一节就显示同样的摘要和“查看对比”，打开同一个对比视图（只读）。对比只用本机原文，不需要先确认脱敏，也不外发。

### 3.5 导出

只给意见，不改原件：

* **批注版**加一个勾选项“同时标出与上一稿的变化（n 处，未留痕 m 处）”，默认勾上。每处变化一条批注，作者“商衡SI”：`【对方改动 · 未留痕】原文：……　本稿：……`。删除的段落挂在后一段开头。定位与逐字校验沿用 14.1，文档文字一字不改。
* **变化对照表**（Word，内存生成）：变化页签右上角“导出对照表”，四列“位置 ｜ 上一稿 ｜ 本稿 ｜ 是否留痕”，未留痕的行加粗。PDF、扫描件的稿子也能导出。
* **审核报告**：增量复审的轮次在结论摘要后加一节“与上一稿的变化”（计数和未留痕清单），问题清单表加一列“本轮状态”。

## 四、增量复审（D-03）

### 4.1 什么时候能用

结果页传入新一稿、确认脱敏后，设置页的“审核范围”有两个选项：

* **只审变化**（满足下列条件时默认选它）：“变化的 9 条条款 + 上轮未解决的 6 个问题，约发送 3,400 字”；
* **全文重审**：“约发送 21,000 字”。

字数来自外发预览（`GET …/outbound` 加 `scope=delta`），不是估算。

“只审变化”需要三个条件：上一稿有一轮已完成或部分完成的审核（作为**基准轮**）；两稿有变化；变化的正文不超过本稿的 60%。超过 60% 时仍可选，但默认改为全文重审，并说明“改动较多，建议全文重审”。两稿正文完全相同时写“与第 1 稿正文一致，无需重审”，两个选项都可点。

基准轮 = 上一稿作主文件的最新一轮（completed 或 partial）。三稿的基准是二稿那一轮，二稿那一轮本身可能就是增量轮——它带着全部未解决的问题（4.3），所以可以一稿接一稿地往下走。

### 4.2 发什么

先在本机把基准轮的问题分成三类，**能确定的不问模型**：

| 上轮问题 | 本机处理 | 发给模型？ |
|-|-|-|
| 已忽略 | 原样带到本轮（仍为已忽略）；所在条款被删时不再带 | 否 |
| 所在条款没有变化（不是缺失型） | 直接标“仍存在 · 条款未改动”，保留处理状态和备注 | 否 |
| 所在条款改了或删了；缺失型问题且本稿有新增或修改 | 交模型判断 | 是 |

外发文本（仍经脱敏、出口复检与网关，同一份对照表）：

```
【审核背景】……本轮为第 2 稿增量复审，只审下列变化与上轮问题
【审核要求】（全部要求，供 req_ids 引用）
【主体说明】……
【待审核文件 · 变化】
<document>
[F2-P23] 本稿该段全文
（上一稿此段：……）
[F2-P24] ……（本稿新增）
（上一稿第 8.3 条已删除：……）
</document>
【上轮问题】
P1 违约金比例偏高｜法律｜高｜[F2-P23]｜问题：……｜建议：……
……
【参考法条】（只按变化的条款检索）
【提醒】……
```

* 每处变化发**所在一级条款的全文**（沿用 `clauses.first_level`），给模型足够的上下文；上一稿的文字取上一稿节点的脱敏文本，与本稿共用代号。
* 上轮问题的位置按对比结果换算成本稿的位置编号；所在段落被删的写“原第 8.3 条（本稿已删除）”。
* **一次请求**，不按四个维度并发（发送量小，并发省不了时间却要 4 倍调用）；变化内容超过分段长度时按条款分段，规则同 11.5。
* system 提示词加增量复审一节（prompt_version 升一版）：只对变化内容提出新问题，不要把上轮问题换个说法再提一遍；对每个上轮问题判断 resolved（已解决）或 persists（仍存在），并用一句话说明依据。

输出在 11.3 的基础上去掉逐条要求结论，增加：

```json
{"doc_summary": "本稿变化概述",
 "prior": [{"id": "P1", "status": "resolved", "note": "已改为 0.1%，并设上限"}],
 "findings": [ … 只针对变化的新问题，locs 限本次发送的位置 … ],
 "sanctions": { … }}
```

校验：`prior` 里没发过的编号丢弃；漏判的记“仍存在（模型未判断）”；新问题与某个“仍存在”的旧问题位置相同、标题相似度 ≥ 0.8 时并为一条（沿用 11.4 第 7 条）。

### 4.3 结果怎么放

增量轮是一个普通轮次（第 n 轮），问题全部写进本轮的 findings，处理、讨论、导出照旧可用：

* **本轮新增**：模型新提的问题；
* **仍存在**：模型判断未解决的，加上本机判定“条款未改动”的；保留上轮的处理状态、备注与讨论稿；
* **已解决**：带模型的一句依据。不计入问题数、待处理数和历史记录的高风险数；批注版不挂；下一稿也不再往下带。

问题栏顶部摘要改为“本轮新增 3 · 仍存在 5 · 已解决 4”，可点击筛选；“已解决”一组默认折叠在最后。卡片标题前加状态小标，“仍存在 · 条款未改动”用次要文字色，与模型判断的区分开。

* **逐条结论**：增量轮不让模型重给全部要求的结论（那等于全文重审）。沿用基准轮的结论，有新增或仍存在问题的要求记为“有问题”；页签顶部写“增量复审沿用第 k 轮的逐条结论，只更新涉及变化的要求”。
* **制裁结论**：取基准轮与本轮的较高一级。
* **覆盖说明**：“增量复审：对照第 1 稿，审核了变化的 9 条条款与上轮 6 个问题；其余 31 条未改动的条款沿用第 1 轮结论，没有重新审核。”报告首页同样写。
* **轮次下拉**：“第 2 轮 · 第 2 稿 · 只审变化（对照第 1 轮）”。旧轮次照常可看。

## 五、数据与接口

一个迁移（0053），只加列：

| 表 | 列 | 说明 |
|-|-|-|
| task_files | prev_file_id uuid 可空 | 上一稿，外键 task_files，删除时置空；唯一（一稿只有一个下一稿） |
| doc_nodes | text_before_enc bytea 可空 | “拒绝全部修订”下的原文，只有带修订的节点有值，按保留期与 text_enc 一起清理 |
| review_runs | scope varchar(5)，默认 full | full / delta |
| review_runs | base_run_id uuid 可空 | 增量轮的基准轮 |
| findings | carry varchar(10) 可空 | 增量轮才有：new / persists / unchanged（条款未改动）/ resolved |
| findings | prev_finding_id uuid 可空 | 上轮对应的问题，删除时置空 |
| findings | carry_note text 可空 | 模型给的一句依据，代号形式 |

增量轮另把“本次发送的变化位置”与计数写进 coverage（只有位置编号与数字，不含原文）。

接口（全部校验 owner，非本人 404）：

* `PUT /assistant/sessions/{id}/files/{fid}/draft` `{prev_file_id | null}`：改稿次关系。审核进行中返回 409 SESSION_BUSY。
* `GET /assistant/sessions/{id}/diff?file_id=`：该文件与上一稿的变化列表（含原文，只给本人界面用，不写日志）。
* `GET /assistant/sessions/{id}/diff/export?file_id=`：变化对照表 Word。
* `POST …/runs` 加 `scope`（默认 full）；delta 时基准轮由服务器按 4.1 确定，条件不满足返回 409 DELTA_UNAVAILABLE 并说明原因。`GET …/outbound` 加 `scope`。
* 批注版导出加 `include_changes`（默认 true）。

## 六、安全口径

* 对比只在本机做，用的是原文；返回界面的变化列表只给本人。日志只记会话编号、文件序号和变化计数。
* 增量复审发出去的仍只有脱敏文本：本稿与上一稿节点的 redacted_text、上轮问题的代号文本、检索到的公开法条；整包照常经出口复检与网关，计入调用上限。上一稿的脱敏文本用同一份对照表，代号不变。
* 不发原件、不发修订记录本身，模型不接收也不产出文件。

## 七、验收与评测

* **样本**（虚构，放 backend/tests/fixtures/drafts/）：一份合同三稿。二稿：开着修订改违约金与付款期限，另关掉修订悄悄改争议解决地、删一条保密期限、中间插入一条（后面的自动编号顺延）；三稿：改回一处、再暗改一处、另一段只改标点。
* **对比质量**：每处人为改动都标出、类型正确、“未留痕”判断正确；编号顺延与只改标点不算实质变化。
* **效率**：对比耗时（300 段合同）；增量复审与全文重审的请求数、输入 token、端到端用时对照（用模拟模型计数；真实模型调用前先告诉你次数，由你录入密钥）。
* **测试**：少量代表性用例——对齐与暗改各一组（纯函数），增量轮的问题分类与合并一组，接口 owner 校验沿用现有用例。不为界面与措辞写测试。

## 八、分工

* **D-02**：稿次关系（自动识别、改关系、默认勾选）、解析加 text_before_enc、对比算法、对比视图（纸面第三态、“变化”页签、确认页摘要）、批注版标出变化、变化对照表、跨会话文件名提示。截图交用户。
* **D-03**：审核范围选择与预览、增量外发与提示词、结果分类与合并、问题栏与轮次显示、逐条结论与覆盖说明、报告一节。调模型前问次数；脱敏外发部分由另一侧交叉复核。

## 九、与计划不同之处

1. 对比结果**不存，现算**（3.3），计划原写“加密存储”。
2. 增量复审**一次请求**，不按四个维度并发（4.2）。
3. 上轮问题**能本机判定的不发**：条款没动的直接记“仍存在”，已忽略的不发（4.2）。
4. 增量轮**不重给逐条结论**，沿用基准轮（4.3）。
5. 不支持把别的会话里的上一稿拉进来，只按文件名提示（第二节）。
