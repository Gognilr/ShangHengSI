## 二、界面设计原则

现有界面的通病有四个：
* 同一件事的进度在两三处重复出现；
* 进度和结果混在同一块；
* 所有内容都是等粗细的列表加细线，看不出主次；
* 对象（投标人、文件）没有“收起”的形态。

对应的原则：

1. **一个对象一张卡片**：投标人、招标文件组、一份合同都是卡片。卡片收起时只显示状态与计数，点开才显示明细。
2. **进度只在一处**：页面顶部一行，或卡片里的进度条。结果区不重复显示进度。
3. **进度与结论分开**：本机检查没完成时，结果区不出结论，只显示“检查中”。扫描页还在识别时，结论标“初步”，识别完成后自动更新。
4. **主从两栏**：左边是问题清单（按严重程度排列），右边是证据（原件页或原文片段）。点左边一条，右边立刻定位。
5. **只有严重的用颜色**：危险色只给严重问题，提示用次要墨色。只用一层卡片阴影，不用装饰性的图形。
6. **名称一律用“代号 + 字号”**，例如“A 甲泵业”。悬停显示全称。

草图已在会话中给出（结果页、材料区、合同审核页），视觉令牌按 docs/design/frontend.md，不新增颜色。

## 三、逐页设计

### 3.1 标书项目页

* 不再用四步条。页面分上下两区：
  * **材料区**：上方一张招标文件卡片，收起时写“n 份 · 已解析 · 抽取 ★ 与否决条款 m 条”；下方是投标人卡片网格，每张卡片显示代号与字号、文件数与页数、进度条、状态（解析中 / 扫描页识别 x/y / 已就绪），结果出来后再加“严重 n”。点卡片打开右侧抽屉，抽屉里是文件明细、密码、加文件、改名。拖入文件夹建卡的规则不变（问题 1、4）。
  * **结果区**：只在“开始检查”之后出现。
* 要求清单在招标文件抽屉里查看和增删。只抽取 ★、否决、“必须 / 不得”类条款。第五十一条各项属于系统自己的检查，**不再作为“要求”列出**；技术参数不当作要求（问题 7）。

### 3.2 标书结果区（取代五个页签）

* **顶部**：投标人汇总条，四张小卡，内容是严重数、提示数、唱标价。有严重问题的卡片用危险色描边。点卡片相当于按该家筛选。
* **左栏**：问题清单。先“严重问题”，再“提示 n 条”（默认折叠）。每行一句话加一行出处（类别 · 文件 · 页）。只有“不是问题”一个操作，点了从清单和导出中移除，可撤销。
* **右栏**：证据。
  * 单家的问题：显示原件页图并高亮命中处。
  * 两家之间的线索：**左右并排显示两家的原件页或段落**，相同部分高亮，可以逐处翻看（问题 5、9）。
* **相似段落**：
  * 同一对投标人合成一条，例如“C 与 D：自写内容相同 9 处，约 1,600 字”；
  * 同一段文字在同一家的多份文件里重复时，合并为一处，并列出所有位置；
  * 审计报告、执照、专利、标准等公共来源的段落一律不报；
  * 招标项目名称、招标人名称及其变体（含“1 万吨 / 年……单元”这类项目自身的称呼）在比对前剔除（问题 2、10）。
* **报价**：唱标价与报价表总价并列放在汇总卡上。
  * 同一家“多个不同总价”要先判断是否属于同一报价范围（例如分标段、分装置）。范围不同时不报（问题 11）。
  * 异常低价降为提示。
* **导出**：一份“问题清单”Word 文件，按投标人分节，每条写问题、依据（招标文件出处）、位置（文件 · 页），不写结论性措辞。

### 3.3 合同审核页（问题 16）

* 顶部一行是文件名，右侧是进度：已脱敏 n 处 → 出口复检 → 模型审核（已出 k 条）→ 还原。去掉大幅的管线图和底部重复的四步。
* 主体两栏：左边原文（问题处高亮），右边问题卡片，逐条流式出现。
  * 卡片写标题、等级、位置、说明、建议条文，建议条文带“复制”按钮。
  * 点卡片，原文滚动到对应位置。
* 导出：审核报告、批注版。

### 3.4 脱敏确认（问题 13、15）

* 任何一个标出项都能点开，菜单里有：改类别、只取消这一处、取消全部同名、扩大或缩小范围。
* 重叠的标出项**各自独立**：取消里层不受外层影响。选区与已有项重叠时，按“合并成一个新项”处理，不再报“所选位置不正确”。
* 签约方卡片里的名称和简称都能改、能删。改动后简称同步登记为同一代号的变体。
* 出口复检拦截时，每一处都给出一键处理（替换为代号 / 加入脱敏），处理后可以直接重发。不允许出现“拦截了却改不了”的死路。

### 3.5 工作台（问题 12）

* “文件处理完成后自动发送 · 取消”放在输入框内、文件标签下方，不再浮在页面左下角。
