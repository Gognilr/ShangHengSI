# V35-C-04 报价形态

`bid/pricing.py`、`compliance.py` 与 `checks.py` 按固定总价、费率或下浮率分别识别与核对报价。费率核对上限，下浮率核对下限。配套税价使用 Decimal 复算，差异附原文证据。主辅机分列且共用数量时合并单价复算。适用边界见 [V35Q-16](../open_questions.md#v35q-16-百分比限值与配套税价口径v35-c-04)。

`requirements.py`、`schemas.py`、`service.py` 和前端关键参数组件接通预填、编辑和回显。初审结论、报价位置条、报价明细与 `export/bid_docx.py` 共用检查结果。百分比项目从文件识别，手工唱标价用于固定总价。

* Docker + pgvector 运行报价、要求清单、初审结论、Word 导出和前端样式专项测试，`35 passed, 1 warning in 54.33s`。虚构 DOCX 覆盖下浮率低于及等于限值、三家下浮率比较与等差、配套税价、换算错误、主辅机分列、报价接口及 Word 内容。另核对费率等于及高于上限、排除税率及金额、精度和参数校验。警告来自 Starlette 测试客户端。
* 两组公开材料在本机只读回放 7 家、61,498 个节点。总价候选、报价规律和分项算术结果均无变化，保留原有 3 家分范围报价。报价分析用时中位数分别为 520.90 → 493.09 ms、8.99 → 9.06 ms。两组均为固定总价，未命中配套税价，正向验收使用虚构样本。
* 前端构建通过。Chromium 使用虚构响应核对预填、422、保存、刷新、Tab、空结果、费率分布和税价明细。浅色及夜幕、完整及精简、5 个视口共 60 个组合，无横向溢出或脚本异常。1366×768 双主题截图留会话。Word 通过导出内容核对，分页目视留待 V35-Z。
* 十条已自查。① 结论在先，② 无问题项用对勾，③ 沿用三层，④ 沿用令牌，⑤ 导出仍为主按钮，⑥ 数值由后端给出，⑦ 出处与核对项可见，⑧ 沿用原页签及位置条，⑨ 固定总价沿用现行文案，百分比使用相应报价及限值名称，⑩ 沿用版心并验证双主题和 1024 宽度。税价计算附在原报价明细末尾。
