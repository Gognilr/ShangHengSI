## 两组公开标书前后对照

用户放行后，在本机开发库上用只读回放（最后回滚），基线为 `639b6a4`，脚本只输出计数。两组样本各 4 家，共 102,663 个节点。

| 项 | 小样本（旧 → 新） | 大样本（旧 → 新） |
|-|-|-|
| 多个总价 | 提示 3 → 0（范围不同，不报） | 提示 3 → 0 |
| 证书过期（严重） | 5 → 0 | 7 → 1 |
| 证书过期（提示） | 0 → 1 | 0 → 1 |
| 相似段落（对数，按强 / 中 / 弱） | 2 / 1 / 3 → 0 / 6 / 0 | 2 / 1 / 3 → 0 / 4 / 2 |
| 相似段落示例行 | 72 → 44 | 72 → 50 |
| 报价、相似两步用时 | 1,771 / 747 → 1,817 / 678 ms | 1,507 / 803 → 1,576 / 776 ms |

* **证书**：原来报的 12 条严重，大多是同类另有有效证书的历史证书（主要是营业执照、认证）。现在剩下的 1 条，是一家投标人的资质证书 2017 年就过期了，而且同类证书里没有有效的。另有 2 条认不出类别，降为提示。
* **简称**：13 家中有 7 家的简称变了，都是 2～4 字。
* **回退已修**：对照中发现，一家投标人的“多个总价”被判成了严重。原因是页标题中的“备件”等词把两页判成同一范围。改为附加范围词只看总价自身的标签，页标题仍按原口径；修后 6 家都判为不同范围。
* **未覆盖**：OCR 修正（签名、水印、地址）需要重新解析才生效，没有参与回放。

## 其他说明

* “受人”这类子串由实体识别模型给出，golden 的模拟识别会绕过过滤，所以没写成 golden。真实模型在样本上没有产出这一项，过滤逻辑只经代码路径覆盖。
* OCR 修正只对新解析的文件生效。
