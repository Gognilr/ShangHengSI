# V35-B-03 表格列头语义向下传播

## 改动

* `redaction/tables.py` 为 DOCX、PDF 和 XLSX 的表格识别姓名、证件号、客户或业主单位、开户行、电话等列头。同列向下继承到下一处已识别的表头，紧邻左格的显式标签优先。合计、空值和普通数字格沿用原有处理。
* `redaction/engine.py` 复用冒号标签和原文偏移处理。2～4 字的名称候选须覆盖整格且实体类别与列头相同，达到原有中置信阈值才升为确定项。
* 新增虚构人员花名册、社保缴纳证明、历史业绩表各一份 golden，覆盖生僻两字姓名、校验失败的证件号、单位简称、银行、空值、合计、表头重置及独立工作表。A-03 生成测试文件时，保留带 PDF 页码的表格网格。

## 实测

| 项目 | 结果 |
| --- | --- |
| 三份新增 golden，共 64 个节点 | 受控实体识别条件下，正确类别命中从 3／8 提升到 8／8 |
| 117 份原有 golden | 模拟空实体结果时，逐份对比替换项、不确定项、对照表与外发文本，差异 0 |
| 本机 CPU 实体识别 | 同一虚构业主简称命中机构类别，分数 0.432，改前为名称不确定项，改后为确定的机构。另一简称没有候选，两版均未识别 |
| 本机 Docker 效率 | 模拟实体识别，预热后 25 次，三份样本为一批，脱敏进程 CPU 时间中位数 15.73 → 14.26 毫秒 |

隔离快照使用本机 CPU 实体识别与临时 pgvector 测试库。golden、表格、引擎、标书、复检、标签、自检、人名共 8 个测试文件，实际输出 `1099 passed, 1 warning in 327.14s`。A-03 验收 140 份虚构样本的模拟外发记录与请求，整个测试文件实际输出 `4 passed, 1 warning in 696.00s`。两轮警告均来自 Starlette 测试客户端的弃用提示。
