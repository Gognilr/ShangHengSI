# V35-B-03 表格列头语义向下传播

## 改动

* `redaction/tables.py` 为 DOCX、PDF 和 XLSX 的表格识别姓名、证件号、客户或业主单位、开户行、电话等列头。同列向下继承到下一处已识别的表头，紧邻左格的显式标签优先。合计、空值和普通数字格沿用原有处理。
* `redaction/engine.py` 复用冒号标签和原文偏移处理。2～4 字的名称候选须覆盖整格且实体类别与列头相同，达到原有中置信阈值才升为确定项。
* 新增虚构人员花名册、社保缴纳证明、历史业绩表各一份 golden，覆盖生僻两字姓名、校验失败的证件号、单位简称、银行、空值、合计、表头重置及独立工作表。A-03 生成测试文件时，保留带 PDF 页码的表格网格。

## 边界与交接

V35Q-10 记录列头判断与继承边界。没有重复表头的 PDF 续页、未选中表头的标书片段，仍缺少列头证据。待 Opus 交叉复核表头与横向填值的区分，以及中置信名称的原文区间。

**V35-Z 同步建议**　SPEC 9.3 第 4 步跨节点预登记与名称槽位证据增加本任务的表头识别、继承范围及名称升档条件。

## 交叉复核（Opus，2026-11-20）

* **横向填值误判为表头（已修）：**“业主单位 | 曜衡 | 联系人”这类行，若末尾的值格为空，原条件会判为混合表头，使“曜衡”失去左邻标签。现规定，列名与值交替出现的行不算混合表头。
* **左邻敏感标签不佐证中置信名称（已修）：**“姓名 | 郗珩”的中置信人名原先不升档，同样的姓名在“姓名”列下方则会升档。现按标签文字确定佐证类别，显式标签的查找范围仍不限类别。左邻是未被识别为标签的敏感列名时，以它作为补充槽位，但列头优先。
* 新增 golden `v35b03_fill_form` 覆盖上述两种情况。代价：两个敏感列名夹一个未知列名的三列表头（如“姓名 | 工号 | 电话”）会按横向填值处理。这类列不再获得列头佐证，与 B-03 之前相同。
* **原文区间：**`ner.mask` 与 `bilingual_label_text` 都保持长度不变，实体偏移直接对应原文。只有覆盖整格、未被其他命中占用的 2～4 个汉字名称才会升档，区间正确；含空格的名称（如“郗 珩”）不升档，偏保守，不处理。
