# V35-B-02 出口复检与片段闭合提速（已完成）

## 做法
| 项 | 结果 |
|-|-|
| 命中直接给原文区间 | `recheck._match_spans` 三条通路（原文、归一化、紧凑）都返回原文起止区间，后两条经 `index_map` 投影回原文；同一位置同类多值命中取最长的。`BlockReason.end` 从约数变为精确值 |
| 删去闭合二次扫描 | `bid/model._close_snippets` 直接用 `reason.end`，不再对每个命中用全部真实值和词条的正则重扫 |
| 中文词条字面查找 | 无空白、句点逗号、英文字母与数字的值（归一化后也没有）走 `str.find`，与原名称正则等价；其余值的编译正则按值缓存（保护项上千时 `re` 自带的 512 项缓存被挤掉） |
| 数字类值 | 逐段复检时数字类值一律参与比对，冷缓存剖析的热点在这里：文本中的数字串、字母数字串改为按文本切一次后缓存；长数字的紧凑命中只取对上的几位，不吞掉同一串里相邻的数字 |

没有采用联合正则：按值逐个 `str.find` 已经足够快，而且命中与原来逐值 `finditer` 的结果完全相同（同一值不重叠、各值独立）。

## 实测（本机，两组公开标书已导入的任务；同一时段先跑改前、再跑改后，事务内执行后回滚）
| 项 | 大样本（1,493 项保护，11 批） | 另一份（967 项，8 批） |
|-|-|-|
| 外发复检，全部批次合计 | 4.93 → **1.35 秒** | 3.04 → **0.76 秒** |
| 重备：段级复检（冷缓存） | 5.5 → 3.4 秒 | 3.9 → 2.2 秒 |
| 重备：片段闭合 | 1.3 → 0.6 秒 | 0.9 → 0.4 秒 |
| 重备合计 | 13.0 → 11.7 秒 | 8.1 → 6.0 秒 |

首次准备仍由实体识别主导（约 110～130 秒，机器负载不同时波动约 ±20 秒），本任务不涉及。worker 进程内段缓存是热的时，同进程第二次准备的闭合只要约 0.1 秒（剖析所见）。

**一致性：**
* 外发复检：每批消息分别用改前、改后两版检查，拦截的类别和位置全部相同（4 份有片段的任务，共 25 批）。
* 片段脱敏文字（复核修复后重测）：12 份无差异；3 份有差异，都来自通用脱敏闭环 `_closure_spans` 改用命中区间。改前按“起点 + 值长度”或“最先命中值的长度”替换，会把词条尾部留在外发文字中（机构名只换了前半段、词条尾部字母漏出、防爆标志与同文件其他位置写法不一），改后整段替换；另有一处只是代号类别名不同。保护项数不变。

## 复核修复（Codex 对 5e1fb39 的 P1、P2）
| 问题 | 修法 |
|-|-|
| P1 宽松命中被直接用来改写正文（`9123456780` 改成 `9[[TERM_1]]0`；`AB123` 跨片段拼接的换行把型号和数量一起换掉） | `BlockReason` 加 `exact`（不含真实值）。在首次匹配时判断：长数字前后紧挨数字、紧凑比对前后紧贴英文字母或数字或中间有换行，记为宽松。网关照常拦截；`_close_snippets` 与引擎闭环 `_closure_spans` 只替换 `exact` 的区间，不重扫。同位置优先取可确认的区间 |
| P2 归一化命中只覆盖原字符展开的一部分（`12M` 对 `12㎒`，`会社` 对 `㍿`） | `_back` 投影时检查起止是否落在同一原字符的展开内部，是则记为宽松，只交给出口复检；字面与正则通路都经过这里 |
| P2 紧凑比对每串只返回首处（`AB-123 A-B123 AB1-23 AB12-3` 三轮后仍剩一处） | 同一串内返回全部不重叠命中，各自判断边界；三轮上限不变。长数字紧凑通路同样改为返回全部命中 |

复核修复后在两组公开标书上重测：外发拦截的类别和位置与改前完全相同（25 批），单次复检 6.11 → 1.87 秒、3.13 → 0.80 秒（与上表同一量级）。B-02 首版中两处宽松命中自动替换后留下的“b”不再出现，回到改前的写法。
