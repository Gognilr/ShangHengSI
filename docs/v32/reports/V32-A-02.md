# V32-A-02 报告：会话发起审核（后端）

完成：2026-11-12（Opus）。取舍见 docs/v32/open_questions.md V32Q-01～07。

* **入口：** `POST /assistant/sessions/{id}/runs`（use.review；只接受 purpose=chat）与 `GET /assistant/sessions/{id}/runs`。请求：stance、source、model_id、user_note、file_ids（默认全部已确认文件，录音除外）、main_file_id、expected_material_version、use_template。与审核任务共用 `review/service._launch`（上限 → 预检出口复检 → 记住名称 → 建轮次 → 入队）。轮次写 file_ids（第一个为主文件）与 material_version。补充说明有变化时写入并按会话规则重算（代号只增）。
* **状态：** 会话的 task.status 不随轮次变化（job 的 _finish/_save 对 kind=assistant 跳过）。存在 queued/running 轮次即“审核进行中”：发送、加/移除文件、确认、改脱敏与我方均 409 SESSION_BUSY；回复生成中不能发起审核。SessionDetail 加 review_running。
* **外发：** `build_outbound(db, task, mode, file_ids, stance)` 按本次操作选择。审核模式对会话也给【主体说明】、报价汇总、本地校验说明、【本地财务比率】，只取所选文件；主体说明只列正文用到的代号，我方始终列出。正文里不插金额比例（V32Q-02）。`/outbound?mode=review` 供确认页查看。
* **解析附加步骤：** 会话文件解析（transcribe.finish、remove_file）改调 `pipeline.session_checks`：chat 会话跑 run_checks 并写条款向量，会议纪要、翻译仍只核验表格。历史条款检索计入会话里被轮次选用过的文件，排除本会话自身。
* **我方：** NeutralAllocator.our(key) 返回该主体的 ORG 代号；旧会话已有的 [[OUR]] 在 seed 时仍归原主体。主体说明写“[[ORG_1]]：我方，卖方”。leaks、standards/compare 按中性代号处理（范本中的我方名称按 ORG 续号）。工作台会话确认后仍可改我方（V32Q-06）。审核仍要求恰好一个我方。
* **日期：** 新建 chat 会话即按全局开关写 `@date_shift_days`（V32Q-03）；engine 对会话按该键识别并平移日期，日期对只增。提问沿用追问的平移；回复、提问显示按还原对还原，未配对的标出；流式暂扣含数字的尾部；译文日期整体移回（V32Q-04）。助手提示词在平移会话加平移说明（VERSION assistant-2026.11-6）。
* **保留期与权限：** 发起过审核、处于待确认的会话也归原件层、结果层；原件删除后 `_writable` 拒绝审核。新建工作台会话需 use.assistant 或 use.review；提问仍按 ensure_cloud_send。
* **范围外的小改动：** parsing/transcribe.py、checks/ratios.py、redaction/router.py、assistant/router.py、assistant/stream.py、assistant/schemas.py，均为接入上述行为所需。

测试：新增 test_session_review.py 三例（主线：先问答后审核同一代号、只确认一次、审核中发送 409、中性主体说明、问题定位与代号还原、本地算式；local_only 零外发；新旧会话日期平移）。golden、A-03、日期、助手、审核、保留期、范本、追问等 25 个相关文件 1240 项通过。按设计有意修改的旧测试：test_neutral_codes 两例（会话我方不再是 [[OUR]]，旧会话的 [[OUR]] 保留）、test_redaction_dates 一例（平移的会话也平移日期）；另修正 test_review_job::test_all_chunks_fail 的过期断言（V311-FIX-01 已改失败轮次说明，与本任务无关）。

**停点：** 交 Opus 新会话做安全复核（出口复检未放宽、代号只增、日期平移一致、权限）。
