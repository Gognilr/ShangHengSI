# V32-B-01 报告：工作台界面与侧栏

完成：2026-11-12（Sonnet）。取舍见 open_questions.md V32Q-08～10。

* **侧栏与路由：** “智能助手”→“工作台”（持有 use.assistant 或 use.review 任一即显示、可进入，homeFor 同步）；“智能审核”保留，指向 `/assistant?mode=review`，只在尚未进入具体会话的审核设置页高亮，点击不建会话；“审核历史”→“历史记录”。`/review/new` 无 task 参数时重定向到工作台审核设置，带 task 的旧未完成任务仍用 ReviewNew（V32Q-08）。会议纪要、翻译不变。全局搜索入口同步改名。
* **工作台：** 顶部标题、“材料 n”按钮、“直接提问 / 全面审核”切换（无 use.review 看不到）。切换只改视图（URL `mode`），不外发、不清空输入。首页的审核视图是拖入/选择/粘贴文件的投放区，第一次放入文件才建会话。
* **全面审核视图（新 components/workspace/ReviewPane.vue）：** 设置（参与审核的文件与主文件、立场、来源、模型、补充说明）→ 审核中（复用 ReviewCeremony，每 2 秒读轮次进度，会话详情由页面轮询）→ 结果（RunResult.vue：复用 ResultCanvas、FindingsRail、ExportButton、ReceiptStrip；轮次选择、“新一轮审核”）。主按钮“确认发送并开始审核”，确认区只列主体说明与补充说明字数（V32Q-10），已确认文件不再逐个核对。local_only 会话只显示本地校验。
* **新错误码：** 发送与发起审核都带 expected_material_version；MATERIAL_CHANGED → 重新取预览/外发内容后再确认；SESSION_BUSY 或 `review_running` → 输入框、加/移除文件锁定并显示“审核进行中”，页面轮询到结束后自动切到结果；FILE_IN_USE 沿用后端中文提示（“该文件已用于审核，不能移除；可在发送时不选它”）。
* **画布读取入口：** ResultCanvas 与 ConfirmCanvas、DocPreview 加 `nodeLoader` / `rawLoader` 属性，会话改读 `/assistant/sessions/{id}/files/{fid}/nodes|raw`。后端：`GET /tasks/{id}/redaction` 改用新依赖 `owned_readable_task`（审核任务，或本人的 purpose=chat 会话，任何状态只读放行；修改类接口限制不变，会议纪要、翻译仍 404）。
* **历史记录：** 新接口 `GET /assistant/sessions/history`（须在 `/{id}` 之前）一页合并本人的会话（purpose=chat，空会话不列）与旧审核任务，按最近活动倒序，行带 kind、last_activity_at、run_count、file_count，沿用文件名/标题搜索与日期筛选；行构造复用 `tasks.service.list_row`。会话点开回工作台（发起过审核的带 `?mode=review`），旧审核任务点开仍是 `/review/:id`。
* **权限：** 只有 use.review 的用户提问框禁用并说明原因（只能在审核问题上讨论，B-02 实现讨论）；不请求助手模型列表。

测试：新增 test_workspace_reads.py 一例（合并历史、会议纪要不在内、搜索、已确认会话的只读脱敏结果、修改类仍 409、别人 404）；tasks、redaction、assistant 会话、会话审核共 150 项通过。前端 `npm run build` 通过。
