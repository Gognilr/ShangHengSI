# V3.2 问题记录

编号 V32Q-01 起。每条写：问题、采用的做法、理由。

## V32Q-01 会话审核的主文件与附件（V32-A-02）

ReviewRun 不加列：会话轮次的 `file_ids` 第一个元素就是主文件，其余为附件。请求可带 `main_file_id`，不带时取会话的 is_main 文件（不在所选中时取第一个）。录音逐字稿不参与审核。

## V32Q-02 会话审核不在正文里插金额比例（V32-A-02）

审核任务的正文在金额后插“（=合同总价的 x%）”。会话的脱敏正文由问答、翻译与审核共用，插入比例会进入译文和问答，所以会话不插；审核外发照常带报价汇总与本地校验说明，【本地财务比率】按 review.send_ratios 设置。

**结案（V32-A-03）：** 对照评测中会话组不插正文比例，问题召回与日期关系类召回持平（均 1.000），结论一致率 0.991 对 1.000，在 ±1 个样本的波动内。维持会话不插。

## V32Q-03 日期平移在会话创建时决定（V32-A-02）

计划写“首次脱敏时决定”。会话可以先提问、后加文件，第一条提问就会写入对照表，所以改为新建工作台会话时按全局开关写入 `@date_shift_days`（关闭时写 0，之后不再开启）；`engine._run` 仍保留“对照表为空时决定”的兜底。旧会话对照表非空且没有该键，永不平移。

## V32Q-04 平移会话的译文日期整体移回（V32-A-02）

译文里的日期都来自原文，换了写法（中译英）无法按还原对匹配，标出也看不出原日期。翻译结果按平移天数把识别出的日期整体移回原值；问答回复仍只还原配对的日期、其余标出（模型可能写出真实世界日期，不能自动移回）。流式显示时暂扣含数字的尾部，避免半个日期先被识别。

## V32Q-05 会话审核进行中的互斥（V32-A-02）

轮次在后台按执行时的正文拼接外发，会话又不进入 reviewing 状态，所以审核排队或进行中时，发送消息、加/移除文件、确认、修改脱敏与我方一律 409 SESSION_BUSY（“审核进行中，完成后再发送”）；反过来，回复生成中不能发起审核。

## V32Q-06 会话确认文件后仍可改我方（V32-A-02）

会话不分配我方代号，改我方不改任何代号，只改主体说明的角色文字；审核又要求恰好一个我方。所以工作台会话在 active 状态也允许 GET/PUT /tasks/{id}/parties，其余脱敏修改仍只在待确认时允许。

## V32Q-07 local_only 会话发起审核（V32-A-02）

会话目前都以 policy=ai 创建。若为 local_only，发起审核返回 409 LOCAL_ONLY、零外发，本地校验结果照常从 /local-findings 查看（解析时已按审核任务的规则跑 run_checks）。

## V32Q-08 /review/new 只在没有 task 时重定向（V32-B-01）

计划写“旧路由 /review/new 重定向到工作台，带原 query 丢弃”。但带 `?task=` 的是**未完成的旧审核任务**（草稿、待确认、审核中），历史记录里的“继续”和结果页对未完成任务的跳转都走这里；一律重定向会让这些任务无法继续。所以只在没有 task 参数时重定向到 `/assistant?mode=review`，带 task 的仍用原 ReviewNew 页面接着做；这类任务做完（或删除）后不再有入口，ReviewNew 随“智能审核”快捷入口一并去留。

## V32Q-09 工作台默认视图（V32-B-01）

进入 `/assistant/:id` 且没有 `mode` 参数时默认“直接提问”；只有“智能审核”权限、没有“智能助手”权限的用户默认“全面审核”（提问框对他们禁用）。历史记录里发起过审核的会话带 `?mode=review` 打开。切换视图写入 URL 的 `mode`，刷新后保持。

## V32Q-10 确认页只显示主体说明与补充说明字数（V32-B-01）

“本轮发送的内容”取 `GET /outbound?mode=review` 的外发正文，只截【主体说明】一行，不展示全文；补充说明在发起审核时才写入并脱敏，发起前只能显示字数。点“确认发送并开始审核”即同意发送。预览带回的 material_version 作为 expected_material_version；409 MATERIAL_CHANGED 时重新取预览，请用户核对后再点。

## V32Q-11 讨论稿的采纳来源与提取标记（V32-B-03）

* **来源记录：** 计划要求“采纳记录所选来源”，A-01 只建了讨论稿三列，所以加迁移 0041：`findings.use_discussed`（布尔，默认 false）。只在有讨论稿时可设为真；保存讨论稿时默认设为真（用户刚核对过、通常就是要用它），问题卡上可改回“原审核建议”。原 `suggested_text` 永不改写；删除讨论稿（空文字）同时清除来源。
* **提取标记：** 讨论提示词要求把替换条文放在【修改条文】与【/修改条文】之间（assistant-2026.11-8）。界面从已还原的回复里取所有标记内文字（多段按行合并）给用户编辑；没有标记时提示让助手重新给出，或手工整理。
* **入库：** 用户核对后的是真实文字，服务器按提问同一套本地脱敏（对照表 + 识别规则 + 会话日期平移）转成代号文本存入，新代号只增写入对照表；未被识别的疑似项与提问相同，原样保留。讨论稿只在本地使用（显示、导出），不进入之后的外发上下文。
* **接口范围：** `PUT /findings/{fid}/draft` 只用于工作台会话（purpose=chat）的轮次，其他任务的问题返回 404；要求“智能审核”权限；原件层到期后返回 SESSION_READONLY；`message_id` 必须是该问题下的回复。
