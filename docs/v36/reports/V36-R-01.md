2026-11-27 · Claude Opus · 用户要求在 V36-Z 之前复核文件审核、合同、标书共用的脱敏与还原，并要求找出的问题本批修完

## 范围与方法

* **读代码**：脱敏引擎与代号分配、还原、出口复检、签约方与格式识别、模型网关、审核的分段 / 输出校验 / 保存 / 增量复审、追问，以及标书片段脱敏。
* **实测**：在测试镜像中挂上本机的实体识别模型（gliner FP32），跑三批虚构样本共 40 余条难写法，走完脱敏、外发、复检、模拟回程还原。难写法包括英文合同、全角号码、IBAN / BIC、中英文大写金额、表格金额列、项目名称、无标签地址。
* **借鉴同类做法**：可逆假名化的公开工程与论文，通行做法有三条：
  * 同一类别、同一值得到同一代号，对照表跨请求复用；
  * 还原按出现处计；
  * 模型自造的代号单列统计。

**复核后未发现问题的部分**：

* 网关的调用顺序：上限检查 → 出口复检 → 发送 → 记录，分段预检与流式发送同样如此；

* 还原能处理括号与下划线变体，对照表里没有的代号会标出，建议条文中模型自己写出的号码与金额会标出；
* 金额比例用 Decimal 与 ROUND_HALF_UP 计算；
* 标书片段的对照表只增、自检闭环；
* 分段与引用核验。

## 实测

* 新增用例与样本：
  * `test_v2b_manual.py::test_codes_stay_after_first_run`（R-01）：撤掉修复时失败，恢复后通过；

  * golden `v36r_numbered_codes`（R-02）：含编号代号的回程标注。
* R-02 带出的一处出口重扫误报：证照标签“许可证编号：”后面紧跟 [证件号_1] 时，代号里的序号被重扫当成了证照号。网关会传入代号清单，所以不拦；A-03 的独立重扫不传代号，所以报了出来。已改为取值整段是代号时不算证照号。
* 旧测试中 11 条断言共用代号写法（[电话]、[地址：中国] 等）的，按新写法改了期望值，属于有意改变的行为；另有 9 条复检用例因上一条误报失败，修正规则后原样通过。
* 前端 `npm run build` 退出码 0。回执文字与追问高亮的改动没有在浏览器里实走。
