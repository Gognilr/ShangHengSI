# V36-I-01 发票管家后端：收票、识别、Excel 清单

2026-11-27 · Claude Opus · 停点为本机样本实测

## 交付

* **新模块 `backend/app/invoice/`**（不引用 `app.llm`，不产生 llm_calls）：
  * `intake` 收票与嗅探：扩展名加文件头，压缩包只在内存中读（条目 ≤ 200、只取文件名、GBK 条目名还原、加密拒收、内层压缩包不打开），上限 100 个、单个 20 MB、合计 200 MB、图片 ≤ 100 页。
  * `structured` XML 与 OFD：lxml 安全设置；OFD 先找内嵌发票 XML，再按 CustomTag 取文字对象，读不出提示改传 PDF。
  * `layout` 按坐标套版式：文字段聚成视觉行再按锚点取值（同一行右侧或下一行），康熙部首归一；购买方、销售方按前缀或先上后下、先左后右；一页多票按号码标签与标题切开，切不开记入未识别。
  * `recognize` PDF 文字层（pdfplumber）、扫描页与照片（复用 `app/parsing/ocr`，照片先 EXIF 转正与透视矫正，只去鲜红印章色）；`qr` 用 opencv 解二维码，200 DPI 解不出再试 300 DPI。
  * `checks` 同号合并（结构化 > 文字层 > OCR）与四项核对，另加“未读到”；`excel` 两张表、文本号码、金额格式、合计行（红字按负数）、提示浅琥珀底。
  * `store` 内存盘：原件、文件名清单与结果用主密钥加密，关联数据带批次 id；识别完即删原件。`service`、`router`、`job`：四个接口（`/api/v1/invoice/batches`），jobs 一行只放批次 id 与 owner_id，每分钟清除到期批次与孤儿目录。
* **部署**：compose 新增 tmpfs 卷 `invoice_mem`（1 GiB，只挂 app 与 worker），环境变量 `INVOICE_MEM_DIR`；worker 解析组加 `invoice` 类型。迁移 0061 只给 jobs 的类型约束加 `invoice`。
* **虚构样本**：`tests/fixtures/invoice/make_invoice_fixtures.py` 生成数电专票 PDF（号码值先于标签写入内容流）、同票 XML、传统电子普票 OFD（前导零）、扫描 PNG、透视变形照片 JPG，票面带“虚构样本”水印。

## 实测

* `pytest tests/test_invoice.py`：**10 passed**（五种格式各一、四项核对、合并同票、Excel 格式、owner 404 与 use.export、清除与定时清除）。`test_migrations / test_jobs / test_config / test_scripts / test_log_safety / test_worker` 通过（test_worker 的分组断言按设计加 `invoice`）。
* **本机真实样本**（`D:\发票`，11 张数电票 PDF；只输出比率与耗时，内容未进仓库、对话与日志）。关键字段按二维码、金额勾稽与大写、税号校验位独立核验；扫描路径把同一 PDF 渲染成 200 DPI 图片整页 OCR，与文字层结果逐字段比对：

| 路径 | 字段命中 | 每张耗时（中位 / 最快 / 最慢） |
|-|-|-|
| 文字层（含二维码） | 132/132（12 个字段 × 11 张） | 0.12 s / 0.10 s / 0.47 s |
| 扫描路径（OCR + 二维码） | 99/99（9 个关键字段 × 11 张） | 1.72 s / 1.56 s / 3.25 s |

* 实测中修掉的两处：数电票版式标签本身是暗红色，原先的去红会把锚点抹掉（扫描路径 1/11 → 11/11）；有一种版式把合计金额排得略高于“合计”标签，改为也看上下紧邻行。
* 未测：真实照片（本机样本没有照片）、100 张一批的总耗时与基线配置，按计划在 I-02 评测。
