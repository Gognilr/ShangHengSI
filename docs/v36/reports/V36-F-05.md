## 复核修正（2026-11-27 · Claude Opus）

对照效果稿 preview.html 与规范 6.10、6.11、第二节，改了以下与稿不符处：
* **时间尺**：原为每天一个数字块。改为每个项目叠一格（最多 3 格，余下写 +n），有严重问题的格为红，已过的日期变淡；接口每天加 `severe` 计数，结论与列表行共用一次计算。行内副标题加“今天 / n 天后”，严重徽标加圆点。
* **开标桌**：卡片加纸面行线，严重与提示徽标都留在卡内；选中改为上浮 8px 加标书橙描边，其余卡变淡；1280 以上 5 列，桌面渐变底。
* **工具条**：从单独一张卡移到标题下的元信息行右端（同稿的工作区顶部）；完成徽标带本机检查用时；发起模型补查后接上紫段（规范第二节），列表行同样接 `model_state`；补查等你或失败时按钮带到补查卡。还没有材料的项目改为“未到”，不再显示琥珀“等你”。
* **结果区**：只有提示时，证据栏写“没有严重问题”并给“展开 n 条提示看证据”按钮。
* **全站动效缺陷**：`motion.css` 的 `si-stagger` 用 `fill-mode: both`，播完后一直压住卡片自己的 transform 与 opacity，完整档下所有依次浮现的卡片悬停不上浮、开标桌选中不变淡。改为 `backwards`，终态不变。

验证：`npm --prefix frontend run build` 通过；`tests/test_bid_folders.py tests/test_bid_report.py` 12 passed。重建本机 app 后，用开发库虚构测试账号与虚构项目在 1440 浅色、1366 深色走查列表页（时间尺叠格、日期筛选与显示全部、排序）与项目页（开标桌选中与变淡、只有提示的证据栏、展开提示），控制台无错误。时间尺红格未在页面上看到（开发库窗口内没有严重项目），由接口逻辑保证。
