# V3.6 计划：全站界面「衡线」

状态：**待用户确认**（2026-11-26 Opus 起草）。问题与待定事项见 [open_questions.md](open_questions.md)（V36Q-01 起）。拟发布版本号 3.6.0，标签 `v3.6.0`。

## 〇、范围与规则

**来源**：2026-11-26 用户要求把整个界面美化，并提供了设计仓库合集。同日的全站方案稿已交用户，用户要求写成规范与计划，计入 V3.6。

**目标**：把产品的往返机制画成一条贯穿全站的“衡线”。往返指原件在本机读取、遮住，经网关给模型，回到本机还原。每个模块配自己的物件与一张主图，Element 默认件全部换皮。

**依据**：[澄明二版设计规范（草案）](../design/v36/澄明二版设计规范-草案.md)。它在 V3.6 内取代 frontend.md 中列出的条目，V36-Z 合并进 frontend.md。CLAUDE.md 所说的“界面视觉以 frontend.md 为准”，在本阶段按“frontend.md 加本草案”理解。

**不做**：
* 新增侧栏菜单或页面：除新模块发票管家（V36Q-13）外，本计划只重做已有页面。
* 更换技术栈或新增前端依赖：Magic UI 的模式用 Vue 重写，不装包。
* 新增数据库表：主图只用现有数据，后端只加两个只读聚合接口和列表字段（V36-B-01 另加合同对比导出接口）。发票管家不建表，只给 jobs 的类型加一个值（V36-I）。
* 标书投标人关系图：已于 2026-11-20 撤下（V36Q-04）。
* 改动脱敏、还原、出口复检的行为。

**随本版发布**：v3.5.1 之后已在 main 上的 V351Q-19～21，即原件缩放与校对入口、删除“参考历史合同”、模型自动计价（V36Q-06）。

**另加**：
* V36-B-01 合同对比与多稿对比的识别准确率（2026-11-27 审核 V35-D-07 后用户确认，V36Q-12）。
* V36-I 新模块**发票管家**（2026-11-27 用户确认菜单与名称，并入 V3.6、不另开 3.7，V36Q-13）。同日精简为**只把发票整理成 Excel 清单**，不留记录（V36Q-16）。功能见 [design/发票管家.md](design/发票管家.md)，界面见规范草案 6.29。全程本机，不接模型网关，不改脱敏、还原、出口复检。

**规则（沿用 V3.5）**：
* **执行方式**
  * main 上串行，一次一个任务，每个任务单独开一个新会话。
  * 提交说明以任务编号开头，用英语或日语，小步提交；`git add` 只暂存本任务文件。
  * 状态写“已完成”时，附 build 或相关测试的实际输出。
* **两侧分工**
  * Claude 与 ChatGPT 谁有额度谁做；Sol 6.1 = GPT-6.1 Sol，Terra = GPT-6.1 Terra。
  * 先用表里的强度，同一验收点两次不过再升一档。
  * 交接只靠仓库：开工读 CLAUDE.md（Codex 另读 AGENTS.md）、本文件第〇节与该任务一节、规范草案的相关小节、上一个任务的报告与 `git log`。
* **每个界面任务**
  * 开工前用 Impeccable 对受影响的页面做 critique，完工后做 audit，要点写进报告。
  * Claude 侧另加载 frontend-design。
  * 自验：Claude 侧用内置浏览器，ChatGPT 侧可用 Playwright MCP。
  * 安装这些技能或工具属于下载，第一次用时先向用户说明来源与大小，取得同意（V36Q-07）。
* **验收**
  * `npm --prefix frontend run build` 通过。
  * 用 http://localhost:5173、虚构数据和模拟服务走查。
  * 浅色、深色 × 1366、1440 截图交用户；涉及动效的覆盖四档。
  * 不为样式、动效、措辞写测试。后端新增接口各写一条代表性用例，含权限校验。
* **规范改动**
  * F-00 设计中发现规范要改的地方，直接改草案，并在报告中列出。
  * 其余任务只把建议写进报告，由 V36-Z 合并。
  * 执行任务不改 SPEC 与 CLAUDE.md。
* **记录**
  * 新问题记在 open_questions.md（V36Q-08 起）。
  * 报告放 docs/v36/reports/，每份不超过一页。
  * 整仓全量只在 V36-Z 跑一次。

### V36-B-01 合同对比与多稿对比的识别准确率

来源见 [V36Q-12](open_questions.md#v36q-12-合同对比与多稿对比的识别准确率)。改的是共用的本机对比引擎 `backend/app/review/drafts.py`，合同对比、会话多稿对比与增量复审一并受益。

* **数字与编号**
  * 段首手写编号只认带分隔符的写法：第X条、1.、1、、(一)、一、。多级编号（8.3）后须是空白，不能紧跟单位（万、元、%、日、台等）。判断放在去空白之前。
  * 数值改动一律算“修改”。
  * “编号”与“标点空格”分成两类。前插一条造成的手写编号顺延，合并成一条“第X条起编号顺延 N 处”。
  * 会话多稿对比默认收起的、增量复审剔除的，只剩真正的标点与空格。
* **配对**
  * 替换块内改为按相似度从高到低的整体最优配对，保持先后顺序，门槛 0.6，不再限前 6 段。
  * 甲乙方名称互换这类短段按位置配成“修改”；短段挪位又改字也能认出。
  * 只有真正挪动的段落才报“位置调整”。
* **补上漏报**
  * 解析常见 Wingdings 勾选符号（□、☑、☒），合同对比与入审都用；解析标识按现行规则更新。
  * 页眉页脚、文本框分区对比，位置上标明分区。隐藏文字改为显示（或反之）报为一类变化。
  * 脚注尾注、批注、图片与嵌入对象不对比。稿件含有时，页面写明“含××，未对比”。
* **暗改**：合同对比打开留痕判断。引擎用 exact 模式，解析器已有拒绝修订文字。每处变化标“已留修订痕迹”或“未留痕”，一处两种都有时分开标。
* **导出对照表**
  * 合同对比结果可下载 Word 对照表：序号、类型、两稿位置、两稿原文与高亮、是否留痕。
  * 导出时重新提交两份文件，在服务器内存现算并生成。不落盘、不留记录、不调模型。
  * 与会话对照表一样需 use.export。取代 V35Q-39“结果只在当前页查看”。
* **页面**：上述标签、分区与提示，加在 F-04 改好的合同对比页与会话变化栏上。
* **文件**：`backend/app/review/drafts.py`、`contract_compare.py`、`router.py`、`backend/app/parsing/docx.py`、前端合同对比页与 `DiffRail.vue`、对应测试。

**验收**
* 用虚构 Word 写少量代表性用例，每类一个：
  * 开头是数字的金额与比例；
  * 删一段改一段的误配；
  * 勾选框；
  * 页眉；
  * 甲乙方名称互换；
