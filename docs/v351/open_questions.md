# V3.51 质量修复版问题清单

基线 `v3.5.0` / `37cf9da9`，日期 2026-11-25。这里记录问题、证据和待定口径。做法、文件与验收见 [PLAN.md](PLAN.md)，核验记录见 [V351-00](reports/V351-00.md)。优先级 P1 用于涉及账号隔离、可恢复性或出件和结果归属的缺陷。P2 用于业务正确性和可恢复操作。实测条目均用当场构造的现版样本，源码确认条目列出现行路径和条件。

## 一、优先修复

### V351Q-01 现场录音草稿跨账号恢复（P1，A-01）

- **触发** 同一浏览器、同一站点，会议账号 A 留下一段未上传录音，随后会议账号 B 登录并打开会议首页。
- **证据** 从空存储导入并执行当前 `recordingStore.ts`。写、读和清除经过同一个全局键，元数据及分片无归属。会议页在当前登录账号下创建会话并上传恢复所得的录音。存储层已复现，跨账号完整页面流程在修复卡验收。 [录音存储](../../frontend/src/utils/recordingStore.ts#L29) · [恢复入口](../../frontend/src/components/meeting/MeetingRecorder.vue#L153) · [上传入口](../../frontend/src/views/Meeting.vue#L87)
- **结论（A-01）** 以登录账号 ID 隔离新录音的元信息和分片，同一账号刷新仍可恢复。旧库的无归属数据原地保留，业务入口对所有账号隐藏主题、分片和恢复操作，任何清理由后续单独授权。

### V351Q-02 备份成功但缺少数据库引用的原件（P1，A-02）

- **触发** 数据库快照完成后、原件归档前，用户删除刚被快照引用的任务。也可在文件名已经枚举但尚未打开原件时触发。定时与手工共用备份实现。
- **证据** 两套空库直接迁移到 `0056`、分别新建虚构任务和加密原件，执行真实 `pg_dump` 和 `pg_restore`。当前备份得到 `status=success`、SHA-256 通过，恢复检查为 `missing=1`、`restore_ok=False`。归档结构验证放行，恢复晚至切换并启动后做缺件校验。 [备份时序](../../backend/app/backup/service.py#L235) · [归档跳过](../../backend/app/backup/service.py#L137) · [恢复顺序](../../deploy/scripts/restore.sh#L175)
- **结论（A-02）** 同份 `db.dump` 中未按保留期删除的行必须有原件或已登记的录音回放副本，已登记的转换件也必须存在。旧版缺少可选列时取原件。备份在发布和轮换前按实际归档成员检查；恢复在停服前复用同一口径。保留版本 1 的归档格式。

### V351Q-03 标书扫描页齐了但初审结果仍是旧版（P1，A-03）

- **触发** 最后一页写入与重算之间打开或轮询结果页。末页与初检首次发布交错时，后台也存在跳过补算的窗口。
- **证据** 新造项目数据运行当前 Vue 轮询函数，`OCR 1/1` 时停刷，页面 0 条严重问题，模拟重算后结果为 1 条。调用实际 Word 出件代码，重算前的文件无该问题且带扫描中的覆盖说明，重算后新导出包含问题。第二种初检交错由源码确认。 [重算](../../backend/app/bid/pipeline.py#L178) · [初检发布](../../backend/app/bid/extract.py#L235) · [轮询](../../frontend/src/views/BidProject.vue#L67) · [Word](../../backend/app/export/bid_docx.py#L86)
- **结论（A-03）** 结果按所用 OCR 覆盖发布。末页入库后持续刷新至补算成功或提示失败，失败保留上次结果并可原位重试。

### V351Q-04 无位置批注用错审核稿次（P1，A-04）

- **触发** 两稿同在一会话，第一稿是会话主文件，当前轮次只审第二稿，并有一条无位置意见。
- **证据** 新 UUID、新建当前版轮次 `file_ids=[第二稿]` 与两份虚构 DOCX，执行实际批注路由和生成逻辑。第二稿返回 409 `ANNOTATED_UNAVAILABLE`，第一稿返回 200，实际 DOCX 包含第一稿正文与第二轮意见。数据库与加密存取用替身。本次从有文件快照的分支触发，旧 `NULL` 轮次兼容单独验收。 [轮次快照](../../backend/app/review/service.py#L408) · [批注归属](../../backend/app/export/annotated_docx.py#L129) · [接口](../../backend/app/export/router.py#L22)

- **结论（A-04）** 有快照的轮次只允许为本轮文件生成批注，首个文件承接无定位的审核意见和无归属的本地校验。旧轮次缺快照时沿用会话原主稿。

## 二、业务与操作缺陷

### V351Q-05 一次性合同对比漏掉跨列和首尾空格（P2，B-01）

- **触发与证据** 手工或程序新建两份文字相同的 Word，将一条表格文字从第 1 列移到第 2 列。另组只在段首加两个空格，原件 XML 保留空格。当前接口两组均返回 HTTP 200 和空差异清单。一次性对比本身不读取之前的任务。 [读取](../../backend/app/review/contract_compare.py#L17) · [丢空格](../../backend/app/parsing/docx.py#L859) · [同文字跳过](../../backend/app/review/drafts.py#L255)

### V351Q-06 同额异币被去重并误判一致（P2，B-02）

- **触发与证据** 单证 A 明列美元和欧元各 `10,000`，单证 B 只列美元 `10,000`。当前本机核对保留美元，丢掉欧元和出处，金额与币种均显示一致。普通金额 T-50 路径触发，信用证金额上限使用独立规则。 [金额归一](../../backend/app/assistant/crosscheck.py#L79) · [去重](../../backend/app/assistant/crosscheck.py#L166) · [币种](../../backend/app/assistant/crosscheck.py#L233)

### V351Q-07 按问题讨论的回复无法导出（P2，B-03）

- **触发与证据** 从现版问题讨论界面导出回复，前端构造 `会话 UUID:问题 UUID`。后端要求路径字段为单个会话 UUID，返回 404。用新会话和当场生成的消息验证，合法会话 ID 可出件。 [前端构造](../../frontend/src/views/Assistant.vue#L260) · [导出接口](../../backend/app/assistant/router.py#L397) · [UUID 校验](../../backend/app/security/deps.py#L28)

### V351Q-08 部分译稿被显示为完成（P2，B-04）

- **触发与证据** 向现版翻译页输入后台产生的 `stopped`、1/5 段状态。执行实际布局代码，界面把全部步骤标为完成。后端保存已译内容，导出仍可用。 [翻译状态](../../frontend/src/views/Translate.vue#L44) · [部分结果](../../backend/app/assistant/local_translation.py#L212)

### V351Q-09 已完成的本地翻译仍提示等待确认后发送（P2，B-04）

- **触发与证据** 新建 `0056` 测试库和本地翻译会话，用实际接口、解析任务和翻译任务跑完一段虚构译文。新消息为 `done`、1/1，历史仍返回 `awaiting_confirm`，翻译待办为 1，云端调用为 0。译机和 NER 使用替身，工作台据此提示待确认。 [本地翻译](../../backend/app/assistant/local_translation.py#L212) · [待确认计数](../../backend/app/assistant/service.py#L707) · [工作台](../../frontend/src/components/assistant/WorkbenchHome.vue#L105)
- **待确认** 尚未发起翻译或旧数据没有方式字段时的展示。建议只从已有翻译消息或者明确的用户选择推断方式，方式未知时给中性提示，避免从文档未确认推断要外发。本卡范围默认采用上述最小口径。

### V351Q-10 历史筛选切换后展示上一类结果（P2，B-05）

- **触发与证据** 先请求「文件审核」，再切「翻译」。用当前 Vue 函数让翻译响应先到，文件审核后到，列表会被旧响应覆盖。全局搜索已有按请求序号防止旧结果覆盖的范例。 [历史](../../frontend/src/views/History.vue#L78) · [全局搜索](../../frontend/src/components/GlobalSearch.vue#L77)

### V351Q-11 备份空间告警读错磁盘（P2，C-01）

- **触发与证据** 单机部署中，备份卷与 app 容器层容量不同。app 内 `/backup` 由镜像创建，真正备份卷只挂到 worker。用空库新建成功备份记录，备份包 2 GiB，worker 回报卷剩余 1 GiB，模拟 app 层空间 100 GiB。实际数据接口返回 1 GiB，账号提醒接口漏报低空间。 [告警](../../backend/app/admin/alerts.py#L32) · [挂载](../../deploy/docker-compose.yml#L101) · [采用实际统计](../../backend/app/admin/data.py#L169)

### V351Q-12 知识库失败后重传同一文件被拒（P2，C-02）

- **触发与证据** 空库新上传虚构 DOCX，替身让嵌入临时失败。通过真实导入处理函数确认条目为 `failed`，再次调用同一上传接口提交同一字节返回 HTTP 409。查重包含刚失败的条目，现有界面需要先删除失败条目。 [失败处理](../../backend/app/kb/job.py#L86) · [查重](../../backend/app/kb/service.py#L34)

### V351Q-16 文件审核 PDF 扫描识别文字缺少校对入口（D-03，入口已确认）

- **现行行为** 文件审核确认页的「原文」显示解析稿，结果页提供只读「原件」。普通审核任务和会话的节点、原件接口均为 GET。调整遮住范围和签约方属于脱敏处理，会议逐字稿编辑与标书签章标注各有自己的业务接口。已在 `v3.5.0` 用断网容器读取实际 OpenAPI 确认。 [确认与结果画布](../../frontend/src/components/ConfirmCanvas.vue#L81) · [审核接口](../../backend/app/tasks/router.py#L144) · [会话节点](../../backend/app/assistant/router.py#L255)
- **签章边界** 使用同一组虚构签字行验证，置信度 0.70 的短字替换为「〔签字处请看原件〕」，置信度 0.90 的文字保留。另用虚构线框和模拟 OCR 输出复现，落入 PDF 扫描表格单元格的低置信短字仍可保留。签章区域按图像证据核验，OCR 文字不足以给出签章结论。 [签字行清理](../../backend/app/parsing/ocr.py#L86) · [PDF 识别与表格分流](../../backend/app/parsing/pdf.py#L342)
- **已确认纳入及入口（2026-11-25）** 在文件审核首次送审前的确认脱敏页面直接改识别文字。点选对应块或单元格，在同页对照原件、编辑、保存或取消，再核对重新脱敏后的待发预览。
- **首版范围** 原件清晰可辨且已有位置的 PDF 扫描文字，保存后重新校验、脱敏、确认。签名看不清、整块漏识或位置不准时人工核验原件。手动画框、已有审核历史的同会话内修改，以及直接完成的仅本地路径是否覆盖，另行确认。

## 四、文件审核和提问的确认链

### V351Q-17 文件审核重开进入普通对话，确认后没有审核轮次（P1，A-05）

- **用户现象** 「确认脱敏」弹窗左上「返回对话」、右下「确认遮住」。这套界面只提交 `POST /assistant/sessions/{id}/confirm`，成功后关闭弹窗并刷新会话。文件审核内嵌确认页走 `POST /assistant/sessions/{id}/runs`，带 `confirm_pending` 时在同一事务里确认并入队。用户本次从何入口进入及服务器上该任务状态未经检查。 [弹窗](../../frontend/src/components/assistant/FilePanel.vue#L175) · [按钮行为](../../frontend/src/components/ConfirmWorkbench.vue#L685) · [审核提交](../../frontend/src/components/workspace/ReviewPane.vue#L307)
- **根因与证据** 文件审核新建会话只在首次地址中加 `mode=review`，后端未持久记录审核入口。空库用新会话和虚构文件验证，首轮前审核历史查不到、待确认数记到工作台。Node 回放实际前端逻辑确认多种重开入口走提问视图。审核视图的文件抽屉可另开普通确认弹窗。后端实际调用普通确认可保存材料并保持零轮次；同一文件随后可正常创建审核轮次。新轮次已经排队时，详情的 `run_count` 仍可为 0，轮次列表有 1 条。 [新建路径](../../frontend/src/views/Review.vue#L28) · [历史分类](../../backend/app/assistant/service.py#L640) · [详情](../../backend/app/assistant/service.py#L118)
- **结论（A-05）** 从文件审核创建时持久记录入口，已有轮次的会话也按文件审核恢复。确认复用同一事务完成脱敏确认和审核入队。旧无轮次会话的原始入口不可可靠推断，保留已有资料和明确进入全面审核的操作；视图切换仅导航。 [当前规格](../SPEC.md#13b-统一工作台v32--v321)

### V351Q-18 工作台只加附件也可能挂起并续发提问（P1，A-06）

- **触发与证据** 工作台首页先写虚构草稿或选择模板，只添加附件而未点击发送。当前代码将文本或模板推断为待发状态。执行实际 Vue 函数并模拟接口，确认脱敏后调用 `confirm → preview → send`；只添加附件且没有草稿或模板的对照只调用 `confirm`。现行约定要求在用户点发送后才挂起。这条路径使用新会话，无真实外发，也与 Q-17 的现场任务证据独立。 [上传动作](../../frontend/src/components/assistant/Composer.vue#L76) · [自动提交标记](../../frontend/src/views/Assistant.vue#L150) · [确认后续发](../../frontend/src/components/assistant/Composer.vue#L185)
- **口径** 只有明确提交的提问才进入等待确认后的续发队列。确认页面要显示保存确认或确认后继续发送的实际结果，待发可取消。
