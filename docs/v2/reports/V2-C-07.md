## 原检查点发现：V2Q-71（现已解决）

真实 `backup_now.sh --wait` 执行 `compose exec -T worker ...`，需要正在运行的 worker。按 V2Q-70，rotate/verify 失败后 worker 保持停止；直接重跑原脚本会先在备份处失败。此时数据库可能为新旧混合密文，不能再当作“数据未动”启动旧密钥服务。

新增模拟实际 stopped 状态的回归已复现：第一次 rotate 失败，第二次 backup 失败，错误地启动旧密钥服务。现已加保守前置检查：worker 已停止时不做备份、不自动启动，直接报告保持停服。这个检查阻止误启动，但仍未满足“同一新密钥重跑脚本完成续做”；自动化断言保留失败，不标绿。
