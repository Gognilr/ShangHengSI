# V2-E-04：pgvector、全文导入与任务条款向量

2026-10-26 · GPT-6.1 Sol

## 范围与实现

- 数据库镜像 `aireview-db:{版本}` 基于 `postgres:16.15`，PGDG 包锁定 `postgresql-16-pgvector=0.8.7-1.pgdg13+1`；Python 依赖新增 `pgvector==0.5.1`。用户已同意本机下载并构建测试镜像。
- 迁移 0019（接 0018）创建 vector 扩展、law_articles（1024 维向量、余弦 HNSW）、law_import_articles 暂存表、task_clause_vectors；jobs 增加 law_embed。降级删除新增队列、三张表及 vector 扩展。
- bge-m3 INT8 引擎按 E-04a 已确认参数接入：CPU、CLS/L2、float32、512 token、不加前缀、每批一段、关闭 CPU 内存池和内存模式；worker 8 线程，app 4 线程。app 启动只校验文件，worker 校验并加载；共享推理加锁。模型从开发机已有选型目录复制，不进 Git；两个文件的 SHA-256 与仓库 MANIFEST 一致。
- 全文上传单个 ZIP，临时加密存放；worker 按右侧日期与目录版本匹配，按内容识别 OLE DOC，沿用 converter 和 OOXML 检查；按设计拆条，确认前只写暂存表与差异。确认在事务内替换条文、更新 fulltext_at、清暂存并入队；放弃不改既有条文。包限制：200 条目、单文件 20 MB、合计 200 MB，拒绝绝对路径、盘符与 `..`。
- law_embed 每批 64 条、每批提交，失败重跑可保留已完成批次；入队使用事务锁防重复 queued，执行使用独立连接会话锁防多个执行者竞争。启动和每次全文确认都会检查入队。
- review.clauses.first_level 与既有 chunk_boundaries 的判据相同。解析成功后将正文一级条款前 2,000 字作为 passage 计算向量；保存点隔离失败，先清旧缓存，失败仅警告任务 ID，解析仍成功。原件层清理同步删除向量，任务删除由外键级联。
- 发布包数据库镜像清单改为 aireview-db；db 构建段也由 build 标记剥离。发布构建新增必填 `--embedding-models`，以仓库清单校验。restore.sh 在停止服务和解密备份前检查 pg_available_extensions。upgrade.sh 原有载入镜像、compose up -d 流程可沿用，无需改代码。运维说明补充镜像清单和独立测试库命令。
