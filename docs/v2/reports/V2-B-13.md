## 实现

按用户已确认 V2Q-143 自动拼音方案实施，下载已于本会话获准。资源由 `backend/scripts/gen_hanzi_pinyin.py` 在断网 Python 3.12 容器从固定 SHA-256 的 Unihan 17.0.0 生成，读 kMandarin / kHanyuPinyin 两字段，保留 GB2312 一二级全部 6763 字及各来源读音。去声调，ü 统一为 v；不生成读音组合笛卡尔积，关联时沿字符 / 拼音位置做动态匹配。

资源 `hanzi_pinyin.txt` 为 65,965 字节，SHA-256 `db74ce13fb1058d289085bb9c630ef7f0a2b896aa9e3f6814522fd74112ecd3a`，头部带来源、生成方法和完整 Unicode License V3。原包与下载哈希见 B-12 报告。生成脚本不进入运行镜像路径，不新增依赖。

`parties.bilingual_links` 输出英文规范名称到中文规范名称的关联：英文企业后缀前连续可切分拼音的首词串，至少两音节；匹配中文主体开头至少两个字的任一来源读音。中英文已知地名可有可无，容纳 T-53 #18 的英文带 Qingdao、中文不带地名场景。双向均唯一才合并；多音字造成的一对多、多个英文名称反向匹配一个中文主体，均不合并。

engine 将关联英文写法转入中文主体的派生别名，同一代号、中文主名称、中文国家和类型，保留全部真实写法于代号#n；不写入已记住名称。原中文角色未定时保留英文原已识别的签约方角色。正文与 NOTE 共用 compute。

追问复用本任务对照表的中文代号，并保存英文别名代号#n；中文主体也是本问题新出现时先分配中文代号再共用。保留原追问的规范化接口，显式将 parties 的去空白规范形式转换回追问规范形式，不改变旧对照表键。

同一代号的通用 restore 仍按既有契约取主写法（中文），未改 restore.py；英文原写法完整保留于别名项，按来源选择该项后可逐字重放。专项验证中文主写法还原和英文别名重放；原 golden 的每个替换原值均在对照表中的检查照常运行。
