# V2-C-04 个人每日限额与重复文件提示

2026-10-26，GPT-6.1 Sol。按第四节与 V2Q-65 实现；V2Q-66 的两处前端范围扩展均获用户明确批准。

## 实现

- `usage.cap_reached(db, user_id, purpose)` 为三处共用只读检查：先每月、后个人。月度沿用全部 sent（含 test）统计；个人按 Asia/Shanghai 当天 0 点起、本人 sent、排除 purpose=test。上限为 0 不做对应计数，个人检查跳过 test 和无 user_id 的调用。
- 确认发送在状态、疑似遗漏、我方、类型检查之后，构建上下文之前预检；追问在可用条件之后、问题脱敏记录之前预检。拒绝不建轮次、排队或问答，不写已记住名称、审计、外发记录或活动时间，不调用模型。网关再次检查，竞态超限仍按其返回处理，未预占名额或加锁。
- 网关与追问增加 USER_CAP_REACHED；确认发送的月度额度也按 V2Q-65 前移。已有 worker 月度额度测试改为“确认成功后、worker 开始前额度用尽”，保留 worker 失败和不发送的原断言。
- 模型设置增加 user_daily_cap，默认 0，保存范围 0～10000；前端类型与设置表单同步。
- 上传通过格式校验后，仅对本人主文件算 SHA-256 并找最近仍存在的匹配任务；命中直接返回 409 和 task_id/title/created_at，不写文件、任务、job 或审计。显式 allow_duplicate=true 跳过提示。附件命中不提示；任务已删不提示；原件已清除但任务仍在，仍可提示上次任务。
- 错误体的业务字段只在内存传递；ApiError 可选 data 保持旧三参数构造和 401/403、下载行为兼容。弹窗按原文提示，可打开旧任务或带 true 重新提交；普通提交显式调用 startParse()，避免把表单事件当成允许重复标志。
- 同时到达的同文件上传不加唯一约束或预占锁；重复提示是上传前的便利检查。并发额度预检与网关之间也不预占，遵从第四节契约。
