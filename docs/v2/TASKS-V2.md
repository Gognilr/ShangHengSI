## 一、执行规则

沿用 docs/TASKS.md 第二节的执行规则，以下几条在 V2 中改为（V2Q-01，用户已确认）：

1. **开工前必读**：CLAUDE.md、本文件对应任务行、所在批次的设计文档（docs/v2/design/V2-x.md）第〇节与任务卡、docs/v2/open\_questions.md（编号规则与索引）和所在批次的 docs/v2/questions/V2-x.md。已完成批次的问题文件和 docs/v2/archive/ 不必读。不需要读 docs/SPEC.md 全文，任务卡已摘录需要的部分。
2. **测试**：任务卡中的测试用例逐条写成自动化测试，不得删除、放宽或改动；单个任务只运行与本任务相关的测试文件，改了脱敏规则的任务另加 `tests/test_redaction_golden.py` 与 `tests/test_a03_outbound.py`；前端任务只跑 `npm --prefix frontend run build`。整仓全量测试与浏览器检查在批次末的“集中测试”任务中进行。
3. **不停顿**：同一批内的任务由 GPT-6.1 Sol 连续完成，不逐个等待审核；批次末的集中测试完成后停下，由 Opus 审核整批。
4. **文件范围、提交**：只改任务卡列出的文件；用 `git add <具体路径>` 只暂存本任务文件；提交说明以任务编号开头，用英语或日语。
5. **不改** docs/SPEC.md、CLAUDE.md、AGENTS.md 和设计文档；SPEC 的变更写在 docs/v2/SPEC-V2.md，由 Opus 在细化时写好。
6. **SPEC 没写明的细节**：按“最简单、最安全”实现，记入所在批次的 docs/v2/questions/V2-x.md，状态“待确认”；编号取 docs/v2/open\_questions.md 索引中的最大编号加一，并在索引中追加。
7. **进度记录**：任务结束时把状态改为“已完成”，在“当前进度”加一条（超过 3 条时把最早的一条移到 docs/v2/archive/progress.md 的最前面）。**每条进度不超过 400 字**，只写结论、关键数字、未完成项和下一任务（编号、模型、强度）；测试明细、命令、证据文件清单写进批次测试报告或任务报告，进度里给出报告路径即可。
