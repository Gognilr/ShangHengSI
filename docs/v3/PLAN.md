# 商衡SI V3.0 整体方案

2026-10-30 · Opus 5.5 细化（V3-00）· **用户已确认（2026-10-30，V3Q-01～V3Q-07 按建议）**

依据：《docs/proposals/商衡SI-V3.0规划初稿-2026-10-29.md》（D1～D12 已确认的功能全部照做，本文件不重复论证）、《商衡SI-UI改进初步规划-2026-10-29.md》第八节（安全不变量）、当前代码 `fae2485`（V2.1）。“永不过度设计”只用于测试、门禁与报告，不用来删减已确认的功能；相对初稿只做了第三节的事实性修正，需用户确认的见 [open_questions.md](open_questions.md)。

## 一、目标

V2.1 已经能“安全地把文件交给模型初审、还原后看结果”。V3.0 让它**更顺手、更可选、结果能直接落到 Word 里**：

1. **界面**：侧栏布局、首页改为智能助手、对话与设置的操作手感、全局搜索、安装到桌面（V3-A）。
2. **多模型**：管理员配置多个模型，审核与助手各有默认，用户可选（V3-B）。
3. **批注版**：把问题以 Word 批注挂在原文副本上，原件一字不改（V3-C）。
4. **修订版**：把已采纳的修改写成 Word 修订，用户在 Word 中逐条接受 / 拒绝（V3-D，等 V3-C 用过后再细化）。

脱敏、出口复检、还原、外发内容、`local_only` 在 V3.0 中**完全不变**。

## 三、相对初稿的修正（只限事实与顺序，功能不删减）

| 初稿 | 本细化 | 理由 |
|-|-|-|
| 安装到桌面：IT 用 Edge 企业策略统一安装、根证书由域策略下发 | 用户在 Edge 中自行“将此站点作为应用安装”，或用 `msedge --app=https://IP/` 快捷方式；根证书沿用 V2-Z 的 `http://IP/cert/` 页面一次导入 | 公司局域网没有域，不能依赖组策略 |
| 设置八类在 V3-A 逐页分节 | 模型页的分节放到 V3-B 整页重做时一起做，其余七类在 V3-A 做 | 避免同一页改两次 |
| 批注版支持旧格式“经 converter 转换后输出” | 解析时把 DOC、WPS、RTF 的转换结果加密保存（与原件同保留期），导出时直接用；V3 之前上传的旧格式文件需重新上传 | 现在转换结果用完即弃，导出时再转换要绕经 worker 与 converter；保存一份更简单可靠 |
| “撤销”类提示（初稿写“单独评估”） | 本版不做 | 后端没有撤销接口；评估结论放 V3Q-05 |

## 四、安全不变量（每批审核时逐条核对）

沿用《UI 改进初步规划》第八节全部条目，另加：

1. 原件永远不改；所有导出都生成新文件，服务器不保留导出文件。
2. 模型从不接收或产出文件；批注版、修订版由服务器按问题清单生成并逐字校验，校验失败不输出。
3. 多模型不改变外发内容与出口复检；每个模型都只经网关调用；普通用户看不到模型的接口地址、密钥、单价。
4. 全局搜索只搜本人的任务与会话（服务端按 owner 过滤）；搜索词不进 URL、不写日志。
5. 选定工作文件夹不触发任何上传，只有用户勾选或拖入的文件才上传；文件夹路径、文件夹名与其中的文件名不发送到服务器、不写日志、不进 URL；导出写入工作文件夹时绝不覆盖已有文件。

## 五、规格与规则的写法

1. **不再单独写 SPEC-V3.md**。每批设计文档最后一节“规格变更”按 SPEC 章节号写“改成什么”，由 Opus 在该批审核任务中合并进 docs/SPEC.md（V2-F 的做法）。docs/design/frontend.md 的修改同样写在 V3-A 设计中、在 V3-A-09 合并。
2. 批次执行期间，设计文档与 SPEC / frontend.md 冲突的地方以设计文档为准；GPT 不改 SPEC、CLAUDE.md、AGENTS.md、frontend.md 与设计文档。
3. 新问题编号 **V3Q-01 起**，规则见 [open_questions.md](open_questions.md)。V2Q 编号到 V2Q-186 为止不再使用。
4. 版本号：V3-A～V3-D 期间不打标签，SPEC 头部、CLAUDE.md 标题、登录页页脚仍为 V2.1；V3-Z 完成时统一改为 V3.0 并打 `v3.0.0`。线上紧急修复在 `v2.1.0` 上开分支，修复合并回 main。
