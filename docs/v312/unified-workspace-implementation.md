# 智能助手与智能审核统一工作空间：实现提案

状态：**V3.1.2 待 Opus 与管理人统一审核，审核后批准；不是执行授权。**

日期：2026-11-11。提案基于当前 main（上一轮审查记录提交 423758e）；实施前重新核对基线。

用户目标：同一份材料可以直接提问、发起全面审核、针对审核问题继续讨论，并把讨论草稿明确保存为修改建议，减少重复上传和脱敏确认。

本文件由用户明确要求编写，供 Opus 评审。它不替代 docs/v311/PLAN.md，不变更 V311-Z 状态，也不授权正式服务器操作。用户已确认本提案与本次审查发现共同归属 V3.1.2；执行模型及正式任务文件范围由统一审核和管理人批准后的计划确定。统一入口见 [REVIEW.md](REVIEW.md)，问题清单见 [open_questions.md](open_questions.md)。下文 UW 编号仅为提案工作包编号。

## 1. 产品决策

推荐：**统一工作空间、共用材料版本与代号，保留直接提问和全面审核两种执行流程。**

不采用以下两种方案：

| 方案 | 不采用的原因 |
|---|---|
| 把审核变成助手提示词模板 | 会丢失审核要求覆盖、问题结构、轮次、原文定位及修订导出的明确契约 |
| 仅在两个现有任务间加跳转或复制文件 | 两套文件、代号和确认状态继续分叉，不能兑现共用材料，长期维护更难 |

范围分为两个交付批次：第一批完成共用材料、双模式、问题讨论和旧数据兼容；第二批完成讨论草稿回填及安全导出。只有两批都完成，才算实现本提案展示的完整流程。

不纳入本次：在线编辑原文件、多人协作、跨用户共享、通用 Agent 自动执行、模型更换、NER 量化、任意跨工作空间合并，以及会议/翻译的存储重构。长文检索和上下文优化只做支持本流程所必需的部分。

## 2. 当前实现约束与重构落点

| 现状依据 | 对实现的约束 |
|---|---|
| assistant/service.py、assistant/prompt.py | 助手使用 kind=assistant、独立消息表、文件选择、模板、流式任务；不能只改 task.kind 就获得审核能力 |
| review/service.py、review/job.py、chat/service.py | 审核运行与审核追问有独立状态和消息；追问当前截取前部正文，不能直接用于后文问题定位 |
| redaction/placeholders.py | 审核用角色代号和部分共用代号，助手用中性唯一代号；跨模式不能直接拼接两种任务的代号文本 |
| redaction/engine.py | 代号、替换位置、文件节点和用户决定以 task 为归属；这是复用材料的主要接缝 |
| db/models.py | ReviewRun、AssistantMessage、ChatMessage 等均关联 task；需要显式迁移与兼容分支 |
| frontend/src/router/index.ts | 现有路由及权限不同；旧链接、会议和翻译需继续可用 |

已有节点缓存、出口复检、实际外发回执、本地计算、审核分段并行等应复用，不重复建设。抽取公共函数后，旧入口也调用同一实现，避免维护第三套脱敏引擎。

## 3. 界面与交互

### 3.1 导航和入口

建议侧栏：新建工作、工作台、会议纪要、翻译、历史记录、设置。由用户确认后替换“智能助手”“智能审核”两个平级菜单；不新增另一套并列工作台菜单。

新建页保留自由输入与拖文件。首次发送或加入文件才创建工作空间。无需文件即可直接问答；全面审核至少需要一个已解析的主文件。历史记录按工作空间聚合，会议/翻译保持现有用途筛选。近期列表显示工作空间标题及最近活动。

工作空间顶部：标题、材料按钮、当前材料版本；其下为“直接提问 / 全面审核”。切换模式只改变视图，不创建任务、不外发、不清除输入。无对应使用权限时显示已有结果，但禁用新建/发送动作并说明原因。

### 3.2 直接提问

采用当前助手单栏阅读布局。输入框显示本次选中的材料；材料抽屉显示解析、待确认、已确认、失败等真实状态。未确认材料不得因切换模式而成为可外发材料。

本批保持现有“选中材料须处理完成后发送”语义；允许取消待发请求并主动取消选择未就绪文件，再发送。不得默默忽略用户选中的材料。

结果可附原文来源链接。对话中展示审核完成事件卡，指向相应版本/轮次；不把事件文案作为模型历史再次发送。

### 3.3 全面审核

首次进入显示设置：主文件、采购/销售/其他立场、文件来源、审核模型、要求和补充说明、local_only 选项。复用已确认材料，不重复要求核对完全相同的替换；改变会影响外发内容的设置后需更新预览。

主按钮“确认发送并开始审核”。本地校验模式使用相应本地按钮，不出现云端发送暗示。模型、要求版本、材料版本与补充说明记录在本轮，不从之后的可变设置推断历史。

审核结果复用左原文、右问题清单；保留本地计算/AI 建议分区、要求覆盖、等级、轮次选择、采纳状态、报告/批注/修订导出。普通聊天不会自动成为审核结论。

### 3.4 问题讨论

点击问题的“继续讨论”，建立讨论锚点：材料版本、审核轮次、问题 ID。跳到对话模式并显示锚点卡；用户可明确解除锚点。

模型上下文包括该问题的原始模型结论、对应条款及必要邻近段落、当前问题和该讨论最近消息。不同问题的讨论不得混入默认历史；普通对话、问题 A、问题 B 分别选择上下文。前端可按时间显示在同一对话视图中，但后端按锚点分组。

如果锚点属于旧版本，界面明确显示“正在讨论合同 v1”；不会混用 v2 的节点、金额或对照表。版本不存在或已清理时给出原因，不自动改指当前版本。

### 3.5 保存修改建议

按钮“保存到该问题的修改建议”打开草稿预览，用户核对文本后保存。只接受结构化提取出的建议条文，不把整段聊天的解释文字当作条文。无有效条文时提示重新生成或手工整理。

保存为独立建议记录，原 Finding 的模型结论、原始 suggested_text 不覆盖；界面显示“原审核建议 / 讨论修改稿”。选择讨论修改稿后仍需执行现有采纳动作。讨论内容不改原件，也不自动重跑审核。

### 3.6 材料变化

首次外发前可以在当前草稿中增删文件、修改脱敏。首次云端发送或本地审核完成后，材料版本封存；需要改材料时用“创建新材料版本”。旧消息和审核仍指向旧版本。

创建新版本复用原件与解析结果，复制必要的加密节点及用户决定，重新核验其适用位置；不复制旧版本的“已确认”时间来伪装新版本已确认。未变化且处理规则一致的文件可复用确认，变化项显示差异摘要。旧结果标为“基于 v1”，不称为 v2 的当前结果。

## 4. 推荐的数据设计：工作空间 + 材料版本

采用增量结构：保留 Task 作为一个材料版本的执行容器，增加 Workspace 作为产品工作空间。避免同时新建 Document、Revision、Dataset 等多套内容归属。

### 4.1 新增与扩展字段（拟议契约）

| 表/字段 | 定义 |
|---|---|
| workspaces | id UUID；owner_id；title；active_task_id 可空；created_at/updated_at；一个用户私有的工作空间 |
| tasks.workspace_id | 可空外键；NULL 为旧任务或会议/翻译原路径 |
| tasks.revision_no | 同 workspace 内递增整数；与 workspace_id 组合唯一 |
| tasks.kind | 新增 workspace 枚举；旧 review/assistant 不改名 |
| tasks.material_version | 单版本内每次影响外发材料或策略的修改递增整数，用于并发与确认校验 |
| tasks.sealed_at | 首次发送/本地审核完成时置位；封存材料与代号中已存在的键值关系 |
| tasks.redaction_style | 明确记录 review/neutral，旧任务按原 kind 回填；新 workspace 固定 neutral |
| assistant_messages.context_run_id/context_finding_id | 可空外键，必须同时属于本消息 task；问题讨论锚点，不接受客户端提交其他 task 的问题 |
| review_suggestion_drafts | id、task_id、run_id、finding_id、source_message_id、text_redacted、created_by、created_at、validation_summary；各 ID 必须同 task |

新工作空间消息复用 AssistantMessage 和流式执行；审核复用 ReviewRun/Finding。旧 ChatMessage 保留，通过只读兼容适配显示，不批量转换内容。新模式不继续向旧 ChatMessage 写入。

不新增通用事件表：审核事件由 ReviewRun 查询投影，合并显示时以类型+ID 标识，使用稳定的时间和 ID 排序。

### 4.2 封存与代号追加

封存后可以追加“消息中新出现的实体”的代号，但不得修改已有键对应的真实值、重新编号或原地重算旧文件。追加代号不改变历史显示。

若用户在消息中选替换的词出现在封存文件未替换位置：**不能直接沿用 A-01 的原地重算路径**。返回需要新材料版本的状态，先完成新版本替换确认，再由用户发送该消息。不能在后台改写已经审核过的材料。未封存草稿继续复用 A-01 的同步替换机制。

同一版本可多轮审核；审核立场/来源等通过轮次参数表达。会改变脱敏正文或“我方”实体绑定的设置需要新版本。新工作空间建议以稳定 ORG 代号表示主体，“我方”仅为本轮角色元数据，避免 OUR 绑定变化破坏旧消息。

### 4.3 原件复用与删除

实施前核查原件存储是否支持多个 TaskFile 引用。若支持，添加引用检查后复用；若不支持，首批在本地复制已有加密原件到新版本归属，不重新上传、不重新解析，不引入未经验证的存储引用系统。

节点及替换信息按版本独立保存，代号可从前版本 seed 后只追加；NER 缓存仅在输入及规则版本一致时复用。相同词不等于同一实体，不能为追求跨版本编号相同而误合并。

删除工作空间覆盖其全部材料版本、消息和结果；保留期清理仍按既有规则执行。共享存储分支必须在最后一个引用清理后才删文件。active_task_id 不构成阻止删除的循环外键，删除顺序与引用置空由迁移和服务显式处理。

## 5. 公共能力拆分

### 5.1 材料与脱敏

在现有 tasks/redaction 服务上抽取材料准备接口。职责为：读取本版本文件节点、验证 owner、确认状态、生成外发正文、返回材料版本号。不得由前端拼接外发文本。

新 workspace 在两种模式下均使用 neutral 代号。审核提示词的角色说明、金额计算、返回校验、原文引用定位、回程标记、报告及修订导出必须一同适配；不是仅替换 Allocator。旧任务走旧 style，历史文本不改。

审核中的机构角色通过本轮主体说明提供。金额、单价、数量、币种保留现有本地计算契约；中性代号不能让模型获得真实金额。日期策略按版本固定：首批新 workspace 建议沿用助手不平移日期的方式，同时在外发说明显示实际策略；该取舍必须由 Opus 与用户确认，不能默默降低审核现有默认保护。

### 5.2 上下文构建

增加公共 context builder，但保留 review 与 assist 的不同 system prompt 和输出验证器。输入显式包含 task_id、material_version、file_ids、可空 run/finding 锚点；输出消息数组及本次覆盖说明。

问题讨论必须优先包含问题关联 loc 的节点，不能沿用 chat._document 的前部截断。先放问题条款和必要上下文，再在总预算内放历史；仍放不下时返回明确错误，不截掉核心证据继续回答。普通问答超限沿用明确拒绝，首批不承诺全库自动检索。

请求预算覆盖 system、文件、参考片段、历史、问题和输出预留。可先沿用配置的保守字符预算，不在无 tokenizer 的情况下声称精确 token 预算。任何省略通过覆盖说明对用户可见。

检索片段进入本版本代号命名空间并再次复检；不直接拼入旧任务代号。每次实际发送继续经过 gateway，回执记录实际请求，不能仅以缓存预览代替。

### 5.3 还原与导出

所有新模式共用候选代号扫描、确定性还原和 marks；流式仅输出不会被后续字符改变的前缀。unknown/variant/date/literal 等既有标记语义继续保留。

保存草稿时用绑定版本的对照表及问题位置执行 clause=True 校验；保存代号文本，不保存还原后的明文。用户在草稿预览手工修改的内容必须先走本地脱敏，不能把编辑后的真实值直接写入 text_redacted。

导出时再次验证；有未能还原、模型自写敏感字面值、未知代号等的条文不得直接进入修订，沿用降为批注策略。导出取所选草稿的不可变内容，而不是读取消息的最新显示文本。Word/表格中保留标记与提示。

## 6. 接口草案

以下为供评审冻结的新增契约；最终按现有路由风格落地，旧接口不删除。

| 接口（/api 前缀） | 请求要点 | 返回/行为 |
|---|---|---|
| POST /workspaces | title 可选 | id、active_revision；首次实际操作时调用 |
| GET /workspaces/{id} | — | owner 校验；版本列表、当前材料、能力权限、审核摘要 |
| GET /workspaces | cursor、limit、query | 游标分页；不一次返回完整消息 |
| POST /workspaces/{id}/revisions | source_task_id、expected_material_version | 新草稿版本；请求必须由本人工作空间版本派生 |
| POST /workspaces/{id}/messages/preview | task_id、material_version、file_ids、message、可空 context | 预览、疑似项、确认是否失效；只读 |
| POST /workspaces/{id}/messages | 上述字段、decisions、模型、request_id | 排队消息及本地复检结果；服务端重算，不能信任预览文本 |
| POST /workspaces/{id}/reviews | task_id、material_version、立场/来源、审核设置、request_id | ReviewRun，复用既有 job |
| POST /workspaces/{id}/suggestion-drafts | task_id、run_id、finding_id、message_id、选定条文或编辑草稿 | 独立建议草稿及校验标记；不自动采纳 |
| GET /workspaces/{id}/activity | task_id 可选、cursor、limit | 消息/审核事件投影；统一分页 envelope |
| DELETE /workspaces/{id} | — | 本人整体删除，沿用确认交互和清理策略 |

文件上传/确认、流式增量、审核结果和导出优先复用现有服务，经 workspace 适配器解析 task，禁止前端凭任意 task_id 穿透归属。

错误：非本人 404；版本变化 409 MATERIAL_CHANGED；封存材料需派生版本 409 MATERIAL_REVISION_REQUIRED；上下文超限 409 CONTEXT_TOO_LONG；跨版本问题引用 422 CONTEXT_MISMATCH；已有处理互斥继续采用现有 SESSION_BUSY/任务冲突错误。

### 6.1 一致性与并发

所有变更统一锁顺序：用户（涉及名额时）→ Workspace → Task → RedactionMap → 对应消息/轮次。不能在新适配器中先拿 map 锁、再反向调用原服务拿 task 锁。

文件/脱敏变更递增 material_version。发送时比对预览版本，变化即返回 409 重新预览；不会因自动等待而发送用户尚未看到的新材料。

同一个材料版本的解析/脱敏写入与外发准备互斥；首批同一版本的审核与助手生成串行，避免共享可变映射和多处名额计数竞争。后续是否放开并发以实际等待证据决定。不同工作空间沿用现有并发配额。

request_id 在数据库内与 owner/workspace/操作类型组合唯一；重复点击返回已有运行，不重复外发。事务内冻结版本、写队列后提交；外部模型调用不持有长事务锁。失败保留版本和已产生结果，重试是显式的新操作。

## 7. 旧数据与权限兼容

1. 首批仅对新创建的 workspace 启用新模型。已有 review/assistant 任务保持原任务 ID、代号、消息表和导出路径。
2. 统一历史页通过适配器同时列出新工作空间和旧任务；不为打开历史记录自动执行迁移。旧路由仍能访问。
3. 旧审核可在统一外壳中显示原结果和旧追问；“以这些材料新建工作空间”是用户显式动作，生成新版本并重新确认脱敏，不转换旧结果为新审核。
4. meeting/translate 的 purpose、权限、模板和路径不变；原有“在助手中继续提问”保留原行为，本批不把录音任务转成可审核材料。
5. use.assistant 控制普通新问答；use.review 控制全面审核及审核问题讨论（保持原审核追问权限语义）；只有 use.review 的用户能讨论自己的审核问题，不因此获得通用助手权限。use.export 仍独立校验。
6. local_only 为材料版本的硬约束，普通问答、问题讨论、检索补充均不得绕过；如果希望改为云端，必须显式派生允许外发的新版本并确认。
7. 失去使用权限不影响查看本人已有结果；任何管理员也不能查看其他人的内容。每个引用对象独立验证 owner 与 task/workspace 归属。

## 9. 代表性验收

只增加能验证核心契约的少量场景；识别类进 golden，模型均模拟，不增加穷举矩阵。

1. **完整主线**：上传虚构合同和报价单 → 确认 → 问答 → 全面审核 → 定位问题 → 讨论 → 保存草稿 → 采纳并导出。文件只上传一次；两种模式同版本同代号；单纯切换模式零模型调用。
2. **版本隔离**：v1 已问答/审核后派生 v2，改变实体或金额；查看、讨论、导出 v1 均使用 v1 的真实值及节点，v2 不改旧结果。
3. **新增敏感词与过期预览**：封存文件中出现新选替换词时必须走新版本；发送前材料版本已变返回冲突，不能沿用过期确认；相同 request_id 不重复外发。
4. **上下文与权限**：后部条款的问题讨论确实包含相关节点；问题 A/B 历史隔离；跨 owner 返回 404，跨版本引用拒绝；local_only 零外发；仅审核权限可用问题讨论但不可通用问答。
5. **回程与导出**：neutral 代号在审核字段、本地算式和导出正确还原；未知/变体仍有标记；不合格建议降为批注；草稿不覆盖原 Finding。
6. **兼容与清理**：旧审核/助手、会议/翻译可读取和使用；删除/保留期不会删掉仍被引用的原件；未清理的旧版本可独立还原。

逐任务仅跑相关测试；golden、A-03、回程与修改模块按批次范围执行，整仓全量在批次末一次。前端依 frontend.md 第十一节验收；不把本会话示意图当作真实浏览器验收。

性能记录同机同输入的上传至待确认、预览、切换模式、首个模型字符、完整审核、长会话打开时间及调用次数。以旧实现对照，重点检查重复 NER/解析和请求体长度；不预先宣称提速百分比。真实模型或下载需另获同意，正式服务器每一步需单独获同意，测试后清理本次容器。
