## 一、为什么不做客户端（评估结论摘要）

| 想解决的问题 | 网页端的解决方式 |
|---|---|
| 各电脑浏览器不同、界面不统一 | 安装为 Edge 应用或用固定以 Edge 应用窗口打开的桌面快捷方式，不受默认浏览器影响；统一使用 Chromium 内核 |
| 窗口被随手关掉 | 处理在服务器上进行，关窗口不影响任务；Edge 应用可设为登录时自动启动 |
| 点开已有会话继续对话 | V2 已实现（服务器保存） |
| 服务器存储压力 | 调整保留期；目前没有实测压力 |
| 从文件夹选文件、报告存回原件旁 | 浏览器文件夹授权接口（Edge / Chrome） |

客户端方案的主要差异是“数据存本机”，其代价（封存包格式长期兼容、落地 / 回填 / 墓碑、退役主密钥、记录散落各电脑、V1 刚上线即重做数据生命周期）大于收益。

## 二、界面改版（采纳《UI 改进初步规划》的部分）

- 侧栏：品牌、新建会话、智能助手 / 智能审核 / 审核历史、近期会话（助手场景）、设置（管理员）、用户菜单。可收起为 64px 窄栏（图标＋悬停提示＋`aria-label`，需修改 frontend.md 图标规则），收起状态在本浏览器记住。
- 页面高度改由主布局容器提供，去掉 `calc(100vh - 64px)`；强制改密期间主区域不渲染业务页面。
- 全局正文保持 14px；对话正文先用 `--si-font-reading`（15/1.8），实测不足再加一档；对话最大宽度约 760px。
- 设置页已是直达结构，只做容器适配；智能审核、历史、结果页只适配新容器，不重新换外观（V2-U 刚改过）。
- 不做：深色模式、字号调整、紧凑密度、登录页改版。
- 1280×800 侧栏展开时审核结果原文预览约 476px，需实测；不足时由用户收起侧栏，不自动收起。

## 三、安装到桌面与工作文件夹

**安装到桌面**

- 前端增加应用清单（名称、图标、独立窗口），支持在 Edge / Chrome 中安装；IT 可用 Edge 企业策略统一安装，或分发以 `msedge --app=https://服务器/` 打开的快捷方式。
- 前提：Caddy 内部根证书通过域策略下发到各电脑并被信任（也消除现有证书警告）。属于部署事项，写入运维说明。
- 不做离线功能，不缓存业务数据。

**工作文件夹（可选）**

- 新建审核、新建会话时可选择一个工作文件夹（浏览器文件夹授权接口），页面列出其中可审核的文件供点选；上传与拖入照旧。
- 选定文件夹**不触发任何上传**，只有用户点选或拖入的文件才上传。
- 导出时默认保存到工作文件夹（同名自动加序号，绝不覆盖）；未选或浏览器不支持时按普通下载处理。
- 授权句柄只保存在本浏览器；文件夹路径与文件名不发送到服务器、不写入日志或 URL。
- 任务数据仍保存在服务器，与工作文件夹无关；文件夹中的文件移动或删除不影响任务。

## 四、导出：报告、批注版、修订版

| 导出 | 内容 | 用途 |
|---|---|---|
| 审核报告（现有，SPEC 14） | 不变 | 内部存档、报批 |
| 批注版副本 | 原文正文一字不改；每条问题以 Word 批注挂在对应原文上（等级、问题、建议、依据），作者“商衡SI” | 内部逐条查看与修改 |
| 修订版副本 | 只把“已采纳”且有 `suggested_text` 的问题写成 Word 修订（删除＋插入），不含批注 | 用户在 Word 中逐条接受 / 拒绝后可对外发送 |

- 文件名：`{原文件名}_商衡SI批注_{yyyyMMdd}.docx`、`{原文件名}_商衡SI修订_{yyyyMMdd}.docx`。导出批注版时提示“批注版含内部审核意见，请勿直接发给对方”。
- 范围：.docx；旧格式经 converter 转换后输出 .docx。PDF、扫描件、Excel 只出审核报告。原件已按保留期删除的任务不提供副本导出。
- 在服务器生成（python-docx 1.2.0 批注、lxml 修订），生成后下载，服务器不保留；导出写审计日志。
- 定位失败的问题：批注挂在所在段落开头，修订版中不做修订；提示“共 N 条，M 条未能精确定位”。
- **硬性校验**：批注版正文与原件逐字一致；修订版“全部拒绝”等于原件、“全部接受”等于预期文本。校验失败不输出文件。
- **模型输出约束（修订版前提）**：提示词要求 `quote` 为某一节点内一字不差的连续片段，`suggested_text` 为对该片段的完整替换；服务器校验 `quote` 在该节点中恰好出现一次才做成修订，否则只加批注。

## 五、多模型

### 5.1 现状

V1 的“不做”包含“多模型切换界面”（SPEC 1.7）。现在设置中只有一组模型配置（`model.*`：接口地址、密钥、模型名称、温度、最大输出、超时、JSON 输出、附加参数、分段长度、单价、每月上限），网关按这组配置调用。`review_runs`、`assistant_messages`、`llm_calls` 已记录所用模型名称。

### 5.2 管理（设置 → 模型，系统管理员）

- 新表 `llm_models` 保存每个模型的配置（字段沿用现有 `model.*`，另加：显示名称、说明、启用、可用于智能审核、可用于智能助手、排序）；密钥照旧加密保存，界面只显示末 4 位。迁移时把现有配置转为第一张卡片，并设为两项默认。
- 页面为卡片网格，每张卡片显示：显示名称、模型名称、接口所在主机、标签（审核默认 / 助手默认 / 已停用 / 仅审核 / 仅助手）、本月调用次数与估算费用、每月上限。操作：编辑（右侧抽屉中的表单）、测试连接、设为审核默认、设为助手默认、停用。末尾为“新增模型”卡片。
- 测试连接增加一项结构化输出测试（不含业务数据）；未通过的模型不能勾选“可用于智能审核”。
- 已被调用过的模型只能停用，不能删除（外发记录与轮次中保留名称）；停用后不出现在选择列表中，默认模型不能停用。
- 上限：每个模型有自己的每月调用上限；每人每日上限（`model.user_daily_cap`）跨模型合计。
- 数量上限 10 个（建议）。

### 5.3 使用

- **智能助手**：输入区有模型选择（只列出启用且可用于助手的模型，显示名称与说明）；新会话默认使用助手默认模型；会话中可随时切换，之后的消息使用新模型，每条回复下方显示所用模型。比价、翻译等需要结构化结果的模板，只列出通过结构化输出测试的模型。
- **智能审核**：新建审核第一步的设置中增加模型选择，默认为审核默认模型；重新审核时可换模型，产生新轮次，便于用另一个模型复核；结果页与报告照旧显示所用模型。
- 普通用户只看到显示名称和说明，看不到接口地址、密钥、单价。

### 5.4 不变的边界

- 所有模型都只经网关调用，按所选模型执行调用上限检查 → 出口复检 → 发送 → 记录；`llm_calls` 增加模型编号。
- 外发内容、`local_only`、出口复检规则与模型无关，完全不变。
- 每增加一个模型就是一个新的外发目的地：卡片上显示接口所在主机；如 IT 配置了出站白名单需同步添加。

### 5.5 待确认

1. 智能审核是否允许普通用户选模型（建议允许，只列出管理员标为“可用于审核”的模型）。
2. 审核默认、助手默认分开设置（建议），还是只设一个默认。
3. 模型数量上限（建议 10）。

## 六、安全不变量

保持《UI 改进初步规划》第八节全部条目。另加：

1. 选定工作文件夹不触发上传；文件夹路径与本地文件名不发送到服务器（上传文件本身的文件名照旧按现行规则处理）。
2. 原件不被修改；所有导出生成新文件，不覆盖。
3. 模型从不接收或产出文件。
4. 多模型不改变外发内容与出口复检；普通用户看不到模型的接口地址与密钥。

## 九、客户端方案的启动条件

出现下列任一情况时，再启动备选方案（客户端与本地存储）：

1. 保留期调到很短后，服务器存储仍长期不足；
2. 需要与操作系统深度集成（文件右键审核、监视文件夹、Word 插件）；
3. IT 无法保证各电脑有可用的 Edge 或 Chrome；
4. 公司要求审核记录不得集中保存在服务器。

## 十、不做

Electron 客户端与本地存储（备选）；顶部 / 侧栏布局切换；更换组件库；深色模式、字号调整、紧凑密度；把文件或图片发给模型；由模型生成文件；在线文档编辑；PDF / Excel 批注；离线使用。
