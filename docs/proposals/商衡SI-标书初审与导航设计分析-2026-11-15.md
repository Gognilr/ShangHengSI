## 〇、结论先行

1. **标书初审做成独立菜单、独立页面，是一个“项目”而不是一次对话**：分“开标前准备”（招标文件 → 要求清单，可提前几天做完）和“开标当天”（按投标人分组拖入 → 本地检查先出 → 模型核对后补）两段。评标前要看的只有一屏“总览”和一张“要求响应矩阵”。
2. **第一期只做不调用模型的部分**（串标线索 + 报价分析 + 确定性的符合性检查 + Word 报告）。这是这个功能里最独特、最确定、零外发的价值，也最不容易出错；模型核对放第二期。
3. **全文脱敏识别不可行，改为“只对要发送的片段做完整脱敏”**：5 家 × 几百页全文跑实体识别要几十分钟以上；串标比对只用规则识别（电话、邮箱、账号、证件号），模型核对只把检索到的片段过完整脱敏与出口复检，用户确认一次。
4. **签章页不做印章 / 签名识别，改成“签章页速览”**：系统只负责把每家要求盖章的页找出来排成缩略图，人眼几秒钟看完，比识别可靠，也不需要新模型。
5. **比价不并入标书初审**，留在工作台；两者共用报价对齐与本地计算，在标书初审首页放一句引导即可。
6. **导航：每个菜单是一类完整的工作，高亮跟着“这件事属于哪类”走，不跟着页面内的视图切换走。**“智能审核”改名“文件审核”并成为真正的独立入口（拖入区 + 最近的审核）；工作台首页去掉“直接提问 / 全面审核”切换，改成“提问框 + 常用工具 + 四个入口卡片 + 继续上次的工作”。
7. **首页“颜色过渡太明显”**：根因是主区域两团彩色氛围光、侧栏选中项的横向渐变加辉光、主按钮蓝色辉光叠在一起。收敛为：页面底纯色、选中项浅色平底加细竖条、按钮不带辉光；渐变只留在 Logo、登录页短横线和“正在工作”的等待动画里。

## 一、标书初审的功能设计

### 1.1 定位与边界（沿用已确定事项）

* 公司作为招标方，企业自主招标 / 邀请招标，3～5 家投标，开标当天用；使用者是采购部或招标办员工，产出交给评标委员会的《初审疑点报告》。
* 只做资格审查、符合性审查和串标线索。**不打分、不排名、不推荐中标人**；界面与报告中不出现“最低价”“第一名”之类的标记，投标人一律按录入顺序排列。
* 所有结论写“疑似”“线索”“未找到”，每条附依据（招标文件条款出处 + 投标文件位置）。界面不出现“合格”“通过”“无问题”（与 SPEC 6.8“不出现审核通过”同一原则），只写“未发现问题”。

**建议补充的专业依据**（让疑点报告站得住，不需要联网）：

* 串标线索按《招标投标法实施条例》第四十条“视为投标人相互串通投标”的六种情形归类：由同一单位或个人编制；委托同一单位或个人办理投标事宜；载明的项目管理成员为同一人；投标文件异常一致或报价呈规律性差异；投标文件相互混装；保证金从同一单位或个人的账户转出。每条线索标注对应哪一项。
* 符合性清单内置第五十一条的否决情形作为默认行（未盖章签字、不符合资格条件、提交两份以上不同投标文件或报价、报价高于最高限价、未响应实质性要求等），招标文件没写也列出，用户可关掉。
* 企业自主招标未必属于依法必须招标的项目，上述条文作为“参照依据”写入报告，最终以招标文件的约定为准。条文编号请在入库前对照法规库原文核对一次。

### 1.2 一个关键改动：把流程拆成“开标前”和“开标当天”

招标文件是公司自己写的，发标时就有了；投标文件开标时才拿到。把要求清单的抽取与确认放到开标前做，开标当天只剩“拖文件、看结果”。这是让“评标前几分钟出结果”成立的最大杠杆。

```
开标前（可提前数日，约 10 分钟）          开标当天
① 建项目、上传招标文件            ③ 按投标人分组拖入投标文件（输入 PDF 密码）
② 核对要求清单 → “待开标”         ④ 本地检查（几分钟）→ 总览先出
                                  ⑤ 确认将发送的片段 → 模型核对（随后补上）
                                  ⑥ 逐条核对、标注 → 导出 Word 报告
```

没有提前准备也能用：开标当天从 ① 一路做下去，只是多等一步。

### 1.3 页面与流程

路由 `/bid`（首页）、`/bid/:id`（项目页）。页面套路与“会议纪要”“翻译”一致：首页 = 一句说明 + 新建 + 最近的项目。

**首页 `/bid`**

```
标书初审
招标文件与各家投标文件在本机比对，找出不符合项与串标线索；不打分、不推荐。
[ 新建初审项目 ]                              只是比较几份报价单？用工作台的“比价” →

最近的项目
  设备采购招标 2026-11     待开标 · 要求 42 条已确认              11-12
  物流服务招标             本地检查完成 · 模型核对 3/5 家         今天 10:20
  备件框架招标             已出结果 · 待核对 7                    11-03
```

**项目页**顶部为四步条（可点击回看，不自动跳页）：招标文件与要求 → 投标文件 → 初审结果 → 导出。

**第 1 步　招标文件与要求清单**

* 填项目名称、开标日期（默认今天；用于证书有效期、投标有效期的比较）。拖入招标文件（Word 或 PDF，可含答疑、补遗、澄清文件——后发的澄清会改掉原要求，必须能一起放进来）。
* 本机解析后，页面为左右两栏：左为招标文件原文画布（复用结果页画布组件），右为要求清单。
* 顶部一张“关键参数”小表单，由系统预填、用户改正：最高限价、投标有效期（天）、保证金金额与形式、是否接受联合体、报价币种。这几项直接驱动确定性的本地检查，必须是经人确认的值。
* 要求清单分组：资格条件 / 实质性条款（★）/ 否决（废标）条款 / 报价要求 / 有效期与保证金 / 签章与格式 / “投标文件格式”章节范围（用作范本白名单）。每行：要求文字（可改）、出处（点击在左侧定位）、检查方式（本地规则 / 模型判断 / 人工核对）、启用开关。

**怎样确认得快**（核心是让用户只看“差额”，不必通读）：

1. **规则先行，模型补充。** ★ 号、含“否决 / 废标 / 无效投标 / 不予受理 / 必须 / 不得”的句子、“投标人须知前附表”“评标办法”“投标文件格式”等章节，用本地规则直接抓出，标“原文标记”；模型（招标文件按现有流程脱敏确认后发送）负责归并、分类和补漏，标“模型提取 · 请核对”。选了“不外发”就只有规则结果加人工补充。
2. **完整性计数器**放在清单顶部：“原文 ★ 共 23 处，已全部进入清单”“含否决字样的句子 17 处，已进入 15，未进入 2（查看）”。用户只需处理那 2 处。
3. 默认全部启用，用户做的是“删掉不对的”而不是“勾选对的”。键盘 J / K 上下、X 停用、E 改文字（沿用确认页的快捷键习惯）。
4. 在左侧原文划选文字 →“加入要求清单”，与确认脱敏的划选补充是同一手势。
5. 确认后状态为“待开标”，可随时回来改；开标后改清单只重跑受影响的行。

**第 2 步　投标文件**

* 每个投标人一张卡片：名称（必填，可由封面 / 投标函自动建议）+ 该家的文件列表。可以把几家的**文件夹一起拖进来，按文件夹名自动分组建卡片**（上传前名称可改）；也可逐张卡片拖入。
* 带密码的 PDF：该文件行显示“需要密码”和输入框，输入后才解析。
* 不要求用户标注“商务标 / 技术标 / 报价表”，系统按内容自己认报价表（复用 SPEC 10.1 的报价表识别）。
* 主按钮“开始初审”。至少 2 家才做串标比对；只有 1 家时只出符合性清单。

**第 3 步　初审结果**（见 1.5）　**第 4 步　导出**（见 1.6）

### 1.4 处理过程与两段式结果

**A 段：本地检查（不调用模型，目标几分钟内出总览）**

处理顺序按“先出结果的先做”：文字页解析 → 文件属性与图片哈希（不依赖正文）→ 规则识别的敏感信息交叉比对 → 报价表计算 → 相似段落 → 向量写入；扫描页 OCR 在后台排队，做完一页补一页，相关检查项先显示“扫描页识别中 n / N”。

| 检查 | 做法要点 | 归类（实施条例 40 条） |
|-|-|-|
| 混装 | 甲的文件里出现乙的名称、乙的联系人或印章页 | （五）相互混装 |
| 联系信息相同 | 电话、邮箱、银行账号、证件号、地址、联系人在不同投标人间重复；只用规则识别器，不跑实体识别模型 | （一）（二）（三）（六） |
| 文件属性 | Word：作者、最后保存者、公司、修订会话标识（rsid）；PDF：文件标识、XMP 文档标识、生成软件、创建时间 | （一）同一单位或个人编制 |
| 相同图片 | 嵌入图片字节哈希相同；厂家授权书、检测报告、产品彩页另归“正常重复” | （一）（四） |
| 相似段落 | 先剔除招标文件原文与“投标文件格式”范本，再比各家自己写的部分；相同的错别字、错误编号、异常标点是强线索 | （四）异常一致 |
| 报价规律 | 分项单价比值恒定、等差、同一尾数习惯；Decimal 计算 | （四）报价呈规律性差异 |
| 确定性符合项 | 报价大小写、算术、多个不同总价、超最高限价、投标有效期天数、保证金金额、证书有效期早于开标日（OCR 置信度低时只提示人工看） | 51 条相应情形 |
| 疑似写给 AI 的指令 | 复用 L-21；投标文件里出现这种文字本身就是一条疑点 | — |

**必须处理的误报来源**：各家都是从公司发出的招标文件 Word 里复制格式页，rsid、样式、甚至作者属性会一起带过去。凡是在招标文件里出现过的 rsid、图片哈希、段落，一律先剔除；“生成软件相同”“创建时间相近”单独出现只算弱线索。

**分级**（强 / 中 / 弱；借鉴 bid-dup-check）：单条即可说明问题的为强（混装、联系信息相同、作者属性相同且非招标方、相同独有错误 ≥ 2 处、报价比值恒定）；需要结合看的为中（自写长段落高度相似、非范本图片相同）；仅供参考的为弱。技术章节降一档（同一厂家的产品参数本来就一样），报价章节升一档。

**B 段：模型核对（可选，随后补上）**

* 对每家、每条“模型判断”类要求：用 bge-m3 向量加关键词检索出该家最相关的 2～3 个片段，连同要求原文发给模型，返回“响应 / 疑似不响应 / 未找到 / 无法判断”和所引片段位置。偏离表与正文矛盾并入同一次判断（把偏离表对应行一起给模型），不单独做一类。
* 一家的若干条要求合并成一次调用，估计一个项目 25～40 次调用；全部经模型网关（调用上限 → 出口复检 → 发送 → 记录 llm_calls），不新增任何外发路径。
* **脱敏与确认**：见 1.7 第 1 条。
* 模型看到的是 [投标人A]、[投标人B] 这样的代号，不知道哪家是哪家，本身也是一种“盲审”，可以写进报告的方法说明。
* 不想外发：项目可选“只做本地检查”，A 段的全部结果和报告照常可用。

**耗时与容量（推算，须实测）**

* 向量：按“1 万字 ≤ 5 秒”，5 家 × 200 页约 60 万字，约 5 分钟。
* OCR：按“每页数秒”、同时 1 个，500 页约 25～40 分钟——所以 OCR 必须后台做、结果渐进补上，不能挡住总览。
* 实体识别：按“1 万字 15～32 秒”，60 万字全文要 15～30 分钟以上，**因此不对全文跑**，只对待发送片段跑（去重后估计 10 万字左右，3～5 分钟，可在用户看本地结果时后台进行）。
* 限制建议：单文件 100 MB、单个 PDF 600 页、每项目 OCR 合计 500 页；“每任务最多 20 个文件”在 5 家各交 4 个文件时就满了，建议招标文件不计入，或放宽到 30（见第四节待决定事项）。同一时间只跑 1 个标书项目的解析。

### 1.5 结果页的信息结构

目标：评标委员会进场前，使用者用 3～5 分钟知道“哪家有否决性疑点、哪两家之间有线索”，然后带着报告去。

顶部状态条：`本地检查 已完成 · 扫描页识别 312 / 500 · 模型核对 3 / 5 家`。下面五个页签：

**① 总览（默认，一屏）**

```
投标人        疑似否决项   其他问题   待人工核对   报价（含税总价 / 与限价）   涉及串标线索
甲公司           2           5          3         1,286,000.00  低于限价        强 1 · 中 1
乙公司           0           3          4         1,301,500.00  低于限价        强 1
丙公司           1           2          2         1,420,000.00  ▲ 超限价        —

串标线索  强 2 · 中 3 · 弱 6            两两关系：甲–乙 强1 中1 │ 甲–丙 弱2 │ 乙–丙 中2
覆盖说明  3 个文件 1,180 页已比对；27 页识别置信度低；丁公司《技术标.pdf》第 40～52 页未能解析
```

每个数字都可点，跳到对应页签并筛选好。覆盖说明沿用 SPEC 11.6 的思路：说清楚哪些没查到，避免“没报问题”被当成“没有问题”。

**② 要求响应矩阵**（最适合评标现场对照）

行是要求（按分组，★ 与否决条款在前），列是投标人；首列固定。单元格只有四种：响应 ✓、疑似不响应 ✕、未找到 ？、人工核对 —，本地规则得出的与模型判断的用不同底纹区分。“只看有问题的行”开关默认打开。点单元格在右侧抽屉显示：要求原文与出处、该家对应片段（可跳原件页）、判断理由、核对状态与备注。

**③ 各投标人**

每家一份问题清单，沿用现有问题卡片样式，等级改为“疑似否决项 / 一般问题 / 提示”，按等级排序；“签章页速览”作为该页的一个分区：把要求盖章签字的格式页逐张以缩略图排开（投标函、授权委托书、报价表……），人工一眼核对，可标“已盖章 / 缺章 / 看不清”。

**④ 串标线索**

按强 / 中 / 弱分组，每条卡片写：涉及哪几家、类型、对应实施条例第几项、证据摘要。展开为**左右并排对照**：两家原文并列，相同文字高亮，相同的错别字加重标出；文件属性类用两列属性表；图片类并排显示两张图。“正常重复”（招标范本、厂家资料）单独一组、默认折叠，让人知道系统看到了、但没算作线索。

**⑤ 报价分析**

各家分项对齐表（对齐复用比价模板的做法：模型只对齐项目代号，价格本地还原计算；不外发时按品名文字对齐）、合计与大小写核对、与最高限价的差额、两两分项比值及其离散程度（比值几乎恒定即线索）。不排序、不标最低价。

**核对状态**：每条问题和线索有“待核对 / 已核实 / 已排除”和备注（先显示、失败回滚，属于 SPEC 6.8 允许乐观更新的一类）。导出时“已排除”的不进正文。

### 1.6 导出报告（Word，沿用服务器内存生成、不留存）

1. 封面与说明：项目名称、开标日期、初审人、生成时间；方法说明（本机比对 + 脱敏后模型核对、模型名称与版本、要求清单版本）；固定声明——“本报告为初审线索，不构成对串通投标或否决投标的认定，由评标委员会核实后决定”。
2. 总览表（同结果页总览）与覆盖说明。
3. 要求响应矩阵（只列有问题的行；完整矩阵作附录）。
4. 各投标人问题清单：每条含要求出处、投标文件位置、原文摘录、说明、核对状态与备注。
5. 串标线索：按强中弱；每条含两家原文对照摘录、对应条文。
6. 报价分析表。
7. 附录：要求清单全文、文件清单与属性、签章页核对结果；末尾留“初审人 / 复核人 / 日期”签字栏。

报告中的投标人用真实名称（本地还原）。另提供“只导出串标线索”一个选项即可，不做更多版式。

### 1.7 与现有系统的衔接

1. **脱敏确认**：招标文件走现有确认页，不变。投标文件新增“片段模式”的确认：只显示将要发送的片段（现有画布已有“节点超过 800 个时只显示有替换的段落”的收拢方式，可借用），按投标人分页签，可切 AI 视野；投标人名称在建卡片时已作为词条，必定替换为 [投标人X]；不确定项按现行规则默认替换；回执写“将发送 n 个片段、约 m 字，已在本机保护 k 处；不发送：原件、图片、报价金额、文件名”。一个按钮“确认并开始模型核对”。确认时后端重新生成并复检，与现有做法一致。
2. **模型网关与调用上限**：全部经 gateway.py；llm_calls.purpose 新增一类（如 bid）。一个项目几十次调用，开始 B 段前在确认页写明“本次约 n 次调用，本月剩余 x 次”，不足时不让开始。
3. **本地校验**：直接复用 L-01、L-02、L-04、L-14（算术、合计、大小写）、L-17（账号）、L-18（名称一致）、L-21（AI 指令）的计算，不另写一套。
4. **历史记录**：合并列表加一种类型“标书初审”，点开回项目页；“类型”列现有“会话 / 审核任务”（frontend/src/views/History.vue 第 140 行）扩成四种并可筛选。全局搜索加“新建标书初审”操作与页面项。
5. **权限**：新增权限点 use.bid（标书初审），默认不给普通用户，由管理员分给采购 / 招标办角色；仍然只有本人能看自己的项目（非本人 404）。评标委员会不登录，只拿 Word。
6. **存储与保留期**：投标文件、要求清单、线索明细、PDF 密码按现有敏感字段加密；向量随项目删除；保留期沿用原件层 / 结果层。日志不写投标人名称、报价、密码。
7. **技术栈**：不需要新库、新模型。PDF 密码与属性用 pdfplumber（及其自带的 pdfminer、pypdfium2）即可读取；Word 属性读 docProps 与 settings.xml；图片哈希用标准库；相似度用句级归一化加 bigram 的本地算法。参考项目只借思路，不引入其代码依赖。
8. **数据结构**（仅示意，待设计文档细化）：tasks 增加一种用途；task_files 加“所属投标人”；新增投标人、要求清单、线索三张表；符合性问题可复用 findings / local_findings 加投标人列。全部走 Alembic。

### 1.8 边界与风险

| 风险 | 应对 |
|-|-|
| 串标误报伤及无辜投标人 | 只叫“线索”；每条带证据与“常见的正常原因”（同一代理机构模板、同一厂家资料、招标范本）；先剔除招标文件来源的内容；强线索要求可直接展示的硬证据；报告首页声明不构成认定 |
| 漏报被当作“没有问题” | 覆盖说明写清未解析、低置信、未比对的范围；界面不出现“合格”“通过” |
| 模型判断出错导致误否决 | 模型只给“疑似不响应 / 未找到”并引原文；“未找到”不等于“未响应”，矩阵里用不同符号；否决性结论必须有人点“已核实”才以肯定语气进报告 |
| 责任归属 | 报告有初审人、复核人签字栏；方法、模型、清单版本可追溯 |
| 投标文件含他人商业秘密与个人信息（身份证、社保） | 原件与图片不外发；只发脱敏片段；项目仅本人可见；按保留期删除 |
| 投标人在文件里埋“给 AI 的指令” | L-21 检出并作为疑点列出；提示词中把投标内容声明为待审数据（沿用 17.5） |
| 开标当天系统慢或模型不可用 | A 段不依赖模型，本地结果与报告始终可出；B 段失败只影响“模型判断”类单元格，显示“未核对” |
| 外部关联关系（同一控制人、股权）查不了 | 明确不做（不联网），在报告“未覆盖事项”里写一句，由人工在公示系统核查 |

### 1.9 建议砍掉或推后的部分

* **印章 / 签名自动识别**：不做，改“签章页速览”。（若以后要做，也只做“红色印章样图形”的像素判断，不引入模型。）
* **目录结构比对**（youmeng 四层之一）：招标文件规定了格式，各家目录本来就一样，价值低，不做。
* **投标文件角色标注、文件类型下拉**：不做，系统自己认报价表即可。
* **打分、排序、推荐、评委在线评审、澄清函流转**：不做。
* **项目内自由追问、重新审核多轮、批注版 / 修订版**：第一版不做；需要问就用工作台。
* **外部工商数据、制裁名单**：不做。
* **不写穷举测试**：相似段落、属性比对各放 2～3 组虚构样本即可；串标识别的样本放在 fixtures 下按 golden 方式标注。

### 1.10 分期建议

| 期 | 内容 | 是否外发 |
|-|-|-|
| 一 | 菜单与项目页、按投标人分组上传（含密码 PDF、放宽限制）、A 段全部本地检查、总览 / 串标线索 / 报价分析、Word 报告 | 否 |
| 二 | 招标文件要求清单（规则 + 模型）、片段模式确认、B 段模型核对、要求响应矩阵 | 是（脱敏片段） |
| 三 | 签章页速览、证书有效期提示、历史记录与搜索的收尾 | 否 |

第一期做完就能在一次真实开标上试用，并据此校准分级阈值。

### 1.11 “比价”要不要并入

**不并入，但共用引擎并互相指路。** 理由：

* 比价是随手的小工具（2～6 份报价单、几分钟、在对话里出一张表）；标书初审是有招标文件、有投标人分组、有报告的项目。合在一起会让简单的事变重。
* 询比价的使用者不一定是招标办；放进“标书初审”里，做日常询价的人反而找不到。
* 代码上，报价分析页直接复用比价的“模型对齐代号、本地算价”和 CompareTable 的表格呈现，不写两套。
* 入口上，标书初审首页右上放一句“只是比较几份报价单？用工作台的‘比价’”。以后若采购类功能增多（询比价项目化、供应商对比），再考虑把菜单升级为“采购”分组，现在不必。

## 二、首页与功能入口的整体设计

### 2.1 现状问题的根因

1. **高亮跳动**：MainLayout.vue 第 56～64 行的选中规则是“在 /assistant 首页且 mode=review 时选中智能审核，其余选中工作台”。于是在首页点“全面审核”切换（Assistant.vue 第 39～43、267 行）时，侧栏高亮从“工作台”跳到“智能审核”；而进入会话后同样的切换又不跳。同一个控件，两种表现，用户无法形成预期。第 46 行注释也写明“智能审核”只是“暂留一个版本”的过渡入口。
2. **一个页面两个入口**：加了“标书初审”以后矛盾更明显——标书初审有自己的菜单和页面，产品名里的“审查”主业却只是工作台里的一个切换。
3. **快捷标签打断**：Composer.vue 第 102～106 行，选了需要文件的模板且会话里没有文件时立刻 `pick()` 打开系统文件窗口。用户可能只是想看看这个标签是什么。
4. **首页信息单薄**：只有问候、输入框和四个不带说明的标签（说明藏在悬停提示里，TemplatePicker.vue 第 8、12 行）。新用户不知道系统能办哪些事，老用户回不到上次的工作（要去侧栏近期会话里找）。

### 2.2 设计原则

* **一个菜单 = 一类完整的工作**，名字是名词，页面套路相同：一句说明 + 拖入区 + 最近的。会议纪要、翻译已经是这样，文件审核、标书初审照此办理。这也是法律科技与招采产品的通行做法：一个自由问答的助手，加上若干有固定流程的“工作流”，再加历史 / 资料。
* **高亮表示“这件事属于哪一类”，不表示页面里当前开着哪个视图。** 页面内的切换永远不改侧栏。
* **工作台是首页兼助手**：能直接问，也告诉你别的事去哪办、上次做到哪。
* 不引入新的层级（不做二级菜单、不做顶部导航）；1366×640 一屏内完成。

### 2.3 候选方案

**方案甲：单入口（改动最小）**

侧栏去掉“智能审核”，只留“工作台 / 标书初审 / 会议纪要 / 翻译 / 历史记录”。首页去掉分段切换，把“全面审核”做成快捷标签里的第一个（主色），点了以后输入框变成“加入要审核的文件”，发送按钮变“开始审核”。

* 好处：改动小（MainLayout 删一行菜单、Assistant 首页、Composer）；高亮不再跳。
* 问题：主业“审核”没有菜单，标书初审反而有，轻重颠倒；只有审核权限的人首页是一个不能提问的输入框，别扭；找“我审过的合同”只能去历史记录。

**方案乙：一事一入口（推荐）**

```
┌ 侧栏 ───────────────┐
│ 商衡SI           «  │
│ [＋ 新建会话]        │
│                     │
│ ⌂ 工作台            │  首页：提问、常用工具、入口、继续上次的工作
│  ─ 文件审查 ─        │  （分组小标题，次要色小字；收起为窄栏时是一条细线）
│ ▤ 文件审核          │  原“智能审核”：合同、报价单、订单、函件
│ ⚖ 标书初审          │  新增
│  ─ 工具 ─           │
│ 🎙 会议纪要          │
│ 文 翻译              │
│  ───────            │
│ ↺ 历史记录          │
│ ⌕ 搜索      Ctrl K  │
│                     │
│ 近期会话 …          │
│ ─────────           │
│ 设置 / 用户 / 外壳   │
└─────────────────────┘
```

* **“智能审核”改名“文件审核”**：有了标书初审之后，“智能审核”指不清是哪一种；审的也不只是合同（SPEC 1.4 五类文件），所以不叫“合同审核”。（保留“智能审核”原名也可以，只是含义偏虚，列为待决定。）
* **文件审核成为真正的页面** `/review`：一句说明 + 拖入区（即现在 Assistant.vue 第 271～278 行的审核首页投放区）+ “最近的审核”列表（历史接口按有审核轮次筛选，带“审核中 / 待处理 n”）。旧任务的 `/review/:taskId`、`/review/new?task=` 不受影响。
* **高亮规则**（替换 MainLayout.vue 第 56～64 行）：
  * `/review`、旧审核任务页、**发起过审核或正在审核设置页的会话** → 文件审核；
  * 其他 `/assistant` 页面 → 工作台；`/bid` → 标书初审；会议、翻译、历史不变。
  * 会话内的“审核结果 / 提问”切换保留为页内页签，**不改高亮**。一个纯提问的会话只有在用户点“对这些材料做全面审核”这个动作时才归入文件审核，这是一次明确的“我要去审核”，不是视图切换。
* **底层不动**：仍是 13B 的“工作空间就是会话”，文件只传一次、只确认一次；变的只是入口、首页和高亮规则。旧地址 `/assistant?mode=review` 重定向到 `/review`。

**工作台首页（方案乙）**


首页的三个角色与优先级：

1. **自由提问**（第一位，零学习成本）：输入框不变。
2. **任务导航**：四张入口卡片，每张一句话说明，按权限显示；卡片与侧栏重复是有意的——侧栏给熟手，卡片给第一次来的人和收起侧栏的人。卡片为白底细边、图标单色，不用彩色底。
3. **继续上次的工作**：最多 3 行，取本人最近活动的会话、审核、标书项目，带类别与状态；没有记录时这一块不显示。

首页不再有“直接提问 / 全面审核”切换。拖进输入框的文件照旧进入对话；会话工具条上放一个按钮“全面审核 →”代替原来的分段控件（没发起过审核时）；发起过审核的会话，页内页签写“审核结果 / 提问”。

**快捷标签怎么处理**

* 四个都保留在工作台（都是“对话里的一次性小工具”，与四个菜单的“完整工作”层次不同），前面加“常用”二字说明身份。
* 点击只选中，不弹系统文件窗口：删掉 Composer.vue 第 105 行的自动 `pick()`；选中后模板行就地显示“需要 n～m 个文件”和一个“加入文件”文字按钮（assistantTemplates.ts 里已有 `needsUpload` 与 `TEMPLATE_LIMITS` 可用），也提示可直接拖入。
* 说明从悬停提示挪到选中后的那一行，不必悬停才知道是干什么的。
* “起草回复”不需要文件，行为不变。
* “比价”留在这里（理由见 1.11）。

### 2.4 推荐与理由

**推荐方案乙。** 对用户的好处：

| 改动 | 好处 |
|-|-|
| 文件审核成为独立页面，高亮按归属 | 彻底没有“点一下切换、侧栏跟着跳”；想审核就点文件审核，想问就点工作台，不用先理解“视图” |
| 菜单分“文件审查 / 工具”两组 | 一眼看出主业是审查，其余是辅助；五六个菜单不显得平铺 |
| 四个菜单同一页面套路 | 学会一个就会四个：说明、拖入、最近的 |
| 首页入口卡片 + 继续上次 | 新人知道能办什么，老用户一步回到昨天的活 |
| 标签只选中不弹窗 | 不被打断；知道需要几个文件后自己决定何时加 |

代价是比方案甲多一个页面和一条高亮规则，但没有新接口之外的后端改动（“最近的审核”“继续上次”都能从现有历史接口取）。若想先小步走，可以先做“标签不弹窗 + 去掉首页切换 + 高亮规则”三件，再做卡片与“继续上次”。

## 三、首页“颜色过渡太明显、不够稳重”的收敛方案

### 3.1 是哪些东西造成的

逐项看了 theme.css、skin.css、MainLayout.vue 和首页样式，问题不在某一处，而在几种“光”叠在同一屏：

| # | 位置 | 现状 | 观感 |
|-|-|-|-|
| 1 | 主区域背景 `--si-ambient`（theme.css 第 50、134 行；MainLayout.vue 第 284 行） | 左上一团蓝（浅色 7%、夜幕 14%）、右上一团靛（5% / 10%）两处径向渐变 | 首页卡片四周的留白左蓝右紫，卡片白、底色灰、光斑彩，三种色在边缘相接，是“过渡明显”的主因；夜幕下浓度翻倍更显 |
| 2 | 侧栏选中项（MainLayout.vue 第 247～249 行） | 蓝 20% → 6% 的横向渐变底 + 3px 竖条 + 蓝色辉光阴影 | 一个菜单项上三种效果；配合高亮跳动，更显得晃 |
| 3 | 主按钮辉光（skin.css 第 63 行，`--si-glow-blue` 为 0 6px 20px 蓝 30% / 35%） | 所有实心主按钮都带一圈蓝色光晕，包括首页的圆形发送按钮 | 输入框右下角一团蓝光，偏“消费级” |
| 4 | “新建会话”按钮（MainLayout.vue 第 252～253 行） | 蓝色描边 + 蓝色浅底 + 蓝字 | 与下方选中项的蓝底紧挨，侧栏上部蓝色面积过大 |
| 5 | 品牌渐变 `--si-brand-gradient`、Logo 三色渐变 | 深海蓝 → 蓝 → 青；用在 Logo 与登录页短横线 | 本身没有问题，是品牌识别；问题是 1～4 让它不再“唯一” |
| 6 | 加载光带与文字流光（skin.css 第 359～371 行） | 蓝 / 青 / 靛三色 | 只在等待时出现，属于“AI 正在工作”的语义，可保留；但静止状态（特效关闭档）下的三色横线可以收成单色 |

frontend.md 总则原本就写“光效只表示‘已在本机保护’和‘AI 正在工作’”。第 1～4 项是装饰性的光，不表达任何状态，正是与这条原则不一致、也让人觉得不稳重的部分。

### 3.2 收敛规则（一句话）

**静止的界面只有纯色、细线和浅平底；渐变与辉光只留给品牌标识和“正在工作”的时刻。**

### 3.3 具体改法

| # | 改为 | 浅色外壳 | 夜幕外壳 |
|-|-|-|-|
| 1 氛围光 | 业务页面去掉：`.main` 不再铺 `--si-ambient`，底色就是纯 `--si-bg-canvas`。登录页左侧品牌区可保留一处（那是品牌展示位） | 纯浅灰底 + 白卡片 + 发丝线边框，层次靠边框与极轻的阴影 | 纯近黑底 + 略亮一档的面板；如觉得太平，可只留左上一团、浓度降到 4% 以内，但建议两套一致地去掉 |
| 2 侧栏选中 | 平底：`color-mix(--si-blue 10%, transparent)` 单色；保留 3px 竖条，去掉竖条的辉光；图标主色、文字 `--si-ink-1` 不变 | 浅蓝灰平底 | 同一规则，浓度 14% 左右以保证对比 |
| 3 主按钮 | 去掉 `box-shadow: var(--si-glow-blue)`；实心蓝按钮本身已足够醒目。悬停只变深浅，不发光 | 实心蓝、无光晕 | 同左 |
| 4 新建会话 | 改为中性描边按钮：`--si-hair-strong` 边、透明底、`--si-ink-1` 字，仅加号图标用主色；悬停为 `--si-surface-2` | — | — |
| 5 品牌渐变 | 保持，且**只**出现在：侧栏与登录页的 Logo、登录页短横线、导出报告的封面条（如有）。页面与组件里不再新用 `--si-brand-gradient` | — | — |
| 6 等待动画 | 运动中的光带、流光、墨点保留三色（V3.3 刚确认的方案，属于“正在工作”）；特效关闭档下静止的那条线改为单色 `--si-blue` 50% 透明度，不再是静止的三色渐变 | — | — |
| 其他 | 首页入口卡片、“继续上次”列表一律白底（面板色）+ 1px 发丝线，图标单色 `--si-ink-2`，悬停只加深边框；不给卡片配不同的彩色底或彩色图标 | — | — |

**品牌色（蓝）允许出现的位置**，收敛为五类：Logo；主按钮与链接；当前选中（菜单、页签、分段控件）与输入焦点；“已在本机保护”的护盾胶囊；进度与等待。其余一律中性色。青与靛只在 Logo 和等待动画里出现。

### 3.4 实现约束与范围

* 十六进制颜色仍只在 theme.css；以上改动全部是改令牌的取值或在组件里换用已有变量，不新增色值。可以在 theme.css 新增一个 `--si-select-bg`（选中平底）令牌，供侧栏、表格当前行等统一使用。
* `--si-ambient`、`--si-glow-blue` 令牌先保留定义（登录页还在用），只是业务页面不再引用；theme.css 第 152 行“氛围光与辉光三档都保留”的注释与 frontend.md 第一节、3.2 节相应改写。
* 涉及文件：frontend/src/styles/theme.css、styles/skin.css（第 63、366 行）、layouts/MainLayout.vue（第 247～253、284 行）、views/Assistant.vue 首页样式；frontend.md 同步。纯样式改动，可与导航改动同批，也可单独先做。
* 验收方式：浅色、夜幕各看首页、文件审核首页、结果页三屏，确认静止时屏幕上除 Logo 外没有任何渐变；按规则在测试虚拟机目检，不加样式测试。
