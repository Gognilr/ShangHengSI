## 一、背景与目标

1. 让智能助手成为日常入口，界面统一、不受各电脑浏览器差异影响，客户端常驻、不会被随手关掉。
2. 任务与文件保存在用户本机，服务器只在处理期间及缓存期内保存任务数据，降低服务器上集中保存的敏感数据量。
3. 点开一个已有任务或会话即可继续工作，体验与 Claude Code 的本地会话一致。
4. 审核建议能落到 Word 文件上（批注、修订），原件不被改动。
5. 网关、出口复检、脱敏、还原、owner 校验、加密存储等安全边界不削弱。

## 二、对《UI 改进初步规划》的审核结论

- 方向采纳：智能助手作为首页、设置直达。
- 不采纳双布局切换：长期双倍回归与维护成本，收益有限；只保留侧栏（D12）。侧栏整合导航与会话列表，可收起为 64px 窄栏；窄栏只显示图标，配悬停提示与 `aria-label`（需修改 frontend.md 的图标规则）。
- 不做组件库验证（原 P2）：草图本身为手写 CSS，目标视觉不依赖换库；现有问题在布局与令牌（D13）。
- 全局正文字号保持 14px；对话正文先用 `--si-font-reading`（15/1.8），浏览器实测不足再加一档。
- 首期不做深色模式、字号调整、紧凑密度、登录页改版。
- 原稿第八节安全不变量、第十三节验收清单可作为任务卡输入。
- 原稿中“V2-D-10 待用户确认”已过时（`4cab63b` 已记录确认）；截图主色为青绿 `#117a70`，与现行深海蓝 `#173B68` 不符，截图只作布局参考。

## 三、产品形态

| | 商衡SI 客户端（所有用户） | 管理后台（网页，仅管理员） |
|---|---|---|
| 菜单 | 智能助手、智能审核、审核历史（侧栏，依此顺序） | 账号、模型、审核要求、法规库、公司范本、知识库、脱敏、数据（沿用现有设置页与角色分工） |
| 设置 | 用户菜单 → 常规设置 | 无 |
| 业务数据 | 本机数据目录 | 不显示任何任务内容 |
| 地址 | 客户端窗口加载 `https://服务器/` | `https://服务器/admin`（Chrome / Edge） |

- 管理员也是普通用户：用客户端审核，用浏览器管理，同一账号按角色进入。
- 管理员提醒（SPEC 6.7）：管理后台照常显示；客户端中管理员账号也显示提醒条，附“打开管理后台”（用系统浏览器打开）。
- 用浏览器直接访问业务页面时，显示“请在商衡SI客户端中使用”，不提供业务功能。
- 前端仍是一套代码，构建两个入口（业务端、管理后台），共用组件、令牌与接口代码。
- 默认首页为 `/assistant`。强制改密期间主区域不渲染业务页面（避免页面请求返回 403 `PASSWORD_CHANGE_REQUIRED` 后在改密对话框背后显示错误）。

## 四、本机数据目录与工作文件夹

| 概念 | 是什么 | 怎么定 |
|---|---|---|
| 本机数据目录 | 全部任务与会话的实际存放位置 | 每台电脑一个；默认 `%USERPROFILE%\Documents\商衡SI`；可在常规设置中更改 |
| 工作文件夹 | 用户业务文件所在的文件夹 | 每个审核任务 / 助手会话可选一个，也可不选；客户端记住最近使用的几个 |

规则：

1. 选定工作文件夹**不等于**把其中文件交给系统。只有用户拖入或点选的文件才上传处理。
2. 本机数据目录下按账号分子目录（以用户 ID 命名），同一台电脑上不同账号互不可见。
3. 同一数据目录同时只允许一个客户端实例使用（锁文件）。
4. 本机数据不自动清理，由用户在审核历史中删除；常规设置显示已占用空间。

## 五、任务存储：本机正本、服务器缓存

### 5.1 任务文件夹

```
商衡SI\{用户ID}\
  index.db                               本地索引（任务 / 会话列表，仅用于加速；可由各 manifest 重建）
  workspace.json                         工作区编号、创建时间、格式版本
  审核\2026-10-29 设备采购合同-{短编号}\
    manifest.json                        任务号、标题、时间、来源路径与哈希、各文件哈希、封存包版本
    原件\设备采购合同.docx               上传时复制的原件副本
    view.json                            还原后的结果与追问记录（明文，供客户端直接显示）
    state.shsi                           封存包
  助手\2026-10-29 付款条款整理-{短编号}\
    manifest.json / view.json / state.shsi / 附件\
```

- `view.json` 与审核报告同属本人已还原的结果，明文保存；本地改动不回写服务器，回填后以服务器数据为准重新生成。
- `state.shsi` 包含影响安全的数据（原文节点、对照表、脱敏与疑似项记录、本地校验结果、各轮外发文本与结果、追问记录、条款向量），客户端不能读取或修改。

### 5.2 封存包格式

- 内容：上述数据的结构化导出（按表分段的 JSON，含格式版本）。
- 加密：主密钥 AES-256-GCM（SPEC 17.3 同法），附加数据包含任务号、所属人、工作区编号、封存包版本号、密钥版本、格式版本；任何改动导致解密失败。
- 格式版本：服务器升级时须能读取此前全部格式版本（读取兼容代码随迁移一起维护，并有测试样本）。
- 密钥版本：见 D15。

### 5.3 服务器缓存与墓碑

- 处理中及最近 90 天（D9）使用过的任务，完整保存在服务器数据库与文件目录中，与现在相同。
- 闲置到期：由 worker 清理任务全部数据（沿用保留期清理机制，计时依据 `tasks.last_activity_at`），只留**墓碑**：任务号、所属人、工作区编号、最新封存包版本号与哈希、清理时间。墓碑不含任何内容。
- 一直留在服务器的：墓碑；外发记录（按其保留期，默认 180 天）；审计日志；知识库、法规、范本、设置。
- 管理后台“数据”中，原“原件与原文”“审核结果与对话”两项保留期合并为“服务器缓存”一项。

### 5.4 落地

1. 每完成一步（一轮审核完成、一次追问回复完成、会话消息完成、处理状态或备注修改），服务器生成新版本封存包。
2. 客户端下载封存包与新的 `view.json`，写入临时文件，校验哈希后替换，回报版本号与哈希。
3. 服务器记录“已落地版本”。缓存清理只清除最新版本已落地的任务；未落地的任务延后清理，并在客户端下次启动时补取。

### 5.5 回填

1. 打开已清除的任务：客户端上传 `state.shsi` 与原件副本。
2. 服务器校验：解密成功；所属人为当前用户；工作区编号与请求一致；版本号与哈希等于墓碑记录；原件哈希与封存包记录一致。任一不符返回 404（与非本人一致）或明确的错误码。
3. 恢复到数据库后照常使用；不重新解析、不重新识别。
4. 旧版本封存包（如用户拷回的旧备份）一律拒绝，提示使用最新版本。

### 5.6 工作区编号与隔离

- 客户端首次使用某数据目录时生成工作区编号，登录后向服务器登记（所属人、编号、创建时间）。
- 任务与会话记录工作区编号；列表、详情、继续、导出等接口同时校验所属人与工作区编号，任一不符返回 404。
- 这是产品规则而非安全边界：本人拷走整个工作区可以在另一台电脑继续使用；他人拿到文件也无法打开。

### 5.7 文件变化与缺失的标识

**工作文件夹中的来源文件**（上传时记录路径、大小、修改时间、哈希；打开任务时检查，大小或时间变化才重算哈希）：

| 情况 | 标识 | 影响 |
|---|---|---|
| 未变 | 无 | 无 |
| 已移动或删除 | 文件名旁灰色小字“原位置的文件已移动或删除” | 无 |
| 内容已修改 | 提示“原位置的文件已修改，与本次审核的版本不同”＋“用修改后的文件新建审核” | 当前任务不变 |

**本机数据目录中的文件**：

| 缺失或损坏 | 仍在服务器缓存内 | 已超出缓存期 |
|---|---|---|
| 整个任务文件夹 | “本机文件缺失”＋“从服务器恢复” | “本机文件缺失，无法打开”，可从列表移除 |
| 原件副本 | 打开时自动从服务器补回 | 可查看结果、可追问；不能重新审核；原文预览显示文字内容（沿用“原件已按保留期限删除”的表现） |
| `state.shsi` | 自动补回 | 只读：可查看结果与报告，不能追问或重新审核 |
| `view.json` | 由服务器重新生成 | 有封存包时回填后重新生成 |

审核历史用小标签标出“来源已变化”“本机文件缺失”“只读”；结果页与会话顶部用持续显示的 `el-alert` 说明原因与可做的操作。

### 5.8 数据目录搬迁

更改本机数据目录时，客户端复制全部内容到新目录、逐个核对哈希，成功后删除旧目录；失败则保持旧目录不变。不允许只改路径。

## 六、页面改动

**智能审核（新建）**：上传区不变；上方增加“工作文件夹：未选择 ▾”（选择 / 切换 / 清除，默认上次所选）；选定后在上传区旁列出该文件夹中可审核的文件，点选加入。确认脱敏、审核中不变。

**智能助手**：新建会话可选工作文件夹（显示在会话标题旁）；会话列表在侧栏中，可按工作文件夹筛选；添加文件方式同审核页。

**管理后台**：现有八类设置原样迁入独立入口；“数据”中保留期按 5.3 调整。

## 七、登录

- 客户端：持久会话，不设空闲过期、不锁屏；会话 30 天未使用自动失效。失效条件还包括：退出登录；修改密码（同时使本人其他会话失效）；管理员停用账号或重置密码（客户端立即回到登录页）。会话 Cookie 保存在客户端配置目录中，由内核用 Windows DPAPI 加密。
- 管理后台：维持 SPEC 17.1（浏览器关闭即失效、空闲 8 小时过期）。
- 其余（argon2id、CSRF、5 次失败锁定 15 分钟）不变。

## 八、导出：报告、批注版、修订版

| 导出 | 内容 | 用途 |
|---|---|---|
| 审核报告（现有，SPEC 14） | 不变 | 内部存档、报批 |
| 批注版副本 | 原文正文一字不改；每条问题以 Word 批注挂在对应原文上（等级、问题、建议、依据），作者“商衡SI” | 内部逐条查看与修改 |
| 修订版副本 | 只把“已采纳”且有 `suggested_text` 的问题写成 Word 修订（删除＋插入），不含批注 | 用户在 Word 中逐条接受 / 拒绝后可对外发送 |

- 文件名：`{原文件名}_商衡SI批注_{yyyyMMdd}.docx`、`{原文件名}_商衡SI修订_{yyyyMMdd}.docx`；同名自动加序号，绝不覆盖。
- 导出批注版时提示“批注版含内部审核意见，请勿直接发给对方”。
- 范围：.docx；旧格式 .doc 等经 converter 转换后输出 .docx。PDF、扫描件、Excel 只出审核报告。
- 在服务器生成（需对照表还原与原文节点到 Word 位置的映射，后端已有 python-docx 1.2.0 与 lxml）；需要原件时用缓存，超出缓存期先回填。生成结果下载到本机，服务器不保留。导出写审计日志。
- 定位失败的问题：批注挂在所在段落开头，修订版中不做修订；导出完成提示“共 N 条，M 条未能精确定位”。
- **硬性校验**（自动测试）：批注版正文与原件逐字一致；修订版“全部拒绝”等于原件、“全部接受”等于预期文本。校验失败不输出文件。
- **模型输出约束（修订版前提）**：审核提示词要求 `quote` 为某一节点内一字不差的连续片段，`suggested_text` 为对该片段的完整替换；服务器校验 `quote` 在该节点中恰好出现一次才允许做成修订，否则只加批注。模型从不接收或产出文件（D11）。

## 九、安全不变量

保持：

1. 模型调用只经网关（调用上限 → 出口复检 → 发送 → 记录）；外发只有脱敏文本与现行允许的引用；`local_only` 不调用模型。
2. 出口复检、还原在服务器进行，使用服务器持有的对照表；客户端不提供、不修改对照表。
3. owner 校验不变，另加工作区编号校验；不符一律 404。
4. 服务器端敏感字段加密方式不变；封存包同样用主密钥加密。
5. 日志、URL、审计中不出现原文、真实名称、金额、密钥、本地路径。
6. 模型回复与原文继续以安全文本节点显示，不引入 `v-html`。

新增：

7. 客户端只连接本系统服务器，不访问外网（关闭内核自动更新、崩溃上报、遥测）。
8. 本地接口不接受页面传入的任意路径：读取只限用户经系统对话框选定或拖入的文件、已选工作文件夹、本机数据目录；写入只限本机数据目录与用户选定的保存位置。
9. 选定工作文件夹不触发任何上传。
10. 原件不被修改；所有导出生成新文件，不覆盖。

## 十、客户端技术方案

- **Electron 薄壳**（MIT）：窗口加载服务器页面，界面随服务器升级；自带固定版本内核，各电脑显示一致。不选 Tauri（Windows 上依赖系统 WebView2，版本随系统变化）。
- 加固：`contextIsolation`、`sandbox` 开启，`nodeIntegration` 关闭；只允许导航到配置的服务器地址；打开 `/admin` 或其他链接时交给系统浏览器。
- 证书：安装时写入 Caddy 内部根证书指纹，客户端只信任该证书，不出现证书警告。
- 本地接口（preload，仅对服务器源开放）：选择数据目录 / 工作文件夹、列出工作文件夹中的可审核文件、读取用户选定文件、读写任务文件夹、计算哈希、在资源管理器中显示、用默认程序打开、系统通知、托盘与开机自启。
- 安装与升级：服务器提供下载页与版本信息；客户端启动时比对，壳版本过低时提示更新（从服务器下载）。
- 浏览器差异只剩管理后台，指定 Chrome / Edge。

## 十三、待确认与开放问题

编号进入正式批次时按当时的问题索引分配。

1. Electron 版本与安装包形式（安装器 / 免安装），在 V3-B 设计中定。
2. 缓存期内未落地的任务（客户端长期未启动）是否设上限，超过后按普通清理处理。
3. 本地索引中的标题为明文（含文件名），与原件同在本机，本稿视为可接受。
4. 浏览器访问业务页面的提示页文案。
5. 退役主密钥的保存方式（与现行主密钥同等保护、只读、不参与新数据加密），在 V3-A 设计中定。

## 十四、不做

共享盘工作区；跨设备同步；换电脑迁移与电脑损坏恢复（用户可自行拷贝整个工作区）；把文件或图片发给模型；由模型生成文件；在线文档编辑；PDF / Excel 批注；顶部 / 侧栏布局切换；深色模式、字号调整、紧凑密度；更换组件库。
