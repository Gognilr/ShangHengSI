## 〇、核心演进原则

1. **严守产品基因与安全铁律**：保持“局域网单机、零重型外部依赖、不引入未批模型、外网仅限模型网关与法规同步双出口、原件与敏感字段全加密、跨人 100% 返 404”。
2. **永不过度设计**：不做华而不实的统计大屏、不做假想攻击的繁琐开关、不无故新增侧栏一级菜单；一切研发投入聚焦于**脱敏更快更准不误拦、标书开标现场 1 小时敢拍板、日常合同与单证审查真正省心**。

## 一、脱敏、反脱敏与出口复检机制优化（效率 × 准确率）

### 1.1 标书片段脱敏补齐 `ner_cache` 与残余文本去重推理（效率）
* **现状根因**：普通审核在 `backend/app/redaction/engine.py`（`_run`）读写了 `NerNodeResult` 节点级缓存；但标书模块 `backend/app/bid/model.py`（`redact`）直接调用 `E.compute()` 时未传 `ner_cache`，且 `compute()` 内未对相同 `residual`（规则掩码后的残余文本）去重。5 家投标书中大量照抄技术规范或通用承诺的相同段落，在 OCR 补页重准备、调整要求或二次核验时，会在 CPU 上反复重跑 FP32 GLiNER。
* **改法**：
  1. `engine.compute()` 内对非空 `residual` 先按文本去重跑一次 `ner.recognize()`，再按节点映射展开；
  2. `bid/model.py` 接入 `NerNodeResult` 加密缓存读写。
* **预期收益**：零模型与识别口径变更，标书片段准备及重跑耗时下降 **50%～80%**。

### 1.2 消除出口复检与片段闭合中的 $O(M \times N)$ 逐词重扫瓶颈（效率）
* **现状根因**：当大样本标书保护项破千时（如 V34Q-36 达 1,207 项），`backend/app/redaction/recheck.py`（`_value_reasons`）对每个词条单独编译正则扫描 3 个文本视图；`backend/app/bid/model.py`（`_close_snippets`）为获取 `MAP/TERM` 精确终点 `end`，在每轮、每个片段上又把上千个正则嵌套重扫一遍（最多 3 轮）。
* **改法**：
  1. `recheck._match_positions` 直接通过 `normalized.index_map` 返回精确原文起止区间 `(start, end)`，删除 `_close_snippets` 中的全量二次正则扫描；
  2. 对占 90% 以上的常规中文词条按长度降序分批合并联合正则（或首字二元组预筛），仅对含特殊跨空白弹性的英文/编号词条走独立模式。
* **预期收益**：20 万字级大标书出口复检与闭合从秒级降至百毫秒内。

### 1.3 打破“对照表只增不减”引发的误识别滚雪球（准确率 · 防误杀）
* **现状根因**：标书片段脱敏无人工逐处撤销环节，GLiNER 中置信（`0.4`）误抓的 2～3 字技术词或通用岗位词一旦写入 `RedactionMap`，不仅被 `_sweep` 全文强替，还会在出口复检时拦死系统自身的固定提示词（V34Q-38、V34Q-47）。
* **改法**：
  1. **系统固定提示词自免疫（Prompt Guard）**：提取各模块固定系统提示词中的常规词汇表，禁止自动 NER 将其中的普通词登记为敏感实体表面值（用户手工指定词条除外）；
  2. **跨投标人横向文档频率（Cross-Bidder DF）抑制**：在标书多投标人场景下，对无机构后缀、无明确冒号槽位、仅由 GLiNER 中低置信（如 `0.40～0.75`）识别出的 2～3 字短词，若同时出现在 ≥ 3 家不同投标文件中且不属于招标方或投标人名称，判定为行业通用术语，抑制入全局表。

### 1.4 表格列头语义向下传播（准确率 · 防漏检）
* **现状根因**：人员花名册、社保证明、历史业绩表中，表头（`姓名 | 身份证号 | 客户名称 | 业主单位 | 开户行`）位于首行，第 2～N 行的生僻两字人名或单位简称因远离标签而缺少槽位证据。
* **改法**：在 `redaction/tables.py` 与 `detect.py` 中识别表头行的列语义类别，向同列下方数据格赋予槽位先验（Slot Prior），无需降低全局 NER 阈值即可精准召回表格内敏感实体。

### 1.5 反脱敏还原统一收敛至 `restore.check()`（还原准确率）
* **现状根因**：普通审核与助手使用 `backend/app/redaction/restore.py` 中的 `check()`（支持全角双括号、空格变体、漏层括号、英文角色别名及剥离金额比例后缀）；而标书 `bid/extract.py` 与 `bid/model.py` 调用的是简陋版 `restore()`，遇到模型输出 `［［ORG_1］］`、`[投标人 A]`、`[ORG_1]` 或裸 `投标人A` 时无法还原。
* **改法**：统一标书要求、矩阵理由、冲突说明与报告摘录的还原入口至 `restore.check()`，并增加标书专属 `[投标人A]` 空格/全角变体的安全归一。

## 二、标书初审功能深化（面向开标现场实战）

### 2.1 升级“章节面包屑 + 评标索引表页码直达”双路检索（解决未找到与漏取响应）
* **现状根因**：V34Q-48 大样本 260 格中有 127 格“未找到 / 无法判断”。`bid/model.py`（`passages` / `retrieve`）按 400 字切块时丢失了父级章节路径，跨页内容失去主题词；未利用投标书前部《评标索引表 / 资格审查导航表 / 偏离表》中现成的“详见第 xx 页”指引；`0.8 × best[0]` 截断易误杀字数极少的 OCR 证照页。
* **改法**：
  1. 每个检索片段拼入 `[一级章节 > 二级章节]` 面包屑前缀参与向量化与二元组评分；
  2. 本地规则解析投标书前部的索引表/响应表/偏离表页码映射，将指向的目标页码节点直接纳入保底候选；
  3. 对“资格条件”类要求，保底保留得分最高的证照类短页，豁免 80% 硬截断。

### 2.2 PDF 独立大图局部 OCR + DOCX 证照贴图渐进 OCR（打通图像凭证盲区）
* **现状根因**：`backend/app/parsing/pdf.py`（`_is_mixed`）规定整页文字 ≥ 200 字或图片面积 < 页面 50% 即跳过 OCR，导致“半页文字说明 + 半页银行保证金回单截图”必漏（V34Q-49）；`parsing/docx.py` 对 `.docx` 内嵌的营业执照、银行回单、社保证明图片完全不识字。
* **改法**：
  1. PDF 页面只要存在内部无矢量文字覆盖的独立大图（如单图面积 ≥ 页面 12% 且短边 ≥ 160pt），仅裁剪该图片区域送 RapidOCR 补作 `ocr_block`；
  2. 标书模式下，将 `.docx` 中达到证照尺寸阈值的内嵌图片排入后台 `defer_ocr` 渐进识别。

### 2.3 多形态报价支持：下浮率/费率报价、含税/不含税同行配套
* **现状根因**：服务、工程与框架招标常见“按基准价下浮 X% / 费率报价”，设备招标常见同行并列“不含税价、税率、含税价”或主辅机分列。
* **改法**：
  1. 第 1 步关键参数增加报价形态选项（固定金额总价［默认］ / 费率或下浮率）；
  2. `bid/pricing.py` 自动识别同行/同表的 `不含税价 × (1 + 税率) ≈ 含税价` 配套关系，验证税额算术并避免误报“多个矛盾总价”。

### 2.4 串标相似段落信噪比提升：公版套话降权 + “同错同瑕”铁证提权
* **现状根因**：`bid/similar.py` 未过滤注册会计师标准审计报告意见段与 `GB/T`、`ISO`、`API` 等标准条文，仅两家附带标准审计报告即可能触发“两家独有相同句 ≥ 5 处”的强线索误报。
* **改法**：
  1. 内置标准审计意见段、常见法定声明套话及含国家/行业标准号的条文识别，自动降为公版参考；
  2. 新增高信噪比串标特征：**非招标基线的罕见错别字共现、残留同一外部项目名/非本标业主名、偏离表自填异常格式或分项异常小数尾数共现**，直接提权进证据链。

### 2.5 扩充本地确定性废标检查项
* **改法**：在 `bid/compliance.py` 中新增三类高频刚性指标的本地确定性比对（`Decimal` + 日期解析）：
  1. **工期 / 交货期**是否超过招标上限；
  2. **质保期 / 缺陷责任期**是否短于招标下限；
  3. **类似业绩一览表**中的合同签订日期是否在要求时间窗内、单项金额是否达标、有效份数是否满足下限。

### 2.6 按投标人一键生成 Word《投标文件澄清/询标函》
* **业务价值**：按《招标投标法实施条例》第五十二条，异常低价、大小写不一致、前后矛盾须书面发出澄清通知由投标人确认。
* **改法**：不增菜单，在结果页支持按家内存拼装导出单份 Word《询标/澄清通知书》（仅含针对该家的待澄清客观事实、原文位置摘录与回复签章栏，严禁混入其他投标人信息，服务器不留存文件）。

## 三、全平台产品功能演进（工作台、合同与单证）

1. **同一会话内“合同修订前后 Diff 对比 + 增量复审”**
   * 在现有工作台审核会话中上传对方改回的二稿/三稿时，本机内存确定性对比两版段落与条款增删改（即使对方关闭了 Word 修订模式也能精准标出暗改处），支持仅对变更条款与上轮未决风险发起增量 AI 复审，节省 60% 以上模型调用额度。
2. **PDF / 扫描件导出《合同修改意见与建议条款对照表》Word**
   * 针对无法原位回写 Word 批注的 PDF 锁版文件，支持一键内存导出“原页码与条款 ｜ 风险说明 ｜ 建议替换条文”双栏 Word 附件，直接用于商务邮件谈判。
3. **企业知识与补充要求的“顺手沉淀”微闭环**
   * 允许一线人员在审核或标书项目中将典型好条款、高频漏检要求一键提交为“公司范本 / 补充要求草稿”，业务管理员在“设置 → 管理”一键审批启用，解决后台知识库无人维护的难题。
4. **单证核对深化：信用证（L/C）单据日期铁律与溢短装容差**
   * 在 `V34-A-08` 本地归一化核对基础上，增加国际贸易审单确定性规则：`提单日 ≤ 最迟装运期`、`保单签发日 ≤ 提单日`、`发票总额 ≤ 信用证金额` 及 `±X%` 溢短装条款识别。
5. **低配内网服务器本地模型内存韧性编排**
   * 经黄金样本对拍评估将 worker 内 `GLiNER` 由 FP32 ONNX 量化至 INT8，并打通 worker 密集 OCR/向量化与 `/spool` 下 `transcriber`、`translator` 的内存繁忙退让信号，保障 16GB～24GB 虚拟机高负载稳定运行。
