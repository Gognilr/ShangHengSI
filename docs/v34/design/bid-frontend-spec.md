# 标书初审结果页前端规范（B-08b 第 6 条、B-09、B-06e 必须遵守）

状态：Claude Opus 5.5 起草，用户 2026-11-17 要求“给严格的规范，防止偏离”。本文是**硬性规范**：凡是这里写明的结构、文案、令牌、顺序，照做，不得自行发挥。确有做不到或明显更好的做法，先在报告里写明理由并问用户，不得先做后报。视觉总则仍以 visual.md 为准；本文与 visual.md 冲突时以本文为准。

## 〇、十条总规则（每次提交前逐条自查，报告中写“十条已自查”）

1. **结论先于数据。** 每个页签第一行是一句结论（`BidLede`，`.bid-lede`）；表格和图只作证据。不得出现没有结论句、开头就是表格的页签。
2. **只摆异常。** 没问题的格子只显示 `✓`（`--si-ink-3`），不显示数字、不写“响应”“正常”。“—”只用于“不适用”，未识别写“未识别”，二者不得混用。
3. **三层，三种样式，不得增加第四种：**
   * 确凿：6px 圆点 `--si-danger` + 文字 `--si-danger-ink` 600；
   * 需核实：6px 圆点 `--si-warn` + 文字 `--si-warn-ink` 600；
   * 参考：无圆点，文字 `--si-ink-3` 400。
   * 未发现问题用墨色对勾 + `--si-ink-2`。
   * 不得用底色块、彩色胶囊、`el-tag` 的 type 色、左侧色条、图标颜色来表示等级。
4. **颜色只用令牌。** 不写十六进制、rgb、hsl，不新增令牌。不得用渐变、阴影（浮层除外）、辉光、半透明彩色底。
5. **每屏至多一个主按钮。** 结果页的主按钮固定为页头的“导出初审疑点报告”，页签内一律用默认按钮或文字按钮。
6. **数字：**
   * 金额由后端给出已格式化的字符串（Decimal，千分位，两位小数），前端不做浮点运算、不重新格式化；
   * 数字列右对齐，`font-variant-numeric: tabular-nums`；
   * 百分比保留一位小数并带正负号，例如 `+3.2%`、`−23.0%`，负号用 U+2212。
7. **不藏关键信息。** 结论、理由、金额不得只放在 tooltip 或悬停中；悬停只能作补充。
8. **不新增：** 页签、页面、菜单、弹窗式向导、图表类型（只允许已有的 PriceStrip、RatioCurve、ClueGraph、SimilarMap、FileTimeline、ProgressBar）、第三方依赖、图标库。图标沿用项目现有的。
9. **文案用本文第五节的原文。** 不得改写成同义说法，不得加感叹号、emoji、英文，不得使用“AI 认为”“智能”。称谓用“投标人”“评标委员会”，不用“供应商”“专家”。
10. **尺寸与检查：**
    * 版心沿用项目页现有宽度；
    * 在 1366×768（浏览器 100%）下，结论区第一屏不滚动必须看到：结论句、每家一行、第一张案件卡的标题行与“需你核实 n”标题；
    * 1024 宽不得出现横向滚动；
    * 浅色与夜幕各截图一张交用户。

```
页头（不变）：面包屑 / 项目名 / meta / 主按钮“导出初审疑点报告”
四步条（不变）
状态行（不变）：模型核对与二次核验进度、“查看实际发送内容”
页签：初审结论 n ｜ 要求响应矩阵 n ｜ 各投标人 ｜ 串标线索 n ｜ 报价分析
```

* 第一个页签“总览”改名为**“初审结论”**，组件 `BidOverview.vue` 改为 `BidConclusion.vue`（旧文件删除，不保留两套）。页签计数＝需核实条数（为 0 时不显示数字）。
* 其余四个页签只作证据与明细：页签内的“待你处理”“逐条核对”入口全部改为指向“初审结论”的“需你核实”，不再在各页签各自维护一份待办。

## 二、“初审结论”页签（自上而下，顺序固定，块间距 32px，沿用 `.bid-tab`）

**1. 结论句**（`BidLede`，最多两行）。按以下句式拼接，没有的部分整段省略：
`{n} 家投标人中，{a} 家建议否决（证据确凿），{b} 家需核实；发现 {k} 组疑似串通投标。`
全部正常时只写：`{n} 家投标人均未发现否决情形与串通线索。`
模型核对或二次核验未完成时，第二行用 `.sub`：`模型核对未完成，结论可能变化。`
只做本地检查的项目，第二行写：`本项目只做本地检查，未核对响应性要求。`

**2. 各家结论表**（`.bid-table`，四列，列宽与顺序固定）：

| 列 | 内容 | 规则 |
|-|-|-|
| 结论（定宽 112px） | `建议否决` / `需核实` / `未发现问题` | 用第〇节第 3 条的样式 |
| 投标人 | 卡片名称，`td.name`，一行，超长省略号 + `title` | 按录入顺序，不排序、不提供排序 |
| 理由 | 最多 3 条短语，用“；”连接，超出写“等 n 项”；每条短语可点击，跳到对应证据 | 短语用第五节的写法，例如“超最高限价 +3.2%”“与丙串通（第四十条（一））”；未发现问题时理由列为空 |
| 投标总价（右对齐） | 金额字符串；来源为人工录入的，下一行小字写“唱标价 · 人工录入” | 未识别写“未识别”（`--si-ink-4`），点击跳到报价分析页对应行 |

不得再出现“疑似否决数”“其他问题数”“核对进度”“与限价”等数字列；这些信息放在理由里，或放到其他页签。

**3. 疑似串通投标**（标题 `.bid-title`：`疑似串通投标` + `.n` 组数；为 0 时整块不显示）。每组一张**案件卡**（`BidCaseCard.vue`，对象卡样式：1px `--si-hair`、`--si-radius-card`、透明底、内边距 16px 20px）：

```
● 甲、丙 疑似串通投标 · 第四十条（一）（四）                 [确凿] 或 [需核实]
  1  两份 PDF 的原始文件标识相同                              查看 ›
  2  分项单价比值恒定：1.0300，变异系数 0.02%，共 12 项        查看 ›
  3  项目经理身份证号相同                                     查看 ›
  已剔除：与招标文件相同的句子 38 句、图片 4 张              ▸ 常见的正常原因
```

* 标题行：圆点与等级按第〇节第 3 条；投标人用卡片简称，用“、”连接，三家以上在标题前加“围标：”；法条写到项。
* 证据行按强度排列，每行一句事实，带序号。数字用等宽字体。行尾“查看 ›”为文字按钮，点开后在卡片内展开：两家原文并排（复用串标线索页签的并排组件）或页图缩略。同一时刻只展开一条。
* 证据行不得写“可能”“或许”；不确定性只由卡片右上角的等级表达。
* “常见的正常原因”默认收起，展开后为细线列表。
* 卡片右下角操作：确凿卡为文字按钮“有异议”；需核实卡为 `Y 属实`、`N 不属实` 两个默认按钮。点击 N 时弹出原因单选，见第四节。

**4. 需你核实**（标题：`需你核实` + `.n` 条数；为 0 时显示一行 `.bid-empty`：`没有需要核实的事项。`）。

* 列表行，不用卡片。每行依次为：
  * 序号；
  * 等级圆点（只有需核实一种）；
  * 一句话，格式为“{投标人简称}：{事实}”，例如“乙：未找到“投标保证金”的缴纳证明（要求 12）”；
  * 右侧依据（法条或“招标文件第 x 章”）；
  * 行尾 `查看 ›`、`Y`、`N`。
* 排序：先疑似否决，再串通（较强），再其他；同类按投标人录入顺序。
* 键盘：J / K 上下移动当前行，Y / N 判定，Enter 展开证据，Esc 收起。沿用 `BidFocus.vue` 的按键实现，不另写一套。
* 判定后，该行原位变为墨色小对勾 + “已核实 · 属实”或“已核实 · 不属实（原因）”，保留 3 秒后移入页尾的“已核实 n 条”折叠区（`.bid-fold`）。不得弹出成功提示。
* 条数超过 10 时，标题右侧 `.end` 写 `超过 10 条，已按严重程度排序`，不分页。

**5. 签认确凿项**：一行，左侧写 `确凿项 {m} 条已由本机证据确定。评标委员会阅后签认即可，有异议可在对应条目点“有异议”。`，右侧放默认按钮 `签认确凿项`。签认后改为墨色对勾加 `已签认（{时间}）`，可撤销，撤销用文字按钮。m 为 0 时整行不显示。

**6. 参考事项**：一行 `.bid-fold`：`参考事项 {r} 条（不影响结论）`，展开后为按类别分组的细线列表，每组标题后带条数，组内每行一句事实。默认收起，折叠状态不记忆。

**7. 现场核验清单**：一行 `.bid-meta` 写 `需在现场核验原件的要求 {q} 条，已写入导出报告的“现场核验清单”。`，后面带文字按钮 `查看`，点击展开细线列表。不提供勾选（在纸上勾）。

**8. 页脚**：沿用 `.bid-foot`，固定两行：`系统只给出建议；否决与串通投标的认定由评标委员会作出。`和`二次核验 {c} 次，均经本机脱敏与出口复检。`（c 为 0 时省略第二行）。

## 三、报价分析页签（B-06e，按 bid-pricing.md，补充硬性规定）

* 顺序固定：结论句 → PriceStrip → 各家报价表 → 报价方面需你核实（只列此类，数据与初审结论页同源，判定在任一处做两处同步）→ 修正后报价（有才显示）→ `.bid-fold` 的“明细（供复核）”。
* 各家报价表只有三列：投标人 ｜ 投标总价 ｜ 结论。
  * 结论为标签串，标签样式按第〇节第 3 条，标签之间用 8px 间距、不加分隔符；没有问题显示 `✓`。
  * 投标总价下一行小字写出处：`开标一览表 · 第 2 页`（可点击，打开页图）或 `唱标价 · 人工录入`。
* 录入唱标价：总价单元格右侧有文字按钮 `录入` 或 `修改`，点击后在格内变为输入框，依次为小写金额、可选的大写金额、`保存`、`取消`。
  * 不弹对话框；
  * 回车保存，Esc 取消；
  * 保存后整页重算，期间只把该页内容变淡，不出现全屏 loading；
  * 金额格式不对时，在输入框下方一行写 `请输入金额，例如 1234567.89`。
* 结论句必须如实写明未识别的情况，不得写“未见问题”：可比较的不足 2 家时写 `{x} 家未识别出投标总价，报价比较与规律检查未进行；可录入唱标价。`；否则写 `{x} 家未识别出投标总价（简称），报价比较不完整；可录入唱标价。`。多个总价、币种不同同样写明（B-06e，用户 2026-11-19 确认）。
* 没有总价的行，结论列写 `—`。
* “明细（供复核）”展开后依次为：总价比较小表（比最低价高、偏离平均）、分项对齐表（只给异常格加 `--si-warn-ink` 文字色，不加底色）、两两比值表、比值曲线（只有发现规律的那一对）。

## 三之二、要求响应矩阵（B-08b 第 6 条）

* 第一行为结论句：`{n} 条要求中，{a} 条有家疑似不响应，{b} 条有家未找到响应内容。`
* 行首为序号，与要求清单、Word 报告一致。
* 分组标题行顺序固定：否决条款 → ★ / 实质性条款 → 资格条件 → 一般要求 → 人工核对。标题行写 `{组名} · {条数}`，右侧用 `.end` 写 `疑似不响应 {x} · 未找到 {y}`（为 0 的项省略）。
* 组内有问题的行在前；每行不再重复组名与判断方式。
* 单元格只用以下五种：
  * `✓`（`--si-ink-3`）表示响应；
  * 需核实圆点加 `不响应`；
  * 需核实圆点加 `未找到`；
  * `？`（`--si-ink-3`）表示无法判断或引文待核实；
  * `—` 表示不适用。
  * 确凿的不响应用确凿样式。
* “只看有问题的行”默认开启。

## 四、交互细则（各处一致）

* **N 的原因单选**：使用 `el-popover`，挂在 N 按钮上。依次为：`招标范本或标准规范`、`同一厂家资料`、`识别错误`、`模型判断有误`、`其他`。选“其他”时出现一行输入框，必填，最多 50 字。下方复选框写 `以后同类不再报（仅本人）`，默认不勾选。确定按钮为默认按钮 `确定`。
* **联动降级提示**：选 N 后，若有同源条目被一并降级，在该行下方一行 `.bid-meta` 写 `同一来源的 {n} 条已一并移入参考事项`，带文字按钮 `撤销`，保留到下一次操作为止。
* **乐观更新**：判定当即显示结果；请求失败时恢复原状，并在该行下方用 `--si-danger-ink` 写 `保存失败，请重试`。不得弹出全局错误提示。
* **跳转**：所有“查看 ›”和理由短语都在本页展开或切换页签并定位。目标出现后 1.2 秒内用 `--si-select-bg` 底提示一次，然后消失。不得打开新窗口。

## 五、标准文案（原样使用）

| 场合 | 文案 |
|-|-|
| 超限价 | `超最高限价 +{金额}（+{x}%）` |
| 多个总价 | `出现 {n} 个不同的投标总价` |
| 大小写 | `大写与小写金额不一致` |
| 计算 | `报价计算错误 {n} 处` |
| 合计 | `报价表合计与投标总价不符` |
| 异常低价 | `低于其余各家平均 {x}%，需澄清是否低于成本` |
| 唱标不一致 | `文件总价与唱标价不一致（差额 {金额}）` |
| 串通（理由短语） | `与{简称}疑似串通（第四十条（{项}））` |
| 不响应 | `未响应“{要求简称}”（要求 {序号}）` |
| 未找到 | `未找到“{要求简称}”的响应内容（要求 {序号}）` |
| 二次核验改判 | `二次核验找到响应，已改为响应` |
| 混装 | `文件中出现{简称}的{封面 / 印章页 / 名称}` |

要求简称取要求原文的前 16 个字，超出时以“…”结尾。

## 六、Word 报告

章节顺序与初审结论页签一致：结论句 → 各家结论表（同四列）→ 疑似串通投标（案件卡逐张转成小节，证据编号相同）→ 需核实事项（写明核实结果；未核实的单列“尚待核实”）→ 已签认的确凿项 → 现场核验清单（带勾选方框）→ 附录：参考事项、完整矩阵、报价明细、文件清单。文案与第五节相同。
