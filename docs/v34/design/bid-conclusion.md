# 初审结论、证据链与二次核验（V34-B-09）

状态：Claude Opus 5.5 起草，**用户 2026-11-17 确认**。用户要求：开标现场时间紧，只给重点；围标、串标要给出证据链，一步到位；审核结果尽量少靠人核实，严重问题才交人核实并反馈、及时改正，必要时二次交模型审核。

本设计改变结果页的组织方式：过去是“列出全部发现，由人逐条排除”，改为“系统先下结论，只把严重又不确定的少数几项交给人”。检查算法本身不推倒重来，而是在其上增加归并、分层、二次核验与反馈。

## 一、三层输出：每条发现必须落在其中一层

| 层 | 含义 | 界面 | 是否要人处理 |
|-|-|-|-|
| **确凿** | 本机确定性证据，误判可能极小：同一 PDF 原始标识 / XMP 文档标识、相同的身份证号 / 银行账号 / 项目经理证号、混装（甲的文件里出现乙的封面或印章页）、有效总价超最高限价、两个以上不同总价，以及二次核验后两轮结论一致的不响应 | 结论区直接写成结论，附证据 | 不逐条核实：评标委员会整体签认一次（“以上确凿项已阅”），有异议才点开某一条改判 |
| **需核实** | 严重（可能否决或构成串通），但证据不确定：单一的中等线索、模型两轮结论不一致、OCR 低置信、引文未核实 | “需你核实”，**每个项目目标 ≤ 10 条**，按严重程度排序 | 是：Y 属实 / N 不属实 + 选原因 |
| **参考** | 不影响结论：弱线索、正常重复、提示、响应的单元格、只差格式的小问题 | 默认收起，只显示条数；Word 报告放附录 | 否 |

规则：一条发现只有在“严重”且“不确定”时才进入需核实。不严重的再不确定也只进参考；确凿的不再要人逐条排除。“待人工核对 56 条”这种做法取消。招标文件要求在现场核验原件等无法在文件中判断的“人工核对”行，不再逐格待办，改为一张“现场核验清单”，导出 Word 后打印给评委勾选。

## 二、串通投标：按“案件”给出证据链

* **归并**：把两两之间的全部信号（文件属性、相同图片、相同联系信息、混装、相似段落、报价规律、保证金账户）按投标人对归并；有确凿或较强证据的对用并查集连成组，三家以上连在一起即“疑似围标”。一组输出一个案件，不再是七条零散线索。
* **证据强度**按证据的组合判定，而不是数量：
  * 任一确凿证据，即成立“视为串通投标”，注明对应的第四十条第几项；
  * 两类以上相互独立的中等证据（例如相似段落加报价比值恒定，或相同图片加同一编制人），为“较强”，进入需核实；
  * 只有单一中等证据，或只有弱证据，归入参考，并写明常见的正常原因。
* **案件卡（一屏）**：结论句（“甲、丙疑似串通投标，第四十条（一）（四）”）→ 证据链按强度排列，每条一行写清事实，例如“两份 PDF 原始文件标识相同”“项目经理身份证号相同”“分项单价比值恒定 1.0300，变异系数 0.02%，共 12 项”→ 每条可展开查看两家原文并排或页图 → 常见正常原因与可以排除的证据（例如已剔除招标范本句子 n 条）。
* 案件卡就是 Word 报告中“串通投标线索”一节的原样，评委拿到即可引用。

## 三、精确度：先本机收紧，再二次核验，最后才交给人

1. **本机收紧（不调模型）**：基线剔除加上招标代理机构的历史范本：本人其他项目中同一代理机构的招标文件句子、图片、rsid 也剔除（只用本人的项目，不跨账号）。生成软件相同、创建时间接近这类弱信号，单独出现时不成为线索，只能作为案件中的辅助证据。B-08b、B-08c 的真值统计用来逐项调整阈值。
2. **二次模型核验（只针对严重且不确定的，次数少）**：
   * 第一轮判为“疑似不响应 / 未找到”的实质性、资格、否决类单元格：扩大检索（前 8 个片段，加偏离表与该家目录中同名章节），用更严格的提示词再判一次，要求逐字引用；两轮一致才算确凿，不一致进需核实，第二轮找到响应的直接改为响应，并注明“二次核验找到响应”。
   * 只有相似段落、需要判断是不是正常原因的线索：把两家的脱敏段落与招标原文发给模型，问“这是共同来源（招标范本、标准规范、同一厂家资料），还是自写内容雷同”，模型给出理由；判为共同来源的降入参考。
   * 文件标识、证件号、账号、金额这类确定性证据**不发给模型**，模型对此判断不了，而且这些本身是敏感信息。
   * 二次核验同样走网关、出口复检与 llm_calls（purpose `bid`），确认页单列“二次核验 n 次”。预计每个项目 3～8 次，开始前照旧告诉用户次数。
3. **人工核实**：只看需核实层。
   * 选 N 时必须选原因：招标范本 / 同一厂家资料 / 识别错误 / 模型误判 / 其他。
   * 同一项目中同一原因、同一来源的其他条目一并降级，例如排除“同一厂家资料”的一张图后，同哈希的其他图片线索随之降级。
   * 选 Y 的问题升为确凿。

## 四、反馈与及时改正

* **项目内即时生效**：改卡片名称、录入唱标价、把某条要求标为“不适用”、核实或排除一条后，只重算受影响的部分：本地检查当场重算；需要模型的，只对受影响的单元格补做二次核验，次数先告诉用户。结论区随之刷新。
* **跨项目记住**：排除时可勾选“以后同类不再报”，在本人范围内按代理机构记住：范本句子、厂家资料图片哈希、某个生成软件。做法与脱敏的“记忆保留项”相同，不跨账号共享，在设置中可以查看和撤销。
* **校准统计**：每次核实结果按检查类别累计“属实率”，属实率持续偏低的检查在设置的统计里提示，留给后续任务调整阈值，不自动改阈值。

## 五、结果页与报告的结构

* **第一屏“初审结论”取代总览**：
  * 一句话：n 家中 x 家建议否决（确凿）、y 家需核实；发现 k 组疑似串通；
  * 每家一行：建议否决 / 需核实 / 未发现问题，后面列 1～3 个理由；
  * 串通案件卡；
  * “需你核实（≤ 10）”；
  * 参考事项只显示条数。
* 矩阵、各投标人、报价分析、串标线索四个页签保留，作为证据与明细，不再承担待办。报价页按 bid-pricing.md 实现，其中的“需要你处理”只列需核实层的报价问题。
* Word 报告的正文只写确凿与核实过的需核实项；参考层和全部明细放附录；未核实的需核实项单列“尚待核实”。

## 六、不变的边界

系统只给“建议”，否决与认定串通由评标委员会决定，措辞保持“疑似 / 建议”。不打分、不排名、不推荐中标人。发给模型的只有脱敏片段，确定性证据与元数据不外发。新增模型调用照旧先告诉用户次数。不新增菜单。

## 七、验收（两组公开标书 + 虚构样本）

* 需核实每个项目 ≤ 10 条。
* 确凿层与真值草稿对照无误报。
* 真值中的应否决情形与串通关系全部出现在确凿或需核实层。
* 结果页第一屏不滚动就能看清结论。
* 二次核验的实际调用次数与确认页的预估一致。
