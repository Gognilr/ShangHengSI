# V34-D-02 扫描页线框表格与低置信单元格的校验降级

状态：已完成。执行：Claude Opus 5.5，2026-11-19。

## 一、做法

* **网格（`parsing/ocr_table.py`，不引入模型）：** OCR 之后取 RGB 最大通道做自适应二值化（红色印章在最大通道里近白，压在表上不成线），用 opencv 形态学开运算取横、竖线；按长横线的中位斜率估计倾角并旋正后取网格；横（竖）线须覆盖区域宽（高）的一半。一行内两列之间竖线缺失即合并为一格，记在左起首列（与 pdfplumber 一致）。OCR 行按中心点落入单元格，同格多行先按行再从左到右以 `ocr.join_text` 拼接，ocr_conf 取最低一行。
* **退回：** 横线或竖线不足 3 条，或区域内能完整落进单元格的 OCR 行不足 80% 时，整张表退回 ocr_block；检测异常也只记日志、照旧出块，不阻断解析。
* **节点：** PDF 扫描页、图文混排页与图片都生效。loc 为 `F-PG-T-R-C`，混排页的 T 号接在文字页已有表格之后；bbox 为单元格框（PDF 点 / 原图像素）。块与表格按纵向位置排序，ord 保持阅读顺序。标书延后 OCR（`ocr_pages`）走同一函数。
* **校验降级（偏离计划，V34Q-57）：** 印章样本上 PP-OCRv6 把“607.80”读成“11607.80”（置信度 0.850），把“41,000.00”读成“41,0.00”（0.976），都高于 LOW_OCR_CONF 0.80；读对的“96,385.50”只有 0.934。阈值分不开对错，所以**凡涉及 OCR 节点的计算类结果**（L-01～L-05、L-13、L-14）一律改为 L-INFO（low）“……可能是识读错误，请核对原件”，低于 0.80 时另注“识读置信度低”，原代码记在 `CheckResult.unsure`。这类结果不计入行错误数与合计是否一致，不参与修正后总价。标书侧显示为提示级“可能不一致（扫描件识读，请核对原件）”，结论写“报价计算待核对 n 处”。LOW_OCR_CONF 不改。
* **顺带：** 报价表列名补“合价”（常见写法，原先整张表不识别）；标书 low_ocr 标记与覆盖说明的低置信页改为看任何带 ocr_conf 的节点，不再只看 ocr_block。报价识别有 table_cell 时自然优先表格，B-08b 的同页 OCR 规则保留作兜底，未改。

## 三、两组公开标书（只在本机，`E:\标书文件`，只输出计数）

同一次运行中 OCR 结果按页缓存，每个文件分别关闭、开启表格检测各解析一次：

| 组 | 项 | 改前 | 改后 |
|-|-|-|-|
| 大样本（15 / 19 可打开，468 OCR 页） | 含扫描表格的页 / 表格 / 单元格 | 0 | 226 页 / 265 张 / 9,040 格（低置信 189 格，2.1%） |
| | 识别出的报价表（其中来自扫描页） | 8（0） | 20（12） |
| | 有报价表的文件 / 报价分项 | 4 / 84 | 5 / 125 |
| | 唯一总价 / 找到总价的文件 | 2 / 4 | 2 / 4 |
| | 确定的 L-01、L-02 / 降为核对原件 | 0 / 0 | 0 / 2 |
| 小样本（2 / 3 可打开，38 OCR 页） | 扫描表格 | 0 | 4 页 / 7 张 / 126 格 |
| | 报价表、总价 | 0 表，2 / 2 有唯一总价 | 不变 |

* 扫描表格大多是资格审查表、基本情况表等表单，所以表格页数远多于报价表；这些单元格也让表格列提示可以作用到扫描页的金额上，属于多脱敏的方向，golden 用例未受影响。
* 总价识别没有变化：总价主要来自“投标总价 / 投标报价”等标签，原先就能在 ocr_block 中取到。
* **无线框扫描表：** 含报价关键词、却没有生成单元格的 OCR 页，大样本从 77 页降到 33 页，小样本从 13 页降到 11 页（只是关键词粗估，含正文中的“报价”字样）。小样本的报价表不在扫描线框表中。占比还不足以支撑另行选型；B-08c 用真值评测时再判断。
* 耗时：大样本两次解析共 1,516 秒（OCR 缓存，第二次只做检测与解析），D-01 单次为 1,357 秒，表格检测的开销在每页 0.3 秒以内。4 + 1 份加密 PDF 未计入（同 D-01）。
