## 改动

* app/bid/similar.py：句级归一化、二元组 Dice，前缀过滤找候选句对；剔除招标文件原文与格式章节、20 字以下句与法条引文；相邻命中合并成段，按段长与“只有两家共有的相同句”分级，技术参数章节降一档、报价章节升一档。
* app/bid/pricing.py：复用 L-01、L-02 识别报价表，取投标总价；分项按品名（或行序）对齐，比值变异系数、等差、尾数习惯（Decimal）；报价分析写 bid_projects.pricing_enc。
* app/bid/compliance.py：多个总价、超限价、分项合计与总价、大小写（L-04）、投标有效期、保证金、证书有效期、写给 AI 的指令（L-21）；“本地规则”要求每家写 bid_cells（source local）。
* app/bid/checks.py：三步依次计算、各自提交（渐进出结果）；重跑保留核对状态与备注；覆盖说明补报价表未识别、扫描页识别进度。
* 扫描页延后识别：parse_pdf 增加 defer_ocr 与 ocr_pages；投标文件 PDF 先解析文字页（按页留出 ord 区间），识别任务逐页补入节点并定时重跑检查；项目详情给出识别进度。无迁移。
* 接口 `GET /bid/{id}/check` 增加 steps、elapsed、pricing、cells、requirement_id。
* 前端：初审中即显示已完成步骤的结果；BidClues 分“不符合项（疑似否决 / 一般 / 提示）”与“串标线索”，相似段落左右并排，报价规律附分项对齐表；状态条显示扫描页识别进度。
* 口径记入 V34Q-20。

## 验证

* test_bid_checks.py 新增两例：三家虚构投标文件——甲乙相似段落（强）、单价比值恒定（强）、乙大小写与有效期、丙多个总价 / 超限价 / 保证金 / 证书过期；照抄招标文件的句子不报；本地规则单元格。另一例扫描页延后识别（模拟 OCR）：先出检查，识别后补入节点、重跑、覆盖说明更新。标书四个测试文件与 test_parse_pdf 共 33 项通过；`npm run build` 通过。
* 规模（验收点）：5 家 × 200 页虚构 Word（每家约 22 万字、200 行报价表）在开发机 Docker 中，本地检查合计 **18.1 秒**（属性等 6.1、报价与符合项 2.5、相似段落 9.1），远低于 10 分钟。
* 浏览器（localhost，1440×900，浅色与夜幕）：同一组虚构文件经页面查看，问题与线索分级、左右对照与分项表显示正确。测试项目已删除。
