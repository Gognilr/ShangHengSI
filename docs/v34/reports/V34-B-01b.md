# V34-B-01b 发标单位一览表与按名单自动分组

状态：已完成。执行：Claude Opus 5.5，2026-11-19。

## 一、做法

* **识别（`bid/invitees.py`，只用本地规则）：** 表格（Word / PDF 表格单元格、D-02 扫描表格单元格、Excel 单元格）前 5 行中找“投标单位 / 投标人（名称）/ 受邀单位 / 单位名称 / 供应商名称 / 企业名称”一类表头，取该列；同一表头行含报价、金额、得分的表跳过。**表格一家都没取到时**才在“发标 / 投标单位一览表、邀请单位名单”等标题后的同页及下一页（Word 无页码时取其后 80 段）按单位名称后缀取名（V34Q-58）。去序号、4～60 字、规范化去重、剔除“招标人 / 采购人 / 代理机构：××”，至少 2 家才算识别成功；每项记出处（file_id、loc、来源 table / scan / text / manual）。
* **第 1 步：** 关键参数下“受邀投标单位 n 家”，两列列表，每项标来源（原文表格 / 扫描页识别 · 请核对 / 原文段落 / 手工），可在原文中定位、改名、删除、补充；识别不到时一句提示。`PUT /bid/{id}/invitees` 整表替换（校验 owner，开始初审前可改），保存后 `invitees_edited`，重新抽取不再覆盖。
* **第 2 步：** 名单中尚无分组的单位显示为虚线待交卡片（可收起），拖入或点选文件时用 groups 上传建分组，不留空分组、不占代号；导入文件夹时文件夹名（去序号与“投标文件”等字样）按全称或简称对名单，唯一对上即预填全称，名称框可从名单下拉选；已有分组是简称而能唯一对上名单的，卡片下提示“名单中为：全称 · 改用”，点了才改名。
* **同名：** 添加、改名按规范化（去空白、NFKC 全半角、`normalize_value`）同名拒绝（422 BIDDER_DUPLICATE）；文件夹分组之间规范化同名拒绝，与已有卡片规范化同名则并入该卡（拖入待交卡片、再次导入同一家）。
* **数据：** 不迁移。名单在 `parameters_enc` 加密 JSON 的 `invitees`、`invitees_edited`；项目详情返回全称列表，要求清单接口返回带出处的条目。日志与审计不写名单。
* **脱敏：** 未建分组的名单单位（全称与简称）作为 ORG 词条进入片段脱敏；招标文件整份脱敏（模型补充要求）时全部名单单位作为 ORG 词条传入，`engine.redact_task` 加可选 `extra_terms`，只有标书传入；不写入用户词条库。
* **基线修正：** `checks._load` 的招标文件节点剔除名单表格（整张）与识别出的段落 / OCR 行，混装、联系信息相同不再被名单屏蔽。
* **上传：** 招标文件放宽到 Excel（xlsx / xls / et）与图片（jpg / png，拍照的一览表，V34Q-58）。
