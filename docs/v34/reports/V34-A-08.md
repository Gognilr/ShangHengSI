# V34-A-08 单证核对改本地核对为主

日期：2026-11-16　执行：Claude Opus 5.5　依据：PLAN V34-A-08、V34Q-09；口径记入 V34Q-16

## 做法

* 新增 backend/app/assistant/crosscheck.py：对所选文件在本机抽取品名、数量、毛重、净重、件数、金额（另出币种行）、发货人、收货人、装运港、目的港、装运日期、发票日期、合同号、发票号、提单号、信用证号，归一化后逐项比较（金额复用 find_amounts 的币种与 Decimal 值，日期复用 find_dates），结论为 一致 / 不一致 / 写法不同 / 文件内有多个值 / 仅一份文件有。并附跨文件 L-17～L-19（收款账号、签约方名称、合同号、同一品名单价数量）。
* 模型只在“某项目部分文件本机没找到”时调用，按 JSON 回答位置编号与原样文字（代号形式）；位置或文字对不上的丢弃，并入后仍由本机比较。全部找到时不调用模型；模型不支持结构化输出或调用失败时只给本机结果并注明。没有调用模型的回复不显示模型名。
* 结果表加密存于已有的 assistant_messages.local_result_enc（无迁移），正文只存计数；因此不进入后续对话历史。查看时补文件名与可读位置。
* 前端：CrosscheckTable.vue（分区标题“本地计算 · 结果确定”，结论用圆点 + 文字，不一致为红），可导出 Word、Excel；快捷标签说明改“在本机逐项核对多份单证是否一致”。提示词 crosscheck 一节改为只定位，版本 assistant-2026.11-10。

* tests/test_assistant_*.py 共 154 项通过（test_assistant_export 一项须整仓挂载，挂载后通过）；npm run build 通过。
* 重建本机 app、worker，在开发库建两个虚构会话，浏览器中点“单证核对”发送：两例表格与样本结论一致；本机 mock 模型不回 JSON，第一例显示“未能请模型定位…”说明。外观被账号设为浅色，夜幕未看（颜色均取令牌）。
