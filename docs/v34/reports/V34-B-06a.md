# V34-B-06a 结果页版式整理

日期：2026-11-17　执行：Claude Opus 5.5　状态：已完成（截图待用户确认）

## 改动

按 V34Q-25 的 9 条决定，细节记入 V34Q-26。

* **骨架**：五个页签都是“结论一两句（BidLede，只让关键短语用危险 / 警告墨）→ 要处理的 → 明细 → 页脚说明”。区块标题一套（16px / 600 + 等宽计数），标题旁的说明句全部移进页脚；页脚与固定声明合为通栏脚注（结果页自带，项目页不再重复）。零值与空值一律“—”。共用样式在 components/bid/results.css，简称、限价口径、核对进度在 results.ts。
* **页头**：“本地检查已完成 / 扫描页识别 / 模型核对”并入四步条右端的“n 份文件已解析”，去掉单独一行（页头由五层变四层）。
* **计数**：核对进度只有一个算法（`reviewTodos`）；已排除的条目不计入任何数字，在列表末尾折叠为“已排除 n”。串标线索页签与分组数字现在一致。
* **总览**：数字条换成结论句 + “核对进度 已核 x / 共 y”；投标人表七列（疑似否决｜其他问题｜投标总价｜与限价｜串标线索｜核对进度），可点的数字带下划线，核对进度点进去就是这一家的全部待核事项；两两关系改为只列有线索的对 +“其余 n 对未见线索”（≥ 5 家仍用三角矩阵）。
* **各投标人**：默认选疑似否决项最多的一家；分段控件按内容宽度；一页列全问题清单｜涉及的串标线索｜需人工核对的要求（就地标注、点开看单元格依据）｜签章页（PDF 缩略图，Word 改为文字行）。
* **条目行**：类型、条文与涉及的投标人同在标题下第二行。
* **报价分析**：顶部只写最高限价；各家报价表加“计算与大小写”列（✓ / ✕ n 条，就地展开问题卡），问题卡不再单独一节；两两比值先写有规律的对，未见规律的折叠；分项对齐表列头注“与 X 比 ≈ k”，随页面滚动。
* **矩阵**：开头一句结论；工具条只留开关与“已隐藏 n 行”；图例收为表下一行。
* **后端**：多个总价时 `over_ceiling_max`＝最高总价 − 限价（Decimal），over_ceiling 含义不变；Word 报告的投标总价与“与限价”同口径（写最高总价并注“n 个总价”）。
