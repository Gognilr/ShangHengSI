状态：**已确认**（2026-11-15 Opus 起草，用户 2026-11-16 确认）。问题与决定见 [open_questions.md](open_questions.md)（V34Q-01～10），设计见 [design/bid.md](design/bid.md)（标书初审）与 [design/visual.md](design/visual.md)（视觉第三版“素纸”，预览 design/visual-preview.html）；背景分析见 docs/proposals/商衡SI-标书初审与导航设计分析-2026-11-15.md。本文件只写怎么做、按什么顺序做。版本号 3.4.0，标签 `v3.4.0`。

## 〇、范围与规则

**来源：** 2026-11-15 与用户的讨论：标书比对能力、首页与导航别扭、颜色过渡不稳重、快捷标签弹窗、历史记录横向滚动、品牌标识。

**目标：**
1. 导航“一事一入口”：侧栏 工作台｜（文件审查）文件审核、标书初审｜（工具）会议纪要、翻译｜历史记录、搜索；高亮不再跳。
2. 视觉第三版“素纸”：全站一张连续的纸；主色松针青 + 辅助色松果赭；新标识“松鳞”；欢迎语一句话、常规字重。
3. 新菜单“标书初审”：招标方对 3～5 家投标文件做资格、符合性审查与串标线索初审，整体设计、一次实施（V34Q-02）。

**不做：** 打分、排序、推荐中标人；印章图像识别；更换本地模型或技术栈；新增依赖（例外：D-01 按 local-models.md 第七节更换 OCR 模型，V34Q-55）；改动现有脱敏、还原、出口复检对审核任务与会话的行为（标书初审的片段脱敏复用同一引擎）。

**规则：**
* main 上串行，一次一个任务，**每个任务单独开一个新会话**；提交说明以任务编号开头（英语或日语），小步提交，`git add` 只暂存本任务文件。不开并行分支或工作树分轨开发；状态写“已完成”须附相关测试的实际输出，未闭环写“进行中”（V34Q-54）。
* Claude 与 ChatGPT 谁有额度谁做。下表每个任务给两侧各一个模型与推理强度，任选其一；Sol 6.1 = GPT-6.1 Sol，Terra = GPT-6.1 Terra。先用表里的强度，同一验收点两次不过再升一档。涉及脱敏、出口的任务（B-05）由另一侧交叉复核。
* 交接只靠仓库：开工读 CLAUDE.md（Codex 另读 AGENTS.md）、本文件第〇节与该任务一节、对应设计文档章节与问题条目、上一个任务的报告与 `git log`。结束时在状态列写“已完成（日期，执行者，报告路径）”并提交。
* 视觉以 design/visual.md 为准：十六进制颜色只写在 theme.css；A 批完成前，docs/design/frontend.md 仍是旧版，Z 时以 visual.md 替换为第三版。
* 标书初审结果页的前端改动以 design/bid-frontend-spec.md 为硬性规范（用户 2026-11-17），偏离须先问用户。
* 前端改动用浏览器检查（http://localhost:5173），浅色、夜幕与三档特效各看一遍，截图只留在会话里。不为样式与措辞加测试（CLAUDE.md）。
* 真实标书只在本机评测（B-08），原文、名称、金额、密码不进仓库、对话与日志；真实模型调用开工前停下，告诉用户调用次数，由用户录入密钥。
* 新问题记在 open_questions.md（V34Q-11 起）。报告放 docs/v34/reports/，每份不超过一页，末尾写建议的 SPEC / CLAUDE.md 改动，由 V34-Z 合并。整仓全量只在 V34-Z 跑一次。

### V34-A-08 单证核对改本地核对为主（V34Q-09）

* **现状：** 模板只靠模型比较代号，同一金额写法不同可能误判；会话不跑 L-17～L-19。
* **做法：** 单证核对时对所选文件在本地抽取品名、数量、重量、件数、金额、币种、收发货人、港口、日期、单号，按归一化值逐项比较（复用 checks 中的跨文件核对与金额解析），结果表由本地生成；模型只对本地无法对齐的项目做对齐（同比价：模型只给代号对应，不给结论）。

### V34-B-08b 评测收尾（B-08 复核意见）

* **1. V34Q-38 定性（先做，安全优先）：** 本机脚本列出 31 处匹配，私有文件给出值、类别、所在请求与位置，报告只写分类计数。每处分为：① 后来误识别（通用词、短词、品牌型号等，本不应保护）；② 真遗漏（招标文件脱敏当时就应识别的人名、地址、单位、账号等）。② 类每一种写法各做一条虚构 golden 样本（redaction_golden），用 A-03 暴露问题，修通用识别；改动现有脱敏行为前先问用户。① 类偏多的，检查片段脱敏的实体识别阈值或短词过滤是否过宽，同样用虚构样本固定。

* **3. 按真值统计并校准（不调模型）：** 按检查类别统计误报与漏报（用户口述的漏报以匿名描述记入）；疑似否决项误报多时，调整模型“疑似不响应”升为疑似否决项的条件（例如须引文核实通过，否则记为一般问题或待核实），先写入 open_questions 并问用户。查清未找到 / 无法判断的成因（检索取不到、要求不适用、OCR 质量），据此调整检索前 n 个、80% 截断与关键词权重，或调整要求补充的去重与过滤；查清 4 家中 2 家未识别出唯一总价的原因（开标一览表在扫描页、标签写法、大写），修正识别并补虚构样本；顺带确认 PDF“创建者”是否误报（B-07）。

### V34-D-01 OCR 选型与升级

* **做法：** 按 docs/v31/design/local-models.md 第七节写选型报告：当前 rapidocr-onnxruntime 1.4.4 对比 RapidOCR 新包（onnxruntime 引擎）搭配的新代次 PP-OCR 中英文检测 / 识别模型（v5；v6 若已发布且有 ONNX 一并比较）。厂商宣传的精度、速度数字不作依据，以实测为准。新包默认会在运行时下载模型：须改为模型文件随镜像打包、在 models.yaml 中写明文件与 SHA-256、关闭下载，断网冒烟通过。
* **评测样本：** 仓库内现有 PDF 样本只够冒烟，没有 OCR 真值。先在 backend/tests/fixtures/ 下做一小组带标注的虚构扫描页（合同正文、报价表、含金额与账号、盖章压字各若干页，几页即可），作为本任务与 D-02 的质量基线；同时记录两组公开标书全量 OCR 的总耗时。
* **比较项：** 整体字错率；金额、账号、日期字段的专项错误（0/O、1/l 等混淆）；单页耗时与内存（1,000 页 OCR 上限下）；包与模型大小；许可证。
* **停点：** 选型报告交用户确认后才改 requirements、models.yaml 与镜像。
* **验收：** 现有 OCR 相关测试与 `model-check ocr --smoke` 通过；报告给出两组公开标书改前改后的低置信页数与耗时。

### V34-D-02 扫描页线框表格

* **做法：** 不引入新模型。扫描页、图文混排页在 OCR 后用镜像中已有的 opencv 做形态学横竖线检测，得到表格网格与单元格 bbox；OCR 行按中心点落入单元格，同一单元格多行按 `ocr.join_text` 拼接，生成 kind=table_cell 节点，loc 为 `F-PG-T-R-C`（混排页的 T 号接在文字页已有表格之后），带 ocr_conf。网格不成形（行或列不足 2、单元格落入率过低）时退回现有 ocr_block 路径，不阻断。
* **校验降级：** OCR 单元格的数字可能识读错。checks 与标书报价凡涉及低于 LOW_OCR_CONF 的单元格，结果改为“请核对原件”一类的提示，不报为确定的计算错误；报价识别有 table_cell 时优先表格，B-08b 的同页 OCR 规则保留作兜底。
* **验收：** 虚构的扫描报价单样本（有线框、盖章压字各一）生成单元格，行合计 / 总计校验能运行；无线框扫描表仍走原路径；两组公开标书报告扫描报价表的识别张数与报价识别前后对比。无线框扫描表若占比明显，记入报告，另行选型。

### V34-D-03 文字页表格与 PDF 页眉页脚

* **受限 text 兜底：** 线框策略无表时，只在出现报价表特征（表头含单价 / 数量 / 金额 / 合计等，且至少 3 列竖直对齐的数字）的区域用 pdfplumber text 策略再检一次，不满足即丢弃，避免把普通正文切成单元格。
* **跨页续表：** 不加节点字段、不做迁移。在 `redaction/tables.py` 增加按文件拼接逻辑表的函数，供 checks 与标书报价读表时使用：相邻页、列 x 区间对齐、续页无表头或表头与上页相同，则视为同一逻辑表（重复表头行不计入数据行），loc 不变；解析 warnings 注明“第 X–Y 页表格按续表合并核对”。现状续页无表头时整张表被跳过、总计不核，续页重复表头时可能误报，两种各用一条虚构样本固定。
* **页眉页脚：** 文字页与 OCR 页的文本块，若位于页顶 / 页底约 8% 带内，数字归一化（兼容页码）后在至少 3 页且至少半数页重复，且不在表格区域内，标 part=header / footer，与 DOCX 一致（不参与外发与 AI 审核，覆盖说明照列）。标书本地检查（`bid/checks.py` 取 part ≠ comment）仍能看到页眉内容。
* **验收：** 带页眉页码的虚构多页合同不再有重复页眉进入正文节点；无线框报价单、跨页报价单各一份虚构样本的核对结果正确；相关测试文件通过。
