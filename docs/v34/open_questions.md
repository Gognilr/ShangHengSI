# V3.4 问题记录

编号 V34Q-01 起；V3.3 及以前的问题见 docs/v33/open_questions.md 等各阶段文件。新问题接着往下编号，写现象、做法与状态，每条几行。

V34Q-01～10 来自 2026-11-15 与用户的讨论（标书比对能力、首页与导航、配色），背景分析见 docs/proposals/商衡SI-标书初审与导航设计分析-2026-11-15.md（下称“分析”），视觉方案草案见 docs/v34/design/visual.md。

### V34Q-01 导航：一事一入口（用户 2026-11-15 确认）

* 现象：工作台点“全面审核”时侧栏高亮跳到“智能审核”；“智能审核”只是工作台的一个视图。
* 做法：按分析 2.3 方案乙。侧栏：工作台｜（文件审查）文件审核、标书初审｜（工具）会议纪要、翻译｜历史记录、搜索；“智能审核”改名“文件审核”并成为独立页面；高亮按“这件事属于哪类”，页内切换不改高亮；工作台首页去掉“直接提问 / 全面审核”切换，改为提问框 + 常用标签 + 四张入口卡片 + “继续上次的工作”。用户要求四张卡片新颖、专业、高端。

### V34Q-02 标书初审：独立菜单，整体设计、一次实施（用户 2026-11-15 确认）

* 定位：招标方对 3～5 家投标文件做初审（资格、符合性、串标线索），不打分、不推荐，疑点写“疑似”并附依据；开标当天使用，报告交评标委员会。
* 用户否决分期：一次设计完成、整体实施（分析 1.10 的三期不采用，任务在 V3.4 内排序）。其余按分析第一节。

### V34Q-03 投标文件 PDF 密码加密保存（用户 2026-11-15 决定）

* 理由：避免重新解析时重复录入；密码由投标方提供，事后再找麻烦。
* 做法：用主密钥 AES-256-GCM 加密保存（同 SPEC 17.3 敏感字段），随项目删除；本人可在项目页查看（默认遮盖，点击显示）；日志、导出报告不写密码。

### V34Q-04 新增权限点“标书初审”（用户 2026-11-15 确认）

* 默认不给普通用户，由管理员分给采购、招标办账号；项目仍只本人可见（非本人 404）。

### V34Q-05 V3.4 顺序（用户 2026-11-15 确认）

* 先做导航、首页、视觉与快捷标签等前端改动，再做标书初审主体。V3.3 已全部完成。

### V34Q-06 工作台欢迎语与副标题同行（用户 2026-11-15）

* 现象：“晚上好，管理员”下一行另起“今天还有哪项工作需要梳理？”。
* 做法：副标题与欢迎语写在同一行，字号、颜色、字重与欢迎语完全一致，读起来是一句话（用户 2026-11-15 更正，先前的“适当调小”与“用字重或颜色区分”均作废）。随 V34Q-08 视觉方案落地。

### V34Q-07 历史记录表格出现横向滚动条与固定列阴影（用户 2026-11-15）

* 现象：表格在常见宽度下出现左右滚动条，操作列固定后有一条明显的过渡阴影竖条。
* 做法：列宽在 1366～1920 下放得下，不出现横向滚动；操作列不固定或固定时不加阴影。

### V34Q-08 全系统视觉重新设计，含品牌标识（用户 2026-11-15）

* 现象：首页颜色过渡太明显、不稳重（两团氛围光、选中项渐变加辉光、按钮辉光）；翻译、会议纪要页灰底与白色拖入框反差突兀。

* 用户 2026-11-15 已定：主色松针青（浅 #1F5F58 / 夜幕 #2F8177），辅助色松果赭（#9C5B34 / #D39A6A）；标识“松鳞”；不用蓝色，不借用 Claude 等现有品牌的图形与配色。其余视觉项按 visual.md 第十节默认采用。

### V34Q-16 单证核对的口径（V34-A-08）

* 比较项目：品名、数量、毛重、净重、件数、金额、币种、发货人、收货人、装运港、目的港、装运日期、发票日期、合同号、发票号、提单号、信用证号。只认明确标签后的值（行内“标签：值”、左标签右值的表格、表头 + 合计行或唯一数据行），不猜无标签的数字；同时附上跨文件的 L-17～L-19 结果。
* 归一化：金额按币种与 Decimal 值；重量换算成千克；数量按数值与单位（件 / PCS、套 / SET 等同义，一方无单位只比数值）；件数只比数目；日期按日历日；单号去空格、短横线、斜杠后大写；名称、港口去标点、空白与大小写，港口只取逗号前的部分并去掉“港 / Port”。中英文写法不同的名称、港口判“写法不同”，由人核对，不判不一致。
* 模型：只有某项目在部分文件中本机没找到时才调用，回答位置编号与原样文字，位置或文字核对不上的丢弃；比较与结论仍在本机。全部找到时不调用模型；模型不支持结构化输出或调用失败时只给本机结果并注明。结果表加密存于 local_result_enc，正文只存计数。

### V34Q-17 标书项目材料与生命周期细节（V34-B-01）

* 权限：现有角色不自动追加 use.bid，新装普通用户也不含该权限；由管理员在已有角色管理中明确分配。只有标书权限的账号首页为 /bid。
* 分组：文件夹先展示分组名称与文件数供修改，再整批建卡、上传；同名现有卡片只有一张时续传，多张时要求逐卡上传。相同内容可出现在不同投标人中，不能全项目按哈希去重，否则会丢失串标线索。投标人按录入顺序展示，删除不重排其余代号；文件序号沿用任务高水位。
* 解析：复用 parse 队列，逐个文件解析、逐个提交，全局事务锁保证同一时间只解析一个标书文件（比“一个项目”更细，资源占用相同）；只解析新加入、换过密码或点了“重新解析”的文件，已解析的不重做。解析期间仍可继续加文件、改投标人名称（开标当天逐卡拖入不必等待）。单份文件缺密码或解析失败时保留其他文件的结果，提示显示在该文件行。投标文件只解析、加密存节点，不对整份投标文件脱敏或调用模型；招标要求与确认流程由 B-02 接续。标书显式传空密码检测加密，旧审核与会话的默认密码错误提示保持不变。
* 保留期：preparing / ready 阶段按未完成任务期限清理；checked 按现有原件与结果分层期限清理；checking 不清理。密码随项目删除，主密钥轮换自动覆盖新增 _enc 列。项目默认选择“只做本地检查”。

### V34Q-18 要求清单的抽取与模型补充（V34-B-02）

* 规则范围：★▲ 与否决字样（否决 / 废标 / 无效投标 / 不予受理 / 拒收等）全文抓取；“必须 / 不得 / 应当 / 严禁”只在非合同、非格式章节抓取（合同条款是中标后的履约要求，抓进来只会让清单变长）。“投标文件格式”章节整体记一行范围作范本白名单，其中句子不进清单。表格中的 ★ 整行作一条（★ 常单独占一格）。
* 完整性计数按原文位置判断：启用的要求覆盖了该句所在位置才算“已进入”；停用或删除后差额列出，可一键加入。
* 自动抽取只在招标文件首次解析完成时做一次；之后加减招标文件只提示“重新抽取”，重新抽取保留手工行、其余重建，不悄悄覆盖用户的修改。关键参数只填用户尚未填写的项。
* 模型补充不走审核的确认页：招标文件是本公司文件，只对招标文件整份脱敏（引擎按 bidder_id 为空限定范围），清单页给回执（字数、调用次数、本机保护项数、剩余次数）并可切 AI 视野核对，确认后才发送；不在此逐处撤销 / 加入保护（需要时改为“只做本地检查”）。llm_calls 与 jobs 新增 bid。模型条目须给出位置与逐字引文，位置无效或引文对不上即丢弃；与规则行重叠的不重复；给出 replaces 时停用被改动的旧行（保留可查）。
* 第五十一条七种情形作默认行，文字按条文转述，V34-Z 合并 SPEC 前对照法规库原文核对；招标文件写明不接受联合体时，“联合体协议”一行默认停用。“只做本地检查”的项目中“模型判断”一律改为人工核对，模型补充入口不显示。
* 确认清单后项目为“待开标”，此后仍可修改（版本号加一）；开标后“只重跑受影响的行”由 B-04 / B-05 按版本处理。

### V34Q-19 本地检查一的口径（V34-B-03）

* 开始初审须先确认要求清单（阶段“待开标”）、文件全部解析完、至少一家有已解析的投标文件；开始后材料锁定。本地检查失败退回“待开标”可重来。检查完成后如何“返回修改材料、重新初审”留给 B-06 一并设计（届时保留核对状态）。
* 文件属性与图片哈希在解析时读取（.docx、.pdf；旧格式转换件的属性由转换器写入，不比；表格与图片文件不比属性）。小于 2 KB 或短边小于 48 像素的图片不比。
* 基线：招标文件中的 rsid、图片、PDF 文件标识、作者、公司、联系方式一律剔除；生成软件相同且创建时间与招标文件相差 10 分钟内的（从招标文件另存）也不算“同时生成”。电脑默认用户名（Administrator、微软用户等）不作为“作者相同”。
* 分级：PDF 原始文件标识 / XMP 文档标识相同、作者或最后保存者相同为强；rsid 重合（剔除后任意一个即报，写明个数）、文档属性中的公司相同为中；生成软件相同且创建时间 10 分钟内为弱。联系信息：电话、邮箱、银行账号、证件号、项目经理为强，联系人 / 授权代表、地址为中；同一组投标人的联系信息合并为一条线索。图片：所在页含检测报告 / 彩页 / 说明书 / 认证证书等归“正常重复”，含盖章 / 签字 / 授权 / 业绩 / 合同 / 营业执照为中，其余为弱（设计未写，取保守一档）。
* 混装：认卡片全称与去掉“有限公司”等后缀、再去掉“某某省 / 市”前缀后不少于 4 字的简称；简称在招标文件出现或是本家名称一部分时不认。不带“市”的地名前缀（如“北京松青”）暂不剥离，B-08 真实标书评测时看漏报再定。
* “项目经理 / 项目负责人 / 技术负责人：某某”由标书模块自认，不改脱敏引擎的人名标签。

### V34Q-20 本地检查二的口径（V34-B-04）

* 相似段落：按 。；！？ 与换行切句，归一化（normalize_value）后去掉标点空白；少于 20 字、含法规书名或“第 X 条”的句子不比。先剔除与招标文件（含格式章节）完全一致或二元组 Dice ≥ 0.9 的句子，再在各家间找完全相同句与 Dice ≥ 0.85 的近似句（前缀过滤找候选，不漏）；两侧都只前进 1～2 句的命中合并为段。一对投标人的命中合计不足 80 字且“只有两家共有的相同句”不足 5 处时不报（多为固定句式）。段 ≥ 200 字或这类相同句 ≥ 5 处为强，段 ≥ 80 字为中，其余为弱；所在章节标题含技术参数 / 规格 / 偏离等降一档，含报价 / 开标一览表 / 投标函等升一档。
* 报价：报价表识别复用 L-01、L-02（需数量、单价、金额列）；分项最多的表为主表。投标总价取“投标总价 / 投标报价 / 总报价”等标签后 40 字内的小写金额（标签单独成格时取下一格）；大写不计入总价，由 L-04 比对。分项按名称列归一化对齐，对上不足 5 项且两表行数相同时按行序对齐；三家及以上同价的分项（招标文件给定）不参与。比值变异系数 < 0.5% 且 ≥ 5 项为强；差额相同或个位数大多（≥ 80%）同为非 0、5 的数字为中。报价分析（总价、表合计、超限额、分项对齐表、两两比值）存 bid_projects.pricing_enc，B-06 展示。
* 确定性符合项的等级：多个不同总价、超最高限价（多个总价时任一超出即报）、投标有效期短于要求、保证金少于要求为“疑似否决项”（参照第五十一条（四）（五）（六））；大小写不一致、分项计算、表合计与总价不符、证书有效期早于开标日为“一般问题”；OCR 低置信的证书日期与写给 AI 的指令为“提示”。“个月”按 30 天计。
* “本地规则”要求按文字归到检查（限价、两个以上报价、大小写、保证金、有效期），每家写一个单元格：yes 响应、no 疑似不响应、missing 未找到、unclear 无法本地判断（如关键参数未填）。对不上的本地规则行（如格式范围行）不写单元格。
* 渐进出结果：本地检查分三步（属性等 → 报价与符合项 → 相似段落）各自提交，初审中页面每 2 秒刷新。投标文件 PDF 的扫描页不在解析时识别，先解析文字页即可开始初审；识别任务（jobs bid / ocr）逐页补入节点，已完成初审的项目每隔 60 秒及识别完成时重跑本地检查；检查运行中识别有进展的，检查结束后自己再跑一轮。重跑保留同一条目的核对状态与备注。招标文件仍在解析时识别（清单抽取需要全文）。

### V34Q-21 模型核对的口径（V34-B-05）

* 触发：外发策略为“本机检查 + 模型核对”的项目，本地检查完成后自动在后台准备片段（检索 + 脱敏），用户看本地结果时即可完成；也可手动“准备 / 重新准备”。扫描页识别未完成时回执中注明，识别完成后可重新准备（不自动重来，避免确认前反复失效）。
* 检索：投标文件按节点合并为约 400 字的片段（标题处断开，表格同一行不拆、单元格以“｜”相连），向量写入 task_clause_vectors；分数 = 余弦 + 0.6 × 关键词二元组覆盖率（偏离表章节略加分），每家每条取前 3 个、低于第一名 80% 的不带。向量模型不可用时退回只按关键词，并在回执注明。
* 脱敏：只对选中的片段节点与要求文字跑完整脱敏（规则 + 实体识别 + 词条 + 记忆保留项），对照表只增：沿用任务已有对照表，新增代号用 [[类别_n]]，投标人（全称与简称）统一改为 [投标人A]……；兜底把仍以原文出现的投标人名称与招标文件对照表中的真实值换成代号。脱敏结果写回投标文件节点的 redacted_text（AI 视野）。不写 redaction_items（投标文件不进入整份脱敏的逐处撤销流程，与 V34Q-18 一致）。
* 确认：确认时由数据库中的片段重新生成全部消息，先逐批出口复检（任一批不过整轮不发，记 blocked），再检查剩余次数（不足不开始）。按家合并，超过 2 万字分批；失败后再次确认只发未完成的批次，已写入的结果保留。
* 判断：响应 / 疑似不响应 / 未找到 / 无法判断写入 bid_cells（source model）；引文须出自所引片段（quote_matches），对不上仍记录判断并标 cite = unverified（待核实）。理由与引文在本机还原后加密保存。“疑似不响应”另写问题条目：资格条件、实质性条款、否决条款为疑似否决项（参照第五十一条（三）（六）），其余为一般问题；偏离表与正文矛盾写一般问题。重跑保留核对状态与备注。
