# V321-E-02 讨论侧栏与讨论稿反馈（方案，待用户确认）

对应 V321Q-28（讨论与结果页割裂）、V321Q-33（讨论稿保存后没有反馈）。只改前端，后端只补一个字段。

## 一、现状与原因

* 点“继续讨论”时，工作台把视图切到“直接提问”（`Assistant.vue` 的 `discuss()` 改路由 `mode`）。审核视图 `ReviewPane` 用 `v-if` 挂载，切换后整个销毁：回来时问题卡收起、原文和列表滚回顶部、筛选也被清掉。
* 讨论时只能看到对话，看不到问题说明、建议条文和原文。
* 讨论稿保存后：后端 `save_draft` 已经把 `use_discussed` 设为真，并返回新的问题数据，但前端没有用这份返回值，结果页里还是旧数据，所以看起来“仍是原审核建议”。对话里的“保存到该问题的修改建议”按钮也没有变成“已保存”。

## 二、布局：讨论放在结果页的右栏

```
┌ 审核结果顶栏（轮次、回执、新一轮、导出）─────────────────────────────┐
│ 原文画布（不动，定位到该问题）       ║ 右栏：讨论问题 03            [×] │
│                                      ║ ┌ 问题卡（精简版，可折叠）─────┐ │
│                                      ║ │ 标题 · 等级                  │ │
│                                      ║ │ 问题 / 修改建议 / 可替换措辞 │ │
│                                      ║ └──────────────────────────────┘ │
│                                      ║ 对话（只显示这个问题下的消息）   │
│                                      ║  …回复  [保存为修改建议]          │
│                                      ║  ✓ 已保存为问题 03 的修改建议    │
│                                      ║ ┌ 输入框 ───────────────────────┐ │
│                                      ║ └──────────────────────────────┘ │
└──────────────────────────────────────╨──────────────────────────────────┘
```

* 讨论**替换右侧问题栏**，原文画布保持不动，并定位、高亮该问题。不做三栏：1440 宽度下三栏会把原文压到 420 像素以下。
* 问题栏不卸载，只是隐藏（`v-show`）。点 [×] 或“← 返回问题列表”后，滚动位置、选中、筛选原样恢复。
* 讨论中在原文上点另一个问题的标注，右栏切换到那个问题的讨论。右栏顶部的问题卡精简显示（标题、问题、修改建议、可替换措辞），可以折叠，给对话让出空间。
* 右栏宽度沿用问题栏的拖动宽度。
* “直接提问”视图不再显示按问题的讨论，只显示普通对话，去掉现在的锚点条。按问题的对话只在结果页右栏里出现，两边不混。
* 工作台的两种视图都改用 `v-show`：在“直接提问”和“全面审核”之间来回切换时，审核结果页也不会被重建。

**实现要点**：消息列表和轮询仍只放在 `Assistant.vue` 一处。讨论用的 `Conversation` 加一个带锚点的 `Composer`，通过插槽经 `ReviewPane` 传到 `RunResult` 的右栏，不复制轮询逻辑。锚点从 `Assistant.vue` 下放给结果页，切换会话时清除，规则和现在一样。

## 三、讨论稿反馈（Q-33）

1. **消息上的标记**：保存后，这条回复的按钮换成“✓ 已保存为问题 03 的修改建议”，旁边留一个“重新保存”。判断依据是问题的 `discussed_message_id` 等于这条消息的 id。后端 Finding 输出补上这个字段，只是读取，不用迁移。
2. **问题卡标题行加标记**：有讨论稿时显示“讨论稿”标签，选用讨论稿时标签用主色，折叠状态下也看得到。
3. **保存后默认选用讨论稿**：后端已经这样处理，前端改为用保存接口的返回值直接更新结果页里的这条问题，不需要刷新。
4. **“保存并采纳”**：保存对话框加一个按钮“保存并采纳”（主按钮），原来的“保存”降为次按钮。“保存并采纳”就是先保存，再把处理状态设为“已采纳”，接连调用两个现有接口；第二步失败时，提示“已保存，采纳未成功，请在问题卡上重试”。
5. 对话框关闭后，不再在右下角弹“已保存”的提示，改由第 1、2 条在原处反馈（与 E-01 的做法一致）。

## 四、改动范围

* 前端：`Assistant.vue`、`ReviewPane.vue`、`RunResult.vue`、`FindingsRail.vue`（隐藏不卸载）、`FindingCard.vue`（标题标记，另做精简版）、`DraftDialog.vue`、`MessageItem.vue`、`Conversation.vue`、`api/runs.ts`。
* 后端：问题输出加 `discussed_message_id`（`review/service.py` 的 `_View.finding`）。不改脱敏、出口复检和网关；发给模型的内容不变，仍然只有该问题的结论和相关条款（已脱敏）。
* SPEC 中工作台讨论的那一节同步改写。
* 测试：前端构建；后端在现有讨论稿用例中加一行断言，检查 `discussed_message_id` 有返回。改完后在浏览器里走一遍：讨论、返回、保存、保存并采纳。
