# V321-E-06 上传到审核一步确认、解析阶段（方案，待用户确认）

对应 V321Q-32。只动“全面审核”入口；从“直接提问”加文件的流程不变（仍是全屏“确认脱敏”，只确认、不发起审核）。

## 一、现状与原因

从“全面审核”首页拖入文件后，用户要走四步：

1. 解析中：设置页已经出现“已确认的 0 个文件……”“主体说明：无”、灰掉的模型下拉，底部写“文件正在解析，请稍候”；抽屉里只有不定进度条和“已用 n 秒”。
2. 解析完：`FilePanel` 自动弹出全屏“确认脱敏”（会话模式），右栏底部按钮是“确认脱敏”。
3. 确认后回到设置页，再选一次我方（确认页里刚选过）、立场、来源、模型。
4. 再点“确认发送并开始审核”。

我方在第 2、3 步各选一次；确认页的回执看不到立场带来的“主体说明”；解析不知道进行到哪。

## 二、新流程：解析阶段 → 确认页（带审核设置）→ 审核中

```
首页拖入 ─▶ ① 解析阶段（审核视图内）─▶ ② 确认页（审核视图内，不再弹全屏）─▶ 审核中
```

### ① 解析阶段

解析中（`status = parsing`）审核视图只显示这一块，不再显示设置页的空内容：

```
┌ 正在本机解析 · 已用 42 秒 ─────────────────────────┐
│ [PDF] 采购合同.pdf      OCR 第 3 / 12 页  ▓▓▓░░░░ │
│ [DOC] 补充协议.doc      转换旧格式…               │
│ [XLS] 报价单.xlsx       等待                      │
│ 识别敏感信息与本地校验  等待                      │
│ 文件不离开本机，可以离开页面，稍后回来继续。       │
└────────────────────────────────────────────────────┘
```

* 每个文件一行，阶段为：等待 / 转换旧格式 / 读取正文 / OCR 第 x / N 页 / 完成 / 失败（失败原因沿用现在的 `error_message`）。最后一行是整批的“识别敏感信息与本地校验”。
* 只有 OCR 有确定的页数，才画确定进度条；其他阶段只显示文字，不画假进度。
* 解析失败时这一块换成失败说明和“移除该文件”，不跳确认页。

**后端上报**：`jobs` 表加一列 `progress`（JSONB，Alembic 迁移），内容只有 `{file_id, stage, done, total}`，不含文件名和正文。解析线程通过一个小函数写入，用独立的短会话提交（与现在的心跳同一做法；解析主事务锁着任务行，不能写在任务行或文件行上），同一文件每秒最多写一次。OCR 页数由 `pdf.parse_pdf` 增加一个可选的每页回调得到。会话详情 `SessionDetail` 加 `parse_progress`，从该会话正在执行的 parse 任务读取；前端沿用现有的 3 秒轮询，不加新接口。审核任务（`kind = review`）走同一个 `_parse_file`，顺带受益。

### ② 确认页（带审核设置）

解析完成、有待确认文件时，审核视图直接内嵌 `ConfirmWorkbench`（不弹全屏对话框；顶部仍有工作台工具条，可以随时切回“直接提问”）。新增一个模式 `session-review`，右栏结构：

```
签约方与我方（选一次，必选）
不确定项
文件（待确认的文件 + 已确认的文件；每行一个“参与本轮”勾选，主文件标记沿用）
──────────── 右栏底部（固定） ────────────
业务立场  [销售][采购][其他]   按我方为买方带出
文件来源  [对方发来][我方拟定]  （沿用上次）
审核模型  （模型名）           （只有一个时显示文字）
＋ 补充说明    查看审核要求
即将发送给（模型名）：正文 12,345 字 · 已保护 86 处
主体说明：甲方为我方，中国，公司 …     查看将发送的全文
[ 确认并开始审核 ]        ← 唯一主按钮
```

* 我方只在“签约方与我方”选一次，立场按我方的买方 / 卖方标签自动带出（`ReviewPane` 现有逻辑搬过来），用户可改；改与标签不一致时给提示。
* 回执和“查看将发送的全文”改为显示审核外发正文（含【主体说明】和补充说明脱敏后的样子），与实际发送一致。
* 提交条件清单沿用现在的写法，增加“请选择业务立场”“没有可用的审核模型”。
* 键盘：会话模式现在关闭了快捷键；`session-review` 模式打开，与审核任务的确认页一致（Ctrl+Enter 只聚焦按钮）。

**后端：一次调用完成“确认 + 发起审核”。** 会话发起审核接口 `POST /assistant/sessions/{id}/runs` 加一个参数 `confirm_pending: true`：在同一事务、同一把任务行锁里先执行现有的确认逻辑（`assistant.confirm`），再执行现有的发起审核逻辑。`expected_material_version` 按确认前的版本核对。这样不会出现“文件已确认、审核没发起”的半截状态，也不用前端先确认、再取预览、再发起三次往返。外发预览接口 `outbound_review` 同时允许 `include_pending`，让确认页在确认前就能看到审核外发正文。出口复检、网关、对照表都不改。

### ③ 第二轮及以后

* 已有结果后再加文件：结果页“新一轮”进入设置时，若有待确认文件，同样进入 ② 的确认页（已确认的文件在“文件”一节默认勾选参与本轮）。
* 没有待确认文件时，“新一轮”仍是现在的设置页，但去掉“请先确认脱敏”的提示块和解析中的空内容，选我方挪到页面上方的“主体说明”行（只在没选过时出现）。

## 三、不变的部分

* “直接提问”里加文件：仍弹全屏“确认脱敏”，只确认。
* 不外发（`local_only`）的会话：仍只显示本地校验。
* 审核中的舞台（`ReviewCeremony`）不改；按 ui-polish.md 在“精简”档下复查一次静态画面。

## 四、改动范围

* 前端：`ReviewPane.vue`（解析阶段块；有待确认文件时内嵌确认页；设置页清理）、`ConfirmWorkbench.vue`（`session-review` 模式与右栏底部设置）、`FilePanel.vue`（审核视图里不再自动弹全屏确认）、`Assistant.vue`（传参）、`api/assistant.ts`。
* 后端：`tasks/pipeline.py` 与 `parsing/pdf.py`（阶段上报）、`jobs` 迁移、`assistant/service.py`（`parse_progress`、`outbound_review` 的 `include_pending`）、`review/service.py`（`confirm_pending`）。
* SPEC 中工作台审核流程一节改写。
* 测试：后端两条——`confirm_pending` 一次调用后文件已确认且有一轮排队；`material_version` 过期时整个回滚、文件仍未确认。前端构建。浏览器走一遍：拖入 PDF + 旧格式文件 → 看阶段 → 确认页选我方 → 一键开始；再加一个文件走第二轮。
